# Рендерер C++: конвейер и паритет с `gm/render.py`

Статус: M4.1/M4.2 частично, M4.4.1/M4.4.3 частично. Код:
`engine/src/render/render.{h,cpp}`, CLI — `--render`/`--level`/`--model`.

## 1. Что уже рисуется

```
.sbw (таблицы + геометрия) ─┐
                            ├─ build_level_meshes → RenderMesh{vertices(world), local, faces}
заголовок объекта (4×f32) ──┘        world = origin + basis × local
                                      local = (world − origin) / |basis_x|

.sbc (лайтмапы) ──────────── Lightmaps: page = records[poly.lightmap − 1]
.sob (модели) ────────────── build_model_meshes (uv_scale = 1/65536)
PICS/SBM.IDX ─┐
sprites/SBM.IDX ├─ AssetCache → SBM → палитра установки → RGB
LOOK16.BMP ───┘
```

Камера: авто-fit по AABB сцены (az/el/zoom/fov) либо явная `--pos/--look`.
Растеризатор: z-буфер, near-clipping (Sutherland–Hodgman, интерполяция UV в
view-space), перспективно-корректные UV, fan-триангуляция, ближайший тексель,
маска страницы лайтмапа, два прохода материалов (`translucent` — mix 0.5, прочие —
add/sub с весом `material+0x2c / 127`).

## 2. Точность

Вся математика — **`double`**, сборка с `-ffp-contract=off`. Это не
косметика: `float32` сдвигает выборку текселей, а FMA-контракция (clang по
умолчанию `-ffp-contract=on`) меняет последний бит в `dot()` и ломает
побитовое совпадение. После этих двух правок кадры совпадают полностью.

Сверка с `gm/render.py` (одинаковые параметры, RGB без альфы, FNV-1a 64):

| кадр | параметры | FNV |
|---|---|---|
| `20mmclp.sob` | 160×160, текстуры | `c376475e890d6879` |
| `MOCLASS.SOB` | 160×160, текстуры | `dff93879e03ce1ab` |
| `code492.sob` | 160×160 | `d3fa091674e86a7a` |
| `desertpc.sob` | 160×160 | `1de0c4538c49b7c7` |
| `moonfb.sob` | 160×160 | `4fb421bc5a2ff221` |
| `level0` | 320×200, orbit | `20e80d077fd4f6bc` |
| `level0` | 320×200, pos (0,0,600) → (0,0,0) | `9e54d79f29ac47c6` |
| `level0` | то же + `--clip 300` | `a4ccdd84a43ca565` |
| `LEVEL10` | 320×200, интерьер | `25e40d77af2f01ba` |

Все константы зашиты в `engine/tests/test_main.cpp` (`test_render`); сравнение
не требует Python в runtime. Диапазон кадров — модели/уровни/интерьер/обрезка.

## 3. Два намеренных отличия от вьювера

1. **Лайтмапы.** `gm/render.py` считает `u/v` от *world*-вершины, хотя
   `poly.centre` и оси — в локальном кадре объекта. Движок сравнивает в одном
   кадре, поэтому C++ по умолчанию использует локальную вершину. Для сверки с
   вьювером есть `--lm-world` (в тестах включён).
2. **`--clip`.** Вьювер меряет расстояние от `face.origin` (у `LevelFace` это
   локальный центр). C++ повторяет это ради паритета; для «правильной» обрезки
   это не образец.

Обе точки помечены в коде и в этом файле; при съёмке эталонов из игры
приоритет — движковая семантика, а не вьювер.

## 4. Производительность

`build/release`, headless, 640×400, steady state (200 кадров):

| уровень | полигоны | FPS |
|---|---:|---:|
| `level0` | 1 449 | ~250 |
| `LEVEL10` | 9 188 | ~130 |

Первый кадр включает ленивую загрузку текстур (SBM/палитра) — на 40-кадровом
замере это даёт «60 FPS»; мерить нужно после прогрева. Debug-сборка медленнее
на порядок, для профилирования/паритета использовать Release.

## 5. Что ещё не сделано (честно)

- 8-битный палитровый framebuffer, апскейл 320×200/640×400 — нет (рисуем RGB).
- Mip-уровни/фильтрация/прозрачный индекс — нет (mip0, nearest, wrap).
- Точная математика смешивания материалов из `gundx.exe` — нет (веса вьювера).
- Скайбокс/туман/подводная палитра, спрайты, частицы, HUD — нет.
- Спавн игрока/первое лицо: камера свободная, позиция из скриптов не читается
  (зависит от SBT-VM/сцен).
- Эталоны из самой игры не сняты; текущий эталон — `gm/render.py`.

Репро:

```
export PATH=$HOME/tools/cmake-4.4.4-linux-x86_64/bin:$HOME/tools/bin:$PATH
cmake --build build/release -j 32
./build/release/engine/gunmetal --render out.png --level level0 --width 320 --height 200
./build/release/engine/gunmetal --headless --level LEVEL10 --frames 200
```
