# Контейнер `.sou`: SOU0 / SOU1 / SOU2

Документ закрывает **контейнерный** слой звуков Gunmetal: заголовки, длину,
хвосты, статистику и побайтовый writer. Кодеки описаны отдельно:
`docs/SOU1.md` (4-битный ADPCM) и `docs/FORMATS.md` §5 (формат 4 / SOU2).
Здесь нет декодирования звука — только байты контейнера.

Проверено на всей поставке:

| архив | записей | `parse` | `parse -> rebuild` побайтово |
|---|---:|---:|---:|
| `sounds/SOU.IDX` | 999 | 999/999 | **999/999** |
| `MUSIC/SOU.IDX` | 3092 | 3092/3092 | **3092/3092** |
| итого | 4091 | 4091/4091 | **4091/4091** |

FNV-1a64 склеенных rebuild-байтов в порядке индексов (sounds, затем music):
`0xbc564b7575f5b7a9`. Прогон: ~22 с на `/mnt/d`.

## 1. Раскладка

```
SOU0 / SOU1                       SOU2
--------------------------        --------------------------
char magic[4]   "SOU0"/"SOU1"     char magic[4]   "SOU2"
u32  sample_rate                  u32  sample_rate
u32  flags       0 или 1          u32  frames     >0, кратно 32
u32  length      байты payload    u32  meta2      хранится, игра не читает
u8   payload[length & ~1]         u32  units      payload = units * 4 байт
                                  u8   payload[units * 4]
```

Все числа little-endian. Заголовок SOU0/SOU1 — 16 байт, SOU2 — 20 байт,
выравнивания и padding между заголовком и payload нет.

### Магические строки

Загрузчик `0x40af30` читает 4 байта и проверяет `"SOU"` + цифру `0/1/2`
(`0x40afc0..0x40afea`); других вариантов нет. Строк `"SOU0"`/`"SOU1"`/
`"SOU2"` в exe нет: цифра подставляется кодом, базовая строка `"SOU"` лежит
по VA `0x4a689c` и имеет ровно одну ссылку — `0x40af77` (обёртка загрузки).

### `flags` (SOU0/SOU1)

Загрузчик берёт **младший байт** (`and edx,0xff`, `0x40b055`) и требует
`<= 1`; бит 0 = стерео. Старшие байты кода не интересуют, но `gm/sou.py`
считает слово `> 1` ошибкой (в поставке только 0/1).

Стерео в поставке — **6 записей** (все SOU1, 32 кГц): `CUT-EMP`, `CUT-PAM`,
`CUT-PREZ`, `INTRO`, `VRCHAMBR`, `VRCHAMHQ`. Ещё 3 стерео-записи — SOU2
(`FINALE`, `OVERTURE`, `WINNER`).

### `length` и правило `& ~1`

`length` — число байт payload. Загрузчик перед `malloc`/чтением делает
`and al,0xfe` (`0x40b0dd`), то есть читает `length & ~1` байт. Это не
косметика: в поставке **481 запись** имеет нечётный `length`.

* 478 из них (8 SOU0 + 470 SOU1) имеют `length == размер файла - 16`; последний
  байт файла загрузчик **не читает** (он остаётся хвостом).
* 3 стерео-записи (`CUT-EMP`, `VRCHAMBR`, `VRCHAMHQ`) имеют
  `length == payload + 1`; после `& ~1` читается ровно payload, хвоста нет.

`Sou.payload` в `gm/sou.py` — это именно прочитанные загрузчиком байты,
а неиспользованный байт/хвост лежит в `Sou.trailer`. Поэтому rebuild не
теряет ни байта.

Загрузчик также требует `length > 0` (для SOU0/SOU1) и `sample_rate > 10`
(`cmp ebx,0xa; jle`, `0x40b0a3`).

### SOU2: `frames`, `meta2`, `units`

Загрузчик (`0x40b0ac..0x40b160`) для SOU2:

1. читает `sample_rate` (смещение 4);
2. читает поле 8 (`frames`) и требует `> 0` **и** `frames & 31 == 0`;
3. читает поле 12 (`meta2`), но **не использует** его;
4. читает `units` (смещение 16), требует `units > 0`;
5. выделяет и читает ровно `units * 4` байт.

`meta2` — единственное поле, которое не влияет на загрузку; в поставке оно
произвольное (например, `DM1A01`: `0xca70f895`), поэтому writer обязан
сохранять его как есть.

Аномалии поставки, которые загрузчик отклонит, но контейнер обязан
round-trip-ить:

| запись | почему |
|---|---|
| `L04I01` | `frames = 0`, `units = 0`, файл ровно 20 байт |
| `L06A01` | `frames = 1` (не кратно 32), `units = 0`, плюс хвост **90 592** байта |

Это единственный реальный хвост в корпусе (`units * 4 = 0`, payload пуст).
Ещё один «хвост» — 478 однобайтовых нечитаемых байт из правила `& ~1` выше.
Итого `ignored_bytes`: sounds 478, music 90 592.

## 2. Статистика

`gm/sou.py::stats(entries)` принимает `bytes` или `(name, bytes)` и не
импортирует кодеки, поэтому считается по всему архиву быстро. Поля:
`entries, parsed, bad, bytes, payload_bytes, frames, seconds, formats, rates,
channels, loadable, ignored_bytes, with_trailer, anomalies, errors`.

Поставка:

| | sounds | music | всего |
|---|---:|---:|---:|
| записей | 999 | 3092 | 4091 |
| байт | 26 738 998 | 75 628 172 | 102 367 170 |
| payload | 26 722 524 | 75 475 740 | 102 198 264 |
| форматы | SOU0 13, SOU1 983, SOU2 3 | SOU2 3092 | SOU0 13, SOU1 983, SOU2 3095 |
| частоты | 8000 — 364, 16000 — 617, 32000 — 18 | 16000 — 2, 32000 — 3090 | — |
| каналы | mono 990, stereo 9 | stereo 3092 | mono 990, stereo 3101 |
| кадров | 52 046 400 | 224 059 265 | 276 105 665 |
| секунд | 2 680.187 | 7 015.151 | 9 695.338 |
| loadable | 999/999 | 3090/3092 | 4089/4091 |
| ignored bytes | 478 | 90 592 | 91 070 |

Формулы длительности (без декодирования):

* SOU0: `frames = len(payload) / channels`.
* SOU1: `frames = 2 * len(payload) / channels` — байт даёт две 4-битные
  выборки на канал.
* SOU2: `frames` из заголовка (для `L04I01` — 0).
* `seconds = frames / sample_rate`.

`loadable` — это проверка **заголовка** загрузчиком (`0x40af30`), а не
декодера. Обе «плохие» записи SOU2 всё равно импортируются и
rebuild-ятся побайтово; это важно для `--check`, который не должен падать
на поставочных аномалиях.

## 3. Writer (`gm/sou.py`)

* `Sou.to_bytes()` — структурная сборка из полей.
* `Sou.rebuild()` — то же плюс проверка, что результат равен `Sou.raw`
  (для распарсенного поставочного файла). Несовпадение — `ValueError`.

Правила:

* SOU0/SOU1: сохраняются `sample_rate`, `flags`, **исходный** `length`
  (включая нечётный) и `trailer`; если payload отредактирован, длина
  пересчитывается как чётная (`len(payload)`).
* SOU2: сохраняются `frames`, `meta2` и `trailer`; `units` пересчитывается
  из `len(payload) // 4`, payload обязан быть кратен 4.
* Никакой нормализации поставочных файлов нет: 481 нечётная длина и хвост
  `L06A01` воспроизводятся байт в байт.

Writer в `gundx.exe` **отсутствует**. Доказательства:

* единственная ссылка на строку `"SOU"` (`0x4a689c`) — `0x40af77` внутри
  загрузчика;
* все три вызова `0x40af30` (`0x40ae1e`, `0x40ae51`, `0x40af00`) — пути
  загрузки сэмпла;
* в exe нет строк/режимов записи для `.sou` (режимы `wb` есть только у
  `look16.tab`, `look162.tab`, `.sbc`, `.sbw`, `.sbm`, `.sbt`);
* ни один участок кода не собирает заголовок `SOU0/1/2`.

Следовательно, `.sou` — read-only формат для игры; пересборка допустима
только инструментами проекта.

## 4. `tools/re/sou_container.py`

Только stdlib + `gm`. Игра открывается на чтение; вывод — только в
`--rebuild DIR`, причём каталог внутри установки запрещён.

```sh
python3 tools/re/sou_container.py --check
python3 tools/re/sou_container.py --stats --json
python3 tools/re/sou_container.py --rebuild /tmp/opencode/sou-out --force
python3 tools/re/sou_container.py --self-test
```

* `--check` — 4091/4091 parse + rebuild + повторный parse, FNV, статистика,
  плюс негативные тесты (15/15).
* `--stats --json` — та же статистика без декодирования; `--source
  sounds|music` ограничивает набор.
* `--rebuild DIR` — пишет `DIR/sounds/<NAME>.sou` и `DIR/music/<NAME>.sou`
  атомарно (temp + `os.replace`), имена пропускаются через
  `bigfile.safe_name`; после записи файл перечитывается и сравнивается с
  исходником. Существующий файл заменяется только с `--force`.
* `--self-test` — пустой blob, битая магия, короткие заголовки, `rate = 0`,
  `flags = 2`, `length = 0xffffffff`, `units > MAX`, обрезанные payload
  SOU1/SOU2, нечётная длина, SOU2 `units=0` + хвост, редактирование payload,
  политика перезаписи.

Лимиты (`gm/sou.py`): `MAX_PAYLOAD = 64 MiB`, `MAX_SOU2_UNITS = 16 777 216`,
`MIN_RATE = 10`, `MAX_RATE = 1 000 000`. Это защита от враждебного архива,
а не ограничение формата: максимум поставки — 3 126 040 байт.

## 5. Интеграция в `gm.py` (предложение, не применено)

`gm.py` не менялся. Минимальные строки, если контейнерные команды нужны в
основном CLI:

```python
# cmd_sounds(): после цикла по bf.entries
st = sou.stats((e.name, e.data(dat)) for e in bf.entries)
print(f"  container: {st['formats']} {st['channels']} "
      f"{st['seconds']:.1f} s, bad={st['bad']}")
```

```python
# новый подкомандный режим: gm.py sounds <game> <out> --rebuild [--force]
if opts.rebuild:
    target = os.path.join(opts.out, "containers")
    for e in bf.entries:
        snd = sou.parse(e.data(dat))
        path = os.path.join(target, bigfile.safe_name(e.name) + ".sou")
        if os.path.exists(path) and not opts.force:
            raise SystemExit(f"refusing to overwrite {path} (use --force)")
        # запись через temp + os.replace, как в tools/re/sou_container.py
```

Политика `--force`:

* по умолчанию существующие файлы не перезаписываются — ошибка, а не
  «тихая» замена;
* `--force` разрешает замену, но только в выходном каталоге, не в
  установке игры;
* каталог игры проверяется через `realpath`/`commonpath` и всегда
  read-only;
* после записи — повторный `sou.parse` и сравнение с исходным blob
  (для неизменённого контейнера обязано быть побайтово).

## 6. Ограничения

* `stats` не проверяет, что декодер принимает payload: для SOU1 это делает
  `gm/sou1.py`, для SOU2 — `gm/sou2.py`. Контейнерный слой сознательно
  отделён.
* `Sou.to_wav()` для SOU1/SOU2 делегирует кодекам; для SOU0 пишет WAV из
  прочитанных байт (при нечётной длине последний байт не входит — так же,
  как у загрузчика).
* `meta2` SOU2 сохраняется, но его смысл не установлен; игра его не читает.
* `L04I01`/`L06A01` остаются в статистике как `loadable=False`; это факт
  поставки, а не ошибка парсера.
* `docs/FORMATS.md` и `ROADMAP.md` в этой задаче не менялись: актуальная
  контейнерная спецификация — этот файл, кодек — `docs/SOU1.md` и
  `docs/FORMATS.md` §5.
