# Gunmetal — перепись мира по 36 поставочным уровням

Что здесь: независимый **тест-перепись** корпуса (`engine/tests/test_world_census.cpp`,
CTest `world_census`) — он загружает все 36 пар `.sbt`/`.sbw` теми же C++-загрузчиками,
что и движок, печатает строку на уровень и сверяет суммы с числами `ROADMAP.md`
`M6.5.4` и `docs/AUDIT_NUMBERS.md`. Python-оракул `gm.py` во время прогона **не
используется**: golden-константы зашиты в тест, как и положено для C++-паритета.

Статус: тест зелёный, **все 7 основных чисел совпали, 0 WARN**
(2026-10-24, установка v1.36 `/mnt/d/games/Gunmetal 3dfx`, зеркало
`~/.cache/gunmetal-re/game` даёт те же числа).

## 1. Что именно считается

Все счётчики берутся из структур, которые вернули загрузчики, а не из полей
заголовков «на веру»: где файл и распарсенное представление расходятся, тест
падает (`inconsistent .sbw totals`).

| категория | поле / источник | определение |
|---|---|---|
| уровень | `parse_sbt` + `parse_sbw` | `.sbt` в **корне** установки, у которого есть одноимённый `.sbw`. Множества `*.sbt` и `*.sbw` обязаны совпадать — иначе тест падает, а не молча пропускает мир. `SAVEGAME/*.sbt` не уровни и не читаются. |
| сектор | `SbwHeader::sectors` | число секторов в шапке `.sbw` (5104 на корпус). |
| объект | `SbwSectorRef::objects` | сумма объектов по секторам. `parse_sbw` строит ровно один `SbwGeometry` на объект, поэтому дополнительно проверяется `geometry.size() == objects == header.object_count`. |
| полигон | `SbwGeometry::polys` | сумма `polys.size()` по всем объектам; сверяется с кэшем парсера `SbwLevel::total_polygons` (его же пинует CTest `sbw_transform`). |
| вершина | `SbwGeometry::vertices` | локальные вершины объектов, сумма; сверяется с `SbwLevel::total_vertices`. |
| дверь | `WorldStats::doors` | число записей `ADD_DOOR` (184) в `SCRIPT` (поставка: записей `DOOR` типа 2 нет ни в одном из 36 файлов), либо записей `DOOR` в сейвоподобном `.sbt`. **Одна запись = одна створка** с `(sector, object)`; `Door::id` — первый ненулевой из `ids[0..2]` (ключ `GENERATE`), `Door::kind = flags & 0xf`. Это не «все створки в мире» и не «пары дверь-переключатель»: переключатель живёт отдельной записью (§ниже). |
| переключатель | `WorldStats::switches` | число записей `ADD_SWITCH` (183) / `SWITCH` (тип 1). Это **запись триггера** с `target`, а не пара «дверь-переключатель»: один переключатель может открывать группу дверей (все, у кого `ids[0..2] == target`), а одну дверь могут вести разные переключатели. `Switch::id` — индекс записи (в формате нет отдельного id). |
| лифт | `WorldStats::lifts` | число `ADD_LIFT` (188) блоков в `SCRIPT` либо записей типа 18 (в поставке — 0). Версия/состояние — `Lift` (docs/DOORS_CPP.md §1.4). |
| остановка лифта | `Lift::stops` | сумма `stops.size()`; 151 на корпус (пинуется и `doors_full`). |

Производные счётчики (печатаются, но **не** являются пунктом `M6.5.4`):

| счётчик | определение |
|---|---|
| `bound` | двери с существующей парой `(sector, object)` в `.sbw` (`Door::bound`). Поставочные — 1779/1779, тест падает на первой же непривязанной двери. |
| `distinct` | число различных `(sector, object)` среди дверей (`WorldStats::doors_distinct_objects`). 1779 = у каждой створки свой объект. |
| `sliding` | `D4..D6 != D1..D3` (`WorldStats::doors_sliding`), 1534. |
| `linked` | `ids[3] != 0` — у двери есть событие «открылась» (`WorldStats::doors_linked`), 200. |
| `rotating` | `door_rotation_axis(door) >= 0`, т.е. хотя бы один угол `A1..A3` не нулевой, 357. |
| `door_kind1/2/3` | `Door::kind` (младший ниббл `flags`): 878 / 350 / 551. `kind = 0` (инертная дверь) в поставе не встречается. |
| `switch_world` | `Switch::kind == 0`: операнды 4..6 — мировые `x/y/z`, 531. |
| `switch_aim` | `kind == 0x101` — прицельный луч, 1855. |
| `switch_blast` | `kind == 0x102`/`0x103` — взрыв/проксимити, 1198. |
| `switch_exact` | `kind == 0x104` — точная точка, 380. |
| `switch_other` | всё остальное (0). |

### 1.1. Жёсткие и мягкие проверки

* **Жёсткие** (`MISMATCH`, `exit 1`): `levels`, `objects`, `polygons`,
  `vertices`, `doors`, `switches`, `lifts`, а также `bad_records`/`bad_bindings`
  (должны быть 0) и целостность (сумма строк = headline, `.sbw`-кэши = суммы
  по объектам, `bound == doors` на каждом уровне).
* **Мягкие** (`WARN`, счётчик `warnings`, `exit 0`): все производные
  счётчики §1. Их эталон — `docs/DOORS_CPP.md` §5.3, `docs/FORMATS.md` §12.4 и
  `tools/re/doors.py`; они уже жёстко запинены CTest `doors_full`, поэтому
  перепись держит их как диагностику, чтобы воротами оставались именно числа
  `M6.5.4`. Дрейф печатается как
  `WARN <имя> got=… reference=… delta=±…` и суммируется в `soft delta`.

Производные (мягкие) — тоже совпали, `0 warning(s)`:
`bound 1779`, `distinct 1779`, `sliding 1534`, `linked 200`, `rotating 357`,
`lift_stops 151`, `door_kind 878/350/551`,

**Расхождений, которые пришлось бы объяснять, нет.** Механика на будущее:
если разойдётся основное число, тест печатает
`MISMATCH <имя> got=… expected=… delta=±…`, считает его в `failure(s)` и
возвращает 1 (CTest красный); если разойдётся производное — печатает
`WARN <имя> got=… reference=… delta=±…`, увеличивает `warnings`/`soft delta`,
но остаётся зелёным. Числа не «подгоняются»: эталоны — константы в тесте,
рядом с каждым указан источник.

## 4. Контроль

| контроль | как сделан |
|---|---|
| сумма по уровням = headline | после прогона строки складываются заново (`accumulate`) и сравниваются с накопленным итогом поле в поле (`same_counters`); расхождение — `MISMATCH table_sum vs total` |
| заголовок `.sbw` = распарсенное | `object_count == Σ objects`, `geometry.size() == objects`, `total_polygons/total_vertices == Σ по объектам`; иначе уровень отвергается |
| все 36 пар на месте | множества stem'ов `*.sbt` и `*.sbw` обязаны совпадать; отсутствующая пара — ошибка, а не пропуск |
| привязка дверей | на каждом уровне `bound == doors`; иначе `MISMATCH` |
| битые записи | `bad_records == 0`, `bad_bindings == 0` — жёстко |
| детерминизм | **второй полный проход** перезагружает все файлы с диска и сравнивает каждую строку и итог поле в поле; расхождение — `MISMATCH determinism …` |

Детерминизм подтверждён: оба прохода дают одинаковые 36 строк и одинаковый
итог (`ok (0 warning(s), soft delta +0)`).

## 5. Запуск и время

```bash
export PATH=$HOME/tools/cmake-4.4.4-linux-x86_64/bin:$HOME/tools/bin:$PATH

      -DGM_WITH_SDL3=OFF \

# точечно (в тесте два полных прохода)
ctest --test-dir build/sandbox -R world_census --output-on-failure
# или напрямую, например с зеркалом игры вместо /mnt/d:
```

* Каталог игры: `GUNMETAL_DIR`, иначе `/mnt/d/games/Gunmetal 3dfx`; если игры
  нет — `game not installed …, skipped`, код 0.
* Время (v1.36; 2026-10-24): на `/mnt/d` (drvfs) `pass1 ≈ 2.3 с`,
  `pass2 ≈ 2.3 с`, CTest `world_census` — **5.3 с**; с зеркалом
  `~/.cache/gunmetal-re/game` по `GUNMETAL_DIR` — **≈0.24 с на проход**
  (≈0.5 с всего, те же числа: drvfs-латентность, не вычисления).
* `ctest` проверяет ещё и вывод по регулярке
  `levels=36 objects=28192 polygons=235069 vertices=357818 doors=1779 switches=3964 lifts=45`:
  переименование/потеря строки в отчёте ловится без разбора кода возврата.

## 6. Ограничения

1. **«Создаются», а не «работают».** Перепись строит `WorldState` (двери
   привязаны, switch-цели разрешены), но не тикает двери и лифты. Поведение
   доказывают другие тесты: `doors`/`doors_full` (`docs/DOORS_CPP.md` §5),
   `door_collision`, `lift_collision`, `swing_door`, `platform_carry`,
   `sim_corpus`.
2. **Тот же загрузчик.** Тест не доказывает корректность `parse_sbt/parse_sbw`
   — он доказывает, что корпусные суммы C++-загрузчика совпадают с
   запиненными числами (парсер независимо пинуют `sbw_transform`,
   `sbwmesh_*`, `sbwobj_*`, `sceneedit_roundtrip` и Python-оракул).
3. **Только корень установки.** `SAVEGAME/*.sbt` (4 файла) — сейвы, не уровни;
   их блоки дверей/переключателей считает `doors` (`saved0/1`: 25/24), а не
   перепись. Подкаталогов с `.sbw`/`.sbt` в поставе нет (проверено `find`).
4. **Только поставочные 36.** Модифицированные уровни и `--level`-фильтры не
   поддерживаются: смысл теста — весь корпус, а не выборка.
5. **Игра только читается.** Каталог установки не изменяется; артефактов тест
   не пишет.
6. **Мягкие числа не ворота.** Производные счётчики при дрейфе дают `WARN`, а
   не падение; жёстко их держит `doors_full`. Если меняется определение
   (например, «дверь» начнёт считаться иначе), обновлять надо §1 этого дока,
   константы теста и `docs/DOORS_CPP.md` §5.3 одновременно — не ослабляя
   проверку.
