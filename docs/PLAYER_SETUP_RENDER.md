# Рендер экрана 36 `PLAYER 1/2 JOYSTICK SETUP` (`engine/src/ui/player_setup_render.h`)

Срез 15 пункта `M8.8`: один кадр экрана **36** фронтенда (`gundx.exe`, ImageBase
`0x400000`) в RGBA-буфер 320×200. Модуль без состояния — рисует то, что ему
передали в `PlayerSetupRenderOptions`, и отдаёт числа (`rows`, `sliders`,
`checks`, `arrows`, `ink_pixels`, `missing_glyphs`). Шрифты, метрики и атласы —
из `render/text_layout` (`FONTS4` в `FRONTEND/BMP.IDX`), точный fade — из
`render/hud_lut`. Ничего не измеряется заново.

Код: `engine/src/ui/player_setup_render.h/.cpp`; тест —
`engine/tests/test_player_setup_render.cpp` (CTest `player_setup_render`, label
`quick`). Соседние срезы — `MOUSE_SETUP_RENDER.md` (22),
`JOYSTICK_CENTERING_RENDER.md` (26), `KEYCFG_RENDER.md` (30/34/35),
`KEY_JAMMING_RENDER.md` (16), `MENU_RENDER.md` (общая механика `0x485dd0`),
`CONFIG.md` §5/§6 (структуры джойстика).

## 1. API

```cpp
#include "ui/player_setup_render.h"

gm::PlayerSetupRenderOptions options;   // умолчания = .data/.bss движка (§2.7)
options.joystick = 0;                   // [0x4bc540/44]: -1 = "Joystick Used: None"
options.joystick_name = "SideWinder Precision Pro";  // 0x4bf7f0 + dev*0x7c, %.30s
options.axes = {1, 2, 3, 4, 5, 6};      // 0x68cd00 + dev*6, пресеты 0..17
options.hats = {0, 8, 10, 0};           // 0x68cd30 + dev*8, пресеты 0..17
options.cursor = 0;                     // [0x68ccf4], строка содержимого
options.background = "PLATE";           // "" = чёрный холст

std::vector<std::uint32_t> rgba;        // 0xRRGGBBAA
int width = 0, height = 0;
gm::PlayerSetupRenderStats stats;
std::string error;
if (!gm::render_player_setup(game, options, rgba, width, height, &stats, &error)) {
    // error: текст с префиксом "player_setup_render: "
}
// width=320 height=200, rgba.size()==64000
// stats: rows=43 sliders=0 checks=0 arrows=1 ink_pixels=3257 missing_glyphs=0
```

| Поле `PlayerSetupRenderOptions` | По умолчанию | Смысл |
|---|---|---|
| `std::string background` | `""` | запись `FRONTEND/BMP.IDX`, рисуется в (0,0); `"PLATE"` — панель экрана; пусто — чёрный холст |
| `int cursor` | `0` | `[0x68ccf4]` = **индекс строки содержимого** (0 — имя устройства, 1..6 — оси, 7..10 — хаты, 11..42 — каналы кнопок); он же задаёт верх окна `max(0, cursor-5)`; вне диапазона ничего не подсвечивает (`-1` — кадр без белой строки) |
| `int player` | `0` | `[0x685afc]`: 0 — `PLAYER 1 JOYSTICK SETUP` (`0x4bd9c0`), иначе `PLAYER 2…` (`0x4bd9a8`); выбор слота устройства — уже в `joystick` |
| `int joystick` | `-1` | `[0x4bc540]`/`[0x4bc544]`: `-1` = не назначен (`.data`), иначе индекс DirectInput-устройства `0..7` (`cmp edi,8` в `0x404880`) |
| `std::string joystick_name` | `""` | имя устройства `0x4bf7f0 + dev*0x7c` как `"%.30s"` (`.bss`, заполняет опрос DirectInput); 30 байт — предел |
| `std::array<int,6> axes` | `{0,0,0,0,0,0}` | `0x68cd00 + dev*6 + i`, индексы в `kPlayerSetupPresetNames` (0..17, кламп) |
| `unsigned axis_present` | `0x7E` | биты наличия осей `[0x4bf7e0 + dev*0x7c]` (0x02..0x40); все шесть — модель «полного устройства» (биты ставит перечисление DirectInput) |
| `std::array<double,6> axis_values` | нули | живые отклонения `0x4bf7b0 + dev*0x7c + i*8`; `|v| >= 0.5` красит **подпись** оси шрифтом 5 |
| `std::array<int,4> hats` | `{0,0,0,0}` | `0x68cd30 + dev*8 + 0..3` (Hat 1 X/Y, Hat 2 X/Y), пресеты 0..17 |
| `bool hat1` / `bool hat2` | `true` / `true` | биты `0x100`/`0x200` того же dword: пара строк хата; обе — модель |
| `unsigned hat_bits` | `0` | `[0x4bf7ec + dev*0x7c]`: биты `0x0A/0x05/0xA0/0x50` красят подпись соответствующего хата шрифтом 5 |
| `std::array<int,32> buttons` | `{0x20,0x8000,-1…}` | `0x4aa490 + dev*0x80`: маски каналов, `-1` = `None`; `.data` = `Fire`, `Activate` |
| `unsigned pressed_buttons` | `0` | `[0x4bf7e8 + dev*0x7c]`: бит канала -> вся строка `Button N` шрифтом 5 |
| `bool fade_lut` | `false` | точный fade `0x682f90` по палитровым индексам |
| `int fade_lut_level` | `11` | 0..15; 11 — тождество, 12..15 светлеют |
| `std::string fade_lut_dump` | `""` | дамп 4096 Б (`load_hud_lut`) |
| `const HudLut* fade_lut_table` | `nullptr` | готовая таблица, приоритетнее дампа |

Публичные помощники (нужны тесту и будущему CLI): `player_setup_row_y(row)`,
`player_setup_scroll(cursor)`, `player_setup_value_x(row_face)`,
`player_setup_rows(options)`, `player_setup_content_rows(options)`,
`player_setup_preset_name(index)`, `player_setup_action_name(index)`,
`player_setup_button_text(channel, mask)`.

`PlayerSetupRenderStats`: `rows` — счётчик самого обработчика `[0x67f10c]`
(1 без устройства, `33 + оси + 2*хаты` с устройством: он заранее считает 32
канала кнопок); `sliders` и `checks` — **всегда 0** (на экране нет ни
`SLIDE`/`KNOB`, ни `CHECK`/`NOCHECK`); `arrows` — число спрайтов `MENUARRW`
(0..2); `ink_pixels` — уникальные пиксели глифов (плата и спрайт стрелки не
считаются, как в соседних модулях); `missing_glyphs` — байты без глифа
(пропускаются, не фатальны).

Контракт буфера: при отказе `rgba` очищается, `width`/`height` = 0, статистика
обнуляется; `stats`/`error` могут быть `nullptr`. Функция только читает
установку, детерминирована, не зависит от текущего каталога.

## 2. Доказано (листинг + данные)

Инструмент: `python3 tools/re/disrange.py`, данные — `tools/re/exelib.py`.
**Обработчик — `0x489d60`** (таблица `0x4883d8`, id 36; `ui_screens.py --json`
даёт `rows 1/33`, `step 9`, `assets plate/fonts`). Диспетчер `0x487e71` кладёт
`eax = [0x4bc440] - 5`, поэтому id 36 — это слот `0x4883d8 + 31*4 = 0x488454`;
его stub `0x487f51` — `call 0x489d60; jmp 0x487f64` (аргумент не кладётся,
обработчик сам читает глобалы). Тело — `0x489d60`..`0x48a2a4` (`ret`), плюс
приватный помощник строки оси `0x48a2b0`.

### 2.1. Пролог и геометрия

| Факт | Где |
|---|---|
| `al = [0x685afc]`, `ebx = [0x4bc540]`, при `al != 0` — `[0x4bc544]` | `0x489d60`, `0x489d76` |
| `step = 9` (`0x662d58`) | `0x489d7e` |
| `rows = 1` без устройства / `33` с устройством (`0x67f10c`) | `0x489d88`..`0x489d91` |
| копия `PLATE` 196×131 в `0x6865f8` | `0x489d96` → `0x486050` |
| окно: `esi = max(0, [0x68ccf4] - 5)` | `0x489dd6`..`0x489dec` |

`0x485dd0(font, text, centered, x, row, item)` пишет в копию платы: при
`item == -1` `row` — абсолютный `y`; при `centered = 1` `x` заменяется на
`(196 - width)/2`; при `row >= 0` `y = row + item*step`; при `item ==
[0x68ccf4]` и шрифте 0 шрифт принудительно 4 (`0x485e0d`..`0x485e19`). Клип —
196×131. Поэтому **все** строки ниже вызваны с отрицательным `row`
(`0xffffffe4 = -28` и далее) и абсолютным `y = 28 + 9*(c - scroll)`.

### 2.2. Заголовок и подсказка

| текст | VA | шрифт | `centered` | `x` | `row` | `y` | сайт |
|---|---|---:|---:|---:|---:|---:|---|
| `PLAYER 1 JOYSTICK SETUP` | `0x4bd9c0` | 5 | 1 | 38 | 11 | 11 | `0x489d9b`..`0x489dba` |
| `PLAYER 2 JOYSTICK SETUP` | `0x4bd9a8` | 5 | 1 | 38 | 11 | 11 | там же (ветка `al != 0`) |
| `Esc Exit, Button To Highlight` | `0x4bd988` | 0 | 1 | 20 | 20 | 20 | `0x489dc2`..`0x489dd1` |

Обе строки передают `item = -1` (`push 0xffffffff`), поэтому не подсвечиваются
никогда.

### 2.3. Строка 0 — устройство

* Устройство не назначено (`ebx == -1`): `sprintf("Joystick Used: None")`
  (`0x4bd974`) и одна строка `x 13`, `y 28`, шрифт 0, `item = 0`
  (`0x489df9`..`0x489e36`); если `scroll > 0`, обработчик выходит сразу
  (`jg 0x48a29d`) — ни строк, ни стрелок.
* Устройство назначено: `call 0x404880(slot)` (проверка/обновление устройства),
  затем `sprintf("%.30s", 0x4bf7f0 + slot*0x7c)` — **одно имя без префикса** —
  `x 13`, `y = 28 - 9*scroll`, шрифт 0, `item = 0`
  (`0x489e41`..`0x489e8e`). Строка рисуется только при `scroll == 0`.

### 2.4. Шесть строк осей (`0x48a2b0`)

Перед циклом обработчик один раз измеряет `"Front/Back: "` (`0x4bd95c`,
шрифт 0) и запоминает ширину в `edi` (`0x489e91`..`0x489e9d`); колонка
значений — `edi + 13` (`lea edx,[edi+0xd]`) для **всех** осей и хатов, т.е.
фиксированная, а не своя у каждой подписи. На поставочном `FONTS4` ширина 54,
колонка `x = 67` (печатает тест).

| ось | бит наличия | маска | текст | VA | значение (`0x68cd00 + dev*6 + i`) |
|---:|---:|---:|---|---|---|
| 0 | 0x02 | `push 0x2` | `Left/Right: ` | `0x4bd94c` | `0x68cd00` |
| 1 | 0x04 | `push 0x4` | `Front/Back: ` | `0x4bd95c` | `0x68cd01` |
| 2 | 0x08 | `push 0x8` | `Up/Down: ` | `0x4bd940` | `0x68cd02` |
| 3 | 0x10 | `push 0x10` | `Angular X: ` | `0x4bd934` | `0x68cd03` |
| 4 | 0x20 | `push 0x20` | `Angular Y: ` | `0x4bd928` | `0x68cd04` |
| 5 | 0x40 | `push 0x40` | `Angular Z: ` | `0x4bd91c` | `0x68cd05` |

Сайты: `0x489eaf`/`0x489ec8`/`0x489ee1`/`0x489efa`/`0x489f13`/`0x489f2c`
(маски), тексты — `0x489ea8`..`0x489f25`. Помощник `0x48a2b0`:

* пропускает строку, если `[dev*0x7c + 0x4bf7e0] & mask == 0`
  (`0x48a2cb`; в карту `0x660744` пишется `-1`, `0x48a3a7`) — оси нет;
* пропускает строку выше окна, если `scroll > c` (`0x48a2db`);
* подпись: шрифт **5**, если `|double(0x4bf7b0 + dev*0x7c + i*8)| >= 0.5`
  (`0x48a2e8`..`0x48a31b`: сравнение с `0.0` `0x4a2950` для знака и с `0.5`
  `0x4a2928`; порог включительный, `test ah,0x41`), иначе 0; `x 13`;
* значение: текст `0x4bc468[preset*12]` (`0x48a36f`), шрифт 0, `x = edi + 13`;
* оба вызова передают `item = c` (`0x48a333`, `0x48a357`), поэтому строка
  курсора получает шрифт 4 через `0x485dd0` (только там, где базовый шрифт 0);
* `[0x67f10c]++` на каждую нарисованную ось (`0x48a391`..`0x48a3a1`).

### 2.5. Четыре строки хатов (`0x489f54`..`0x48a16b`)

Пара включается битом `0x100` (`test ch,0x1`, `0x489f51`) или `0x200`
(`test ch,0x2`, `0x48a064`) того же dword `0x4bf7e0`; `[0x67f10c] += 2` на пару.

| слот | текст | VA | байт значения | биты «активности» |
|---:|---|---|---|---|
| 0 | `Hat 1 X: ` | `0x4bd910` | `0x68cd30 + dev*8` | `0x0A` (`0x489f82`) |
| 1 | `Hat 1 Y: ` | `0x4bd904` | `0x68cd31 + dev*8` | `0x05` (`0x489fff`) |
| 2 | `Hat 2 X: ` | `0x4bd8f8` | `0x68cd32 + dev*8` | `0xA0` (`0x48a097`) |
| 3 | `Hat 2 Y: ` | `0x4bd8ec` | `0x68cd33 + dev*8` | `0x50` (`0x48a111`) |

Подпись — `x 13`, значение — `x = edi + 13`. Подпись красится шрифтом 5, если
`[0x4bf7ec + dev*0x7c] & <биты строки>` не ноль; значение всегда шрифт 0
(+подсветка курсора). **Квирк:** у значения Hat 2 Y `x = edi + 26`, потому что
`0x48a136` делает `add edi,0xd` до блита и не восстанавливает `edi`; тест это
фиксирует (строка `Hat 2 Y` — значение на `x 80` вместо `67`).

Строки хатов не проверяют десятирядное окно (только `scroll > c`), поэтому при
`scroll = 0` последняя строка хата стоит на `y 118` — вне «десяти полос», но
внутри 131 px платы.

### 2.6. 32 канала кнопок (`0x48a170`..`0x48a263`)

Цикл по `i = 0..31` (`cmp eax,0x21`), строка `Button <i+1>` на
`y = 28 + 9*(c + i - scroll)`, `x 13`, `item = c + i`:

* маска `[0x4aa490 + (dev*32 + i)*4]`; `-1` (`test eax,eax; jl 0x48a1b2`) —
  текст `Button %d: None` (`0x4bd8cc`), иначе `0x4863a0(mask)` = позиция
  единственного бита (`0x4863a0`: `mask == 1 << n` -> `n`, `-1` -> `-1`), и
  текст `Button %d: %s` (`0x4bd8dc`) с именем `0x4bc558[n]`
  (`Move Forward` … `Linear Right`, 31 запись);
* вся строка шрифт **5**, если `[0x4bf7e8 + dev*0x7c] & (1 << i)`
  (`0x48a1f7`..`0x48a20c`), иначе 0 (+курсор -> 4);
* **все** 32 канала рисуются всегда (не назначенный — как `None`), поэтому
  строк всего `1 + оси + 2*хаты + 32 = [0x67f10c]`;
* окно: цикл прерывается, когда `c + i - scroll >= 10` (`0x48a197`), а
  начинается с первого канала, чья строка не выше окна (`0x48a181`:
  `edi = max(0, scroll - c)`).

### 2.7. Стрелки и значения по умолчанию

* После кнопок (значит, поверх них): up — `0x485d00(0x68681f, 0xc4)` при
  `scroll > 0`, down — `0x485cc0(0x68c33b, 0xc4)` при `scroll + 10 < rows`
  (`0x48a269`..`0x48a29a`). Адреса — `(159, 2)` и `(159, 121)` копии платы,
  спрайт `MENUARRW` 16×8; `0x485d00` блитит те же 128 байт задом наперёд, т.е.
  up = down, повёрнутая на 180° (проверено тестом: 41 зажжённый пиксель в обеих
  ориентациях).
* `.data`: `0x4bc540/0x4bc544 = -1` (устройство не назначено), `0x4aa490` во
  всех четырёх слотах `{0x20, 0x8000, -1×30}` = `Fire`, `Activate`; `.bss`:
  `0x4bf7e0`, `0x4bf7e8`, `0x4bf7ec`, имена устройств `0x4bf7f0`, пресеты
  `0x68cd00`, байты хатов `0x68cd30` — нули (`Not Used`).
* `[0x68ccf4]` на входе не пишется: экран наследует 5 или 6 — пункт
  `1: …`/`2: …` экрана 10, поэтому подсветка реально попадает на строку 5/6,
  а не на первую; Esc (`0x48e599`) восстанавливает `[0x68ccf4] = [0x660788]`
  (этот же пункт 5/6). API по умолчанию берёт 0 — «первая строка, окно 0», как
  у `keycfg_render`; значение 5/6 воспроизводится явно.
* `[0x664594]` (первая строка хатов) и `[0x683f94]` (первая строка кнопок) —
  побочные записи обработчика для ввода; в кадре не участвуют.

### 2.8. Ассеты

`FRONTEND/BMP.IDX`: `PLATE` 196×131 (текстовая копия), `FONTS4` (грани 5/0/4),
`MENUARRW` 16×8 — но **только когда рисуется стрелка** (у кадра без устройства
её нет). `SLIDE`/`KNOB`/`CHECK`/`NOCHECK` обработчик не вызывает: в
`0x489d60`..`0x48a2a4` нет ни `0x486070`, ни `0x4860b0`, ни `0x4833e0` —
виджетов-слайдеров и чекбоксов на экране 36 нет.

## 3. Модель (и чем она отличается от факта)

1. **Холст** 320×200, непрозрачный `#000`; опционально `background`
   (`FRONTEND/BMP.IDX`) в (0,0), клип по холсту.
2. **Плата.** `PLATE` загружается и проверяется всегда: обработчик копирует её
   в `0x6865f8` (`0x486050`), без ассета кадр пуст. Куда движок блитит этот
   буфер на 320×200, не задокументировано (`MENU_RENDER.md` §2), поэтому панель
   не рисуется неявно: `background = "PLATE"` кладёт её в (0,0), пусто — чёрный
   холст.
3. **Клип текста** — 196×131 (окно записи `0x485dd0`).
4. **Строки** идут в порядке обработчика: заголовок, подсказка, затем
   содержимое с верхом окна `max(0, cursor-5)`, затем стрелки.
5. **Значения** — пресеты `0x4bc468` (18 имён) и маски кнопок `0x4aa490`
   (через `0x4863a0`). Индексы пресетов клампятся в 0..17, каналы — в 0..31.
6. **Подсветка** — три независимых правила оригинала: шрифт 4 на строке
   курсора (в `0x485dd0`), шрифт 5 на подписи отклонённой оси (`|v| >= 0.5`) /
   активного хата (биты `0x4bf7ec`) / нажатой кнопки (бит `0x4bf7e8`). Нажатая
   кнопка остаётся красной даже на строке курсора (её базовый шрифт 5, а
   `0x485dd0` меняет только 0 -> 4).
7. **Квирк Hat 2 Y** (`x = edi + 26`) воспроизведён буквально; это единственное
   место, где колонка значений сдвинута.
8. **Клампы, не отказы:** курсор вне 0..rows-1 просто ничего не подсвечивает;
   `joystick` вне `-1..7` трактуется как «назначен» (рисуется кадр с устройством;
   оригинал берёт `[0x4bc54x]` как есть); имя обрезается до 30 байт; маска
   кнопки, не являющаяся одной битой, даёт `None` — в оригинале `0x4863a0`
   на многобитной маске не завершился бы, а на 0 вернул бы 32 (за 31-й записью
   таблицы имён); в поставочных данных таких масок нет.
9. **Точный fade** `0x682f90`: индекс палитры каждого нарисованного пикселя
   проходит через `render/hud_lut.h::map(level, index)` **до** выборки цвета;
   уровень 11 — тождество, 12..15 — реальные таблицы. Нужна таблица
   (`fade_lut_table`) или дамп 4096 Б (`fade_lut_dump`), иначе отказ.
10. **Отказы** (текст с префиксом `player_setup_render:`): пустой каталог игры,

    `background`-записи/не 8 bpp, `fade_lut` без таблицы и дампа, нечитаемый

## 5. Ограничения

* Только кадр: нет ввода (циклирование пресетов `0x48c1b6`/`0x48d32b`,
  переназначение кнопок, опрос DirectInput `0x404880`/`0x405450`), нет
  UI-звуков, таймеров и анимаций. Esc -> состояние 10 (`0x48e599`) не
  моделируется.
* **CLI — есть (срез 17).** `--player-setup [--player-setup-cursor N]
  [--player-setup-joystick N] [--player-setup-player N] [--no-plate]
  [--png OUT] [--fade-lut N]`: без устройства
  `player_setup: player=0 rows=1 sliders=0 checks=0 cursor=0 joystick=-1
  arrows=0 ink=825`; джойстик 0 — `rows=43 arrows=1 ink=2640`; плеер 2,
  джойстик 2, курсор 10 — `arrows=2 ink=2404`. CTest `cli_player_setup`,
  `_device`, `_player2`; `cli_fade_lut` (11 = без fade).
* **Настройки не читаются и не пишутся.** `GUNMETAL.CFG`/`KEYCFG` не
  открываются: устройство, имя, пресеты осей/хатов, маски кнопок и живые биты
  приходят из `PlayerSetupRenderOptions` (умолчания — `.data`/`.bss`, §2.7).
* **Живое состояние — маски и `double`.** Оригинал решает о красной подписи по
  `double`-отклонению (`0x4bf7b0`) и битам `0x4bf7ec`/`0x4bf7e8`; API несёт их
  как `axis_values[6]`, `hat_bits`, `pressed_buttons`. Кто и как их заполняет —
  сторона опроса устройства.
* **`axis_present`/`hat1`/`hat2` по умолчанию — модель.** Биты `[0x4bf7e0]`
  ставятся перечислением DirectInput (`0x404e78`..`0x40524e`), а не лежат в
  файле; «полное устройство» (6 осей, 2 хата) — удобное умолчание, не байт
  поставки.
* **Позиция платы** на экране (196×131 внутри 320×200) не доказана — поэтому
  `background` явный.
* **Квирк Hat 2 Y** воспроизведён как в бинаре (значение на 13 px правее). Это
  выглядит как ошибка оригинала, но листинг однозначен (`0x48a136`), и кадр
  должен совпадать с игрой, а не с ожиданием.
* **Не назначенная кнопка рисуется** как `Button N: None` — так делает
  обработчик для всех 32 каналов; «скрыть» их нельзя, это не модель.
* `ink_pixels` — уникальные пиксели глифов; плата и спрайт стрелки не в счёте
  (то же правило, что в `menu_render`/`keycfg_render`).
* **Виджетов-слайдеров и чекбоксов нет:** `sliders` и `checks` всегда 0;
  `SLIDE`/`KNOB`/`CHECK`/`NOCHECK` на этом экране не читаются и не требуются.
