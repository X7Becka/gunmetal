## 1. Что доказано, что — модель

| поле `ChassisParams` | источник | статус |
|---|---|---|
| `mass` | op0 (`0x81c378`, record `+0x148`) — **предел** массы; живой вес `0x81c374` считается отдельно (`0x4524d0`) | данные; как инерция — **MODEL** (исходный цикл массу не читает) |
| `max_speed` | `op4` (`0x81bd70`, ед/тик) → `op4·91/(1-k)` ед/с; это установившееся значение `v ← k·v + Δv`, а не зажим | **доказано** (формула + данные) |
| `drag` | `k` = op20 записи = `0x81bfb8`, 4-й `double` блока `+0x48`; непрерывная форма `-91·ln k` | k — данные; линейная форма — **MODEL** (квадратичного сопротивления в коде нет) |
| `accel` | `drag·max_speed`, чтобы плато полунеявной схемы было ровно `max_speed` | **MODEL** (в оригинале шаг скорости, а не ускорение) |
| `suspension_k` | `90 1/с²` (ω = 9.4868 рад/с, период 0.662 с) | **MODEL**: блок подвески записи (`+0x48`..`+0x84`) копируется без потребителя (`docs/CHASSIS.md` §3/§7) |
| `suspension_d` | `8 1/с` (ζ = 0.4216) | **MODEL**, там же |
| `ride_height` | `3.0` ед. — высота загруженного равновесия (не `op9` eye height 10..14 и не радиус SOB) | **MODEL** |
| `gravity` | `700`, синтетическая `ControllerConfig::gravity`; оригинал масштабирует член подвески `0x80f840` (op 96), скалярной базы нет | синтетика (как в контроллере), **MODEL** физически |

`op1` (`speed_penalty`) и health-фактор в этот модуль не входят: это
`ChassisMotion`/`weight_limited_speed` контроллера.

## 2. Восемь `double` записи — сверены

`docs/PLAYER_GHIDRA.md` §4.1: восемь `double` копируются с record `+0x48` в
`0x81bfa0`..`0x81bfd8`; четвёртый — retention `k` (`0x81bfb8`, запись
`0x799640`). Файловые dword 23–24 … 37–38 = операнды `op17..op24`:

|---|---:|---:|---:|---:|---:|---:|---:|---:|
| `LIGHT CHASSIS` | 13.0 | 400.0 | 1600.0 | **0.90** | 64.0 | 1.0 | 80.0 | 0.2 |
| `MEDIUM CHASSIS` | 12.5 | 500.0 | 1600.0 | **0.92** | 64.0 | 1.0 | 80.0 | 0.2 |
| `STEALTH CHASSIS` | 12.5 | 500.0 | 1600.0 | **0.92** | 64.0 | 1.0 | 80.0 | 0.2 |
| `HEAVY CHASSIS` | 12.0 | 600.0 | 1600.0 | **0.96** | 64.0 | 1.0 | 80.0 | 0.2 |
| `57 CHEVY` | 13.0 | 400.0 | 1600.0 | **0.90** | 64.0 | 1.0 | 80.0 | 0.2 |

Проверка — `test_chassis_physics`: **616/616** записей, **36/36** уровней,
ровно одна комбинация на имя (145 записей LIGHT/MEDIUM/STEALTH/HEAVY, 36
CHEVY; в `level20` 21 запись вместо 17 — два лишних безусловных блока,
`docs/CHASSIS.md` §2). Тест же проверяет, что все восемь полей — `D` в
сигнатуре (`player_type_field_is_real`), т.е. `double`, а не dword.

Только четвёртое поле (`k`) используется физикой; остальные семь — порог и
числа урона/режима, их роль в движке не реализована.

## 3. API

```cpp
namespace gm {

struct ChassisParams {                 // все поля — double, provenance в §1
    double mass, max_speed, drag, accel;
    double suspension_k, suspension_d, ride_height, gravity;
};

struct ChassisState {
    Vec3d position, velocity;          // ступни/точка контакта, ед/с
    double suspension_offset;          // 0 = ride_height, + = сжатие
    double suspension_velocity;
};

std::optional<ChassisParams> chassis_params(const ChassisSpec& spec,
                                            double retention,             // op20
                                            std::string* error = nullptr);

class ChassisPhysics {
    bool   configure(const ChassisParams&, std::string* error = nullptr);
    bool   step(ChassisState&, double dt, Vec3d input,
                std::string* error = nullptr) const;   // dt по умолчанию kChassisDt
    double speed(const ChassisState&) const;           // плоская, sqrt(vx²+vy²)
    double suspension_force(double offset, double offset_velocity) const;
    double body_height(const ChassisState&) const;     // ride_height - offset
    const ChassisParams& params() const;
};

} // namespace gm
```

Шаг (`dt = kChassisDt = 1/91`, полунеявный Эйлер; `u` — вход, `|u| ≤ 1`):

```
v      ← (v + accel·u·dt) / (1 + drag·dt)      // демпфирование неявное
vz     ← vz − gravity·dt                        // баллистическая вертикаль
p      ← p + v·dt
ω      ← (ω − suspension_k·x·dt) / (1 + suspension_d·dt)
x      ← x + ω·dt                               // x = suspension_offset
```

Установившееся значение плоской скорости — `accel/drag` = `max_speed`
(ровно, для любого `dt`); для пружины `ω·dt < 2` (иначе `step` отказывает).

`chassis_params()` валидирует `retention ∈ (0,1)`, `mass > 0`, `op4 > 0`.
`configure()` требует конечных значений, `mass/max_speed/drag/suspension_k/
ride_height > 0`, `accel/suspension_d/gravity ≥ 0`. Отказ — `false` + текст,
состояние не меняется.

## 5. Ограничения

1. **Не подключено** к `player/controller.*`, `runtime.*`, `main.cpp`: это
   самостоятельный модуль, контроллер продолжает работать как раньше
   (`gravity = 700` остаётся там).
2. Нет **коллизий** и определения земли: `position.z` свободно падает;
   контакт с полом/стенами — по-прежнему `render/collide.*` + контроллер.
3. Нет **трения шин/скольжения**, кривой двигателя, наклона/крена корпуса,
   поосной подвески (одна скалярная пружина) и крутящего момента.
4. Подвеска — **MODEL**: её `k_s/d_s/ride_height` не сняты с записи; блок
   `+0x48`..`+0x84` только копируется (нет потребителя). `gravity` —
   синтетика контроллера, не физическая `g` игры.
5. `drag` — линейный; исходная рекурсия дискретная (`v·k` за тик), поэтому
   непрерывная форма точна только в пределе `dt → 0`; при `dt = 1/91`
   расхождение `t10` ≈ 0.003 с (см. таблицу).
6. `mass` в динамике сокращается (как и в оригинале, где массы в цикле нет):
   различие шасси по массе проявится только через будущие импульсы/коллизии,
   не через разгон.
7. `op1` (штраф скорости за вес) не моделируется — он в
   `ChassisMotion`/`weight_limited_speed`.

`M6.1.1` остаётся 🟡: точные `n`/`param_2` интегратора (`NEXT.md` 7), полная
семантика блока подвески и подключение к контроллеру не сделаны. Закрыта
лишь часть «8 `double` не сверены» — теперь сверены (616/616).
