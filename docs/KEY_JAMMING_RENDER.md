# Рендер экрана 16 `KEY JAMMING` (`engine/src/ui/key_jamming_render.h`)

Срез 11 пункта `M8.8`: один кадр экрана **16** фронтенда (`gundx.exe`, ImageBase
`0x400000`) в RGBA-буфер 320×200. Модуль без состояния — рисует то, что ему
передали в `KeyJammingRenderOptions`, и отдаёт числа (`rows`, `keys`,
`ink_pixels`, `missing_glyphs`, `arrows`). Шрифты, метрики и атласы — из
`render/text_layout` (`FONTS4` в `FRONTEND/BMP.IDX`), имена клавиш — из
123-записной таблицы игры через `input/controls.h::Controls::key_name`, точный
fade — из `render/hud_lut`. Ничего не измеряется заново.

Код: `engine/src/ui/key_jamming_render.h/.cpp`; тест —
`engine/tests/test_key_jamming_render.cpp` (CTest `key_jamming_render`, label
`quick`). Соседние срезы — `MATCH_SETUP_RENDER.md` (27), `MOUSE_SETUP_RENDER.md`
(22), `KEYCFG_RENDER.md` (30/34/35), `MENU_RENDER.md` (общая механика
`0x485dd0`), `CONTROLS_CPP.md` (таблица имён клавиш), `INIT.md` §8 (опрос
DirectInput).

## 1. API

```cpp
#include "ui/key_jamming_render.h"

gm::KeyJammingRenderOptions options;   // умолчания = состояние входа движка (§2.6)
options.cursor = 4;                    // [0x68ccf4], унаследован от экрана 10
options.pressed_keys = {17, 57};       // [0x4bf2a8]: коды нажатых клавиш 0..122
options.background = "PLATE";          // "" = чёрный холст

std::vector<std::uint32_t> rgba;       // 0xRRGGBBAA
int width = 0, height = 0;
gm::KeyJammingRenderStats stats;
std::string error;
if (!gm::render_key_jamming(game, options, rgba, width, height, &stats, &error)) {
    // error: текст с префиксом "key_jamming_render: "
}
// width=320 height=200, rgba.size()==64000
// stats: rows=1 keys=<0..28> ink_pixels=<...> missing_glyphs=0 arrows=0
```

| Поле `KeyJammingRenderOptions` | По умолчанию | Смысл |
|---|---|---|
| `std::string background` | `""` | запись `FRONTEND/BMP.IDX`, рисуется в (0,0); `"PLATE"` — панель экрана; пусто — чёрный холст |
| `int cursor` | `4` | `[0x68ccf4]`; влияет **только** значение `0`: имена клавиш рисуются шрифтом 4 вместо 0 (§2.5) |
| `std::vector<int> pressed_keys` | пусто | `[0x4bf2a8]` как список кодов; дубликаты и коды вне `0..122` игнорируются, порядок не важен — кадр идёт по возрастанию кода |
| `bool fade_lut` | `false` | точный fade `0x682f90` по палитровым индексам |
| `int fade_lut_level` | `11` | 0..15; 11 — тождество, 12..15 светлеют |
| `std::string fade_lut_dump` | `""` | дамп 4096 Б (`load_hud_lut`) |
| `const HudLut* fade_lut_table` | `nullptr` | готовая таблица, приоритетнее дампа |

Поля `key_name` **нет**: на этом экране нет подстановки `%s` (§2.3) — динамика
здесь не строка формата, а список имён из таблицы `0x4a5b88`.

Публичные помощники (нужны тесту и будущему CLI): `key_jamming_key_x(slot)`,
`key_jamming_key_y(slot)`, `key_jamming_keys(pressed_keys)`,
`key_jamming_key_font(cursor)`.

`KeyJammingRenderStats`: `rows` (всегда 1), `keys` (сколько имён нарисовано,
`0..28` — счётчик `esi` из `0x488f1b`), `ink_pixels` (уникальные пиксели
глифов; фоновая плата не считается — как в `menu_render`/`match_setup_render`),
`missing_glyphs` (байты без глифа, не фатальны), `arrows` (`MENUARRW` на этом
экране не рисуется — всегда 0).

Контракт буфера: при отказе `rgba` очищается, `width`/`height` = 0, статистика
обнуляется; `stats`/`error` могут быть `nullptr`. Функция только читает
установку, детерминирована, не зависит от текущего каталога.

## 2. Доказано (листинг + данные)

Инструмент: `python3 tools/re/disrange.py`. **Обработчик — `0x488e90`**
(таблица `0x4883d8`, id 16; `tools/re/ui_screens.py --map` даёт `rows 1`,
`step 0`, `title 0x4bd640`, `assets plate/fonts`), тело
`push ebx/esi/edi` (`0x488e90`) … `ret` (`0x488f6c`).

### 2.1. Пролог и геометрия

| Факт | Где |
|---|---|
| `rows = 1` (`0x67f10c`) | `0x488e93` |
| `step = 0` (`0x662d58`) | `0x488e9d` |
| копия `PLATE` 196×131 в `0x6865f8` | `0x488ea7` → `0x486050` |
| заголовок: шрифт 5, `0x4bd640`, `centered=1`, `x=38`, `row=14`, `item=-1` | `0x488eac`..`0x488ebb` |

`0x485dd0` при `item == -1` трактует `row` как абсолютный `y`
(`0x485e04`..`0x485e0b`: `xor ecx,ecx`, поэтому член `item*step` исчезает), при
`centered=1` заменяет `x` на `(196 - width)/2` (`0x485de2`..`0x485dfa`), при
`row >= 0` кладёт текст в `y = row + item*step`
(`0x485e4b`..`0x485e5c`: `imul ecx,[0x662d58]`, `add ecx,edx`), при `row < 0` —
в `y = -row` (`0x485e2b`..`0x485e38`). Поэтому `y` в таблице — вычисленный
(здесь `step = 0`, так что `y = row`).

### 2.2. Четыре вызова `0x485dd0`

| текст | VA | шрифт | `centered` | `x` | `row` | `y` | сайт |
|---|---|---:|---:|---:|---:|---:|---|
| `KEY JAMMING` | `0x4bd640` | 5 | 1 | 38 | 14 | 14 | `0x488eb4` |
| `Hold down keys to check` | `0x4bd628` | 0 | 1 | 38 | 26 | 26 | `0x488ecb` |
| `if they jam.` | `0x4bd618` | 0 | 1 | 38 | 35 | 35 | `0x488ee2` |
| `Press Esc to close.` | `0x4bd604` | 0 | 1 | 38 | 44 | 44 | `0x488ef9` |

Все четыре передают `item = -1` (`0x488eac`, `0x488ec3`, `0x488eda`, `0x488ef1`)
и `centered = 1` (`0x488eb2`, `0x488ec9`, `0x488ee0`, `0x488ef7`); `x = 38`
(`push 0x26`) — неиспользуемый аргумент центрированной ветки. Строки —
заголовок (тёмно-красный, шрифт 5) и три подсказки (тёмно-серые, шрифт 0).

### 2.3. Список клавиш (`0x488f08`..`0x488f67`)

Цикл сканирует 123 байта состояния `0x4bf2a8` (коды игры `0..122`):

```
488f11: mov al,[ebx+0x4bf2a8]     ; состояние кода ebx
488f17: test al,al / je skip      ; 0 -> не рисуется
488f1b: cmp esi,0x1c / jge skip   ; уже 28 нарисовано -> дальше только скан
488f20: mov eax,esi / ... / sar eax,2
488f2d: lea eax,[eax*8+0x36]      ; row = 0x36 + 8*(n/4) = 54 + 8*(n/4)
488f35: mov eax,esi / ... and eax,3
488f45: shl ecx,4 / add ecx,eax   ; 17*(n%4)
488f4a: lea edx,[ecx+ecx*1+0x1e]  ; x = 0x1e + 34*(n%4) = 30 + 34*(n%4)
488f51: push edi / push 0    ; текст = 0x4a5b88 + code*6, шрифт 0, item 0
488f5d: add edi,0x6          ; шаг таблицы имён — 6 байт
488f61: cmp edi,0x4a5e6a / jl ; конец таблицы (123 записи)
```

То есть сетка **4 столбца × 7 строк**: `x` 30/64/98/132, `y` 54/62/70/78/86/94/102;
`item = 0` и `step = 0` делают `y` независимым от пункта, имя берётся из таблицы
`0x4a5b88 + code*6` (`docs/UI_SCREENS.md` §7, `Controls::key_name`), шрифт 0,
`centered = 0`. Порядок — возрастание кода (скан массива, а не журнал нажатий),
не более 28 имён: 29-й и следующие коды в кадр не попадают.

**Подстановки `%s` нет** и «механизма джемминга» тоже: обработчик ничего не
считает и ни во что не пишет — он только перерисовывает то, что опрос
клавиатуры положил в `0x4bf2a8`. Экран нужен игроку, чтобы увидеть, какие
одновременно зажатые клавиши клавиатура ещё различает (отсюда подсказка
`Hold down keys to check / if they jam.`); самого порога/флага «jam» в
бинаре нет — поиск по `0x4bf2a8` даёт только записи опроса и это чтение.

### 2.4. Состояние клавиатуры и таблица имён

* `0x4bf2a8` — массив «клавиша нажата» (байт на код): опрос `0x405450`
  (`GetDeviceData(+0x28)`) отображает код устройства через `0x405790` и пишет
  `1` при нажатии (`0x4054eb`, `0x4055de`), `0` при отпускании (`0x40550a`,
  `0x4055c3`); инициализация `0x404b00` обнуляет первые `0x80 = 128` байт
  (`0x404b14`). `docs/INIT.md` §8.
* Таблица имён `0x4a5b88` — **123** записи по **6** байт
  (`(0x4a5e6a − 0x4a5b88)/6 = 123`), запись 0 — `NONE`; коды выше 122 в кадр
  не попадают, потому что ограничен и массив (128 байт), и таблица (123
  записи).
* `KEY JAMMING` — единственный потребитель `0x4bf2a8` во фронтенде (второе
  чтение — сам опрос, `0x4054d2`).
* Переход в 16 — `0x48d1ce`..`0x48d1d9`: `[0x660788] = edi` (игрок),
  `[0x4bc440] = 0x10`. `[0x68ccf4]` **не** пишется, значение наследуется от
  экрана 10, где `Keyjamming` — пункт 4 (`docs/UI_SCREENS.md` §3.1).
* Esc возвращает в 10 (`0x48e599`); своего ввода у экрана нет.

### 2.5. Квирк подсветки `0x485dd0`

`0x485dd0` меняет шрифт вызывающего на 4 (белый) только если
`item == [0x68ccf4]` **и** вызывающий передал шрифт 0
(`0x485e0d`..`0x485e19`). Вызов списка клавиш передаёт `item = 0` и шрифт 0,
поэтому при унаследованном курсоре `0` **все** имена клавиш становятся белыми;
при любом другом значении (в том числе при реальном входе с курсором 4) они
тёмно-серые. Четыре строки §2.2 передают `item = -1`, что срезает проверку
(`0x485e04`..`0x485e0b`), — они не подсвечиваются никогда. Полос/рамок/
`MENULIT` на экране нет.

### 2.6. Значения и умолчания

* `rows = 1`, `step = 0` — immediate-записи обработчика (`0x488e93`,
  `0x488e9d`); пунктов у экрана нет.
* Ассеты: `PLATE` + `FONTS4` (`docs/UI_SCREENS.md` §2, строка «5–6, 10–14, 16,
  21–26, 31–37 — plate + шрифты»). `CHECK`/`NOCHECK`, `SLIDE`/`KNOB`,
  `MENUARRW` не читаются: в `0x488e90` нет вызовов `0x4833e0`, `0x486070`,
  `0x4860b0`, `0x485cc0`/`0x485d00`.
* Курсор входа — 4 (§2.4); умолчание API тоже 4, потому что `0` — не
  нейтральное значение, а переключатель шрифта (§2.5).
* Палитра: заголовок шрифт 5 → `(155,15,15)`, подсказки и имена шрифт 0 →
  `(19,15,15)`, шрифт 4 → `(239,239,239)` (`docs/MENU_RENDER.md` §3).

## 3. Модель

1. **Холст** 320×200, непрозрачный `#000`; опционально `background`
   (`FRONTEND/BMP.IDX`) в (0,0), клип по холсту.
2. **Плата.** `PLATE` (196×131) загружается и проверяется всегда: обработчик
   копирует её в `0x6865f8` (`0x486050`), и без ассета кадр пуст. Куда движок
   блитит этот буфер на 320×200, не задокументировано (`docs/MENU_RENDER.md`
   §2), поэтому панель не рисуется неявно: `background = "PLATE"` кладёт её в
   (0,0), пусто — чёрный холст.
3. **Клип текста** — 196×131 (окно записи `0x485dd0`).
4. **Строки**: заголовок `KEY JAMMING` (шрифт 5) и подсказки
   `Hold down keys to check` / `if they jam.` / `Press Esc to close.` (шрифт 0)
   центрируются в полосе 196 px, `y` = 14/26/35/44.
5. **Список клавиш**: `key_jamming_keys(pressed_keys)` — коды `0..122`,
   по возрастанию, без дубликатов, максимум 28; имя — `Controls::key_name`
   (таблица `0x4a5b88`), позиция слота `n` — `(30 + 34*(n%4), 54 + 8*(n/4))`,
   шрифт 0 (шрифт 4 при `cursor == 0`), `centered = 0`.
6. **Клампы** (не отказ): курсор вне `0` — обычные имена; коды вне `0..122`
   отбрасываются; дубликаты схлопываются; лишние имена сверх 28 не рисуются.
   Оригинал тоже держит индексы в диапазоне (скан 123 записей), поэтому кадр
   не ломается.
7. **Точный fade** `0x682f90`: индекс палитры каждого нарисованного пикселя
   проходит через `render/hud_lut.h::map(level, index)` **до** выборки цвета;
   уровень 11 — тождество, 12..15 — реальные таблицы. Нужна таблица
   (`fade_lut_table`) или дамп 4096 Б (`fade_lut_dump`), иначе отказ.
8. **Отказы** (текст с префиксом `key_jamming_render:`): пустой каталог игры,
   нет/битый `FRONTEND/BMP.IDX`, нет шрифта 5/0/4, нет `PLATE` или размер не
   196×131, нет `background`-записи/не 8 bpp, `fade_lut` без таблицы и дампа,
   нечитаемый дамп.

## 5. Ограничения

* Только кадр: нет ввода (опрос `0x405450`, `Esc` → состояние 10 `0x48e599`),
  звуков интерфейса, анимаций и таймеров.
* **Нет «механизма джемминга»**: в бинаре нет ни порога, ни флага, ни особого
  поведения — экран лишь показывает имена клавиш, которые опрос клавиатуры
  считает нажатыми (`0x4bf2a8`). Модель это повторяет буквально; «зажата» ли
  клавиша физически — решает опрос, а не этот модуль.
* Состояние клавиатуры приходит от вызывающего (`options.pressed_keys`); сам
  модуль ничего не опрашивает и не хранит.
* Настройки **не пишутся**: модуль не трогает `GUNMETAL.CFG`/`KEYCFG`.
* **CLI — есть (срез 13).** `--key-jamming [--key-jamming-keys 30,31,...]
  [--key-jamming-cursor N] [--no-plate] [--png OUT] [--fade-lut N]`:
  `key_jamming: rows=1 keys=0 cursor=4 ink=752 missing=0 arrows=0`; коды
  `17,30,31,57,109` — `keys=5 ink=939`. CTest `cli_key_jamming`, `_keys`;
  `cli_fade_lut` (11 = без fade). `CHECK`/`NOCHECK`, `SLIDE`/`KNOB` и
  `MENUARRW` не читаются, `arrows` всегда 0.
* Положение платы на экране (196×131 внутри 320×200) не доказано — поэтому
  `background` явный.
* `ink_pixels` — уникальные пиксели глифов; фоновая плата не в счёте
  (то же правило, что в `menu_render`/`match_setup_render`).
