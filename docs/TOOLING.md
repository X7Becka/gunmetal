# Инструменты помимо Ghidra: что брать и зачем

Ghidra + `tools/ghidra/mcp.py` — основной декомпилятор проекта
(`docs/GHIDRA.md`). Но один инструмент не закрывает весь цикл: для **живого**
состояния нужен отладчик, для **LE-бинарника** `gun.exe` — другой загрузчик, для
**диффов** — bin-diff, для **скорости** — профилировщик. Ниже — карта, что
именно даёт больший выигрыш и чего в этом окружении нет.

Проверено `command -v` на этой машине: есть `objdump`, `readelf`, `nm`,
`strings`, `perf`; **нет** `radare2`/`rizin`, `gdb`, `lldb`, `wine`, `ndisasm`,
`hyperfine`, `py-spy`, Python-пакетов `capstone`/`unicorn`/`angr`/`pefile`
(и нет `pip`). Всё, что ниже помечено «нет», требует установки на Windows- или
Linux-сторону и не должно становиться обязательной зависимостью репозитория.

## 1. Что уже закрыто своим кодом

| задача | чем | почему не тащим внешнее |
|---|---|---|
| x86-оракул по байтам | `tools/re/x86mini.py`, `tools/re/emu.py` | нужен детерминизм и запуск без зависимостей; уже проверен на SOU1/SOU2/SBV |
| PE-карта, строки, xref | `exelib.py`, `strdump.py`, `xref.py` | хватает для VA↔offset и поиска ссылок |
| таблицы/сигнатуры/раскладки | `cmdtable.py`, `sig.py`, `table_layout.py`, `copy_trace.py` | специфично для Watcom-кода игры |
| статический дизасм | `objdump` + индекс в кэше | быстрый и всегда под рукой |
| профилирование Python | `python3 -m cProfile -s cumtime …`, `perf` | `cProfile` нашёл реальные hotspot’ы (scene decode, FNV) |

## 2. Ghidra-экосистема (дешёвые дополнения)

| инструмент | что даёт | статус |
|---|---|---|
| `pyghidra-mcp` + `tools/ghidra/mcp.py` | headless-запросы, batch-режим | есть |
| **BSim** (встроен в Ghidra) | поиск похожих функций → узнать Watcom-рантайм и не реверсить его заново | включить в проекте |
| **Diaphora** | bin-diff двух сборок/версий, перенос имён | нет, ставится плагином |
| **Ghidra Scripts / pyghidra** | экспорт структур в JSON, сверка `names.csv` ↔ символы | написать при необходимости |
| PDB/Map-импорт | имена, если появится карта от сборки | нет исходной карты |

Правило прежнее: Ghidra — источник гипотез; факт подтверждается данными и
тестом (`docs/RE_METHOD.md` §1).

## 3. Статический анализ: чем дополнить

| инструмент | зачем именно здесь | как получить |
|---|---|---|
| **rizin / radare2** (`r2 -A`, `rz-bin`) | скриптуемый дизасм, **поддержка LE/LX** (это `gun.exe`, `objdump` его не читает), встроенный emul/ESIL | пакет/сборка; в WSL сейчас нет |
| **Cutter** | GUI поверх rizin для быстрого триажа | опционально |
| **IDA Free** | лучший декомпилятор x86 для спорных функций; читает LE | Windows-сторона, бесплатная версия |
| **Binary Ninja** | HLIL и скрипты; удобен для сравнения версий | коммерческий, только если появится бюджет |
| **ndisasm** (NASM) | сырой дизасм по offset без PE-обвязки | `apt install nasm` |
| **detect-it-easy / PE-bear** | определить Watcom-рантайм, секции, энтропию, упаковку | Windows/GUI |
| **diffoscope / radiff2 / bsdiff** | диффы v1.36 ↔ другой сборки, поиск изменённых функций | по необходимости |
| **`pefile` / `lief`** | разбор PE/LE в Python (релокации, импорты, оверлеи) | `pip`; текущий `exelib` покрывает базовое |

## 4. Динамика: то, чего статикой не достать

В `NEXT.md` есть открытые вопросы, для которых нужен **живой** оригинал:
числовые `n`/`param_2` в кадре игрока, поведение подвески/коллизий, реальные
значения заряда. Здесь Ghidra бессильна.

| инструмент | что даёт | где |
|---|---|---|
| **x32dbg/x64dbg + ScyllaHide** | breakpoint по VA (`0x4453d0`, `0x46f0f0`, …), просмотр x87 ST(0..7), патч в памяти | Windows |
| **WinDbg + TTD** | запись трейса игрового цикла и повтор без повторного запуска; лучший способ поймать редкое состояние | Windows |
| **Cheat Engine** | найти адреса значений (заряд 0..1, скорость, HP), pointer-map структур | Windows |
| **ReClass.NET** | снять раскладку рантайм-структуры и сверить с `docs/*_FIELDS.md` | Windows |
| **API Monitor** | вызовы DirectDraw/DInput/D3D — что игра реально просит у системы | Windows |
| **Process Monitor / Explorer** | какие файлы/ключи читаются на старте уровня | Windows |
| **DOSBox-X debugger / Watcom `wd`** | отладка `gun.exe` (DOS4GW LE), если понадобится DOS-сборка | отдельно |

Ограничение: из WSL GUI-игру не отладить (нет доступа к рабочему столу);
запуск забирает экран пользователя, поэтому это ручной шаг, а не CI.

## 5. Эмуляция и символьные методы

| инструмент | когда оправдан | статус |
|---|---|---|
| **Unicorn / Qiling** | исполнить функцию целиком без ОС, быстрее текстового `emu.py`; полезно для кодеков и x87-плотных участков | нет; нужен `pip` |
| **Triton** | символьное исполнение одной функции (какие входы дают ветку) | нет; тяжёлый |
| **angr** | автоматический поиск пути к `END`/ветке в VM-скриптах | нет; для 1998-игры чаще избыточен |
| **Intel SDE / SoftFloat-векторы** | эталон x87-семантики (80-бит, округление) | нет; сейчас сверяем трассой |

Практика: прежде чем тащить Unicorn/angr, проверить, решает ли задачу
`x86mini.py` + `docs/PLAYER_GHIDRA.md` §4.8 (там расхождение 1 ulp уже
объяснено x87).

## 6. Скорость и качество самого тулкита

| инструмент | зачем | статус |
|---|---|---|
| `cProfile`/`pstats` | найти hotspot (пример: 17 с в `fnv1a` на фильмах) | есть |
| `perf record -g` | профиль Python/C++ без правок кода | есть |
| `hyperfine` | честные замеры «до/после» с прогревом | нет (`time` в цикле — замена) |
| `py-spy` | профиль без перезапуска, удобно для TUI/сервисов | нет |
| `tools/qa/coverage.py` (stdlib `trace`), `--missing MODULE` | чего не тестируем (см. `docs/REGRESSION.md` §4) | нет; `llvm-cov` для C++ не собран |

## 7. Что не тащить

* **Декомпилятор как источник кода.** Clean-room: в `engine/` идут интерфейсы
  и поведение, а не псевдо-C (`AGENTS.md`).
* **Тяжёлые фреймворки ради одной функции** (angr/Triton для линейного
  x87-цикла) — дороже, чем прочитать байты и сверить с эмулятором.
* **Инструменты, требующие записи в установку** (патчеры, «краки») — игра
  только читается; все артефакты в `~/.cache`/`build`/`out`.
* **Автоматизация GUI-отладки в CI** — экран один, прогон невоспроизводим;
  такие снимки делаются вручную и складываются с хэшем состояния
  (`docs/ORACLE.md`).
