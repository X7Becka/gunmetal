# Методика реверса `gunmetal-re`

Рабочая инструкция: как добывать факты о `gundx.exe` и данных игры так, чтобы
их можно было проверить, повторить и не потерять, тратя минимум времени и
токенов. Дополняет `AGENTS.md` (правила проекта) и `tools/re/README.md`
(инструменты). Числа в разделе «Скорость» — замеры на этой машине (32 ядра,
`/mnt/d` — drvfs, `/tmp` — tmpfs, `~` — `/dev/sdd`).

## 1. Лестница доказательств

Каждый факт в документации обязан стоять на одной из трёх ступеней. Ступень
пишется рядом с фактом, а не подразумевается:

| статус | что это значит | чем подтверждается |
|---|---|---|
| **proven** (✅) | инструкция и данные согласованы | адрес инструкции + наблюдение на реальном файле/сейве; для алгоритмов — совпадение с эмулятором байтов или побайтовый round-trip |
| **hypothesis** (🟡) | одна сторона: форма кода **или** значение в данных | явно написано, что подтверждено, а что нет |
| **unknown** (⬜) | известен offset/тип, смысл не установлен | «не проверено» — тоже результат, его фиксируют |

Правила:

* «Код написан» ≠ «пункт готов». Готовность — это тест, прогон `regress.py`,
  побайтовое совпадение или сверка с оракулом.
* Один факт — одна строка/абзац с адресом. Если адрес не назван, факт нельзя
  перепроверить, и он не считается доказанным.
* Данные важнее догадок: сначала прочитать реальный файл (36 уровней, 672
  модели, 983 звука — корпус уже есть), потом объяснять код.
* Отрицательный результат фиксируется: «в поставке `CHEVY` не встречается»,
  «индексы 2896/2896 валидны», «`CONTROLS.CFG` игра не читает» — это такие же
  факты, как положительные.

## 2. Провенанс: всегда известно, *что* мы реверсим

* exe: `/mnt/d/games/Gunmetal 3dfx/gundx.exe`, SHA-256
  `929ffa72…5ac0acd17` (v1.36 3dfx). Полный манифест установки —
  `docs/manifests/gunmetal-3dfx-136.sha256` (2161 файл).
* Проверка окружения и кэша: `python3 tools/re/gmcache.py status --json`.
* `tools/re/exelib.py` берёт exe из `GUNMETAL_EXE`, листинг — из `GUNDX_ASM`,
  кэш — из `GUNMETAL_CACHE`.
* Игра **только читается**. Любая запись — в `build/`, `out/`, `~/.cache`,
  `/var/tmp`; в каталоге установки не появляется ничего.

Если манифест/exe не совпал — сначала выяснить, что изменилось (обновили игру?
подменили файлы?), и только потом продолжать: иначе все адреса и голдены
относятся к другой версии.

## 3. Рабочий цикл одного адреса

1. **Найти.** `grep` по `tools/re/names.csv`, `docs/` (лучше через
   `python3 tools/ctx.py addr 0x4752d0`), затем `names.py`/`xref.py`.
2. **Прочитать код.** `python3 tools/re/disrange.py 0x4752d0 0x475380`
   (листинг в кэше, диапазон читается по индексу), при необходимости —
   `tools/ghidra/mcp.py decompile 0x4752d0 --xrefs` (батчем, см. §6).
3. **Снять данные.** Прочитать реальный файл/сейв тем же `gm.py`, которым
   пользуется оракул; распечатать ровно нужные поля (`--json` + фильтр), а не
   весь дамп.
4. **Подтвердить исполнением.** Если алгоритм сомнительный — исполнить байты
   (`tools/re/x86mini.py`, `tools/re/emu.py`) или сравнить замкнутую форму с
   трассой; расхождение 1 ulp — это x87, а не ошибка модели.
5. **Записать.** Строка в `docs/*_FIELDS.md`/`FORMATS.md` + статус + адрес;
   при изменении scope — `ROADMAP.md` сразу, `NEXT.md` в конце хода.
6. **Закрепить тестом.** Golden в `engine/tests/` или проверка в `regress.py`
   (ровно одна категория), иначе факт сломается молча.

## 4. Скорость скриптов

Правило: **сначала замер, потом оптимизация**. Замеры этого репозитория:

| что | было | стало | чем |
|---|---:|---:|---|
| `exelib.disasm()` — диапазон | ~100 мс (перепарсинг 283 626 строк) | ~0,02 мс | бинарный индекс `gundx.asm.idx`, bisect + seek |
| 100 запросов диапазона | 11,1 с | 0,002 с | то же |
| `gm.py sob --check` на `/mnt/d` | 1,5 с | 0,07 с | зеркало установки на `/dev/sdd` |
| `gm.py inventory` | 7,1 с | 0,14 с | зеркало |
| `python3 regress.py` | 79 с | 46 с | `--mirror` (drvfs → `/dev/sdd`), 113/113 в обоих |

Практика:

* **Тяжёлое — не в `/tmp`.** `/tmp` — tmpfs (≈50 % RAM) и стирается при
  `wsl --shutdown`. Кэш, зеркало, сборки — в `~/.cache/gunmetal-re`,
  `/var/tmp`, `~/build`. Потеря листинга в `/tmp` уже ломала половину
  инструментов и `regress.py`.
* **Кэшируй разбор, а не результат.** Листинг objdump (14,6 МБ) генерируется
  один раз; индекс (2,3 МБ) — один раз на версию листинга; индекс
  сам инвалидируется по size/mtime.
* **Игра по drvfs медленная.** `tools/re/gmcache.py mirror --sync` держит
  локальное зеркало (замер: 4215 файлов, 383 МиБ; полная синхронизация ~65 с,
  инкрементальная ~16 с). `regress.py --mirror` сам синхронизирует зеркало при
  расхождении и кэширует успешную проверку на 15 минут
  (`GUNMETAL_MIRROR_TTL`).
* **Параллель.** Независимые проверки — `check_many(..., workers=16)`;
  фоновые сабагенты — минимум 3 (правило `AGENTS.md`), каждый в своём
  worktree.
* **Не гонять `--full` без нужды.** `regress.py --category save,vm` — секунды
  вместо минуты; `--full` — только перед интеграцией.
* **Профилировать, а не гадать:** `python3 -X importtime`, `time`, счётчики в
  `regress.py` (метка `t+…s` на каждой проверке уже показывает виновника).

## 5. Токены и контекст

Бюджет по умолчанию: **один запрос — ≤ 40 строк вывода**, чтение файла —
только того, что будешь править. Большие файлы (`FORMATS.md` 207 КБ,
`ROADMAP.md` 126 КБ, `NOTES.md` 86 КБ, `AI_CPP.md` 76 КБ) целиком не читаются.

```sh
python3 tools/ctx.py ls                    # какие доки есть
python3 tools/ctx.py outline FORMATS       # оглавление + номера строк
python3 tools/ctx.py doc FORMATS sbw       # только раздел (--max 120 при нужде)
python3 tools/ctx.py addr 0x4752d0         # где адрес документирован
python3 tools/ctx.py find "apply_weapon_blast" --scope code --max 10
python3 tools/ctx.py task                  # верх NEXT.md
python3 tools/ctx.py index                 # пересобрать docs/INDEX.md
```

Правила:

* `grep -n`/`ctx.py find` вместо чтения целиком; указывай `--include`/`--scope`.
* Вывод длинных команд — `| tail -3` / `| head`; `gm.py` уже печатает итоговую
  строку (`36 parsed, 0 failed`) — её и проверяй.
* Не вставляй в контекст содержимое файлов игры, большие JSON и логи; нужен
  конкретный факт — извлекай поле (`--json | python3 -c ...`).
* Сабагенту выдавай ссылки на факты (`docs/X.md §N`, адрес, команду проверки),
  а не пересказ всей истории; список «можно менять» — явный.
* `docs/INDEX.md` — карта: файл → размер → число адресов → о чём. Начинай с неё,
  а не с `ls docs/`.
* Обновляй `NEXT.md` один раз в конце хода, а не после каждого шага.

## 6. Инструменты: что когда

| задача | инструмент |
|---|---|
| адрес → строки листинга | `tools/re/disrange.py` (кэш + индекс) |
| кто ссылается на адрес/строку | `tools/re/xref.py`, `docs/…` через `ctx.py addr` |
| размер записи по сигнатуре | `tools/re/sig.py` |
| таблицы команд/условий | `tools/re/cmdtable.py` |
| раскладка записи по store-функции | `tools/re/table_layout.py` |
| копирование записи A→B | `tools/re/copy_trace.py` |
| декомпиляция/граф вызовов | `tools/ghidra/mcp.py` (headless, `batch` для пачки) |
| исполнить байты как оракул | `tools/re/x86mini.py`, `tools/re/emu.py` |
| состояние кэша/зеркала | `tools/re/gmcache.py status` |
| контекст из доков | `tools/ctx.py` |

Ghidra MCP: сервер на `127.0.0.1:8765`, проект `re/ghidra/`. Для серии
запросов — `batch reqs.jsonl` (одна MCP-сессия), а не десяток запусков.
Имена из `tools/re/names.csv` — единственный источник подписей; новое имя
сначала появляется там, потом в экспорте Ghidra и в доках.

## 7. Документирование фактов

Шаблон строки в `*_FIELDS.md`/`FORMATS.md`:

```
| +0x1d4 | int32 | HP вещи | proven: пишет 0x470c70, читает 0x46f0f0; saved0=100 |
```

Шаблон раздела «разобрано»:

1. что доказано (с адресами и числами);
2. чем доказано (файл/сейв/эмулятор/тест);
3. что осталось и почему (гипотеза, нужен отладчик, нет данных);
4. ссылка на пункт `ROADMAP.md`.

Не дублируй длинные листинги: 5–15 строк вокруг инструкции достаточно,
полный дамп — в `docs/re/`/`out/`, если он нужен для повторной проверки.

## 8. Чеклисты

**Перед началом**

- [ ] `python3 tools/re/gmcache.py status` — exe тот, кэш на месте.
- [ ] Найден пункт в `ROADMAP.md`/`NEXT.md`; область не пересекается с
      работающими сабагентами.
- [ ] Понятно, какой проверкой факт будет доказан.

**Перед утверждением «доказано»**

- [ ] Назван адрес инструкции и наблюдение на данных.
- [ ] Прогнан профильный тест/`regress.py --category …`.
- [ ] Проверено на всех уровнях/файлах, а не на одном (`36/36`, `672/672`).
- [ ] Числа согласованы между Python-оракулом, C++ и доками.

**Перед коммитом**

- [ ] `python3 regress.py` (при интеграции — `--full`), CTest.
- [ ] `ROADMAP.md` обновлён в том же коммите; id пункта — в сообщении.
- [ ] `NEXT.md` — следующий конкретный шаг.
- [ ] Ничего из игры не скопировано в репозиторий (только хэши/имена).

## 9. Антипаттерны (уже стоили времени)

* Читать `FORMATS.md`/`ROADMAP.md` целиком ради одного адреса.
* Держать листинг/`gundx.exe` в `/tmp` и удивляться после `wsl --shutdown`.
* Перепарсить листинг на каждый вызов `disasm()` (100 мс × сотни вызовов).
* Тестировать на `/mnt/d` там, где нужен только разбор (I/O drvfs).
* Хардкодить `LEVEL0.SBW` — на drvfs регистр не важен, на ext4-зеркале важен;
  в `regress.py` для этого есть `gp()`.
* Записывать «сделано» без теста; закрывать пункт молча.
* Запускать `--full` на каждый чих и держать десяток параллельных сборок в
  `/tmp` (tmpfs → swap → лаги).
* Обновлять доки «потом»: следующий агент поверит устаревшей строке.
