# Альфа мировых текстур и постоянный цвет кадра (M4.1.5)

Вопрос был узкий: **откуда у мировых текстур берётся альфа** (если
`docs/MATERIAL_BLEND.md` §4 объясняет ею весь блендинг) и **что подаётся в
`grConstantColorValue`** — не является ли этот цвет фактическим затенением
кадра. Инструмент: `tools/re/alpha_audit.py` (`--json`, `--self-test`; stdlib +
`gm/sbm.py`, `gm/sbw.py`, `tools/re/exelib.py`, всё только чтение).

Коротко: **альфы в `.sbm` нет вообще**. Прозрачность бинарная и делается
хрома-кеем по индексу палитры 0; альфа-блендинг кадра берёт альфу из
`LOCAL(ITERATED)` — вершинную (или константную 1.0, если alpha-параметр не
включён), но не из текстуры. `grConstantColorValue`
в кадровом проходе получает литерал `0xFFFFFFFF` (белый, непрозрачный) — это
не свет и не цвет палитры; затенение — отдельный проход `lighttable`.

Ничего в `gm/`, `engine/`, `regress.py`, `ROADMAP.md`, `AGENTS.md`, `NEXT.md`,
`docs/FORMATS.md` не менялось; игра только читалась.

---

## 1. Формат `.sbm`: альфа-канала нет (доказано)

`gm/sbm.py` / `docs/FORMATS.md` §2: 8 бит на тексель, индексы палитры, mip-цепочка.
Если бы в блобе были альфа-биты или отдельный alpha-plane, полезная нагрузка
была бы **больше** `12 + expected_size()` — разница попадает в `Sbm.extra`.

| архив | блобов | `12 + expected_size` | `extra` | бит на тексель |
|---|---:|---:|---|---|
| `PICS` | 1648 | 1648 / 1648 | `{0: 1648}` | 8 (индекс) |
| `sprites` | 179 | 179 / 179 | `{0: 179}` | 8 (индекс) |

То есть **ни одного лишнего байта** ни в одном из 1827 блобов: ни alpha-plane,
ни «полутона», ни второго канала. Альфа может быть только бинарной — через
один индекс палитры.

### 1.1. Поле `flags` — это и есть признак прозрачности (доказано)

Заголовок `+0x08 u32 flags`. По поставке:

| архив | `flags` | что значит |
|---|---|---|
| `PICS` | `0:1481, 1:126, 2:5, 16:36` | бит 0 — transparent, бит 1 — sky, бит 4 — water |
| `sprites` | `256:1, 257:178` | бит 8 — «спрайт», бит 0 — transparent |

Совпадение с тем, что движок считает сам (`0x423947`, `docs/MIPMAPS.md` §2.3),
**точное по множествам**, а не по количеству:

* загрузчик ставит `type = 1`, если в **уровне 0** есть индекс 0 и
  `zero_count >= 1 << min(log2w, log2h)`; для `PICS` иначе печатает
  `"Warning: Illegal transparent texture %s"` (`0x4a8d88`, `0x423a31`) и
  сбрасывает тип;
* множество текстур `PICS`, прошедших эту эвристику, — ровно множество с
  `flags & 1` (126 = 126, симметрическая разность пуста);
* `flags & 2` — ровно 5 текстур `SKY1..SKY5` (загрузчик `0x4238f3` ставит
  `type = 2` по имени `SKY*` и вообще не сканирует нули);
* `flags & 16` — ровно 36 текстур `WAT*` (загрузчик `0x423a40` делает
  `type |= 0x10` по имени `WAT*`);
* у спрайтов `flags & 1` — ровно у 178 блобов с индексом 0 (179-й,
  `WTRB0014`, без нулей и с `flags = 256`).

Единственное расхождение «сырых» нулей и флага — 4 текстуры `PICS`, где нулей
слишком мало и движок их **не** клюет:

| текстура | размер | нулей | порог `1<<min(log2w,log2h)` | `flags` |
|---|---|---:|---:|---:|
| `ANBUGGY` | 256×128 | 4 | 128 | 0 |
| `CTHBILL` | 128×256 | 14 | 128 | 0 |
| `IRISF` | 128×128 | 7 | 128 | 0 |
| `PUDISINX` | 64×64 | 3 | 64 | 0 |

Поэтому «альфа» — это не свойство текселя, а **тип текстуры**:
`transparent` / `sky` / `water` / обычная.

### 1.2. Как прозрачность реализуется в Glide (доказано по коду)

Палитра для `P_8`-текстур (`GR_TEXFMT_P_8 = 5`; формат пишется как
`[0x4d729c + tmu*0x14] = 5` на `0x41864c`) собирается в `0x4d31a0`
из игровой палитры `0x83d320` (`0x4186f4`..`0x4187a8`). Все 256 записей
получаются с **нулевым альфа-байтом** (`R6<<18 | G6<<10 | B6<<2`), а затем
запись 0 **перезаписывается** на `0x010101`:

| что | адрес | значение |
|---|---|---|
| `mov ds:0x4d31a0, 0x010101` | `0x4187b4` | палитровый индекс 0 = `0x010101` |
| `grTexDownloadTable(0, GR_TEXTABLE_PALETTE=2, 0x4d31a0)` | `0x4187c7` | таблица в Glide |
| `grChromakeyValue(palette[0])` (`mov ecx,ds:0x4d31a0; push ecx`) | `0x4187d4` | ключ `0x010101` |
| `grChromakeyMode(1)` при `[slot+4] == 1`, иначе `0` | `0x418ab5`..`0x418ace` | тип из `0x423947` |

То есть индекс 0 не «полупрозрачный», а **вырезается хрома-кеем** (уникальный
почти-чёрный `0x010101`, чтобы не путаться с настоящим чёрным). `grAlphaTest*`
в импортах `gundx.exe` нет вовсе — только хрома-кей.

## 2. `grConstantColorValue` в кадровом проходе (доказано)

Импорт разрешается динамически: `GetProcAddress("_grConstantColorValue@4")`,
результат кладётся в слот `0x4d7468` (`mov ds:0x4d7468,eax` на `0x416a6a`;
строки имён — в `.rdata`, `0x4a865c`). Все вызовы в образе:

| адрес вызова | аргумент | функция | роль |
|---|---|---|---|
| `0x418988` | `0x00FFFFFF` | `0x4188b2` | 2D/sprite-путь |
| `0x4189df` | `0x00FF0000` | `0x4188b2` | 2D/sprite-путь |
| `0x418cb8` | `0x00FFFFFF` | `0x4188b2` | 2D/sprite-путь |
| **`0x440be8`** | **`0xFFFFFFFF`** | **`0x4409b8`** | **кадровый проход** |

Аргумент везде — **непосредственное значение** (`push imm32`), а не цвет из
света/палитры. В кадровом проходе — белый непрозрачный `0xFFFFFFFF`.

Состояние кадра (`0x4409b8`, ветка `ctx+0xec & 0x800` = Glide-режим):

```
grColorCombine(1, 0, 1, 2, 0)    0x440a74
    function = LOCAL(1), factor = NONE(0),
    local = CONSTANT(1), other = CONSTANT/NONE(2)
    => RGB = grConstantColorValue (белый 0xFFFFFFFF)
grAlphaCombine(1, 0, 0, 2, 0)    0x440a84
    function = LOCAL(1), factor = NONE(0),
    local = ITERATED(0), other = CONSTANT/NONE(2)
    => alpha = LOCAL(ITERATED): вершина (или константа 1.0, если alpha-параметр
       не включён), НЕ текстура
grAlphaBlendFunction(ONE, ONE_MINUS_SRC_ALPHA, ZERO, ZERO)   0x440abe
grFogColorValue(0xFFFFFF)        0x440a97   (фог к белому, docs/MATERIAL_BLEND §4)
grConstantColorValue(0xFFFFFFFF) 0x440be8
```

Значения enum — Glide 2.x (`GR_COMBINE_FUNCTION_LOCAL = 0x1`,
`GR_COMBINE_LOCAL_CONSTANT = 0x1`, `GR_COMBINE_LOCAL_ITERATED = 0x0`,
`GR_COMBINE_OTHER_CONSTANT = 0x2`); те же числа использует и сама Glide для
заливки сплошным цветом (`grColorCombine(LOCAL, NONE, LOCAL_CONSTANT,
OTHER_NONE, FALSE)` в её `initState`).

**Вывод.** `grConstantColorValue` — это RGB-источник кадрового прохода, но он
жёстко белый, поэтому затенения не несёт. Затенение кадра — это
`lighttable`-пост-обработка 8-битного буфера (`0x441b41`/`0x441b59`,
`docs/MATERIAL_BLEND.md` §4): `buf[i] = lighttable[level*0x100 + buf[i]]`,
`level = clamp(0x3f − floor(z), 4, 0x3f)`. Постоянный цвет не зависит ни от
`light`, ни от материала, ни от палитры.

⚠️ Уточнение к `docs/MATERIAL_BLEND.md` §4: «прозрачность — из альфы текстуры»
не подтверждается. Текстура альфы не имеет; альфа-блендинг использует
iterated-альфу, а видимая прозрачность текстур — хрома-кей. Кроме того,
`0x4409b8` по `docs/JOURNAL.md` — программный растеризатор/презентация
8-битного кадра (буферы `ctx+0x104` / `ctx+0xd4`), а не обход полигонов с
`guDrawPolygonVertexListWithClip`; последние вызовы — в путях `0x417xxx`/
`0x418xxx`. Это не меняет вывод про альфу и постоянный цвет, но формулировку
«один Glide-стейт на все полигоны» стоит перепроверить отдельно (см. §5).

## 4. Источник альфы → как использовать в `gm/render.py`

| источник | статус | как использовать |
|---|---|---|
| 8-битная альфа в `.sbm` | **опровергнуто** | не искать; `extra == 0` у всех 1827 блобов |
| палитровый альфа-байт | **опровергнуто** | все записи палитры строятся с `A = 0`, но не используются |
| индекс 0 + `flags & 1` | доказано | бинарная альфа: `alpha = 0`, если индекс текселя 0; иначе 255. Ключевать только текстуры с `flags & 1` |
| эвристика загрузчика (`0x423947`) | доказано | для `PICS`: `type=1`, если `zeros >= 1<<min(log2w,log2h)`; 4 текстуры (`ANBUGGY`, `CTHBILL`, `IRISF`, `PUDISINX`) ключевать **нельзя** |
| `SKY*` / `flags & 2` | доказано | тип 2, нули не сканируются: не ключевать, рисовать фоном |
| `WAT*` / `flags & 16` | доказано | тип `|0x10` (вода): к альфе отношения не имеет, это отдельный признак |
| `poly+0x7c & 2` | эмпирика (318 полигонов `level0`) | помечает грань как «прозрачную» (текстура из `sprites`); использовать как подсказку, не как альфу |
| iterated-альфа вершин + `ONE/ONE_MINUS_SRC_ALPHA` | доказано (стейт) | если включать блендинг в вьювере — брать альфу вершины/грани, не текстуры |
| `grConstantColorValue` | доказано | `0xFFFFFFFF` в кадре; не применять как затенение |
| `lighttable` (`0x441b41`) | доказано | затенение кадра — отдельный пасс; в `gm/render.py` уже приближён `f = light/127` |

Практическое следствие для текущего кода: `gm.render.Texture.transparent_index`
возвращает 0 при **любом** нуле в уровне 0. Для 126 «настоящих» текстур это
совпадает с движком, но 4 текстуры из таблицы выше в игре **не** прозрачны —
если `alpha_test` когда-нибудь станет режимом по умолчанию, их надо исключать
по `flags & 1` (или по порогу загрузчика). Спрайты — наоборот: у всех 178
«нулевых» `flags & 1` выставлен, так что для `sprites` достаточно наличия
индекса 0.

## 5. Что осталось

1. **Mip-alpha.** Ключ применяется к каждому mip-уровню отдельно, а уровни в
   `.sbm` хранятся готовыми. У 125 текстур `PICS` нижний mip имеет на ≥2 п.п.
   больше нулей, чем уровень 0 (последние уровни часто 50–100 % нулей).
   Glide делает хрома-кей **после** фильтрации, поэтому на границах возможны
   тёмная кайма/«дыры»; наш вьювер тестирует покрытие после bilinear
   (`alpha` в `gm/render.py`), это модель, а не трассировка драйвера.
   Нужно решение: ключевать по уровню 0, по каждому mip или по покрытию.
2. **Аддитивные спрайты/эффекты.** Материал (`add`/`varadd`) в 3dfx-пути не
   читается (доказано ранее), но 2D/sprite-пути ставят **разные**
   `grAlphaBlendFunction`: в образе есть `(SRC_ALPHA, SRC_ALPHA, SRC_ALPHA,
   ZERO)` — аддитивный (`0x4188ea` и др.), `(SRC_ALPHA, ONE_MINUS_SRC_ALPHA,
   SRC_ALPHA, ZERO)` — обычный over (`0x418b42`), `(ZERO, DST_ALPHA,
   SRC_ALPHA, ZERO)` (`0x418bf3`), `(SRC_ALPHA, ZERO, …)` (`0x41881c`),
   `(ZERO, ONE, …)` (`0x417b20`). Какая ветвь рисует эффекты (68 граней
   `level0` с `poly+0x00 < 0`) — не разобрано; «аддитивность» спрайтов пока
   гипотеза, но режимы для неё в образе есть.
3. **Семантика хрома-кея в драйвере.** Точная формула (сравнение до/после
   фильтрации, поведение на mip-границах) — внешняя спецификация
   `glide2x.dll`; в `gundx.exe` видны только `grChromakeyValue(0x010101)` и
   переключение режима по типу текстуры.
4. **Кто рисует мировые полигоны в 3dfx-сборке.** `0x417xxx`/`0x418xxx`
   вызывают `guDrawPolygonVertexListWithClip`, а `0x4409b8` пишет 8-битный
   буфер (`ctx+0x104`) и делает пост-обработку. Разграничить «мировой проход»
   и «презентацию» — отдельная задача; на выводы §1–§2 это не влияет.
5. `exflare` не резолвится в пуле (как и в `tools/re/tex_audit.py`), `overlay`
   не наносится — без изменений.

## 6. Воспроизведение

```sh
python3 tools/re/alpha_audit.py --self-test          # 22 проверки, rc=0
python3 tools/re/alpha_audit.py --level level0       # отчёт + вердикт
python3 tools/re/alpha_audit.py --level level0 --json > /var/tmp/alpha.json
python3 tools/re/alpha_audit.py --no-exe             # без gundx.exe/listing
python3 tools/re/disrange.py 0x440a64 0x440c02       # Glide-стейт кадра
python3 tools/re/disrange.py 0x4186f4 0x4187d8       # палитра, entry0, chromakey
python3 tools/re/disrange.py 0x4238f3 0x423aa0       # тип текстуры (sky/water/zero)
```

`--self-test` синтетический: текстура без нулей / с нулями, граница порога
7 и 8 нулей при `8×8`, «лишние байты» как подозрение на alpha-plane,
детерминизм, декодирование enum Glide, извлечение `push`-аргументов из
синтетического листинга; на поставке — `0xFFFFFFFF` в `0x440be8`,
`0x010101` в палитре и в `grChromakeyValue`.
