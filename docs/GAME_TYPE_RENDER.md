# Рендер экрана 19 `MULTIPLAYER GAME TYPE` (`engine/src/ui/game_type_render.h`)

Срез 1 пункта `M8.8`: модуль **рисует экран 19** в RGBA-буфер 320×200 из
реальной установки: заголовок `MULTIPLAYER GAME TYPE`, список режимов
мультиплеера, отфильтрованный байтом доступности `0x4c1290`, `Cancel` последней
строкой, подсветку курсора шрифтом 4 и плату `PLATE`. Геометрия — из
обработчика `0x48a580` (`docs/UI_SCREENS.md` §2/§3.8), атласы — из
`render/text_layout` (`FONTS4` в `FRONTEND/BMP.IDX`), байт маски — из
сетевого старта `0x407560`.

Код: `engine/src/ui/game_type_render.h/.cpp`; тест —
`engine/tests/test_game_type_render.cpp` (CTest `game_type_render`, label
`quick`). Канон поведения — `docs/UI_SCREENS.md` §3.8 и этот документ; образец
того же класса задач — `docs/START_GAME_RENDER.md`.

Проверка:

```sh
export PATH=$HOME/tools/cmake-4.4.4-linux-x86_64/bin:$HOME/tools/bin:$PATH
cmake --build build/sandbox --target gm_game_type_render_tests -j 4
./build/sandbox/engine/tests/gm_game_type_render_tests
ctest --test-dir build/sandbox -R '^game_type_render$' --output-on-failure
python3 regress.py --mirror --json
```

## 1. Что доказано (`0x48a580`, docs/UI_SCREENS.md §2/§3.8)

Обработчик занимает `0x48a580`..`0x48a77d` (последний `ret`; дальше `nop` до
`0x48a780`). Всё в таблице — его сайты и сайты общего отрисовщика `0x485dd0`
(листинг: `python3 tools/re/disrange.py 48a580 48a780` и `485dd0 485e80`).

| факт | значение | источник |
|---|---|---|
| длина списка | **12** (`0x67f10c = 0xc`) = 11 режимов (items 0..10) + `Cancel` (11) | `0x48a581` |
| шаг строки | **8** (`0x662d58 = 8`) | `0x48a58b` |
| плата | `0x486050` копирует `PLATE` 196×131 в `0x6865f8`; весь текст пишется в эту копию (клип 196×131) | `0x48a595`; §3, §9 |
| заголовок | `MULTIPLAYER GAME TYPE` (`0x4bdae0`), шрифт **5**, `centered=1`, `x 18`, `row 10`, `item -1` → **y 10**, x = (196 − width)/2 | `0x48a59a`..`0x48a5ae`; `0x485de2`..`0x485dfa` |
| `centered` | `x = (196 − measure(text)) / 2`, целочисленно | `0x485de2`..`0x485dfa` |
| `item == -1` | обнуляет `item·step`, поэтому y = row | `0x485e04`..`0x485e09` |
| `One Computer` | `0x4bdad0`, item **0**, **безусловно**: `row=-18` (абсолютный y 18), `x 18`, шрифт 0 | `0x48a5b1`..`0x48a5c0` |
| первый шаг | `esi = [0x662d58] + 18 = 26` | `0x48a5c5`..`0x48a5cd` |
| фильтр | читается **байт** `0x4c1290` (`mov al`), тесты `test BYTE PTR` | `0x48a5d0`, `0x48a5fa`, `0x48a646`, `0x48a670`, `0x48a6bc`, `0x48a6e6`, `0x48a710`, `0x48a73a` |
| сдвиг | `add esi, step` стоит **внутри** взятой ветки каждого блока, поэтому `y = 18 + 8·k`, где `k` считает только разрешённые режимы; пустых строк нет | концы блоков `0x48a5f8`, `0x48a644`, `0x48a6ba`, `0x48a6e4`, `0x48a70e`, `0x48a738`, `0x48a762` |
| `Cancel` | `0x4bda0c`, item **11**, `row = -(18 + 8·k)` (абсолютный y), `x 18`, шрифт 0; рисуется всегда последним | `0x48a764`..`0x48a774` |
| подсветка | `item == [0x68ccf4]` и текст не пуст → шрифт принудительно **4**; `Cancel` — тоже item, поэтому тоже может подсвечиваться | `0x485e0d`..`0x485e19` |
| стрелки | обработчик не вызывает `0x485cc0`/`0x485d00`; полный список кончается на y 106 (8 px ячейка), прокрутка не нужна | листинг `0x48a580..0x48a77d` |
| порядок | заголовок → `One Computer` → восемь тест-блоков (по порядку бит) → `Cancel` | порядок вызовов `0x48a5a9`..`0x48a774` |

### 1.1. Порядок пунктов и id

Пункты идут в порядке **убывания адресов строк** (как записано в §3.8):

| item | строка | VA | y при полной маске |
|---:|---|---|---:|
| 0 | `One Computer` | `0x4bdad0` | 18 |
| 1 | `Network Client` | `0x4bdac0` | 26 |
| 2 | `Network Server` | `0x4bdab0` | 34 |
| 3 | `Network No Render Server` | `0x4bda94` | 42 |
| 4 | `TCP/IP Client` | `0x4bda84` | 50 |
| 5 | `TCP/IP Server` | `0x4bda74` | 58 |
| 6 | `TCP/IP No Render Server` | `0x4bda5c` | 66 |
| 7 | `Serial Cable Client` | `0x4bda48` | 74 |
| 8 | `Serial Cable Server` | `0x4bda34` | 82 |
| 9 | `Modem Client` | `0x4bda24` | 90 |
| 10 | `Modem Server` | `0x4bda14` | 98 |
| 11 | `Cancel` | `0x4bda0c` | 106 |

`y = 18 + 8·k`, где `k` — номер **нарисованной** строки. При выключенных
режимах подписи сдвигаются вверх, пустых строк не остаётся. Item id — это
**не** номер видимой строки: id фиксирован таблицей выше (так их и пушит
обработчик), а позиция зависит от маски. Навигация `0x48ef00` поэтому хранит в
`[0x68ccf4]` именно item id и пропускает выключенные биты (повторяет
`esi += delta`, пока кандидат не разрешён, `0x48ef1b`..`0x48ef72`; `Cancel`
зациклен на `One Computer`, `0x48ef69`; вверх с `One Computer` — на `Cancel`,
`0x48ef2c`).

### 1.2. Байт маски `0x4c1290`

Маска заполняется сетевым стартом `0x407560`: он сбрасывает её в 0
(`0x407563`), затем по типу протокола ставит биты (jump tables `0x407cec` и
`0x407cfc`, or-сайты `0x407c23`..`0x407cc9`). Экран 19 тестирует те же биты:

| бит | строки экрана 19 | тип в `0x407560` |
|---:|---|---|
| `0x01` | `Network Server`, `Network No Render Server` | сервер, тип 1 (`or al,0x1`, `0x407c23`) |
| `0x02` | `Network Client` | клиент, тип 1 (`or al,0x2`, `0x407c86`) |
| `0x04` | `TCP/IP Server`, `TCP/IP No Render Server` | сервер, тип 2 (`or al,0x4`, `0x407c37`) |
| `0x08` | `TCP/IP Client` | клиент, тип 2 (`or al,0x8`, `0x407c9a`) |
| `0x10` | `Modem Server` | сервер, тип 3 (`or eax,0x10`, `0x407c4b`) |
| `0x20` | `Modem Client` | клиент, тип 3 (`or al,0x20`, `0x407cae`) |
| `0x40` | `Serial Cable Server` | сервер, тип 4 (`or al,0x40`, `0x407c5f`) |
| `0x80` | `Serial Cable Client` | клиент, тип 4 (`or al,0x80`, `0x407cc2`) |

Тип 1..4 — порядок таблиц: `0x407cec` (сервер) = `0x407c23`/`0x407c37`/
`0x407c4b`/`0x407c5f`, `0x407cfc` (клиент) = `0x407c86`/`0x407c9a`/
`0x407cae`/`0x407cc2` (значения таблиц прочитаны из образа). У типа 3
серверный or идёт через `edi = 0x10` (`0x407bae`), поэтому это тот же бит
`0x10`.

`One Computer` и `Cancel` бита не имеют. Значит, **пустой набор режимов
недостижим**: при `mask = 0` экран рисует две строки — `One Computer` и
`Cancel`. Модуль не выдумывает отказ «нет режимов»; защитная ветка на пустую
таблицу оставлена только как контракт (как `slots.empty()` у
`ui/start_game_render`), из поставочной таблицы она не срабатывает.

Старшие биты `0x4c1290` не читаются: `0x48a5d0` грузит `al`, остальные тесты —
`test BYTE PTR`. Поэтому `mask = 0x100` эквивалентен `0`, а `0x1FF` — `0xFF`
(проверено тестом).

## 2. Модель кадра

* Холст — 320×200 (`0x6d8fc0`, mode 13h), по умолчанию непрозрачный чёрный
  `#000000FF`. `options.background` — имя записи `FRONTEND/BMP.IDX`,
  нарисованной в (0,0) **до** текста; пустая строка = чёрный холст.
  Доказанная плата экрана — `PLATE` 196×131 (`0x486050`), но она не рисуется
  неявно (как у экранов 13/14/17/30).
* Текст клипается к полосе 196×131: `0x485dd0` пишет в копию `PLATE`
  `0x6865f8`, за её пределы пиксель не попадает. Холст вне платы остаётся
  чёрным.
* Шрифты — три грани `FONTS4`: заголовок 5, строки 0, подсветка 4
  (§3). Цвета из палитры атласа: заголовок (155,15,15), строки (19,15,15),
  подсветка (239,239,239). Ячейка 8×8; строка `y` занимает `y..y+7`.
* Заголовок центрируется по ширине **advance**-сумм (`0x47fa50`), а не по
  чернилам: при поставочном `FONTS4` `x = (196 − 120)/2 = 38`.
* Подсветка — только смена грани на 4 (`0x485e0d`..`0x485e19`): ни полосы,
  ни рамки, ни `MENULIT` на этом экране нет.
* `options.cursor` — item id `0..11`, а не видимый номер строки. Курсор на
  выключенном режиме не подсвечивает ничего (кадр побайтово равен
  `cursor = -1`); значения вне `0..11` тоже ничего не подсвечивают.
* Точный fade (`fade_lut*`) — тот же индексный слой `0x682f90`, что у
  `ui/start_game_render`/`ui/pager_render`: таблица применяется к индексу
  палитры **до** поиска цвета, поэтому видит индекс, которым пиксель нарисован.
  Без таблицы и дампа — отказ, не «молча без fade».

## 3. API

```cpp
struct GameTypeRenderOptions {
    std::string background;              // "" = чёрный; "PLATE" = плата экрана
    int cursor = 0;                      // [0x68ccf4], item id 0..11
    std::uint32_t mask = 0xFF;           // [0x4c1290], читается младший байт
    bool fade_lut = false;
    int fade_lut_level = 11;             // 0..15
    std::string fade_lut_dump;           // 4096 байт, docs/HUD_LUT.md §2
    const HudLut* fade_lut_table = nullptr;
};

struct GameTypeRenderStats {
    int rows;             // нарисованные строки, включая Cancel
    int modes;            // разрешённые режимы (0..11)
    int first_row;        // всегда 18
    int cancel_row;       // 18 + 8*modes
    int highlight_item;   // item под курсором или -1
    int arrows;           // всегда 0 (на экране нет прокрутки)
    int ink_pixels;       // уникальные пиксели чернил глифов
    int missing_glyphs;
};

bool render_game_type(const std::filesystem::path& game,
                      const GameTypeRenderOptions&,
                      std::vector<std::uint32_t>& rgba,
                      int& width, int& height,
                      GameTypeRenderStats* = nullptr,
                      std::string* error = nullptr);
```

Вспомогательные (для CLI/UI и тестов): `game_type_entries()` (11 записей
`{label, bit, item}`), `game_type_allowed(entry, mask)`,
`game_type_rows(mask)` (разрешённые режимы + `Cancel`), константы
`kGameTypeBit*`, `kGameTypeRows = 12`, `kGameTypeItemStep = 8`.

Отказы (префикс `game_type_render:`): пустой путь игры; нет/битый
`FRONTEND/BMP.IDX`; нет атласа `FONTS4` (шрифты 5/0/4); неизвестная/битая/
не-8-bpp запись фона; `fade_lut` без таблицы и дампа или с нечитаемым дампом.
При отказе `rgba` очищен, `width = height = 0`, статистика обнулена.

Курсор (полная маска): подсветка = 121/134/125/57 «белых» пикселей

10 `Modem Server` / 11 `Cancel`; чернила полосы 154/166/164/76.
Курсор 2 при `mask = 0x02` (Network Server выключен) — подсветки нет, кадр
побайтово равен `cursor = -1`; курсоры `-1/12/99` — тоже без подсветки.

`background = "PLATE"`: кадр совпадает с независимо декодированной платой +
глифами (0 отличий), от чёрного кадра отличаются 23198 пикселей, 38324
пикселя вне платы остаются чёрными, чернила те же 2478.

Fade: уровень 11 — 0 отличий от кадра без fade; уровень 0 меняет 2478
пикселей (все чернила), `ink_pixels` не меняется, вне платы нечёрных 0.

## 5. Ограничения

* **Нет ввода/навигации**: модуль не читает клавиатуру и не двигает
  `[0x68ccf4]`; правило обхода (`0x48ef00`, пропуск выключенных битов,
  зацикливание `Cancel ↔ One Computer`) описано в §1.1, но реализуется
  вызывающим (UI/CLI), а не рендерером.
* **Нет звука**: `updown`/`select` (`docs/UI_SOUNDS.md`) не моделируются.
* **CLI — есть (срез 2):** `--game-type [--game-type-mask HEX]
  [--game-type-cursor N] [--no-plate] [--png OUT] [--fade-lut N]`. Печатает
  `game_type: mask=0xff rows=12 modes=11 cancel_row=106 highlight=0
  arrows=0 ink=2478 missing=0`; маска `0x01` — `rows=4 modes=3
  cancel_row=42 ink=1014`. CTest `cli_game_type`, `_mask`, `_png`;
  `cli_fade_lut` сверяет 11 = без fade, 13 ≠ без fade.
* **Нет сетевых диалогов**: за каждым пунктом в оригинале стоит свой экран
  настройки; здесь рисуется только список типов.
* **Маска — байт**: старшие биты `options.mask` игнорируются, как в
  `0x48a5d0`/`test BYTE PTR`; это не «нормализация», а доказанное поведение.
* **Пустой список не выражается**: `One Computer` и `Cancel` безусловны, поэтому
  отказ «нет режимов» из поставочной таблицы недостижим (см. §1.2).
* **Соответствие «номер шрифта → атлас»** для 0/4/5 взято из
  `docs/UI.md` §10.3/`docs/MENU_RENDER.md` §3; независимой привязки номеров в
  коде нет — это общее открытое место фронтенда, не специфика экрана 19.
