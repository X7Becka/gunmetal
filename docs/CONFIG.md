# `GUNMETAL.CFG` / `CONTROLS.CFG` — карта полей

Статус: **1.93 разобран (чтение + запись, побайтовый round-trip)**;
`CONTROLS.CFG` — **opaque** (контейнер тот же, тело не разобрано, см. §8).
Реализация: `gm/config.py`; проверка: `python3 tools/parity_config.py`.
Эталонная установка — `/mnt/d/games/Gunmetal 3dfx` (v1.36), файлы только
читаются.

Ниже `u8/u16/u32` — little-endian, если не сказано иное; смещения — от начала
файла. Адреса — VA `gundx.exe` (`ImageBase 0x400000`, карта секций —
`tools/re/README.md`). Дизассемблерный листинг: `objdump -D -M intel`.

---

## 1. Что это за файл

`GUNMETAL.CFG` — **дамп фиксированной структуры на 0x2000 байт** (не
текстовый конфиг и не «список ключ=значение»). Загрузчик читает ровно
0x2000 байт, сверяет 0x25 байт магии и раскладывает последовательность
`u32` по глобальным переменным движка. Писатель собирает такую же картинку на
стеке и сбрасывает её при выходе из игры.

| роль | адрес | как вызывается |
|---|---|---|
| загрузчик | `0x484cf0` | `0x44a518` (после установки режима по умолчанию) |
| писатель | `0x485440` | `0x4908b2` внутри `0x4908a0` (`printf("\n%s is done.\n", "GUNMETAL")`), вызывается из отдельной функции `0x44da10` |
| вызов писателя | `0x4908a0` | — |

Загрузчик:

| шаг | адрес |
|---|---|
| `fopen("GUNMETAL.CFG","rb")` (`0x4bc370`, режим `0x4a6388`) | `0x484dcd` / `0x484e64` |
| `fread(buf, 0x2000, 1, f)` (`0x40dc70`) | `0x484e8a` |
| сравнение магии с `0x4bc380` | `0x484e9b`…`0x484ed2` |
| скалярные поля (0x190…0x1DC) | `0x484ed8`…`0x484fcc` |
| два имени профилей (0x1E0…0x227) | `0x484fd2`…`0x484ff8` |
| массивы по 4 dword (0x228…0x247) | `0x485001`…`0x485021` |
| осевые пресеты, чувствительность, кнопки (0x248…0x278) | `0x485023`…`0x48517f` |
| четыре записи контроллера (0x27C…0x8AB) | `0x48518b`…`0x485257`, цикл 4× |
| «пол» чувствительности 0.2 с | `0x485272`…`0x4852e4` |
| разбор `KEYCFG\*.KEY` и выбор профиля по имени | `0x4852e7`…`0x4853e6` |

Писатель:

| шаг | адрес |
|---|---|
| сохранить все `KEYCFG\%.8s.key` (`fwrite … 0x178`) | `0x485440`…`0x4854e0` |
| скопировать магию в буфер `[esp+0x40]` | `0x4854f4` |
| 20 скалярных полей `[esp+0x1d0]`…`[esp+0x21c]` = 0x190…0x1DC | `0x48552a`…`0x485630` |
| имена, массивы, пресеты, кнопки (0x1E0…0x278) | `0x48564e`…`0x48575b` |
| записи контроллера, курсор `ebx` = индекс dword | `0x485762`…`0x48582a` |
| `fopen("GUNMETAL.CFG","wb")` / `fwrite(buf,1,0x2000,f)` / `fclose` | `0x485830` / `0x485855` / `0x48585e` |

Курсор писателя стартует с `0x78` (смещение 0x1E0), за 4 записи по 99 dword
доходит до `0x22B` (0x8AC) и дальше не идёт — это и есть граница
«определённой» части файла.

## 2. Контейнер

```
0x0000  char  magic[0x25]   // "GUNMETAL Configuration File. av1.93\x1a\0"
0x0025  u8    undefined[0x16B]   // 0x025..0x18F — писатель их не трогает
0x0190  ...   поля (см. §3)
0x08AC  u8    undefined[0x754]   // 0x8AC..0x1FFF — писатель их не трогает
```

* Размер: ровно **8192 (0x2000)**. `fread` запрашивает `0x2000` элементов по
  1 байту с count=1, т.е. файл короче 8 КБ не загрузится (загрузчик уйдёт в
  ветку ошибки `0x485269` и оставит значения по умолчанию).
* Магия сверяется **целиком вместе с завершающим NUL** (`0x484e9b`:
  побайтовое сравнение до `\0`), поэтому строка версии — часть формата:
  `av1.93` для `gundx.exe` 1.36. `av1.91` (см. §8) отвергается.
* В `Config.to_bytes()` область 0x025..0x18F и 0x8AC..EOF сохраняется
  дословно (`gap`/`tail`); для нового файла — нули.

### 2.1. Почему «undefined» — это действительно мусор, а не поля

Писатель выделяет `0x2030` байт стека (`0x485440`: `mov eax,0x2030; call
0x40d950`), пишет только магию, поля и записи, а затем делает
`fwrite(buf, 1, 0x2000, f)` (`0x485855`). Области 0x025..0x18F и
0x8AC..0x1FFF в буфере не инициализируются вообще — туда попадает то, что
лежало на стеке.

Подтверждение данными:

* у `GUNMETAL.CFG` в 0x100..0x180 видны похожие на указатели значения
  `0x001AE070`, `0x773DC06A`, `0x001AE080`, `0x773DC075` (типичный остаток
  стека, а не конфиг);
* `CONTROLS.CFG` в тех же местах содержит другие байты (см. §8);
* в `KEYCFG/*.key` «хвост» 0x108..0x177 (писатель тоже сбрасывает 0x178 байт,
  а осмысленных там 0x108) **одинаков у всех трёх файлов**: `f3 78 51 6d` в
  0x108, `00 40 29 00` в 0x160, `70 e0 1a 00 6a c0 3d 77` в 0x170 — то есть
  это один и тот же остаток стека от одного и того же пути записи.

Поэтому парсер их не интерпретирует, но и не теряет.

Тип всех полей — `u32`; в колонке «куда» — глобал движка, в который загрузчик

### 3.1. Биты `play_flags_p1` / `play_flags_p2`

Метки экрана PLAY OPTIONS (`0x4bd040`), порядок проверок — `0x48619d`…`0x486316`:

| бит | опция |
|---|---|
| 0x00400 | Skip Empty Weapons (`0x4bd02c`) |
| 0x01000 | Don't Auto-Target when Looking (`0x4bcfb0`) |
| 0x04000 | Skip Deadly Weapons (`0x4bd018`) |
| 0x08000 | Switch Weapon To Picked-Up Ammo (`0x4bcffc`) |
| 0x10000 | Auto Switch Weapons When Ammo Depleted (`0x4bcfd8`) |
| 0x100000 | Mouse Cheating (`0x4bcf98`) |

`0x44d68c` маскирует именно эти шесть бит (`and 0x11D400`) при копировании в
структуру игрока — это подтверждает, что остальные биты слова не используются.
В поставочном файле стоят `0x400 | 0x10000`.

## 4. Имена профилей 0x1E0…0x227

Два имени по **9 символов**, каждое хранится как девять `u32` (загрузчик берёт
только младший байт: `mov dl,[eax]`), причём имена **чередуются**:

```
0x1E0 + 8*k  u32  name1[k]     k = 0..8
0x1E4 + 8*k  u32  name2[k]
```

В поставочном файле: `name1 = "PERFECT"`, `name2 = "SPLIT1"`.

Доказательство семантики — не догадка: после чтения конфига тот же
загрузчик сканирует `KEYCFG\*.KEY` (`0x4852e7`), читает по 0x178 байт
(`0x48534a`) и сравнивает первые 9 символов имени файла с этими двумя
буферами (`0x48537e`, `0x485398`), выставляя индексы профилей
`0x5a4910`/`0x4aa488`. На диске лежат ровно `PERFECT.key`, `SPLIT1.KEY`
(и неиспользуемый `SPLIT2.KEY`) — см. `tools/parity_config.py`, проверка
«config key names exist in KEYCFG/».

| 0x248 | u32 | `joystick_used_by` | `0x5a4938` | 1 = Player 1 (`'Used By: %s'` `0x4bd8b4`, таблица `0x4bc548`) |
| 0x24C | u32 | `axis_left_right` | `0x68cd70` | 4 = Linear Turn L/R (`'Left/Right: %s'` `0x4bd8a4`) |

| 0x254 | u32 | `axis_up_down` | `0x68cd78` | 0 = Not Used (`'Up/Down (3D): %s'` `0x4bd86c`) |
| 0x258 | u32 | `sensitivity[0]` | `0x4aac38` (double) | 2200 → 2.2 с |
| 0x25C | u32 | `sensitivity[1]` | `0x4aac40` (double) | 2200 → 2.2 с |
| 0x260 | u32 | `sensitivity[2]` | `0x4aac48` (double) | 2200 → 2.2 с |
| 0x264 | u32 | `buttons[0]` | `0x4aac10` | 5 = Fire (`'Button 1: %s'` `0x4bd85c`) |
| 0x268 | u32 | `buttons[1]` | `0x4aac14` | 15 = Activate (`Button 2`) |
| 0x26C | u32 | `buttons[2]` | `0x4aac18` | 5 = Fire (`Button 3`) |
| 0x270 | u32 | `buttons[3]` | `0x4aac1c` | 15 = Activate (`Button 4`) |
| 0x274 | u32 | `assign_slot[0]` | `0x4bc540` | −1 |
| 0x278 | u32 | `assign_slot[1]` | `0x4bc544` | −1 |

* `0x4bc540/0x4bc544` — не настройка, а **состояние UI**: индекс слота
  (0..3) или −1, который экран назначения клавиш сейчас назначает игроку 1/2
  (`0x48c146`, `0x48c17e` пишут в массив `0x5a4918`).
* `0x4a5ae8`/`0x4a5af8` — по 4 dword, инициализированы `0xFFFFFFFF`; кроме
  загрузчика, писателя и сброса (`0x48d22e`) **никем не читаются**. Смысл
  неизвестен, поэтому в модели это «spare», а не «key1/key2».
* Осевые пресеты: таблица `0x4bc468`, 18 записей по 12 байт
  `{char *name; u32 mask_lo; u32 mask_hi}`; загрузчик берёт `[idx*12+4]` и
  `[idx*12+8]` в `0x4aac20`…`0x4aac34`. Имена: `Not Used`, `Forward/Back`,
  `Accel Turn L/R`, `Accel Turn R/L`, `Linear Turn L/R`, `Linear Turn R/L`,
  `Strafe L/R`, `Strafe R/L`, `Look Up/Down`, `Look Down/Up`, `Speed ± Slide`,
  `Speed ∓ Slide`, `Speed ± Nudge`, `Speed ∓ Nudge`, `Weapons ±`, `Weapons ∓`,
  `Equip Cycle ±`, `Equip Cycle ∓`.
* Кнопки джойстика индексируют таблицу `0x4bc558` (20 названий действий:
  Move Forward … Headlights).
* Чувствительность: загрузчик делает `fild qword(поле)` (старшая половина
  нулевая, т.е. фактически u32) `* 0.001` (`0x4a2910`); если результат
  `< 0.2` (`0x4a2930`), ставится 0.2. Писатель делает обратное —
  `double * 1000.0` (`0x4a2938`) и `FISTP` (`0x40e0e0`), поэтому в файле
  лежат **миллисекунды**. Парсер хранит сырое `u32` и отдаёт секунды через
  `Config.sensitivity_seconds`.
* «Странность» поставочных данных: `axis_forward_back` = 8 = `Look Up/Down`.
  Это именно то, что записано в файле (0x250 = 8), а не ошибка разбора:
  отображение строки «Forward/Back» берёт значение из `0x68cd74` (`0x489afa`).

## 6. Четыре записи контроллера (0x27C…0x8AB)

Загрузчик крутит цикл 4 раза (`0x485257`), писатель — тоже 4
(`cmp eax,0x4aa890`). Размер записи — **0x18C**, база `0x27C + 0x18C*i`;
`0x27C + 4*0x18C = 0x8AC` — точное закрытие формата.

```
+0x000  u32  slot                       -> 0x5a4918[i]        (4 dwords)
+0x004  u32  buttons[32]                -> 0x4aa490 + 0x80*i  (4 x 0x80 Б)
+0x084  6 x { u32 mask_a; u32 mask_b; u32 preset }
                                        -> 0x4aa894 + 0x30*i, байт preset -> 0x68cd00 + 6*i
+0x0CC  16 x { u32 bit; u32 lo; u32 hi }
                                        -> 0x4aaa10 + 0x40*i, байты lo/hi ->
                                           0x68cd30 + 2*(4*i + k/4)
```

Поставочные значения (все 4 записи идентичны):

* `+0x000 = 0`;
* `+0x004`: `0x20`, `0x8000`, далее 30 × `0xFFFFFFFF`;
* `+0x084`: `(4,8,0)`, `(1,2,0)`, `(0x800,0x800,0)`, `(-1,-1,0)` ×3;
* `+0x0CC`: `(6,0,0)`, `(13,0,0)`, `(7,0,0)`, `(14,0,0)`, далее 12 × `(-1,0,0)`.

Семантика (что доказано кодом):

* `buttons[32]` — **битовые маски действий** для 32 входных каналов:
  `0x44bfd4` читает `[0x4aa490 + (player*32 + channel)*4]`, отрицательное
  значение (`-1`) пропускает канал, иначе делает `test <битовое поле>, mask`.
* `+0x084` — пары масок `value`/`extra` для шести осей/хаток; третий элемент
  (`preset`) — индекс в ту же таблицу `0x4bc468`, но во время работы он
  берётся из байтового массива `0x68cd00 + 6*i + slot`, который крутится по
  модулю 18 (`0x48c1f5`: `(v+17) % 18`) и служит счётчиком «залипания».
* `+0x0CC` — **номера битов** (`1 << bit`, `0x44c054`), а не маски; `-1` =
  не назначено. Байты `lo/hi` попадают в `0x68cd30`; при четырёх записях по
  16 значений в каждой паре `(4*i + k/4)` остаётся только последнее значение
  группы из четырёх (`k % 4 == 3`), остальные затираются — так устроен код,
  и это отражено в модели (все 16 значений хранятся для round-trip).
* `slot` — состояние UI («какому слоту сейчас назначается клавиша»).

Что **не** доказано и потому не названо: какое физическое устройство
соответствует каждой из 4 записей и каждому из 32 каналов; почему в
поставочном файле первые два канала имеют маски `0x20` и `0x8000`.

## 7. Значения по умолчанию (когда файла нет / он отвергнут)

До вызова загрузчика игра ставит (`0x44a4ee`…`0x44a512`):

```
width = 640, height = 480, colour_depth = 8, refresh = 0, mode_flags = 0
```

Остальные глобалы — `.bss` (нули), кроме того, что загрузчик сам ставит
`marker = 1` и «пол» чувствительности 0.2 с. Отсюда значения по умолчанию в
`dataclass Config` (`640×480×8`, `sensitivity = 200` мс и т.д.). Учтите:
`0x1BC` (`unknown_1bc`) в модели по умолчанию 0, а в поставочном файле 1.

## 8. `CONTROLS.CFG` — тот же контейнер, другая версия

* 8192 байта, магия `"GUNMETAL Configuration File. av1.91\x1a\0"` (май 1998;
  `GUNMETAL.CFG` — `av1.93`, октябрь 1998).
* **Ни один поставочный exe не ссылается на имя `CONTROLS.CFG`**: в
  `gundx.exe` есть только `GUNMETAL.CFG`, `KEYCFG\%s`, `KEYCFG\*.KEY`,
  `KEYCFG\%.8s.key`; в `gun.exe` — только `GUNMETAL.CFG`. Строки `CONTROLS`
  в обоих бинарях нет.
* Загрузчик 1.36 сравнивает магию целиком, поэтому `av1.91` он всё равно
  отверг бы.
* Тело — не раскладка 1.93: уже на 0x190 лежит `2`, `1`, `3`, а с 0x19C
  начинается ASCII `GODKEYS` (в 1.93 там `u32`-поля). Видны повторяющиеся
  блоки по **0x9C** байт с именами `GODKEYS` на 0x64 / 0x100 / 0x19C и
  парами `u32` (похоже на таблицу привязок клавиш старой сборки), но без
  exe этой версии это недоказуемо.

Поэтому `gm.config.parse(..., kind="auto")` возвращает для него
`OpaqueConfig` (магия + тело), а `kind="gunmetal"` — `ValueError`. Это
сознательный отказ от угадывания: поля 1.93 к нему не применяются.

## 9. `KEYCFG/*.key` — другой загрузчик

`.key` **не** используют загрузчик конфига; у них свой путь, но он находится
в той же функции сохранения/загрузки:

* загрузчик: `0x4852e7` (`findfirst "KEYCFG\*.KEY"`), `0x48534a`
  `fread(buf, 0x178, 1, f)`, `0x48536b` `strncpy(name, buf, 16)`,
  `0x4853b2`…`0x4853d5` — разложение 31 пары на два массива;
* писатель: `0x485465`…`0x4854e0`, путь `"KEYCFG\%.8s.key"` (`0x4bcdd4`),
  `fwrite(buf, 1, 0x178, f)` (`0x4854cf`).

Формат файла (376 = 0x178 байт):

```
0x000  char name[16]
0x010  45 x { u32 a; u32 b }
```

* загрузчик использует только **31 пару** (0x010…0x107) и раскладывает её в
  рабочую запись `0x108` байт: `u32 a[31]`, `u32 b[31]`, `char name[16]`
  (имя — в конце, `0x6c1f60 + i*0x108 + 0xF8`; чтение имени в UI — `0x488be3`);
* остальные 14 пар (0x108…0x177) — тот же неинициализированный стек, что и в
  конфиге; в поставке они одинаковы у всех трёх файлов;
* `a`/`b` — две таблицы кодов по 31 действию; `b` во всех поставочных файлах
  нулевая, её смысл (второй вариант клавиши? джойстик?) не доказан;
* имена профилей: `PERFECT`, `SPLIT1`, `SPLIT2`; конфиг выбирает первые два.

Round-trip всех трёх файлов уже покрыт `gm.small.parse_key` (и проверяется в
`tools/parity_config.py`); отдельный парсер в `gm/config.py` не нужен.

## 10. `gunmetal.hi` — третья история

`.hi` — таблица рекордов: 9 записей по 64 байта (`i32 score` + `char
name[60]`), загрузчик `0x45c8b3`. К `GUNMETAL.CFG` отношения не имеет;
round-trip проверяется через `gm.small.parse_hi`.

## 11. Что доказано, что данные, что гипотеза

**Доказано кодом (адреса выше):**

* размер 0x2000, магия `av1.93` + NUL, полное совпадение строки;
* смещения и типы всех полей 0x190…0x8AB и глобалы-получатели;
* границы «определённой» части: 0x190…0x8AB; 0x025…0x18F и 0x8AC…EOF
  писатель не инициализирует;
* размер записи 0x18C, их количество 4, раскладка подобластей;
* семантика: ширина/высота/глубина цвета, громкости, gamma/border/
  reflections/light maps/dynamic camera, биты play options, DM-режим,
  starting cash, DM-флаги, имена профилей `.key`, привязки осей и кнопок;
* «пол» 0.2 с и преобразование мс ↔ секунды (0.001/1000.0).

**Доказано данными (сверка с поставкой):**

* побайтовый round-trip `GUNMETAL.CFG` (FNV-1a `c1460f4e` до и после);
* побайтовый round-trip `CONTROLS.CFG` (FNV `a78fcc36`);
* имена `PERFECT`/`SPLIT1` в конфиге совпадают с именами файлов в `KEYCFG/`;
* четыре записи контроллера идентичны;
* значения попадают в диапазоны своих таблиц (gamma 0..3, border 0..9,
  light maps 0..2, camera 0..2, DM 0..2, cash 0..11).

**Гипотеза / не доказано:**

* `refresh` — это частота обновления (значение 60 правдоподобно, но код
  только кладёт его в глобал вместе с остальными параметрами режима);
* смысл битов `mode_flags` (кроме проверяемого 0x800);
* шкала громкостей (16/20 — не проценты: полоса в `0x488a4f` считает
  `v*2.7`);
* назначение `spare_keys_a/b` (0x4a5ae8/0x4a5af8) — потребителей нет;
* смысл `unknown_1bc` (0x4aac80) — потребителей нет;
* физический смысл 32 каналов и 4 записей контроллера;
* вторая таблица кодов в `.key` (`b[31]`, везде нули);
* поля `mask_a/mask_b` в `+0x084` (трактуются как маски по аналогии с
  `buttons[32]`, но отдельного `test` именно для них не найдено).

## 12. Опровергнутые догадки

* **«Это текстовый конфиг»** — нет: только 37-байтовая шапка, дальше
  двоичные `u32`.
* **«Поля идут подряд с 0x24»** — нет: первые 0x24 байта после магии
  (0x025…0x18F) не читаются и не пишутся; первое поле — на 0x190.
  В `CONTROLS.CFG` на 0x28 лежат правдоподобные коды клавиш, что и создаёт
  иллюзию «поля с 0x24» — но это мусор стека.
* **«`CONTROLS.CFG` — это конфиг управления, который читает игра»** — нет:
  имени файла нет ни в одном exe, версия 1.91 не совпадает с ожидаемой 1.93.
* **«`.key` пишется тем же загрузчиком/форматом»** — нет: другой `fread`
  (0x178 против 0x2000), другое тело (name[16] + пары), другое рабочее
  представление (a[31]/b[31]/name[16]).
* **«0x1D8 — лимит времени, 0x1DC — флаги DM»** (моя первая версия) —
  опровергнуто порядком store-инструкций писателя: 0x1D8 ← `0x4bc728`
  (индекс «Starting Cash», `0x48860f`), 0x1DC ← `0x68cd88` (флаги DM).
* **«Магия сравнивается по префиксу»** — нет: сравнение идёт до NUL
  включительно, поэтому версия — часть формата.

## 13. Ограничения

* Поддержана только версия 1.93. Для любой другой `kind="auto"` вернёт
  `OpaqueConfig`; принудительный `kind="gunmetal"` бросит `ValueError`.
* «Мусорные» области сохраняются, но не интерпретируются: если игра
  перезапишет файл, они изменятся, и round-trip перестанет совпадать с
  исходным снимком (это свойство самого формата, не парсера).
* Файл короче 0x8AC отвергается; короче 0x2000 игра не загрузит.
* `to_bytes()` нового (`Config()`) файла даёт нули в мусорных областях —
  это валидный файл, но не побайтовая копия поставочного.
* CLI `gm.py` пока использует `gm/small.parse_cfg` (только шапка); строки для
  переключения на `gm/config.py` — в §14.

## 14. Проверка и интеграция

```sh
python3 tools/parity_config.py                 # 22 проверки, round-trip + FNV

python3 tools/parity_config.py --json           # машиночитаемо
```
