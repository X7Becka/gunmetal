# `.sub` — таблицы подстановок спрайтов/текстур

**Статус:** семантика закрыта (2026-10-20). Разобраны загрузчик `0x422f75`,
регистрация подстановки `0x42307a`, сборка таблицы `0x4232b7` и источник
числа-«веса» `0x404630`. Проверены все 6 мелких файлов поставки; round-trip
**6/6**, `tools/re/sub.py --exe-check` — **14/14**, self-test — **31/31**,
`regress.py` — **113/113**.

**Коротко:**

| что | результат |
|---|---|
| `.sub` в поставке | **3**: `PICS/textures.sub` (119), `sprites/sprites.sub` (64), `sounds/sounds.sub` (161) |
| раскладка textures/sprites | первая строка — счётчик, далее `weight replacement replaced` |
| раскладка sounds | tab-separated пары, **без** счётчика и веса |
| число `20` / `16` | **класс RAM** (МБ сверх ~4 МиБ), не вероятность и не вес варианта |
| когда применяется | только если `ram_class <= weight`; на машине с >~24 МБ — **никогда** |
| что делает строка | рисует спрайт `replaced` картинкой `replacement` (подмена изображения) |
| выбор кадров `.soa` | `.sub` **не участвует**; кадр по-прежнему выбирает `0x41de7d` |
| дубликаты `replaced` | действует **только первая** строка; остальные молча игнорируются |
| мёртвые строки | 21/119 текстур и 5/64 спрайтов ссылаются на имена, которых нет ни в одном SBM-архиве |

## 2. Формат и загрузчик `0x422f75` (доказано)

Текст, `latin1`, CRLF. Загрузчик:

```
sub_load(dir, name, kind, ram_class)          // 0x422f75
    f = open(build_path(dir, name, "SUB"))     // 0x40d1a0, расширение 0x4a8ccc
    if !f: return -1                           // молча, вызывающий не проверяет
    if fscanf(f, "%ld", &count) != 1:          // 0x422fb1, формат 0x4a8cd0
        fclose; return -1
    while (count > 0) {                        // 0x422fe1 .. 0x423060
        if fscanf(f, "%ld %s %s", &weight, repl, target) != 3:
            fclose; return -1                  // 0x422fff, формат 0x4a8cd4
        if (ram_class <= weight)               // 0x42302c / 0x423035 (jg = skip)
            register_sub(repl, target, kind)   // 0x42307a
        count--
    }
    fclose; return 0
```

* Буферы: `count` — `[ebp-0x208]`, `weight` — `[ebp-0x20c]`, имена —
  `[ebp-0x100]` и `[ebp-0x200]` (по 256 Б). `%s` **без ширины**, поэтому
  имя длиннее 255 Б переполняет стек (баг игры; наш парсер это только
  валидирует, см. §8).
* Счётчик читается как знаковый; `count <= 0` — цикл не выполняется.
* Лишние строки после `count` не читаются; недостающие — `fscanf` вернёт
  меньше 3 и загрузка **всей** таблицы отменяется.
* `kind`: `0` — текстуры (`pics\`), `1` — спрайты (`sprites\`), `4` — флаги
  (`flag\`). `.sub`-вызовы используют только 0 и 1.

Два места вызова (оба передают `ram_class = [0x4bf290]`):

| VA | аргументы |
|---|---|
| `0x4426d3` | `("pics", "textures", 0, ram)` — `PICS\textures.sub` |
| `0x4426ee` | `("sprites", "sprites", 1, ram)` — `sprites\sprites.sub` |
| `0x4432fa` | `("pics", "textures", 0, ram)` |
| `0x443319` | `("sprites", "sprites", 1, ram)` |

Строки `0x4ab54c "pics"`, `0x4ab554 "textures"`, `0x4ab544 "sprites"`;
`0x40d1a0` умеет открывать и BIGFILE-архивы, поэтому имена — виртуальные
(`PICS\ALUMNM5.SBM`), а не файлы на диске.

## 3. Вес — это класс RAM (доказано)

`[0x4bf290]` заполняется один раз при инициализации (`0x40449e` вызывает
`0x404630`):

```
GlobalMemoryStatus(&ms);                       // IAT 0x841324, вызов 0x404640
[0x4bf290] = (ms.dwTotalPhys - 4000000) / 1048576;   // 0x40465c
```

То есть значение = «сколько мегабайт физической памяти сверх ~3.81 МиБ».
Для типовых машин 1998 года: 16 МБ → 12, 20 МБ → 16, 24 МБ → 20, 32 МБ → 28.
Отсюда веса в данных:

* `sprites.sub` — `16`: подмены включаются на машинах класса ≤16 (≈20 МБ);
* `textures.sub` — `20`: на машинах класса ≤20 (≈24 МБ);
* при `ram_class = 28` (32 МБ) и выше **не включается ни одна строка**.

На любой современной машине `ram_class` — тысячи, поэтому обе таблицы
фактически мертвы: это low-memory fallback, а не «варианты на выбор».
Сравнение — `ram_class <= weight` (`0x42302f cmp ecx,[ebp-0x20c]`,
`0x423035 jg`), знаковое.

Тот же порог используется соседними таблицами «альтернативных имён»:
`0x40b800` возвращает запись, если её порог `> [0x4bf290]`, а `0x49125c`
при `[0x4bf290] >= 14` включает низкий режим детализации. Это подтверждает
смысл поля как ресурсного порога, а не вероятности.

## 4. Что именно подменяется (доказано)

`register_sub(repl, target, kind)` — `0x42307a`:

1. Ищет в реестре спрайтов (`0x76ed40`, 0x800 слотов по 16 Б; имя `+7`)
   спрайт с именем **`target`** и тем же `kind`.
2. Если он уже отображён (`word[0x5350c0 + 2*i] != 0`) на запись с именем
   **`repl`** — ничего не делает (idempotent). Если на другое имя —
   возвращает 0, **не перезаписывая**: поэтому из дубликатов действует
   только первая строка.
3. Если `target` ещё не зарегистрирован — возвращает 0. Строка **молча
   теряется**: `.sub` загружается на старте уровня, до/после регистрации
   имён из `.sob`/`.sbt`, и не «доклеивается» позже.
4. Иначе ищет свободный слот в таблице подстановок `0x55a0c0`, копирует туда
   `repl` (`strncpy(..., 9)`), `kind`, `loop = (kind == 0)`, `ptr = 0`,
   и пишет `map[target] = slot + 1`.

Слот `0x55a0c0` (16 Б): `+0` указатель на картинку/цепочку mip,
`+4`/`+5`/`+6` — служебные байты (`kind`, `loop`, позже число уровней),
`+7` — `char name[9]`.

`0x4232b7` завершает сборку:

* каждому загруженному спрайту без подстановки создаёт свой слот с его же
  именем (`0x423386`..`0x42342b`);
* считает число живых ссылок на каждый слот в `0x5330c0`
  (база `0x5330bc`, индекс — `map`), `0x423437`;
* для слотов с ненулевым счётчиком и `ptr == 0` грузит картинку по имени
  слота: `pics\` (`0x4a8cfc`), `sprites\` (`0x4a8d04`), `flag\`
  (`0x4a8d0c`) через `0x4401a5` (`0x4235eb`..`0x42367f`);
* строит mip-цепочку в `0x422462` и упаковывает её в буфер `tempdata1`
  (`0x4a8ce0`, 64 КиБ, `0x423536`).

Итог: спрайт с именем `target` получает изображение `repl`. Пример:
`20 alumnm4 alumnm5` — на машине класса ≤20 спрайт `alumnm5` рисуется
картинкой `alumnm4`.

### Сверка с `.soa` / `docs/SOA.md`

* `.soa` хранит **имена** кадров; `0x424eab(name, kind)` превращает имя в id
  спрайта (refcount, `0x424eb8`…`0x424fcd`). Подстановка к этому моменту уже
  лежит в `map`/`0x55a0c0`, поэтому анимация автоматически получает
  подменённую картинку — отдельного «выбора варианта» в `.soa` нет.
* Селектор кадра `0x41de7d` и режимы 0/1/100/101/102 не читают `.sub`
  вообще (см. `docs/SOA.md` §4, §6). `.sub` не влияет ни на `declared`,
  ни на `period`, ни на `loop`.
* Рендер `0x41c78b` берёт id кадра и индексирует таблицу дескрипторов
  изображений через `[0x9e82c8] + (id-1)*16` (`0x41c883`). Запись этой
  базы в `gundx.exe` не найдена (только чтения), поэтому последний шаг
  «`0x55a0c0` → таблица рендера» — **гипотеза** (см. §9).

Практический вывод: `.sub` — это подмена **картинки за именем**, а не выбор
спрайта/анимации; для `.soa`/`.soo` он прозрачен.

## 5. `sounds.sub`

Формат другой: `replacement<TAB>replaced`, без счётчика и веса. Наш парсер
и round-trip это поддерживают.

Однако единственный потребитель в `gundx.exe` — `0x44b0a1`
(`sounds\sounds.sub` → `0x40b510`), а `0x40b510` сначала читает **число**
(`"%ld"`, `0x4a6910`), затем `count` записей `"%ld %s %s"`
(`0x4a68c0`). Первая строка поставки — `alarmk\talarmkbig`, `%ld` не
сматчится, загрузка вернёт `-2`, вызывающий результат игнорирует. То есть в
этом билде `sounds.sub` **не загружается**; вероятно, файл остался от
DOS-версии (`gun.exe`) или другой ветки. Это зафиксировано как факт, а не
как «недоделка».

## 6. `.sni` — альтернативный путь (доказано)

`path.sni`, 3 байта: `".\r\n"`. Загрузчик `0x484cf0`:

1. `fopen("path.sni", "rt")` (`0x4bcdc8`, режим `0x4a6914`);
2. `fgets(buf, 0x4f, f)` (`0x40e050`);
3. обрезает хвостовые `CR`/`LF`/пробелы (`0x484d6c`…`0x484d85`);
4. передаёт строку в `0x4420e0` — «set alternate path» (рядом строки
   `"couldn't set alternate path"`, `0x4bcd7c`).

К спрайтам/анимациям отношения не имеет — это путь установки/CD.

## 7. `.skk` / `.skb` — сообщения об убийстве (доказано)

Один загрузчик, `0x485a00` (`.skk`) и `0x485b2f` (`.skb`) в той же функции:

* `fopen(..., "r")` (текстовый режим, `0x4a6888`), строки через
  `fgets(buf, 0x400, f)` (`0x40e050`);
* берутся только строки с `0 < strlen(line) < 0x20` (`0x485a7d`); в текстовом
  режиме CRLF уже превращён в LF, значит текст ≤ 30 символов;
* максимум `0x80` сообщений (`0x68ddb8` для `.skk`, `0x68ddb4` для `.skb`);
* любой `%<символ>` нормализуется в `%s` (проверка `%` + `s` в
  `0x485ad6`…`0x485ae1`): в данных `%S` превращается в `%s`.

Из поставки реально загрузятся **50 из 73** строк `.skk` и **69 из 91**
строк `.skb` (остальные длиннее 30 символов и отбрасываются). Массивы
сообщений — `0x662d60` и `0x67fd38`. К спрайтам/анимациям `.skk`/`.skb`
отношения не имеют; с `.sub` их роднит только модуль `gm/small.py`.

## 8. `gm/small.py`: API

Старое API сохранено: `SubEntry(value, left, right)`, `SubFile`,
`parse_sub()`, поля `count`/`tab`/`eol`/`trailing`/`blanks`. Добавлено:

```python
s = parse_sub(raw)

s.count, s.is_counted, s.entries, s.tab
e = s.entries[0]
e.weight, e.replacement, e.replaced   # = value, left, right
e.to_text()                           # строка как в файле

s.count_text         # строка счётчика как в файле (пробелы сохранены)
s.weights()          # {20: 119}
s.variants()         # {'alumnm5': ['alumnm4', ...], ...}
s.variants(20)       # только записи этого веса
s.active(12)         # записи, которые загрузит движок при ram_class=12
s.resolve(12)        # {'alumnm5': 'alumnm4', ...} (первая строка побеждает)
s.validate()         # жёсткие ошибки: count/weight/пустые/длинные имена
s.warnings()         # >8 символов — движок обрежет имя
s.to_bytes()         # byte-exact, включая пустые строки и отсутствие EOL
Sub = SubFile        # тип-алиас
```

`parse_sub` по-прежнему терпим: 2 поля в файле со счётчиком дают запись без
веса, которую `validate()` пометит; явно битые строки (1 или 4+ поля,
нечисловой вес) бросают `ValueError`.

## 9. Доказано / гипотеза / остаток

**Доказано кодом и данными:**

* раскладка `.sub`, счётчик, `%ld %s %s`, отсутствие счётчика у sounds;
* вес = класс RAM из `GlobalMemoryStatus`, условие `ram_class <= weight`;
* направление подмены `replacement -> replaced`, первая строка побеждает;
* подстановка выполняется на уровне «имя спрайта → слот картинки»
  (`0x42307a`, `0x4232b7`), а не при выборе кадра `.soa`;
* `.sni` — альтернативный путь; `.skk`/`.skb` — сообщения, лимит 30 симв.;
* `sounds.sub` не совместим с единственным загрузчиком `0x40b510`.

**Гипотеза:**

* `0x9e82c8` — база таблицы дескрипторов, в которую попадают слоты
  `0x55a0c0`; запись этой базы в дизассемблированном коде не найдена
  (возможно, инициализируется в оверлее/рантайме).
* Два вызова `sub_load` (`0x4426d3`, `0x4432fa`) — это два пути загрузки
  уровня (старт/восстановление сейва); какой именно — не проверялось.
* `sounds.sub` — наследие DOS-версии; проверить `gun.exe` в этой сессии
  нельзя (задача ограничена `gundx.exe`).

**Остаток:**

* проследить инициализацию `0x9e82c8` и окончательно связать
  `0x55a0c0` с рендером;
* проверить, не перезагружается ли `.sub` при смене уровня/сейва и какие
  спрайты уже зарегистрированы в этот момент (от этого зависит, сколько
  строк реально применяется);
* визуальная проверка на машине с эмуляцией `ram_class = 12/20` — вне
  рамок read-only репозитория.

## 10. Проверка

```sh
python3 tools/re/sub.py --check        # 6/6 round-trip, 6/6 valid
python3 tools/re/sub.py --self-test    # 31/31 (включая негативы)
python3 tools/re/sub.py --exe-check    # 14/14 якорей в gundx.exe
python3 tools/re/sub.py --dump         # все записи
python3 tools/re/sub.py --json
python3 regress.py                     # 113/113
```

Негативы в self-test: усечённый файл (count > записей), запись без веса,
отрицательный вес, имя >255 Б, нечисловой вес, ключ >8 Б (warning),
2-полевая запись в счётном файле, отсутствие финального EOL, LF вместо CRLF,
внутренние/хвостовые пустые строки. Парсер не пишет в игру и не меняет
`gundx.exe`.
