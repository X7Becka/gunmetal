# Рендер экрана 18 `SELECT VIDEO MODE` (`engine/src/ui/video_mode_list_render.h`)

Срез 7 пункта `M8.8`: модуль **рисует экран 18** в RGBA-буфер 320×200 из
реальной установки: заголовок `SELECT VIDEO MODE`, строку `Press Esc to close`,
десять полос списка режимов с шагом 9 и подсветкой курсора шрифтом 4, стрелки
прокрутки `MENUARRW` и плату `PLATE`. Геометрия — из обработчика `0x48a8b0`
(`docs/UI_SCREENS.md` §2/§3.8), атласы — из `render/text_layout`
(`FONTS4` в `FRONTEND/BMP.IDX`), таблица режимов — **модель** (§2).

Код: `engine/src/ui/video_mode_list_render.h/.cpp`; тест —
`engine/tests/test_video_mode_list_render.cpp` (CTest `video_mode_list_render`,
label `quick`). Канон поведения — `docs/UI_SCREENS.md` §2/§3.8 и этот документ;
ближайшие образцы того же класса — `docs/LEVEL_SELECT_RENDER.md` (17, та же
схема «плата + окно в 10 полос + стрелки»), `docs/VIDEO_MODE_RENDER.md` (37,
подтверждение выбранного режима) и `docs/GAME_TYPE_RENDER.md` (19).

## 1. Что доказано (`0x48a8b0`, docs/UI_SCREENS.md §2/§3.8)

Обработчик занимает `0x48a8b0`..`0x48a999` (последняя инструкция — `ret` в
`0x48a999`; дальше `nop` до `0x48a9a0`, где начинается экран 23). Таблица
диспетчера `0x4883d8` (id 5..37) для id 18 указывает на stub `0x487f1d` =
`call 0x48a8b0; jmp 0x487f64` (слот `0x48840c`). Всё в таблице — сайты
обработчика, общего отрисовщика `0x485dd0` и форматтера `0x486500` (листинг:
`python3 tools/re/disrange.py 48a8b0 48a9a0`, `485dd0 485e80`,
`486500 486700`, `48d730 48d790`).

| факт | значение | источник |
|---|---|---|
| длина списка | `[0x67f10c] = [0x4c05bc]` — счётчик таблицы режимов, до 100 (`0x4065f9`) | `0x48a8b0`..`0x48a8b8` |
| шаг полосы | **9** (`0x662d58 = 9`) | `0x48a8bd` |
| плата | `0x486050` копирует `PLATE` 196×131 в `0x6865f8`; весь текст и стрелки пишутся в эту копию (клип 196×131) | `0x48a8ca`; §3, §9 |
| заголовок | `SELECT VIDEO MODE` (`0x4bdb94`), шрифт **5**, `centered=1`, `x 38`, `row 11`, `item -1` → **y 11**, x = (196 − measure)/2 | `0x48a8cf`..`0x48a8de`; `0x485de2`..`0x485dfa` |
| вторая строка | `Press Esc to close` (`0x4bd7c8`), шрифт **0**, `centered=1`, `x 25`, `row 20`, `item -1` → **y 20** | `0x48a8e6`..`0x48a8f5` |
| окно | `first = cursor ≥ 5 ? cursor − 5 : 0`; если `first + 10 ≥ count`, то `first = count − 10`; если `first < 0`, то 0 | `0x48a8fa`..`0x48a921` |
| число полос | ровно **10** (`cmp esi,0xa`) | `0x48a98e` |
| `x` полосы | **38** (`push 0x26`) | `0x48a97e` |
| `y` полосы | `row = −(29 + 9·i)`, а отрицательный `row` — абсолютная форма отрисовщика (`y = −row`), значит **y = 29 + 9·i**: 29, 38, …, 110 | `0x48a971`..`0x48a985`; `0x485e27`..`0x485e48` |
| `item` полосы | `first + i` — индекс в таблице режимов | `0x48a957`..`0x48a95f` |
| текст полосы | `0x486500(buf, item)` — форматирование записи таблицы (см. §1.2) | `0x48a960` |
| подсветка | `item == [0x68ccf4]` **и** вызывающий передал шрифт 0 → шрифт принудительно **4**; точное сравнение, бара/рамки/`MENULIT` нет | `0x485e0d`..`0x485e19` |
| стрелки | `MENUARRW` 16×8 (загружен в `0x67fcb0` из `0x48fe59`): вверх — `0x485d00(0x68681f, 0xc4)` при `first > 0`, вниз — `0x485cc0(0x68c33b, 0xc4)` при `first + 10 < count` | `0x48a923`..`0x48a952` |
| место стрелок | `0x68681f = 2·196 + 159` (вверх) и `0x68c33b = 121·196 + 159` (вниз), т.е. колонка 159, строки 2 и 121 | арифметика адресов при stride 196 |
| ориентация | `0x485cc0` читает 128 байт вперёд (`0x485cda`), `0x485d00` — те же байты назад (`mov al,[edx-1]; dec edx`, `0x485d1a`), т.е. стрелка «вверх» = «вниз» повёрнутая на 180° | листинг |
| порядок | плата → заголовок → `Press Esc to close` → стрелки → 10 полос | порядок вызовов |
| курсор при входе | `0x48d74d`..`0x48d784`: пункт 5 экрана 12 копирует 5 dword текущего режима `0x4c05c0`, пишет `state=0x12`, затем `[0x68ccf4] = 0x4864a0(дескриптор)` — **индекс текущего режима** в таблице (0, если его там нет), и сразу вызывает `0x48a8b0` | `0x48d74d`..`0x48d784`, `0x4864ed` |
| выход/выбор | `ESC` → состояние 12 (`0x48e55a`); `Enter` применяет режим `0x48ed10(cursor)` и открывает экран 37 (`0x48e182`, `docs/VIDEO_MODE_RENDER.md` §1.2) | §4 `UI_SCREENS.md` |

### 1.1. Геометрия

| элемент | x | y | шрифт |
|---|---:|---:|---:|
| `SELECT VIDEO MODE` | (196 − 95)/2 = **50** | 11 | 5 |
| `Press Esc to close` | (196 − 83)/2 = **56** | 20 | 0 |
| полоса `i` (0..9) | 38 | 29 + 9·i (29, 38, …, 110) | 0, курсор — 4 |

Строки заголовка и подсказки центрируются по **advance**-суммам (`0x47fa50`),
а не по чернилам, поэтому `x`, переданный в `0x485dd0`, для них не используется.
Ячейка шрифта 8×8; полосы 29..117 (последняя 110..117) не пересекаются и
укладываются в 131 px платы. Самый длинный текст модели (`800x600 Glide 3Dfx`)
занимает 38..129, т.е. тоже внутри 196 px.

### 1.2. Тексты полос (`0x486500`)

`0x486500(buf, index)` берёт запись таблицы `0x4bfd18 + index·20`
(`width`, `height`, `bpp`, `refresh`, `flags`) и печатает её одной из
двенадцати строк. Порядок проверок флагов (`0x486510`..`0x4866f7`):

| условие | текст (`VA`) |
|---|---|
| `flags & 0x200` | `%ldx%ld Direct 3D` (`0x4bd13c`) |
| `flags & 0x400` | `%ldx%ld Open GL` (`0x4bd12c`) |
| `flags & 0x800` | `%ldx%ld Glide 3Dfx` (`0x4bd118`) |
| `flags & 0x002` | `%ldx%ld TV Mode` (`0x4bd108`) |
| `flags & 0x001` | `%ldx%ld 256 Mode X` (`0x4bd0e0`) / при `flags & 0x100` — `%ldx%ld 256 Skip X` (`0x4bd0f4`) |
| `flags & 0x100`, bpp 8/15/16/иначе | `256 Skip` (`0x4bd094`) / `32k Skip` (`0x4bd0a8`) / `64k Skip` (`0x4bd0bc`) / `Skip` (`0x4bd0d0`) |
| иначе, bpp 8/15/16/иначе | `256 Colours` (`0x4bd050`) / `32k Colours` (`0x4bd064`) / `64k Colours` (`0x4bd078`) / `%ldx%ld` (`0x4bd08c`) |

Эта цепочка реализована в `video_mode_list_label()` и закреплена тестом
(15 ветвей); счётчик `[0x4c05bc]` — длина списка, `refresh` (`+0x0c`)
форматтер не читает.

## 2. Модель: какие режимы в списке

Таблица режимов **строится в рантайме** и из поставляемых файлов не
воспроизводится:

* `0x405fc0` вызывает `DirectDraw::EnumDisplayModes(3, …)` с колбэком
  `0x4065a0` → `0x4065f0(desc, 0x100)`: каждый режим 320..800 × 200..600
  (высота делится на 2, флаги `0x100`, т.е. «Skip») дописывается в таблицу
  `0x4bfd18`, счётчик — `[0x4c05bc]` (`docs/INIT.md` §6.1);
* `0x406083` (ветка `[0x4a6170] & 0x800`) дописывает **Glide-набор**
  `512×384 / 640×480 / 800×600` из статической таблицы кандидатов `0x4a6110`
  (фильтр 320..800 × 200..600, `bpp = 32`, флаги `0x804`) — тот же документ;
* `0x406189`..`0x4061f6` сортирует всю таблицу **по убыванию
  `(width, height, bpp)`** (ключ `(w<<13 + h)<<6 + bpp`, пузырёк), поэтому
  порядок строк — производная от набора, а не от порядка перечисления.

Набор режимов зависит от драйвера, разрешения рабочего стола и наличия
`glide2x.dll`, поэтому `kVideoModeListModes` — **модель**: типичный набор
`EnumDisplayModes(3)` эпохи (стандартные VGA + обычные SVGA, 8 и 16 bpp) плюс
задокументированная Glide-тройка, отсортированный по доказанному правилу.
Доказаны: счётчик `[0x67f10c]`, шаг, окно, стрелки, подсветка и все тексты;
не доказано: *какие именно* режимы сообщает конкретная машина.

| # | запись (`w×h`, bpp, flags) | текст |
|---:|---|---|
| 0 | 800×600, 32, `0x804` | `800x600 Glide 3Dfx` |
| 1 | 800×300, 16, `0x100` | `800x300 64k Skip` |
| 2 | 800×300, 8, `0x100` | `800x300 256 Skip` |
| 3 | 640×480, 32, `0x804` | `640x480 Glide 3Dfx` |
| 4 | 640×240, 16, `0x100` | `640x240 64k Skip` |
| 5 | 640×240, 8, `0x100` | `640x240 256 Skip` |
| 6 | 640×200, 16, `0x100` | `640x200 64k Skip` |
| 7 | 640×200, 8, `0x100` | `640x200 256 Skip` |
| 8 | 512×384, 32, `0x804` | `512x384 Glide 3Dfx` |
| 9 | 360×240, 16, `0x100` | `360x240 64k Skip` |
| 10 | 360×240, 8, `0x100` | `360x240 256 Skip` |
| 11 | 360×200, 16, `0x100` | `360x200 64k Skip` |
| 12 | 360×200, 8, `0x100` | `360x200 256 Skip` |
| 13 | 320×200, 16, `0x100` | `320x200 64k Skip` |
| 14 | 320×200, 8, `0x100` | `320x200 256 Skip` |

Что осталось (честно):

* **точный набор и порядок на реальной машине** не проверены: нужен запуск
  оригинала под 3dfx/DDraw и снимок `[0x4c05bc]` + таблицы `0x4bfd18`;
* почему в поставочном `GUNMETAL.CFG` текущий режим — `800×600`, 8 bpp,
  `mode_flags = 0` (не `0x100`/`0x804`), не объяснено: флаги пишутся в конфиг
  из применённого режима, а не из таблицы;
* значение `refresh` (`+0x0c`) и поле `+0x08` для Glide-записей в модель не
  входят: форматтер их не читает (кроме bpp в «Skip»-ветках);
* поведение при `count < 10` (оригинал всё равно рисует 10 полос и печатает
  нулевые слоты таблицы как `0x0`) модуль не воспроизводит: он рисует
  `min(10, count − first)` реальных полос. Для модели (15 записей) разницы
  нет, для маленького списка кадр отличался бы — это осознанное отклонение.

## 3. API

```cpp
struct VideoModeListRenderOptions {
    std::string background;              // "" = чёрный; "PLATE" = плата экрана
    int cursor = 0;                      // [0x68ccf4], индекс в списке 0..14
    bool fade_lut = false;
    int fade_lut_level = 11;             // 0..15
    std::string fade_lut_dump;           // 4096 байт, docs/HUD_LUT.md §2
    const HudLut* fade_lut_table = nullptr;
};

struct VideoModeListRenderStats {
    int rows;             // длина списка ([0x67f10c]) = 15
    int first_row;        // первая видимая запись (0..5)
    int arrows;           // 0..2: вверх при first_row > 0, вниз при first_row+10 < rows
    int ink_pixels;       // чернила глифов (пиксели стрелок не считаются)
    int missing_glyphs;
};

bool render_video_mode_list(const std::filesystem::path& game,
                            const VideoModeListRenderOptions&,
                            std::vector<std::uint32_t>& rgba,
                            int& width, int& height,
                            VideoModeListRenderStats* = nullptr,
                            std::string* error = nullptr);
```

Данные и правила доступны как константы/функции: `kVideoModeListModes[15]`
(`width`, `height`, `bpp`, `flags`), `video_mode_list_label(entry)` (доказанная
цепочка `0x486500`), `video_mode_list_first_row(count, cursor)` (окно
`0x48a8fa`), `kVideoModeListTitle`, `kVideoModeListHint`,
`kVideoModeListVisibleRows = 10`, `kVideoModeListRowX = 38`,
`kVideoModeListFirstRowY = 29`, `kVideoModeListRowStep = 9`,
`kVideoModeListTitleY = 11`, `kVideoModeListHintY = 20`,
`kVideoModeListPanelName = "PLATE"`,
`kVideoModeListPanelWidth/Height = 196/131`,
`kVideoModeListArrowName = "MENUARRW"` (16×8, колонка 159, строки 2 и 121),
`kVideoModeListModeCount = 15` (длина модели, она же `[0x67f10c]`).

Отказы (префикс `video_mode_list_render:`): пустой путь игры; нет/битый
`FRONTEND/BMP.IDX`; нет атласа `FONTS4` (шрифты 5/0/4); неизвестная/битая/
не-8-bpp запись фона; нет/битый/не тот размер `MENUARRW` (только когда стрелка
действительно рисуется); `fade_lut` без таблицы и дампа или с нечитаемым
дампом. При отказе `rgba` очищен, `width = height = 0`, статистика обнулена.

## 5. Ограничения

* **Нет ввода/навигации**: модуль не читает клавиатуру и не двигает
  `[0x68ccf4]`; `options.cursor` — уже готовое значение. Переход по пунктам,
  `ESC` (состояние 12) и `Enter` делает `frontend_menu`/оригинал.
* **Нет звука**: `updown`/`select` (`docs/UI_SOUNDS.md`) не моделируются.
* **CLI — есть (срез 8).** `--video-mode-list [--video-mode-list-cursor N]
  [--no-plate] [--png OUT] [--fade-lut N]`:
  `video_mode_list: rows=15 first_row=0 cursor=0 arrows=1 ink=2838
  missing=0`; курсор 14 — `first_row=5 arrows=1 ink=2816`. CTest
  `cli_video_mode_list`, `_end`; `cli_fade_lut` (11 = без fade).
* **Нет самого переключения режима**: `0x48ed10` (применить), сохранение
  прежнего индекса `0x678180`, экран 37 с таймером `[0x678140]` и переходы в
  состояния 12/37 не воспроизводятся — это делает оригинал (и будущий
  `frontend_menu`).
* **Список — модель** (§2): счётчик, тексты, окно, стрелки и подсветка
  доказаны, членство и порядок записей — нет. На машине с другим набором
  режимов оригинал покажет другой список (и, возможно, другое число строк).
* **`count < 10`**: модуль рисует `min(10, count − first)` реальных полос, а
  оригинал — всегда 10 слотов (пустые печатаются как `0x0`); для модели
  разницы нет (§2).
* **Соответствие «номер шрифта → атлас»** для 0/4/5 взято из `docs/UI.md`
  §10.3/`docs/MENU_RENDER.md` §3; независимой привязки номеров в коде нет —
  это общее открытое место фронтенда, не специфика экрана 18.
* **`Press Esc to close` — общая строка** (`0x4bd7c8`) с другими экранами,
  поэтому путь «строка → экран» по ней не строится; она доказана листингом
  `0x48a8e6`..`0x48a8f5`.
