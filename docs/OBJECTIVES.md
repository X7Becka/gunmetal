# Цели, секреты и триггеры конца уровня (`M6.4.5`)

* **Статус:** карта снята по `gundx.exe` v1.36 (ImageBase `0x400000`) и по
  36 поставочным `.sbt`; игра только на чтение, Ghidra не использовалась.
  Ветка `feat/objectives`, база `master` `d61065d`.
* **Инструмент:** `tools/re/objectives.py` (новый; без Ghidra). Проверки:
  `--self-test` — **120/120**, `--summary` — 36 уровней, `--anchors` —
  **43/43** байтовых якоря, `--json` — детерминированный отчёт.
* **Канон:** опкоды — `docs/VM_EXEC.md` §3–4, поток кампании —
  `docs/CAMPAIGN_FLOW.md` §4–5, экран конца уровня и `-8` — `docs/GAME_OVER.md`
  §4–5, сборка/сброс уровня — `docs/LEVEL_LOAD.md` §4, события —
  `docs/EVENTS.md` §4.1, подбор/радиус-триггер — `docs/PICKUP.md` §4/§7,
  сейв — `docs/SAVE_FIELDS.md` §9/§11. Здесь — только то, чего в них не было,
  плюс независимый пересчёт чисел.

Обозначения: **код** — байты/инструкции exe или скрипта; **данные** —
измерено на 36 файлах (N/N); **гипотеза** — не доказано.

## 2. Цели

### 2.1. Опкоды и хранение

```
103 DEFINE_LEVEL_OBJECTIVES  u32 n (<=30) + n строк
    0x45bdf6  cmp eax,0x1e          ; больше 30 -> 0x45c4c1 (ошибка)
    0x45be04  mov ds:0x80d7ec,eax   ; count
    0x45be11  mov esi,0x80d800      ; массив указателей
    0x45be21  mov [esi],ebx         ; указатель на строку в блоке кода
    0x45be34  add esi,4 / inc edi / cmp edi,eax
104 OR_LEVEL_OBJECTIVES_BITS  L
    0x45be49  or  ecx,edx
    0x45be4e  mov ds:0x80f9d0,ecx   ; единственный писатель маски
```

Строки целей **не копируются**: в `0x80d800[i]` лежит указатель внутрь кода
уровня (блок 11), поэтому в сейве они не нужны — это код.

`DEFINE_LEVEL_OBJECTIVES` может встречаться в одном скрипте несколько раз.
Это не «варианты на этапе компиляции», а **последовательные обновления
списка**: скрипт по ходу миссии переписывает `count`/указатели, и HUD
показывает актуальный набор. Пример `level19`: 7 объявлений (12 строк), три
из них под `IF SOURCEPLAYER_KEY_BITS_SET`; первые два — безусловные.

### 2.2. Условие «все цели выполнены»

```
7 LEVEL_OBJECTIVES_COMPLETE  (пустая сигнатура), обработчик 0x45e9f0
    0x45e9f2  mov edx,ds:0x80d7ec
    0x45e9fa  jle 0x45f29d          ; count <= 0 -> ложь
    0x45ea00..0x45ea17              ; for i<count: if !(mask & (1<<i)) -> ложь
    0x45ea19  mov eax,1             ; иначе истина
```

Правило: `count <= 0` → ложь; лишние старшие биты игнорируются; нужны все
`1<<i`, `i < count`. В корпусе условие 7 встречается **48** раз, все — как
`IF`; `EVAL`-форм нет.

### 2.3. Кто и когда пишет биты

Маску пишет **только скрипт** командой 104; движок сам её не трогает.
Проверка `--self-test`: у `0x80f9d0` ровно 7 dword-ссылок — сброс
(`0x4570a5`), 104 (загрузка `0x45be45`, запись `0x45be50`), условие 7
(`0x45ea01`), сейв-писатель (`0x462f2b`, `0x462f55`), HUD (`0x48735a`).
Других писателей нет.

Типичная цепочка (`level1`, байты скрипта):

```
1480 DEFINE_LEVEL_OBJECTIVES [FIND SWITCH ONE .. FOUR]
1497 OR_LEVEL_OBJECTIVES_BITS 1
1504 IF LEVEL_OBJECTIVES_COMPLETE { GENERATE 300 }
1506 OR_LEVEL_OBJECTIVES_BITS 2
...
```

`entity 300` (`level1`): `PLAY_SAMPLE`, `ADD_SCREEN_TEXT 2 "MISSION
OBJECTIVES COMPLETE - PROCEED TO TRANSIT GATE"`, `ADD_SOURCEPLAYER_CASH 10000`.
Выход с уровня — `entity 305`: `IF SOURCE_IS_PLAYER { SHOW_LEVEL_END_SCREEN }`.

То есть «цель выполнена» — это решение скрипта уровня (взрыв, найденный
предмет, вход в сектор и т.п.), который в нужный момент делает `OR бита`;
движок только хранит маску и проверяет её условием 7.

### 2.4. Как цель видна игроку

* **HUD.** Панель рисует `FUN_004869c0` (`0x4869c0`); список целей —
  `0x487337`: `mov eax,[0x80d7ec]`, `[esp+0x20]=0x80d800`,
  `mov edx,[0x80f9d0]`, `1<<i`, вызов `0x4833e0` (маркер) и `0x47faf0`
  (строка). Вызывается из `0x487aec` и `0x488309` (одно- и многопользовательская
  ветки HUD).
* Маркер: `0x4833e0(dst, x, ?, bit)` кладёт **16 байт** из `0x67fc10`
  («check»), если бит стоит, и **8 байт** из `0x683fb8` («nocheck»), если
  нет. Оба буфера заполняются при загрузке фронтенда из ассетов
  `frontend`/`check` и `frontend`/`nocheck` (`0x48fdb9`, `0x48fdf8`;
  имена — `0x4be318`, `0x4be310`).
* `'*'` в тексте цели — **перенос строки**: `0x487394..0x4873a3` копирует
  символы до `'*'`, рисует, затем продолжает со следующего. Из 58 разных
  текстов 41 содержит `'*'` (данные; `--self-test` проверяет отсутствие
  `\n`).
* **Экран конца уровня списка целей не содержит** (`0x483a70..0x483e30`:
  `KILLS`, `SECRETS FOUND`, `SALVAGE`, `TIME`, `BEST TIME`). Проверено
  негативно: ни одна ссылка на `0x80d7ec`/`0x80f9d0` не попадает в этот
  диапазон (`--self-test`, «экран конца не читает цели»).

### 2.5. Сброс и сейв

* Сброс — в общем `reset` уровня `0x456f50` (вызывается из `0x454cf0` →
  `0x454d13`): `0x45709d` обнуляет count, `0x4570a3` — маску, `0x45708a` —
  объявленные секреты. `docs/LEVEL_LOAD.md` §4 описывает `0x454d13` как
  «эффекты/анимации»; по факту там же сбрасываются цели/секреты.
* Сейв: биты дописываются под-скриптом сущности **`-3`**
  (`INTERNAL_LEVEL_RESUME`): писатель `0x462f2a` проверяет `0x80f9d0 != 0`,
  `0x462f38` кладёт опкод `0x68` (104), `0x462f53..0x462f66` — значение; сущность `-3`
  создаётся в `0x462e0c`. Это блок 11 сейва (`docs/CAMPAIGN_FLOW.md` §4).
  Живого сейва с выполненными целями в поставке нет (оба сейва — `level0`),
  поэтому end-to-end не проверен и сейчас.

## 3. Секреты

### 3.1. Объявленное число и счётчик

```
94 SET_LEVEL_SECRETS L      0x45b81e  mov ds:0x80d8c0,edx
95 INCREMENT_SOURCEPLAYER_SECRET_TALLY
   0x45b978  and eax,0xffff / jl / cmp eax,8 / jge   ; индекс игрока 0..7
   0x45b98d  call 0x4536b0
0x4536b0(player):
   stride = ((i*3)*9*2 - i)<<4 + i)<<4 = i*0x3510
   0x4536cf  lea eax,[ecx+0x81c40c]
   0x4536db  inc ecx / mov [eax],ecx                ; tally += 1
```

`player` = `0x819040 + i*0x3510`; поле `+0x33cc` → `0x81c40c`. Восемь слотов
(индексы 0..7). Геттер `0x442290` берёт текущий индекс `[0x83d308]` и
возвращает `[0x81c40c + i*0x3510]`. Сброс — на старте уровня:
`0x452430` (вызов из загрузки уровня `0x442f5a`) → `0x452730` → `0x45280f`
`mov [ebx+0x81c40c],esi(=0)`.

### 3.2. Что видит игрок

* Экран конца уровня `0x483c07`: `mov edx,[0x80d8c0]` (второй аргумент),
  `0x483c11 call 0x442290` (tally, первый), формат `"%ld / %ld"`
  (`0x4bcb78`), подпись `"SECRETS FOUND:"` (`0x4bcbb0`). Порядок: найдено /
  объявлено.
* Панель F6 `0x499534`: `"SECRETS FOUND"` (`0x4beb10`), tally из
  `[edi+0x81c40c]`, объявленное из `0x80d8c0`, формат `"%ld/%ld"`
  (`0x4be7d8`, без пробелов — отличается от экрана конца).

### 3.3. Сейв

Tally лежит в блоке 9 (структура игрока `0x3510`, `docs/SAVE_FIELDS.md` §9):
`+0x33cc` входит в неё. Объявленное число — статическое поле уровня
(опкод 94 в блоке 11), а tally обнуляется при каждой загрузке уровня, поэтому
в сейве имеет смысл только для сохранения «внутри уровня».

### 3.4. Числа и арифметика

Измерено на 36 `.sbt` (`--summary`, локальный декодер):

| величина | значение |
|---|---:|
| `SET_LEVEL_SECRETS`: сайтов / уровней | 25 / 25 |
| сумма объявленных секретов | **101** |
| `INCREMENT_SOURCEPLAYER_SECRET_TALLY`: сайтов / уровней | **105** / 27 |
| уровни без объявления, но с инкрементом | `secrt2` (2), `temple` (1) |

Арифметика сходится: `101 + 2 (level3: 8 сайтов на 6 объявленных) − 1
(level15: 4 на 5) + 3 (secrt2/temple) = 105`. Это же число независимо
подтверждает `docs/AUDIT_NUMBERS.md` §3 (op 94/95).

## 4. Триггеры

### 4.1. Секторы: события и урон

`SECTOR_STUFF` — `0x800b60`, 256 записей по `0x58`; смещения:
`+0x38` event_a, `+0x3c` event_b, `+0x40`/`+0x44` damage_a/b, `+0x50` flags
(`docs/RECORDS.md` §2, `docs/VM_EXEC.md` §3.2).

* `SET_SECTOR_EVENTS` (13, `0x4579ab`): пишет `event_a`/`event_b`.
  Потребитель — физика игрока: `0x445026` сравнивает `[player+0x81c27c]` с
  `eax` из `[esp+0xc]`; при различии `0x44503f` берёт `event_b` (`+0x3c`) по
  индексу `eax`, а `0x445095` — `event_a` (`+0x38`) по индексу
  `[player+0x81c27c]`; оба уходят в `event_post 0x4795b0` с 11 аргументами
  (id, 0, 0, level, source, координаты). **Какое из двух полей означает вход,
  а какое выход — не доказано** (`docs/RECORDS.md` §2 оставляет имена
  нейтральными; здесь уточнено только, какой индекс читается). Ноль в поле —
  события нет.
* `SET_SECTOR_DAMAGE` (11, `0x457961`): пишет `damage_a = v & 0xffff`,
  `damage_b = v >> 16` (арифметически). Каждый тик `0x4450f6/0x4450fc`
  читают обе половины, умножают на `dt` (`0x445102/0x445105`) и при
  ненулевом результате зовут урон `0x453b50(..., -1)`.
* `SET_SECTOR_FLAGS` (14) → `+0x50`, читается в коллизии/движении
  (`0x444169`, `0x44476a`, `0x46bce1` и др.).

### 4.2. Радиусный триггер вещей

`0x469770(source, x, y, z, flags)` — скан 300 записей предметов
(`0x806398`, шаг `0x60`) каждый тик: `0x445165` зовёт его из физики игрока с
`flags=3`; вещи с битом `0x80` в `+4`/`0x800000` в `+8` — из `0x471e03`.
Условие — `distance < radius` (`0x4344df` длина, `fild [esi+0x14]` —
`0x4697eb`), радиус в `+0x4c`. Попадание постит событие из `+0x44`
(`docs/PICKUP.md` §4). Это и есть механизм «подобрал/вошёл» для предметов
и сюжетных вещей.

### 4.3. Маркер регенерации

`DEFINE_REGENERATION_MARKER` (174): sob → `0x80d878` (в корпусе у всех 36
`19`), два double (`0x80f9e0`, `0x80f830`) никто не читает. Потребитель —
`0x468840/0x468841`: в DM вместо исчезнувшего предмета появляется маркер
(`docs/PICKUP.md` §7). К целям/секретам отношения не имеет, но входит в
«секторно-радиусный» набор триггеров задания.

### 4.4. Системные события, завершающие уровень

| id | имя | сайты (код) | что делает |
|---:|---|---|---|
| -3 | `INTERNAL_LEVEL_RESUME` | `0x4426a5 push 0xfd`, call `0x45fa00` (`0x4426a7`); создатель сущности — `0x462e0c` | под-скрипт восстановления состояния (сюда пишутся биты целей) |
| -4 | `INTERNAL_LEVEL_STARTUP` | `0x44328c push 0xfc`, call `0x45fa00` (`0x443299`) | старт уровня; не через очередь |
| -7 | `SYSTEM_PLAYER_KILLED` | `0x4537a5 push 0xf9`, `0x4537a7 call 0x4795b0` | смерть игрока (`state=7`, `docs/GAME_OVER.md` §2) |
| -8 | `SYSTEM_LEVEL_FINISHED` | `0x44549f..0x4454a2 push 0xf8`, `0x4454a4 call 0x4795b0` | Activate на экране конца (`test ah,0x80` в `0x445456`) → под-скрипт `-8`: `NEW_LEVEL`/`NEXT_LEVEL` |
| -17 | `SYSTEM_PLAYER_LIFE_HALF_GONE` | `0x453ef4`, `0x470867` | жизнь пересекла половину вниз |
| -18 | `SYSTEM_PLAYER_ABOVE_HALF_LIFE` | `0x453f51`, `0x45421f`, `0x45b096`, `0x4603a3`, `0x4704e7` | жизнь пересекла половину вверх |

`-8` постится только при `[0x83cb7c]==5` (экран конца) и бите действия
`0x8000` в `[player+0x81c384]`; аргументы — 11 штук, включая координаты и
сектор.

### 4.5. Экран конца уровня

`SHOW_LEVEL_END_SCREEN` (91, `0x45c057`): `[0x5a46e4]/91` → `0x83d638`,
`frame_submode=5` (`0x45c066`), `0x45c880` обновляет `GUNMETAL.HI`.
Отрисовка — `0x483a70` (один игрок) / `0x483550` (несколько). В корпусе
**38** сайтов на **31** уровне — это все уровни, кроме пяти штабов
(`level0`, `level00`, `level000`, `level0a`, `level0b`); в DM-картах
`dm1`/`dm2`/`dm3`/`dm4` он тоже есть и завершает матч.

Шесть уровней объявляют цели, но битов не ставят (`dm3`, `level13`,
`level16`, `level18`, `level21`, `level24`): их конец запускает другой
триггер. Пример `level13`: `entity 305` при `SOURCE_IS_PLAYER` сразу даёт
`ADD_SOURCEPLAYER_CASH 85000` + `SHOW_LEVEL_END_SCREEN` (в DM-ветке —
телепорт), а `OR_LEVEL_OBJECTIVES_BITS` в скрипте нет вовсе.

**Уточнение к `CAMPAIGN_FLOW` §4.** «51 строка» — это сумма текстов только
первых объявлений (то, что игрок видит на старте). Полный корпус объявляет
**67** строк, из них **58** разных: у `level19` 7 объявлений и 12 строк,
у `level2` — 3 и 6, у `level7` и `level18` — по 2. Поздние объявления
перетирают массив `0x80d800`/`0x80d7ec` по ходу миссии, поэтому «сколько
целей в уровне» зависит от момента; первое объявление — стартовый список.

**Уточнение к `LEVEL_LOAD` §4.** `0x454d13 call 0x456f50` — не только
«эффекты/анимации»: там же `0x45709d/0x4570a3/0x45708a` сбрасывают count
целей, маску битов и объявленные секреты.

## 7. Доказано, гипотезы, остатки

**Доказано кодом:** адреса и семантика 103/104, условия 7, 94/95 и
`0x4536b0` (включая stride `0x3510` и `+0x33cc`), сбросы
`0x45280f`/`0x45708a`/`0x45709d`/`0x4570a3`, геттеры `0x442290` и экран
конца `0x483c07`, HUD `0x487337` + маркеры `check`/`nocheck`, сейв через
сущность `-3` и опкод `0x68`, секторные события/урон, радиус-триггер
`0x469770`, сайты событий `-3/-4/-7/-8/-17/-18`.

**Доказано данными (36/36):** все числа §5, аномалии `level3`/`level15`/
`secrt2`/`temple`, список 6 уровней без битов, 7 объявлений `level19`.

**Гипотезы/остатки:**

1. Что именно лежит в буферах `0x67fc10`/`0x683fb8` после загрузки
   `frontend`/`check`/`nocheck` (16 и 8 байт) — имена ассетов доказаны,
   содержимое — нет; маркеры рисуются как глифы 8×16/8×8.
2. Зачем `level3` имеет 8 сайтов инкремента на 6 объявленных (вероятно,
   альтернативные ветки/повторный вход) и почему `level15` — 4 на 5.
3. Смысл двух double в `DEFINE_REGENERATION_MARKER` (`0x80f9e0`,
   `0x80f830`) — по-прежнему не найден (совпадает с `docs/PICKUP.md` §7).
4. End-to-end сейв с ненулевой маской целей не проверен: в поставке нет
   сейва дальше `level0`.
5. `SET_LEVEL_VERSION` (`0x80f9d4`) семантически не разобран; известно
   только, что это не цели.

## 8. Воспроизведение

```sh
python3 tools/re/objectives.py --self-test
python3 tools/re/objectives.py --fields

python3 tools/re/objectives.py --anchors
```

печатаются как `SKIP`, а не падают. Зеркало игры
(`~/.cache/gunmetal-re/game`) используется по умолчанию, если существует.
