# Рендер экрана 37 `NEW VIDEO MODE OK?` (`engine/src/ui/video_mode_render.h`)

Срез 5 пункта `M8.8`: модуль **рисует экран 37** в RGBA-буфер 320×200 из
реальной установки: заголовок `NEW VIDEO MODE OK?`, два пункта `Yes`/`No`,
подсветку курсора шрифтом 4 и плату `PLATE`. Геометрия — из обработчика
`0x488990` (`docs/UI_SCREENS.md` §2/§3.8), атласы — из `render/text_layout`
(`FONTS4` в `FRONTEND/BMP.IDX`), курсор по умолчанию — из входа в состояние
`0x25` (`0x48e1c6`).

Код: `engine/src/ui/video_mode_render.h/.cpp`; тест —
`engine/tests/test_video_mode_render.cpp` (CTest `video_mode_render`, label
`quick`). Канон поведения — `docs/UI_SCREENS.md` §3.8 и этот документ;
образцы того же класса задач — `docs/LOCAL_PLAYERS_RENDER.md` (21),
`docs/DIFFICULTY_RENDER.md` (23) и `docs/GAME_TYPE_RENDER.md` (19).

Проверка:

```sh
export PATH=$HOME/tools/cmake-4.4.4-linux-x86_64/bin:$HOME/tools/bin:$PATH
cmake --build build/sandbox --target gm_video_mode_render_tests -j 4
./build/sandbox/engine/tests/gm_video_mode_render_tests
ctest --test-dir build/sandbox -R '^video_mode_render$' --output-on-failure
python3 regress.py --mirror --json
```

## 1. Что доказано (`0x488990`, docs/UI_SCREENS.md §2/§3.8)

Обработчик занимает `0x488990`..`0x4889ee` (последний `ret`; дальше `nop` до
`0x4889f0`, где начинается экран 11). Таблица диспетчера `0x4883d8` (id 5..37)
для id 37 указывает на stub `0x487eec` = `call 0x488990; jmp 0x487f64`
(слот `0x488458`). Всё в таблице — сайты обработчика и общего отрисовщика
`0x485dd0` (листинг: `python3 tools/re/disrange.py 488990 4889f0` и
`485dd0 485e80`).

| факт | значение | источник |
|---|---|---|
| длина списка | **2** (`0x67f10c = 2`) = `Yes` (item 0), `No` (item 1) | `0x4889ae` |
| шаг пункта | **16** (`0x662d58 = 0x10`) | `0x4889a4` |
| плата | `0x486050` копирует `PLATE` 196×131 в `0x6865f8` (6419 dword = 25676 байт); весь текст пишется в эту копию (клип 196×131) | `0x488990`; §3, §9 |
| заголовок | `NEW VIDEO MODE OK?` (`0x4bd474`), шрифт **5**, `centered=1`, `x 38`, `row 14`, `item -1` → **y 14**, x = (196 − measure)/2 | `0x488995`..`0x4889b8`; `0x485de2`..`0x485dfa` |
| `centered` | `x = (196 − measure(text)) / 2`, целочисленно | `0x485de2`..`0x485dfa` |
| `item == -1` | обнуляет `item·step`, поэтому y = row | `0x485e04`..`0x485e09` |
| пункт 0 | `Yes` (`0x4bd3dc`), item **0**, `x 38`, `row 27`, шрифт 0 → **y 27** | `0x4889c0`..`0x4889d4` |
| пункт 1 | `No` (`0x4bc7a4`), item **1**, `x 38`, `row 27`, шрифт 0 → **y 43** (= 27 + 16) | `0x4889d7`..`0x4889eb` |
| `y` при `row >= 0` | `y = row + item·[0x662d58]` — оба вызова передают row 27, поэтому шаг 16 разносит пункты: 27, 43 | `0x485e4b`..`0x485e5c` |
| подсветка | `item == [0x68ccf4]` **и** вызывающий передал шрифт 0 (`test esi,esi`) → шрифт принудительно **4**; оба пункта — обычные item, поэтому подсвечиваться может любой | `0x485e0d`..`0x485e19` |
| стрелки | обработчик не вызывает `0x485cc0`/`0x485d00`; список кончается на y 43 в полосе 131 px, прокрутки нет | листинг `0x488990..0x4889ee` |
| порядок | заголовок → `Yes` → `No` | порядок вызовов `0x4889b8`, `0x4889d4`, `0x4889eb` |
| курсор при входе | **0** (`Yes`): ветка состояния 18 `0x48e182` пишет `0x25` в `0x4bc440` и обнуляет `0x68ccf4` | `0x48e1b5`, `0x48e1c0`, `0x48e1c6` |

### 1.1. Порядок пунктов и геометрия

| item | строка | VA | x | y |
|---:|---|---|---:|---:|
| 0 | `Yes` | `0x4bd3dc` | 38 | 27 |
| 1 | `No` | `0x4bc7a4` | 38 | 43 |

`x` у обеих строк — 38 (`push 0x26`), шрифт 0. Второй `push 0x26` заголовка —
аргумент `x` вызова с `centered=1`, он не используется: `0x485de2` заменяет
его на `(196 − measure)/2`. При поставочном `FONTS4` ширина заголовка 101 px,
поэтому **x = 47** (проверено bbox’ом в тесте). Ячейка шрифта 8×8: строки
занимают 27..34 и 43..50, не пересекаются.

### 1.2. Что делают ответы (сам модуль их не выполняет)

Экран 37 — подтверждение только что применённого видеорежима. Вход
(единственный, который его рисует) — ветка состояния 18 в общем обработчике
ввода: `0x48e182` копирует 5 dword дескриптора из `0x4c05c0`, вызывает
`0x4864a0` (поиск этого дескриптора в таблице режимов `0x4bfd1c`, результат —
индекс) и кладёт индекс в `0x678180`; затем `0x48ed10(cursor)` применяет
выбранный режим, `0x4bc440 = 0x25`, `0x68ccf4 = 0`, а `0x678140 = now + 1000`
(`0x48e1b5`..`0x48e1d6`). Дальше:

* **`Yes` (item 0)** — режим остаётся; `0x48e1db` сравнивает курсор с `ecx`,
  который в этом обработчике равен 1 (`mov ebx,1` на `0x48b9c4`), сравнение не
  совпадает, поэтому ветка восстановления не выполняется; экран уходит в
  состояние `0x0c` (GRAPHICS OPTIONS) с курсором `[0x660788]` (`0x48e1f6`..
  `0x48e201`);
* **`No` (item 1)** — курсор == 1, `0x48ed10([0x678180])` возвращает прежний
  режим (`0x48e1e8`..`0x48e1f3`), затем то же состояние `0x0c`;
* **`ESC`** — `0x48e4df` для состояния `0x25` делает ровно то же: прежний режим
  и состояние `0x0c` (`0x48e4e4`..`0x48e502`);
* **таймаут** — `0x48f2be`: если тик `[0x5a4a74]` больше `[0x678140]` (порог
  1000 из `0x48e1cd`), режим откатывается сам (`0x48f2d3`..`0x48f2f4`), т.е.
  молчание = `No`.

Модуль рисует только вопрос; применение/откат режима (`0x48ed10`), таймер и
переходы — не его работа.

## 2. Модель кадра

* Холст — 320×200 (`0x6d8fc0`, mode 13h), по умолчанию непрозрачный чёрный
  `#000000FF`. `options.background` — имя записи `FRONTEND/BMP.IDX`,
  нарисованной в (0,0) **до** текста; пустая строка = чёрный холст.
  Доказанная плата экрана — `PLATE` 196×131 (`0x486050`,
  `menu_panel_asset(Screen::NewVideoMode)`), но она не рисуется неявно.
* Текст клипается к полосе 196×131: `0x485dd0` пишет в копию `PLATE`
  `0x6865f8`, за её пределы пиксель не попадает. Холст вне платы остаётся
  чёрным.
* Шрифты — три грани `FONTS4`: заголовок 5, строки 0, подсветка 4 (§3).
  Цвета из палитры атласа: заголовок (155,15,15), строки (19,15,15),
  подсветка (239,239,239). Ячейка 8×8.
* Заголовок центрируется по ширине **advance**-сумм (`0x47fa50`), а не по
  чернилам: при поставочном `FONTS4` `x = (196 − 101)/2 = 47`.
* Подсветка — только смена грани на 4 (`0x485e0d`..`0x485e19`) и только когда
  вызывающий передал шрифт 0; ни полосы, ни рамки, ни `MENULIT` здесь нет.
  Курсор 0/1 подсвечивает `Yes`/`No`; значения вне `0..1` (например `-1` или
  `99`) не подсвечивают ничего — это точное сравнение `0x485e0d`, а не кламп.
* Точный fade (`fade_lut*`) — тот же индексный слой `0x682f90`, что у
  `ui/start_game_render`/`ui/local_players_render`: таблица применяется к
  индексу палитры **до** поиска цвета. Без таблицы и дампа — отказ, не «молча
  без fade». Уровень 11 — тождество (0 отличий), 0..10 затемняют, 12..15
  осветляют.

## 3. API

```cpp
struct VideoModeRenderOptions {
    std::string background;              // "" = чёрный; "PLATE" = плата экрана
    int cursor = 0;                      // [0x68ccf4], item id 0..1
    bool fade_lut = false;
    int fade_lut_level = 11;             // 0..15
    std::string fade_lut_dump;           // 4096 байт, docs/HUD_LUT.md §2
    const HudLut* fade_lut_table = nullptr;
};

struct VideoModeRenderStats {
    int rows;             // пункты, 2 (они же строки)
    int ink_pixels;       // уникальные пиксели чернил глифов
    int missing_glyphs;
    int arrows;           // всегда 0 (на экране нет прокрутки)
};

bool render_video_mode(const std::filesystem::path& game,
                       const VideoModeRenderOptions&,
                       std::vector<std::uint32_t>& rgba,
                       int& width, int& height,
                       VideoModeRenderStats* = nullptr,
                       std::string* error = nullptr);
```

Данные экрана доступны как константы: `kVideoModeEntries[2]` (`label`,
`item`), `kVideoModeTitle`, `kVideoModeYes`, `kVideoModeNo`,
`kVideoModeRows = 2`, `kVideoModeItemStep = 16`,
`kVideoModeItemFirstY = 27`, `kVideoModeNoY = 43`, `kVideoModeItemX = 38`,
`kVideoModeTitleY = 14`, `kVideoModeDefaultCursor = 0`,
`kVideoModeNoItem = 1`, `kVideoModePanelName = "PLATE"`,
`kVideoModePanelWidth/Height = 196/131`.

Отказы (префикс `video_mode_render:`): пустой путь игры; нет/битый
`FRONTEND/BMP.IDX`; нет атласа `FONTS4` (шрифты 5/0/4); неизвестная/битая/
не-8-bpp запись фона; `fade_lut` без таблицы и дампа или с нечитаемым дампом.
При отказе `rgba` очищен, `width = height = 0`, статистика обнулена.

| `ink_pixels` | **356** |
| bbox заголовка | x 47..147, y 14..20, 101×7, 278 px |
| bbox `Yes` (подсвечен) | x 38..52, y 27..33, 15×7, 43 px |
| bbox `No` | x 38..47, y 43..49, 10×7, 35 px |

|---:|---:|
| 11 | **0 / 64000** |
| 0 | 25676 (все пиксели платы; чёрных 64000) |
| 12 | 17062 |

## 5. Ограничения

* **Нет ввода/навигации**: модуль не читает клавиатуру и не двигает
  `[0x68ccf4]`; правило «пункт == item» — модель выделения, а сам переход по
  пунктам делает `frontend_menu`/CLI.
* **Нет звука**: `updown`/`select` (`docs/UI_SOUNDS.md`) не моделируются.
* **CLI — есть (срез 6).** `--video-mode [--video-mode-cursor N]
  [--no-plate] [--png OUT] [--fade-lut N]`:
  `video_mode: rows=2 cursor=0 ink=356 missing=0 arrows=0`; курсор 1 —
  `cursor=1`. CTest `cli_video_mode`, `_png`; `cli_fade_lut` (11 = без fade).
* **Нет самого переключения режима**: `0x48ed10` (применить), `0x48ed10` на
  откате, таймер `[0x678140]`/`[0x5a4a74]` и переходы в состояние `0x0c` не
  воспроизводятся — это делает оригинал (и будущий `frontend_menu`), здесь
  только кадр. `0x678180` (прежний индекс режима) не читается и не пишется.
* **Курсор вне `0..1` не клампится**: это точное сравнение `0x485e0d`;
  поставочная навигация держит значение в диапазоне, поэтому «пустая»
  подсветка — валидное состояние API, а не ошибка.
* **Соответствие «номер шрифта → атлас»** для 0/4/5 взято из `docs/UI.md`
  §10.3/`docs/MENU_RENDER.md` §3; независимой привязки номеров в коде нет —
  это общее открытое место фронтенда, не специфика экрана 37.
* **`No`-строка делит VA `0x4bc7a4`** с другими экранами (`QUIT GAME?` и др.),
  поэтому `tools/re/ui_screens.py --json` находит только `Yes`; вторая строка
  доказана листингом `0x4889d7`..`0x4889eb`, а не поиском строк.
