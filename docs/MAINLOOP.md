# Главный цикл и машина состояний (M2.2.2)

Каркас собран по коду `gundx.exe` v1.36 (ImageBase `0x400000`), без Ghidra.
Пометки: **код** — проверено по дизассемблеру (адрес указан рядом),
**гипотеза** — не доказано. Все адреса — виртуальные (VA).

## 1. Запуск и цикл сообщений

```
0x401000  PE entry (Watcom CRT)
  └─ 0x40114d  call 0x404680                     ; WinMain
       0x404692  call 0x404320(hInst, cmd, show) ; класс, окно, DirectDraw/DI
       0x404440  RegisterClassA                  ; WndProc = 0x404070
       0x40447d  CreateWindowExA
       0x44a460  инициализация игры
```

WinMain (`0x404680`), цикл с `0x4046be`:

```
PeekMessageA(&msg, 0, 0, 0, PM_REMOVE)       ; IAT 0x8413e0
├─ сообщение есть
│   ├─ msg == WM_QUIT (0x12) → 0x404701, выход:
│   │     0x407550 ([0x4c0608] = 1), 0x44b460, 0x406eb0, 0x405ed0,
│   │     0x405a40, 0x44da10, 0x407e00
│   └─ иначе TranslateMessage + DispatchMessageA   ; 0x8413e4 / 0x8413f8
└─ сообщений нет
    ├─ [0x4a598c] != 0 → WaitMessage                ; 0x8413dc
    └─ иначе 0x405450 (DirectInput) + 0x44c230 (кадр)
```

Сопоставление импортов проверено разбором таблицы импорта: `0x8413e0`
PeekMessageA, `0x8413e4` TranslateMessage, `0x8413f8` DispatchMessageA,
`0x8413dc` WaitMessage.

`[0x4a598c]` — «окно неактивно»: WndProc пишет туда `(wParam == 0)` при
`WM_ACTIVATE` (`0x4040ec`), поэтому в фоне кадр не считается, а игра ждёт
сообщений.

## 2. WndProc

Адрес взят из WNDCLASS: в `0x404320` перед `RegisterClassA` в поле
`lpfnWndProc` (`[esp+0x14] = 0x404070`, команда `0x404430`).

Диспетчеризация: `eax = msg - 2`, `cmp eax, 0x1e`, байтовая карта `0x404144`,
таблица переходов `0x404130`.

| msg | обработчик | действие |
|---|---|---|
| 2 WM_DESTROY | `0x404111` | `PostQuitMessage(0)` (`0x8413ec`) |
| 6 WM_ACTIVATE | `0x4040e3` | `[0x4a598c] = !wParam`; `0x4059c0` — Acquire/Unacquire DirectInput |
| 0xf WM_PAINT | `0x40409d` | BeginPaint (`0x8413b4`), `ExtTextOutA` (строка `0x4a5994`), EndPaint (`0x8413d8`) |
| 0x20 WM_SETCURSOR | `0x4040fb` | `SetCursor` (`0x8413e8`) |
| прочие 2..0x20 | `0x404119` | `DefWindowProcA` (`0x8413f0`) |

`0x4059c0` — перезахват устройств DirectInput: у каждого из
`0x4bfcf4`/`0x4bfcf8`/`0x4bfca8` вызывается метод `vtable+0x20`.

## 3. Кадр `0x44c230`

Порядок (код):

```
три float-часа 0x4aa390 / 0x4aa398 / 0x4aa438 += ... * 0x4a23e8
0x48efc0
[0x83d620] == 4 → выход (0x44c2a2 -> 0x44c617)
отложенное имя: 0x5a47c8 -> 0x5a4778, 0x442ef0 / 0x442cf0
switch [0x83cb7c]:
  0 → 0x447610 (клавиши/мышь); если [0x4aa384] != 0 → 0x40c080; выход
  1 → 0x44c760; выход
  иначе:
      dt = [0x5a4a74] - [0x5a49e8], clamp <= 0x2d
      для i = 0..3: 0x453400([0x83d2d0 + 4i]) → [0x83d308 + 4i], копия в 0x4ac078
      проверки [0x4bc440] (0 / 3) и [0x5a4700] == 2
      0x44c7f0 (если dt == 0), иначе 0x44be50(0), 0x44be50(1)
      0x44c620(dt)   — sprintf(buf 0x4aa445, fmt 0x4ac094 = "%ld %ld %ld/%ld", ...)
      0x44c710
      0x44b490       (дважды при некоторых условиях)
      0x44d4c0
```

## 4. Переменные состояния

### 4.1 `[0x4bc440]` — режим игры

Значения, которые реально пишутся в код (поиск по `mov [0x4bc440], ...`):

| значение | писатель (код) | что известно |
|---|---|---|
| 0 | `0x442448`, `0x4424fa`, `0x44256b`, `0x4425f8`, `0x44277e`, `0x4427c0`, `0x442927`, `0x442a72`, `0x44b85a`, `0x466d03`, `0x485c50` | сброс/выход (гипотеза) |
| 1 | `0x44b5d2`, `0x44d2c9`, `0x457594`, `0x48347e`, `0x487709`, `0x48b57a` | `0x48b57a`: Esc в режиме 5 → 1 |
| 2 | `0x45c259`, `0x466c6b` | `0x45c259`: команда `.sbt` → `0x44bed0(1)` |
| 3 | `0x45c240` | команда `.sbt` → `0x44bed0(1)` |
| 4 | `0x445514` | — |
| 5 | `0x44c2ed`, `0x44c30e`, `0x45c066`, `0x466b98`, `0x466cf9` | `0x44c2ed`/`0x44c30e`: по флагам `0x442ef0`/`0x442cf0` |
| 6 | `0x443af9`, `0x48b54c` | `0x48b54c`: Esc в режиме 9 → 6, затем `0x487500` |
| 9 | через регистр (`0x44ae54`, `0x44b1ea`) | **уровень** (доказано читателями: `0x48b531`, `0x4876af`); конкретный писатель не локализован |
| 0xe | `0x48b710` | Esc в режиме 0xf → 0xe |
| 0xf | (ветка `0x48b691`) | ввод имени: A-Z/0-9/пробел, буфер `0x661280`, до 0x12 символов (гипотеза: таблица рекордов) |
| 0x11 | `0x48b13c` | старт игры: `0x48b3f0` → 0x11 → `0x48b170` → `0x48a3c0` |
| 0x15 | `0x48b11c` | старт игры, ветка `[0x664598] ∉ {0,3}` → `0x48a780` |
| 0x22 | `0x48b885`, `0x48b8d5`, `0x48b8fc` | — |

Вывод «9 = уровень» держится на читателях: `0x48b531` (Esc в режиме 9
открывает меню/паузу), `0x4876af` (в режиме 9 грузится `frontend`/`DEMOTION`,
320×200). Семантика остальных значений — гипотеза.

### 4.2 `[0x83cb7c]` — подрежим кадра

| значение | писатель |
|---|---|
| 0 | `0x442448`, `0x4424fa`, `0x44256b`, `0x4425f8`, `0x44277e`, `0x4427c0`, `0x442927`, `0x442a72`, `0x44b85a`, `0x466d03`, `0x485c50` |
| 1 | `0x44b5d2` (по клавишам 0x8000), `0x44d2c9`, `0x457594`, `0x48347e`, `0x487709`, `0x48b57a` |
| 2 | `0x466c6b` |
| 4 | `0x445514` |
| 5 | `0x45c066`, `0x466b98`, `0x466cf9` |

Значение 1 — отдельная ветка кадра (`0x44c760`), 0 — только ввод
(`0x447610`), остальные — полный конвейер.

### 4.3 Прочее

* `[0x83d620] == 4` — кадр пропускается (`0x44c2a2`); сбрасывается в `0x44a4c9`.
* `[0x4aa384] != 0` — в подрежиме 0 вызывает `0x40c080`.
* `[0x5a4700] == 2` — условие ветки кадра (`0x44c4f4`).

## 5. Передний план

* `0x48b4d0` — ввод и переходы меню: `0x498ac0`, затем клавиши; по
  `[0x4bc440]`:
  * 9 + Esc (`0x1b`) → 6 и `0x487500` (`0x48b531`);
  * 5 + Esc → 1 (`0x48b56c`);
  * 3 + ... (`0x48b596`);
  * 0xf — ввод имени (`0x48b691`), Esc → 0xe (`0x48b710`).
* `0x48b0c0` — старт игры: `[0x68cd84]` (0..4) → `[0x678148]`, ветки 0x11/0x15.
  Вызывается из обработчика `0x48dc12`.
* `0x48f4a6` — вызов `0x48b4d0` из кадра переднего плана.

## 6. Открытые вопросы

* Семантика режимов 0..6, 0xe, 0x22 (нужны сценарии: меню, загрузка, смерть,
  победа).
* Точные роли `0x44c620` / `0x44c710` / `0x44b490` / `0x44d4c0`.
* `0x48a3c0` и `0x48a780` — что грузится в каждой ветке старта.
* `[0x83d620] == 4` — какой экран/фильм.
* Диалог `0x404180` (`DialogBoxParamA`, шаблон `0x66`) в `0x4044a3`.

## 7. Воспроизведение

```
objdump -D -b pei-i386 -M intel gundx.exe > /tmp/opencode/gundx.asm
python3 tools/re/disrange.py 0x404680 0x404730
python3 tools/re/names.py            # 90 адресов, проверка секций
```

Карта адресов — `tools/re/names.csv` (подсистемы `main`, `frontend`, `input`).
