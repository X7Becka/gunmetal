# Кокпит: собранный кадр 320×200 (M4.4.5, срез 3)

* **Статус:** одна функция собирает кадр кокпита `level0` целиком из
  поставочных ассетов: `PANEL` 320×78 в `(0,122)`, две иконки 24×24, подписи и
  цифры слоя `0x4926a0`, заливки шкал и (опцией) ленту компаса. Формат кадра —
  `0xRRGGBBAA`, 320×200, альфа 255; мир не рисуется, фон чёрный.
* **Ветка:** `feat/cockpit`, база `master` `c4383cb` (задача выдана от
  `b0f287b`; worktree уже стоял на двух merge-коммитах), дата 2026-10-24.
* **Игра:** только чтение (`FRONTEND/BMP.IDX`, `FRONTEND/GAMEPAL.BMP`, шрифты
  `FONTS3`/`NUMFONTS` из того же архива). Ничего не пишется; синтетические
  BIGFILE-пары теста — в системном tmp.
* **Файлы:** `engine/src/render/cockpit.h`, `engine/src/render/cockpit.cpp`,
  `engine/tests/test_cockpit.cpp`; строка `src/render/cockpit.cpp` в
  `engine/CMakeLists.txt`, цель `gm_cockpit_tests` / тест `cockpit`
  (label `quick`) в `engine/tests/CMakeLists.txt`. Других изменений нет.
* **Эталон:** `docs/HUD_COMPOSE.md` часть II (панель, шрифты, порядок слоёв),
  `docs/HUD_ICONS.md` §1–§5 (ассеты иконок, направление строк, компас),
  `docs/HUD_AUDIT.md` §2.7–§2.9 и §4 (координаты и поля), `docs/TEXT_LAYOUT.md`
  §2.3 (метрики шрифтов), `docs/PAGER_RENDER.md` (формат RGBA-кадра).

`render/hud*`, `render/hud_icons.*`, `res/bmp.*`, `main.cpp`, `config.*`,
`ROADMAP.md` не менялись. `hud_compose.*` (слой `.sml`/`.sof`-фильмов) в этой
задаче не участвует: кокпит — не фильм `128×64`, а панельный слой; композиция
повторяет `tools/re/hud_compose_ref.py`/`gm/hud.py`, а не `compose_hud`.

## 1. Слои и порядок

Порядок повторяет `0x491a70` → `0x4926a0` (`docs/HUD_AUDIT.md` §2.9):

| # | слой | ассет | куда | база |
|---:|---|---|---|---|
| 1 | панель | `PANEL` 320×78, ключ — индекс 0, строки в порядке движка (`flipV`) | `(0,122)` | **доказано** §2.7 |
| 2 | иконка оружия | `WICONn`/`WCONn` из записи `DEFINE_WEAPONS`, сверху вниз | `(23,162)` | **доказано** `0x49295b`, §2.9 |
| 3 | иконка экипировки | `equip<n>`, снизу вверх (вертикальное зеркало) | `(201,162)` | **доказано** `0x492cf5` |
| 4 | заливки | тяга 4×53 `0xf3`; полосы гексагона 3×17, цвет по длине | `(202,155)`; `(148,151)`/`(148,177)` | геометрия **доказана** §2.9, цвет полос — правило `0xf3/0x2b/0xff` |
| 5 | текст | шрифт 6 (`FONTS3`) — подписи; 9/10/11 (`NUMFONTS`) — цифры | таблица ниже | **доказано** `0x49289f`…`0x492fdd` |
| 6 | компас (опция, по умолчанию выкл.) | рисованный: риски каждые 22.5°, буквы `N/E/S/W` | окно `x 79..129`, `y 2..15` | **MODEL** `docs/HUD_ICONS.md` §5 |

### 1.1 Координаты: кодовая строка минус 8

`0x47faf0(font, text, buf, x, y, pitch, 0)` пишет *низ* клетки в строку `y`
(строки глифа идут вверх по атласу), а HUD-слой для поставленной раскладки
(`case 3`, `DAT_004bc1c8`) сдвигает буфер на 8 строк вверх
(`docs/HUD_AUDIT.md` §2.9). Поэтому в кадре клетка занимает `y-8 … y-1`:

| элемент | шрифт | константа кода | клетка в кадре |
|---|---|---:|---:|
| имя оружия / `NO WEAPON` | 6 | `(23,162)` `0x49291e` | `(23,154)` |
| `KILL` | 6 | `(52,186)` `0x49289f` | `(52,178)` |
| `DAMAGE` | 6 | `(141,150)` `0x4928c6` | `(141,142)` |
| `THROTTLE` | 6 | `(205,159)` `0x492fbf` | `(205,151)` |
| патроны | 10 | `(72-8·(n-1), 171)` `0x4929f4` | верх `163` |
| убийства | 11 | `(72, 185)` `0x492fdd` | верх `177` |
| урон `%` | 9 (< 70 %) / 10 | `(156-8·(n-1), 189)` `0x49270e` | верх `181` |

Иконки в коде стоят в буферных строках `0xaa` (170) — те же `-8` дают 162, что
и совпало с кадром (`NCC 0.888` для `WICON1` в `(23,162)`, `0.955` для
`EQUIP0` в `(201,163)`; `docs/HUD_ICONS.md` §4). Сдвиг применяется один раз ко
всем текстовым и иконным позициям, поэтому подпись и иконка стыкуются без
зазора (154…161 и 162…185).

### 1.2 Палитра

Кадр собирается как **индексный** холст 320×200 и один раз переводится в RGBA
по `GAMEPAL` (`FRONTEND/GAMEPAL.BMP`, `0x83d320`; `installed_palette`), альфа
255. Это повторяет движок: текст и иконки рисуются **после** фейда сырыми
индексами (`docs/HUD_AUDIT.md` §2.9), а проверка по живому дампу дала
`965/965` пикселей текста и `576/576` + `576/576` пикселей иконок.
`LUT` затемнения (`0x682f90`) не применяется — его таблицы в поставке
отсутствуют, кадр отдаёт исходный арт панели (см. §5).

## 2. API

```cpp
struct CockpitState {
    int weapon_id = -1;    // DEFINE_WEAPONS слот 0..18 (порядок level0)
    int ammo = 0;
    int armor = 0;         // сотые доли, player+0x3248
    int armor_max = 10000; // сотые доли, player+0x3244
    int kills = 0;         // player+0x3270
    double speed = 0.0;    // доля тяги 0..1 (модель, см. §4)
    int equipment_id = 0;  // player+0x3320, слот 0..12
    double yaw_deg = 0.0;  // player+0x0028, для компаса
};

struct CockpitOptions { bool icons = true; bool numbers = true; bool compass = false; };

struct CockpitStats {
    int elements_drawn = 0;  // элементы, записавшие хотя бы один пиксель
    int missing_assets = 0;  // не найденные иконки/шрифты (пропуск, не отказ)
    int ink_pixels = 0;      // пиксели текстового слоя (подписи + цифры)
    int panel_pixels = 0;    // пиксели панели (не ключевые)
};

bool render_cockpit(const std::filesystem::path& game, const CockpitState& state,
                    CockpitOptions options, std::vector<std::uint32_t>& rgba,
                    int& width, int& height, std::string* error,
                    CockpitStats* stats = nullptr);
```

* `speed` — **доля 0..1**, а не `engine_power`; длина тяги
  `lround(clamp(speed,0,1)·53)`, нефинитный вход — 0.
* `armor` клампится в `[0, armor_max]`; `armor_max <= 0` — отказ (деления на
  ноль нет). Урон считается целочисленно:
  `100 - (100·armor + armor_max/2)/armor_max`, кламп `0..100`.
* `weapon_id` вне `0..18` (или `-1`) — не отказ: рисуется подпись `NO WEAPON`
  (строка `0x4be5cc`), иконка пропускается и считается в `missing_assets`.
* `equipment_id` вне `0..12` — иконка пропускается, `missing_assets++`.
* `icons=false` убирает обе иконки, `numbers=false` — весь текстовый слой
  (`ink_pixels == 0`); заливки рисуются всегда, компас — только по опции.
* При успехе `error` очищается, `width/height = 320/200`, `rgba` — 64000
  элементов. При отказе `rgba` очищается, `width = height = 0`, `error` —
  текст.

Отказы (все — до первой записи в кадр):

| ситуация | текст |
|---|---|
| пустой каталог / нет индекса | `cockpit: no FRONTEND/BMP.IDX under '...'` |
| нет `PANEL` | `cockpit: PANEL: asset 'PANEL' is not in .../FRONTEND/BMP.IDX` |
| `PANEL` не 320×78 | `cockpit: PANEL is 2x3, expected 320x78 (the 320x200 frame)` |
| битая палитра | `cockpit: palette: not a BMP` |
| `armor_max <= 0` | `cockpit: armor_max must be positive (got 0)` |

## 4. Доказано / модель

**Доказано кодом и данными:**

* панель: `PANEL` 320×78, ключ — индекс 0, строки в порядке движка (буфер
  `0x678188` = `flipV(parse_bmp)`, совпадение с дампом `100.0 %`);
* иконка оружия — третий операнд `DEFINE_WEAPONS`, у вида один растр 24×24;
  экипировка — `sprintf("equip%d")`, 12 слотов HUD; оружие копируется снизу
  вверх, экипировка сверху вниз (`0x49295b`/`0x492cf5`);
* координаты всех подписей и цифр — константы `0x4926a0` минус 8 строк;
  патроны выравниваются вправо шагом 8 px, урон — тоже, `KILL` фиксирован;
* шрифты: 6 = `FONTS3` (8×8, origin `(8,0)`, шаг 16, обрезка по чернилам,
  `advance = ширина + 1`), 9/10/11 = `NUMFONTS` (копия клетки 8×10/8×8,
  `advance = 9`); цвета — сырые индексы `GAMEPAL` (965/965 и 576+576/1152);
* тяга: 4 строки от `(202,155)`, максимум 53 px, цвет `0xf3`;
* полосы гексагона: 3 строки, максимум 17 px, цвет по длине `0xf3/0x2b/0xff`.

**Модель (и это видно в API/доке):**

1. **Полосы гексагона от урона.** В коде они читают
   `charge_accumulated (+0x2FA8)` — гипотеза, в кадрах полосы пусты, поля
   заряда в `CockpitState` нет. Здесь длина полосы =
   `round(damage%·17/100)`, то есть шкала показывает урон, а не заряд. Границы
   шкалы (`armor=0` → 102 px заливки, `armor=max` → 0) проверены тестом.
2. **`speed` как доля тяги.** Код берёт `engine_power (+0x2F48)` и множитель;
   нормализация в 0..1 — наша, поэтому `speed` в структуре назван долей.
3. **Компас.** Геометрия (`x = 102.62 + 0.2940·(bearing - yaw)`, окно
   `79..129`, `y 2..15`) — подгонка по `win1..win3` (rms 1.08 px). Адрес
   отрисовки не найден; шаг рисок 22.5° и буквы `N/E/S/W` — модель,
   цвет — ближайший к зелёному кадра `GAMEPAL` индекс 191 `(0,255,0)`
   (в кадре `(12,252,12)`). Поэтому опция `compass` по умолчанию **выкл.**
4. **Имя и число экипировки не рисуются.** Имени нужна таблица
   `DEFINE_EQUIPMENT` уровня (в модуль не передаётся), число — остаток
   боеприпаса типа `DEFINE_EQUIPMENT +0x20`, поля в `CockpitState` нет.
   Иконка экипировки рисуется (`equipment_id`).
5. **`%` после урона не рисуется.** В `NUMFONTS` это отдельная 11-я клетка
   атласа (`(166,182,10,9)`), не код шрифта; `gm/hud.py` её тоже не рисует,
   а 100 % текстовых пикселей дампа достигнуты без неё.
6. **Панель в `(0,122)`, а не в 130.** Задача и раскладка `default` дают
   78 строк; в кадрах `win2`/`win3` включён `case 3` (панель в 130, видно 70
   строк). Поэтому полоса сравнивается с независимым блитом, а не с кадром.
7. **Без `LUT` затемнения.** `0x682f90` строится в рантайме, в поставке его
   нет; кадр отдаёт арт панели без фейда (это и есть главная причина невысокого
   `corr` по фону в §3).

## 5. Тесты

`engine/tests/test_cockpit.cpp` (68 проверок, `label quick`):

* **поставка**: кадр при `armor=10000, ammo=2000, kills=3, speed=1.0` и
  `weapon_id=0` (MACHINE GUN) — `elements_drawn=11`, `missing_assets=0`,
  `ink_pixels=765`, `panel_pixels=21196`; второй прогон побайтово равен
  первому; `weapon_id=4` (GRENADE) даёт другой кадр, `ink=715`, `missing=0`; повторный
  прогон тоже побайтово равен (`weapon 4 is deterministic too`);
* **панельная полоса**: `PANEL` читается тестом заново через `BigFile` +
  `parse_bmp`, блитится независимо (`flipV`, ключ 0, `GAMEPAL`); сравнение
  побайтовое (`mismatches=0`), число пикселей панели совпадает (`21196`), выше
  `y=122` — `0` непустых пикселей;
* **границы шкал**: `armor=0` → урон `100`, `ink=845`, `elements=13`,
  заливка `102` px; `armor=armor_max` → `ink=765`, `elements=11`, заливка
  `0`; кадры различаются;
* **переключатели**: `icons=false` меняет ровно два прямоугольника 24×24
  (549 + 571 = 1120 пикселей, вне них — ничего), текст цел (`ink=765`);
  `numbers=false` даёт `ink=0`, `elements=4`, разница `764` пикселя;
* **компас**: `compass=true` пишет 69 пикселей, все внутри окна `79..129`
  (проверяется по `x`), смена `yaw` (344.61 → 100) двигает ленту
  (`129` пикселей разницы), `elements=12`;
* **кламп брони**: `armor=-5` побайтово равен `armor=0`, `armor=20000` —
  `armor=armor_max`;
* **негативы** (синтетика, без игры): пустой каталог, архив без `PANEL`,
  `PANEL` 2×3, битый носитель палитры (`FLAG/naUSA.BMP` не BMP),
  `armor_max=0` — везде текст ошибки, `rgba` пуст, `width/height = 0`.

## 6. Ограничения

* **Нет 3D-слоя кокпита.** Верхние 15 строк полосы (в кадре `130..144`) —
  геометрия кабины, подсвеченная 3D-проходом; здесь их заменяет плоский арт
  `PANEL`. Иконки в кадре стоят на 3D-квадах с перспективой, но 2D-слой с теми
  же ассетами совпадает по NCC 0.888/0.955, поэтому взят он.
* **Нет анимаций**: LED (`BLINK0..3`, `0x491ec9`), мигание форсажа, фазы
  шкал; кадр статичен.
* **Нет звука и курсора**, нет прозрачного наложения на мир: фон кадра —
  чёрный, вызывающий заменяет его кадром `render_scene`.
* **Нет `LUT`** затемнения панели (см. §4.7) и **нет `PANELTOP`** (25-строчная
  полоса фронтенда к кокпиту не относится).
* **Шрифты — только латиница** (`FONTS3`/`NUMFONTS`); кириллицы и шрифтов
  пагера (`FONTS1/2/4`, `text_layout`) модуль не использует.
* **Таблица оружия — `level0.sbt`** (19 видов). Другие уровни нумеруют
  `DEFINE_WEAPONS` заново: `weapon_id` вне `0..18` даёт `NO WEAPON`, а не
  подстановку чужой иконки.
* **CLI — есть (срез 4):** `--hud-png OUT` собирает кадр из реальных
  ассетов, `--hud-weapon N`, `--hud-ammo N`, `--hud-armor N`,
  `--hud-kills N`, `--hud-speed X` задают состояние; `--png-scale` и
  `--fade` работают как у остальных кадров фронтенда. Проверено:
  `--hud-weapon 0 --hud-ammo 2000 --hud-kills 3` → `elements=10
  missing=0 ink=765 panel=21196`, PNG 320×200 (256 283 Б); CTest
  `cli_hud_png`, `cli_hud_png_scale`, `cli_hud_png_fade`. Состояния из
  рантайма и наложения на `render_scene` по-прежнему нет (следующий срез).

## 7. Следующий срез

1. **CLI и главный цикл:** `--hud`/`--hud-state` в `main.cpp`, состояние из
   рантайма (`+0x3248/+0x3244`, `+0x329c`, `+0x3270`, `+0x2F48`, `+0x3320`,
   `+0x0028`), наложение на кадр `render_scene` вместо чёрного фона.
2. **`LUT` затемнения** (`0x682f90`): дамп таблиц (как
   `tools/win/dump_lut.lua`) и уровень `k = (player+0x81c24c + 0x80) >> 4`;
   без него фон панели не совпадёт с кадром.
3. **3D-слой кабины** (верхние строки полосы) и LED-анимация.
4. **Имя/число экипировки** — таблица `DEFINE_EQUIPMENT` уровня и тип
   боеприпаса (`+0x20` записи).
5. **`%` урона** отдельной клеткой `NUMFONTS` и цвет урона по порогам
   (красный с 70 % уже поддержан выбором шрифта 9/10).
