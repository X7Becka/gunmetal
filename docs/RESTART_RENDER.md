# Рендер экрана 6 `RESTART GAME` (`engine/src/ui/restart_render.h`)

Срез 6 пункта `M8.8`: модуль **рисует экран 6** в RGBA-буфер 320×200.  Это
единственный экран фронтенда с **динамическим** числом пунктов: строитель
`0x488850` сам решает, сколько строк выпустить (2–4), нумерует их `0..n−1` и
только в конце пишет количество в `0x67f10c`.  В кадр входят заголовок
`RESTART GAME` (шрифт 5, по центру, строка 14), пункты (`x 10`, базовая строка
27, шаг 16), подсветка курсора шрифтом 4, опциональная плата `PLATE` и точный
fade `0x682f90`.

Код: `engine/src/ui/restart_render.h/.cpp`; тест —
`engine/tests/test_restart_render.cpp` (CTest `restart_render`, label `quick`).
Канон поведения — `docs/UI_SCREENS.md` §2/§3.8 и `docs/GAME_OVER.md` §4.1/§4.2;
образцы того же класса — `docs/QUIT_RENDER.md` (33, тот же «плата + заголовок +
`x 38/10` + шаг 16»), `docs/DIFFICULTY_RENDER.md` (23), `docs/LOCAL_PLAYERS_RENDER.md`
(21).  Кирпичи общие: атласы `FONTS4` из `FRONTEND/BMP.IDX`
(`render/text_layout`), плата 196×131 через `0x486050`, точные таблицы fade
`0x682f90` (`docs/HUD_LUT.md` §2).

Проверка:

```sh
cmake --build build/sandbox --target gm_restart_render_tests -j 4
./build/sandbox/engine/tests/gm_restart_render_tests
ctest --test-dir build/sandbox -R '^restart_render$' --output-on-failure
python3 regress.py --mirror --json
```

## 1. Что доказано (`0x488850`, docs/UI_SCREENS.md §2/§3.8)

Обработчик занимает `0x488850`..`0x488980` (`ret`), затем `nop` до `0x488990`
(экран 37).  Листинг: `python3 tools/re/disrange.py 488850 488990`, общий
отрисовщик — `485dd0 485e70`.  Все числа в таблице — сайты этих двух функций и
`0x486050`, а не догадка по картинке.

| факт | значение | источник |
|---|---|---|
| плата | `0x488853` вызывает `0x486050` — копию 196×131 `PLATE` из `0x6d2b60` в `0x6865f8` (`rep movs` 0x1913 dword = 25 676 Б); текст пишется в неё, клип 196×131 | `0x488853`, `0x486050`; §3, §9 |
| шаг строки | **16** (`[0x662d58] = 0x10`) | `0x488867` |
| заголовок | `RESTART GAME` (`0x4bd464`), шрифт **5**, `centered=1`, `x 38`, `row 14`, `item -1` → **y 14**, x = (196−width)/2 | `0x488858`..`0x488871`; `0x485de2`..`0x485dfa` |
| `x` пунктов | **10** (`push 0xa`), `centered=0`, `row 27`, шрифт 0 | `0x488886`..`0x488897` и далее |
| шаг/строка пункта | `y = row + item·step` = **27 + 16·item** → 27, 43, 59, 75 | `0x485e4b`..`0x485e5c` |
| число пунктов | **не константа**: `esi` — счётчик выпущенных строк, `0x488979` пишет его в `[0x67f10c]` **в конце**; диапазон §2 — 2..4 | `0x488851`, `0x488979` |
| id пунктов | динамические `0..n−1`: id хранится рядом с меткой в `[0x4bc278]`/`[0x4bc27c]`/`[0x4bc280]`/`[0x4bc284]`; `-1` = «строка не выпущена» | `0x48888f`, `0x4888bb`, `0x488931`, `0x48895c`; `0x4888a6`, `0x4888da`, `0x488950` |
| пункт 0 | `Reload last saved game` (`0x4bd44c`), гейт `[0x4bc274] >= 0` (индекс последнего слота, `-1` = нет) | гейт `0x488876`..`0x488880`; вызов `0x48889c` |
| пункт 1 | `Restart level with same R.P.V.` (`0x4bd42c`), гейт `[0x836ad0] != 0` | гейт `0x4888b0`..`0x4888b7`; вызов `0x4888d0` |
| пункт 2 | `Restart level from HQ` (`0x4bd3fc`), гейт: имя уровня `0x5a48b8` **не** `LEVEL20`/`SECRT1`/`SECRT2` (три вызова `0x416850`) **и** `[0x818650] != 0` | гейт `0x4888e4`..`0x48892d`; вызов `0x488946` |
| пункт 3 | `Quit to title` (`0x4bd3ec`), **без гейта** — последняя строка всегда | `0x48895a`..`0x488971` |
| `rows` | `[0x67f10c] = esi` после последнего пункта: 2..4 | `0x488979` |
| подсветка | `item == [0x68ccf4]` и текст не пуст → шрифт принудительно **4**; сравнивается **id пункта**, а не номер видимой строки | `0x485e0d`..`0x485e19` |
| стрелки/слайдеры/чекбоксы | **нет** ни одного вызова: только `0x486050` и `1 + n` вызовов `0x485dd0` | весь листинг `0x488850`..`0x488980` |
| порядок | плата → заголовок → пункт 0 … пункт n−1 | порядок вызовов |
| `ESC` | **ветки нет**: клавиатурный диспетчер сравнивает `0x1b` только для состояний 9 (`0x48b536`), 5 (`0x48b571`), 2 (`0x48b5d9`), 0x0f (`0x48b6ff`), 0x23 (`0x48b880`), 0x22 (`0x48b973`); у состояния 6 (`0x48d994`) есть только ветка подтверждения, строки `ESC TO CANCEL` в обработчике тоже нет | поиск `cmp bl,0x1b`/`cmp ebp,0x6` по листингу |
| вход в состояние | `0x48b54c` — `Esc` в in-game menu (состояние 9); перед этим `0x48b53f`..`0x48b55c` вызывает `0x487500(0, 0, 320, 200, 0)` — **очистка экрана в чёрный**, затем `[0x4bc440] = 6` и `[0x68cca0] = 0`.  Второй писатель — `0x443af9` (путь конца миссии) | `0x48b531`..`0x48b55c`, `0x443af9` |
| курсор при входе | **не инициализируется** ни в `0x48b54c`, ни в `0x443af9`: `[0x68ccf4]` остаётся от предыдущего экрана | оба сайта входа |

### 1.1. Что делают пункты (модель, вне рендера)

Активация — ветка `cmp ebp,0x6` в диспетчере `0x48d994`, дальше выбор по id из
`0x4bc278`/`0x4bc27c`/`0x4bc280`/`0x4bc284` (docs/GAME_OVER.md §4.1):

| id | что происходит | сайт |
|---:|---|---|
| 0 `Reload` | `[0x4bc274]` (слот) → `0x442340(slot)`; при успехе `[0x4bc274] = -1`, `[0x4bc440] = 5` | `0x48d9e9`..`0x48db6c`, `0x48db82` |
| 1 `R.P.V.` | `push 0` → `0x4428f0(0)` — снимок старта миссии (структура `0x8338c0`) | `0x48d9fd`..`0x48da15` |
| 2 `HQ` | `push 1` → `0x4428f0(1)` — снимок штаба (`0x815440`), счётчик миссий −1 | `0x48da09`, `0x4428f0` |
| 3 `Quit to title` | `[0x4bc440] = 1` (титул), `0x44b830` | `0x48da25`..`0x48da40` |
| любой | id вне `0..n−1` — ничего (`jne 0x48e4ac`) | `0x48da2b` |

Модуль это **не** выполняет: он рисует один кадр и не пишет ни одного глобала.

## 2. Модель кадра (не доказано кодом)

* **Число пунктов и модель счёта.**  Гейты трёх первых пунктов независимы,
  поэтому оригинал может показать любую их комбинацию, а `Quit to title` есть
  всегда; §2/§3.8 фиксируют доказанный диапазон **2..4**.  API принимает одно
  число `items` и берёт **первые `items−1` гейтованных строк + безусловный
  `Quit to title`**:
  `2` → `Reload`/`Quit`; `3` → `Reload`/`R.P.V.`/`Quit`; `4` → все четыре.
  Это ровно порядок выпуска `0x488850` с закрытыми хвостовыми гейтами, и каждый
  из трёх кадров достижим в оригинале (для 2/3 достаточно открытого гейта
  `Reload`).  Комбинации, пропускающие ведущую строку (например
  `R.P.V.`+`HQ`+`Quit`), требуют флагов на каждый пункт и в этот рендер не
  входят (см. §5).
* **`items` вне 2..4 — кламп, не отказ.**  Число строк в оригинале —
  runtime-величина (`esi` → `0x67f10c`), а не константа обработчика; 1 или 5 —
  ошибка вызывающего, а не битый ассет, и кадр остаётся полностью определённым.
  Границы — доказанный диапазон §2.  Тест пинит: `1 → 2`, `99 → 4`
  (0 отличий от кадров `items 2`/`items 4`).
* **Курсор.**  `RestartRenderOptions::cursor` — это `[0x68ccf4]`, **id пункта**
  (`0..items−1`), а не номер текстовой строки.  Сравнение точное, как в
  `0x485e0d`: значение вне диапазона не подсвечивает ничего (в оригинале курсор
  при входе не сбрасывается и может «не попасть» ни в одну строку), `-1` даёт
  кадр без подсветки.  Начальное значение `0` — нейтральное значение API:
  доказанного «первого кадра» у экрана нет.
* **Цвета** — палитра атласа `FONTS4`: заголовок (шрифт 5) → `9b0f0f`
  (155,15,15), строки (0) → `130f0f` (19,15,15), подсветка (4) → `efefef`
  (239,239,239).  Это проверено не только документацией (`docs/MENU_RENDER.md`
  §3), но и пикселями: тест ищет в полосе заголовка `0x9b0f0fff`, в полосах
  пунктов `0x130f0fff`, у подсвеченной строки `0xefefefff`.
* **Плата.**  `PLATE` рисуется в (0,0) в порядке `parse_bmp`, как в соседних
  рендерах; экранный origin копии `0x6865f8` не документирован (`docs/UI.md`
  §8).  Модуль **не** рисует плату неявно: её включает
  `options.background = "PLATE"`; пустая строка — чёрный холст, и именно так
  выглядит вход в состояние 6 (очистка `0x487500(0,0,320,200,0)`).
* **Клип.**  Глифы обрезаются полосой 196×131 (буфер `0x485dd0`).  Самый
  широкий текст — `Restart level with same R.P.V.` (135 px по ink), так что
  клип — страховка.
* **Ориентация глифов.**  `FontGlyph::pixels` row 0 — верхняя строка
  визуального глифа (проверено на `L`/`T`/`V` шрифта 0: у `L` перекладина в
  последней строке, у `T` — в первой), поэтому строка `r` глифа пишется в
  `y + r`, как в соседних UI-рендерах.
* **`rows`/`arrows` в статистике.**  `rows` = 2..4 — ровно то, что обработчик
  пишет в `0x67f10c`; `arrows` = 0 всегда — у экрана нет прокрутки и вызова
  `MENUARRW`; поле оставлено ради общей формы статистики.
* **Fade.**  `fade_lut` — точный путь `0x682f90`: таблицы индекс → индекс,
  поэтому уровень применяется к индексу палитры каждого нарисованного пикселя
  **до** поиска цвета (`render/hud_lut.h::map`).  Уровни 0..15 берутся как
  есть (12..15 — реальные таблицы, они brighten).  Таблица — из памяти
  (`fade_lut_table`) или из дампа 4096 Б (`fade_lut_dump`, `docs/HUD_LUT.md`
  §2); без обоих — текстовый отказ, не «молча без fade».

## 3. API

```cpp
struct RestartRenderOptions {
    std::string background;      // "" = чёрный холст; "PLATE" — плата экрана 6
    int items = 2;               // 0x67f10c: 2..4, кламп; последняя строка — Quit
    int cursor = 0;              // [0x68ccf4], id пункта; вне диапазона — без подсветки
    bool fade_lut = false;
    int fade_lut_level = kHudLutIdentityLevel;  // 11 — тождество, 0..15
    std::string fade_lut_dump;   // 4096-байтовый hud_lut.bin
    const gm::HudLut* fade_lut_table = nullptr; // приоритетнее дампа
};

struct RestartRenderStats {
    int rows = 0;            // 2..4 — выпущенные строки (0x67f10c)
    int ink_pixels = 0;      // уникальные пиксели глифов
    int missing_glyphs = 0;  // символы без глифа (пропускаются)
    int arrows = 0;          // всегда 0: на экране нет MENUARRW
};

bool render_restart(const std::filesystem::path& game,
                    const RestartRenderOptions& options,
                    std::vector<std::uint32_t>& rgba,
                    int& width, int& height,
                    RestartRenderStats* stats = nullptr,
                    std::string* error = nullptr);
```

Константы: `kRestartTitle = "RESTART GAME"`, `kRestartReloadLastSaved`,
`kRestartSameRpv`, `kRestartFromHq`, `kRestartQuitToTitle`,
`kRestartGatedItems[3]`, `kRestartMinItems/MaxItems = 2/4`,
`kRestartItemStep = 16`, `kRestartItemX = 10`, `kRestartItemFirstY = 27`,
`kRestartTitleY = 14`, `kRestartTitleX = 38`, `kRestartPanelName = "PLATE"`,
`kRestartPanelWidth/Height = 196/131`, `kRestartTitleFont/RowFont/SelectedFont =
5/0/4`; хелперы `restart_item_count(int)` (кламп 2..4), `restart_item_y(int)`,
`restart_item_label(int item, int items)`.

Контракт ошибок: любой отказ — текст с префиксом `restart_render:` (пустой
каталог игры, нет/битый `FRONTEND/BMP.IDX`, нет грани 5/0/4, нет/битый/не-8bpp
фон, fade без таблицы и дампа или с нечитаемым дампом).  При ошибке `rgba`
очищается, `width`/`height` = 0, `*stats` обнуляется.  Успех: `width == 320`,
`height == 200`, `rgba.size() == 64000`; вызов только читает установку,
детерминирован и не зависит от текущего каталога.

  `BMP.IDX` только с `FONTS1` (→ «FONTS4»), неизвестный фон `NOSUCH`;
* детерминизм: два одинаковых вызова дают 0 отличающихся пикселей.

## 5. Ограничения

* **Нет ввода и перехода.**  Модуль только рисует кадр: не двигает курсор, не
  обрабатывает Enter/Esc, не пишет `[0x4bc440]`/`[0x68ccf4]`.  Ветка активации
  `0x48d994` и переходы — в `ui/frontend_menu` (`docs/UI_SCREENS.md` §4,
  `docs/GAME_OVER.md` §4.1).
* **Нет гейтов.**  Какие строки реально выпустит `0x488850`, решают
  `[0x4bc274]`, `[0x836ad0]`, `[0x818650]` и имя уровня `0x5a48b8`; рендер
  получает только число строк.  Поэтому он не может нарисовать, например,
  `R.P.V.`+`HQ`+`Quit` (пропущен ведущий `Reload`) — это ограничение
  count-only модели, а не геометрии: шрифты, `x`/`y` и подсветка одинаковы для
  любой комбинации.  Оригинал может выпустить и **одну** строку (`Quit to
  title`), когда все три гейта закрыты; §2 называет доказанный диапазон 2..4, и
  API клампит снаружи в него.
* **Нет звука.**  `updown`/`select` и прочие UI-звуки — `ui/ui_sounds`,
  `docs/UI_SCREENS.md` §8.
* **CLI — есть (срез 7).** `--restart [--restart-items N] [--restart-cursor N]
  [--no-plate] [--png OUT] [--fade-lut N]`: `items=2` —
  `restart: rows=2 cursor=0 ink=585 missing=0 arrows=0`, `items=4`,
  курсор 3 — `rows=4 cursor=3 ink=1132`. CTest `cli_restart`,
  `_four`, `_png`; `cli_fade_lut` (11 = без fade, 13 ≠ без fade).
* **Нет самого перезапуска.**  `0x442340(slot)` (загрузка слота),
  `0x4428f0(0/1)` (снимок миссии/штаба) и `[0x4bc440] = 1` — поведение хоста,
  а не рендера; в модуле они не вызываются.
* **Плата не рисуется неявно.**  Без `background = "PLATE"` кадр — текст на
  чёрном; это осознанный контракт соседних рендеров, а не расхождение с
  оригиналом (в оригинале экран перед композицией очищается в чёрный
  `0x487500`).
* **Шрифты.**  Номера 5/0/4 — из таблицы `text_layout`; если в установке нет
  `FONTS4`, кадр не рисуется (отказ), а не подменяется другим атласом.
* **`ESC` не обрабатывается и в оригинале.**  На экране нет строки
  `ESC TO CANCEL`, потому что её нет и в обработчике; у состояния 6 нет и
  ветки `0x1b` в клавиатурном диспетчере.
