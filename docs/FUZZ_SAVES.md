# Фаззинг сейвов и миров через CLI (`tools/qa/fuzz_saves.py`, M12.1 slice 2)

`tools/fuzz_formats.py` гоняет **Python**-парсеры внутри процесса. Этот
инструмент — его внешний (out-of-process) двойник: он подаёт испорченные сейвы
и миры **настоящему бинарнику** `gunmetal` и судит по тому, что видел
процесс, а не по коду возврата парсера. Так ловятся дефекты доверия, которые
не видны ни golden-тестам, ни Python-матрице: падение по сигналу, зависание,
переполнение кучи/стека, `assert`, сообщение ASan/UBSan.

* **Статус:** инструмент работает; полный прогон на `build/sandbox` —
  **495 кейсов, 0 падений, 0 зависаний, 0 ASan**; ASan-прогон — те же 0.
* **Игра:** только чтение. Все мутанты и выводы — в `/tmp/opencode/fuzz_saves`
  (или иной каталог под `/tmp/opencode`/`/var/tmp`); каталог установки
  инструмент даже не пытается открыть на запись (см. §6).
* **C++ не меняется:** проверяются существующие `--dump`, `--save-out`,
  `--info` (`engine/src/main.cpp`).

## 1. Команды

```sh
python3 tools/qa/fuzz_saves.py --self-test        # 18 инвариантов генератора
python3 tools/qa/fuzz_saves.py --quick            # 44 кейса, ~4 с
python3 tools/qa/fuzz_saves.py                    # 495 кейсов, ~66 с
python3 tools/qa/fuzz_saves.py --json --seed 7    # машинный отчёт, другой корпус
python3 tools/qa/fuzz_saves.py --bin build/asan/engine/gunmetal   # санитайзер
```

Ключи: `--game DIR`, `--bin PATH`, `--seed N`, `--quick`, `--timeout SEC`
(по умолчанию 20 с на один запуск CLI), `--out DIR`, `--keep`, `--json`,
`--self-test`. Сводка всегда начинается строкой

```
fuzz_saves: cases=495 failures=0 hangs=0 asan=0 seed=0 mode=full bin=…
```

Код возврата: `0` — все кейсы завершились штатно; `1` — есть падение,
зависание, сигнал, сообщение санитайзера или неожиданный код; `2` — ошибка
использования (нет бинарника/игры, `--out` вне разрешённых каталогов).

## 2. Что берётся за основу

| цель | файл | как гоняется |
|---|---|---|
| `save0` | `SAVEGAME/saved0.sbt` (243 368 Б) | `--dump FILE` + `--dump FILE --save-out OUT` |
| `save1` | `SAVEGAME/saved1.sbt` (243 368 Б) | то же |
| `world:level0` | `level0.sbw` (254 439 Б) | `--dump FILE` + `--info --game TMP --level fz` |
| `world:dm1` | `dm1.sbw` (1 008 875 Б) | то же |
| `world:level000` | `level000.sbw` (255 570 Б) | то же |
| `level:level0` | `level0.sbt` (127 338 Б) | `--dump FILE` + `--info` (мутант как `fz.sbt`) |

Для `--info` мутант монтируется в приватном каталоге `…/game/` под именем
`fz.sbw` (или `fz.sbt`), а поставочные `fz.sbt`/`fz.sbc`/`fz.sbw` подлинного
уровня подкладываются **симлинками**: читается только то, что нужно
`load_level()` (`engine/src/res/level.cpp`), копий мегабайтных файлов нет.
Так проверяется весь путь `resolve_ci → load_level → parse_sbw → parse_sbt →
parse_sbc`, а не один `parse_sbw`.

Смещения блоков сейва для «блочных» мутаций берутся из вывода `--dump`
самого бинарника (строки `id N count C size S @0xOFF`) — второго парсера
контейнера в инструменте нет. Если проба не удалась, используется лестница
`0x13d / 0x800 / len/2`, и это не считается падением.

## 3. Что мутируется

На каждый файл-основу (в скобках — число кейсов в полном режиме):

| семейство | что делает | full | quick |
|---|---|---|---|
| `trunc` | префиксы длины 1, 2, `len/2 - 1` | 3 | 3 |
| `header` | один байт заголовка: 6 смещений × `00/01/80/ff` (сейв: `+0x00`, `+0x01`, `+0x0c`, `+0x50`, `+0x54`, `+0x13c`; мир/`sbt`: `+0x00..+0x04`, `+0x08`) | ≤24 | 1 |
| `block` | один байт в блоке/таблице: 3 смещения × `7f/ff` | ≤6 | 1 |
| `insert` | dword `0xffffffff` **вставлен** туда, где ожидается id/счётчик/длина (сейв: `+0x13c`, `+0x13d`, `len/2`; мир: `0`, `4`, `len/2`) | 3 | 1 |
| `zero` | счётчик/размер блока обнулён (`u32 = 0` в начале payload) | ≤3 | 1 |
| `random` | 1–8 случайных байт, свой LCG (см. §5) | 48 | 1 |

Итого 495 кейсов в полном режиме (по целям: 86 + 84 + 81 + 81 + 79 + 84) и
44 в быстром. Фактическое число чуть меньше арифметики «6 × 80»: мутация,
которая не меняет байт (значение уже такое), пропускается, а совпавшие по
байтам кейсы дедуплицируются — тратить прогон на копию основы смысла нет.

## 4. Что считается падением

Кейс проходит, только если **каждая** его CLI-фаза:

1. завершилась сама (не убита сигналом) и не превысила `--timeout`;
2. вернула код `0` или `2` — оба задокументированы в `main.cpp` как
   «обработано» / «отказ с сообщением»; любой другой код — находка;
3. не написала в stdout/stderr ни одного из маркеров `AddressSanitizer`,
   `UndefinedBehaviorSanitizer`, `LeakSanitizer`, `runtime error:`.

Падение, зависание и срабатывание санитайзера считаются отдельно
(`failures` / `hangs` / `asan`); код возврата 1 при любом из них. Для
упавших кейсов в отчёт попадают команда, код/сигнал, хвост stderr/stdout
(по 800 символов), sha256 входа и каталог кейса; каталог упавшего кейса
сохраняется целиком (`input.*`, `out.sbt`, `game/`), чтобы reproduс был
буквальным:

```sh
/tmp/opencode/fuzz_saves/137-save0-insert/input.sbt        # вход
build/sandbox/engine/gunmetal --dump \
    /tmp/opencode/fuzz_saves/137-save0-insert/input.sbt
```

Успешные кейсы удаляются сразу (`--keep` оставляет и их). В отчёте по
каждому кейсу остаются цель, семейство, размер, sha256 и коды всех фаз.

## 5. Воспроизводимость

Случайные мутации делает LCG из десяти строк (константы Knuth MMIX,
`A=6364136223846793005`, `C=1442695040888963407`), а не `random`: поток
каждой цели выводится из `sha256("<seed>|<target>")`, поэтому порядок целей
на байты не влияет, а `--seed 7` на той же установке даёт тот же корпус.
Seed печатается в сводке и в JSON. Последовательность LCG закреплена в
`--self-test` (18 проверок: детерминизм потоков, лестница усечений, наличие
всех семейств, запрет записи `--out` в игру/репозиторий и т. п.).

## 6. Куда пишется

* Корень по умолчанию — `/tmp/opencode/fuzz_saves` (tmpfs; успешные кейсы
  удаляются, поэтому чистовой прогон не занимает места).
* `--out` разрешён только внутри `/tmp/opencode` или `/var/tmp`; путь внутри
  каталога игры или в репозитории отвергается с кодом 2 **до** запуска.
* `--save-out` всегда указывает в каталог кейса под `--out`; путь игры в
  качестве выхода не подставляется ни при каких ключах.
* Каталог установки за прогон не меняется: `SAVEGAME/` сохраняет исходные
  mtime/размеры, новых файлов в игре нет.

## 8. Ограничения

1. **Не покрыты UI, сеть, кампания, рендер.** Матрица бьёт только парсеры,
   до которых доводит `--dump`/`--save-out`/`--info`; `--save-load`,
   `--sim`, окно и рендер не запускаются (это отдельные срезы).
2. **Мутации не «умные»:** нет coverage-guidance, нет libFuzzer-корпуса и
   минимизации; обход структуры (таблицы, записи) не перебирается
   по-элементно — только фиксированные смещения и случайные байты.
3. **Зависание режется таймаутом процесса**, а не внутренним watchdog:
   `--timeout` (20 с) убивает группу процессов и помечает кейс `hang`; при
   очень медленной машине возможен ложный `hang`, поэтому число
   фиксируется вместе с таймаутом.
4. **ASan-прогон только если бинарь собран.** Инструмент ищет
   `build/asan/engine/gunmetal` и сообщает `available/current`; в этом
   worktree его не было, поэтому ASan-числа получены бинарником основного
   чекаута на том же коммите `b61c2f2` (исходники идентичны).
5. **Корпус — поставочные файлы.** Других сейвов и миров в установке нет;
   самодельные структуры (8 слотов игрока, блоки без `0xff`, миры с
   нештатными счётчиками) этой матрицей не строятся — их покрывают
   `engine/tests/test_fuzz.cpp` и синтетические тесты.
6. **Отчёт хранит тело только для находок.** Успешные кейсы после прогона
   удалены; чтобы получить тела всех кейсов, нужен `--keep` (полный корпус —
   ~430 МБ, почти весь объём дают три мира и `dm1` в 1 МБ на кейс; поэтому
   умолчание — хранить только находки).
7. **Коды 0/2 — соглашение CLI.** Если `main.cpp` начнёт возвращать другие
   коды для «обработанных» входов, инструмент отметит их как находки; это
   осознанно, чтобы изменение контракта не прошло незамеченным.
