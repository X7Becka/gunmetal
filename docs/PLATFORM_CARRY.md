## 1. Модель

Правило включается только явно (`set_platform_carry(true)`) и добавляет один
шаг на тик. Никакой новой физики: контроллер (`gm::step`) и его зонд пола
остаются единственным источником движения и контакта.

### 1.1. Детект (после шага физики)

После того как тик зафиксировал новое состояние, повторяется зонд пола
контроллера (`ground_contact()` в `player/controller.cpp`): сфера радиуса
`config.radius` из центра нижней сферы капсулы (`pos + (0,0,radius)`) вниз на
`0.05`, фильтр — только полы (`min_normal_z = 0.8`). Отличие одно: попадание
сохраняется, а не превращается в `bool`.

* `SphereHit::dynamic == false` (статика) или промах → панели нет;
* `dynamic == true` → запоминается треугольник: `triangle_index` (порядок
  динамического набора стабилен), ключ `(sector, object, source_poly)`,
  `centroid`, `normal`, `data_normal`. Это и есть «стоит на панели».

Стоять можно только на полу-подобной грани: вертикальная створка двери под
ногами не детектируется (см. §4).

### 1.2. Перенос (до шага физики)

На следующем тике панель ищется в текущем `CollisionWorld::dynamic_triangles()`
рантайма: сначала по сохранённому индексу с проверкой ключа, иначе — по ключу,
ближайший центроид (у веера одной полигоны общий `source_poly`). Затем

```
delta = centroid_now - centroid_then
```

* панель не найдена → забыть (панель ушла из динамики);
* нормали (`normal`, `data_normal`) изменились больше `1e-9` → это поворот
  (`DoorAxis::Rotating`), забыть: перенос — только трансляция;
* `|delta| <= 1e-9` → панель стоит, переносить нечего;
* «игрок всё ещё на ней»: `|dot(feet - centroid_then, normal_then)| <=
  radius + 1e-6` — расстояние по плоскости **запомненной** позы, поэтому
  подъём кабины на 260 за тик это условие не ломает;
* иначе игрок сдвигается на `delta` **до** `gm::step`: шаг начинается на
  текущей позе панели, и собственный контакт с полом контроллера удерживает
  капсулу на ней.

Запомненная поза обновляется на наблюдённую **всегда**, даже если перенос
отменён: иначе отменённый сдвиг накопился бы и прыгнул на более позднем тике.

### 1.3. Отмена переноса

Перенос — обычная трансляция капсулы. Если панель едет в стену или в потолок,
капсула оказалась бы внутри статической геометрии; тогда перенос отменяется
целиком и игрок остаётся на прежней позиции.

Проверка — «половина `depenetrate()`» контроллера: AABB капсулы →
`overlap_aabb` (только статика; динамический набор не участвует, иначе панель
блокировала бы собственный перенос) → `closest_point_on_triangle` для трёх
сфер. Пересечением считается `distance < radius - 1e-6`, т.е. реальное
проникновение, а не штатный зазор `contact_skin = 1e-6`, на котором стоит
любой игрок на полу. Быстрая панель проверяется по пути с шагом `radius/2`
(как субшаги контроллера), поэтому капсула не проскакивает тонкую стену между
тиками.

### 1.4. Когда панель забывается

* зонд после шага не нашёл динамический пол (сход, прыжок, панель ушла);
* `result.jumped` — прыжок сбрасывает панель всегда, даже если в тике взлёта
  панель ещё в пределах зонда;
* панель исчезла из динамики или повернулась;
* `init()`/`respawn()` (новая жизнь) и `set_platform_carry(false)`;
* тик с **другим** `GameRuntime` (`runtime_ != &runtime`): панель прошлого мира
  здесь не ищется.

### 1.5. API

```cpp
void set_platform_carry(bool enabled); // по умолчанию false
bool platform_carry() const;           // правило включено
bool on_platform() const;              // стоял на динамическом треугольнике в прошлом тике
Vec3d platform_delta() const;          // на сколько игрок был перенесён в прошлом тике
```

`set_platform_carry()` — конфигурация, как `set_regen()`: переживает
`init()`/`respawn()`, сбрасывается только сама панель. `platform_delta()` за
прогон суммируется в ход панели (`260`/`−260` в тесте). Пока правило
выключено, зонд не выполняется вообще: старый тик бит-в-бит прежний.

## 2. Что доказано числами

Тест `platform_carry` (реальный `level14`, привязка кабины та же, что в
`lift_collision` — стенд-ин `sec=35 obj=1`, `pos_delta=(0,0,260)`):

```
$ ./build/sandbox/engine/tests/gm_platform_carry_tests
platform_carry up/down: static=52 dynamic=52 suppressed=1 lifts=1 panel_top=760.000000
  settle: feet z=760.000001 on_ground=1 on_platform=1 delta=(0.000000, 0.000000, 0.000000)
  raise: height=65535 panel_top=1020.000000 feet z 760.000001 -> 1020.000001 dz=260.000000 carried=260.000000 on_platform_ticks=30/30 on_ground=1
  lower: panel_top=760.000000 feet z 1020.000001 -> 760.000001 dz=-260.000000 carried=-260.000000 on_platform_ticks=30/30 on_ground=1
  step off: tick 73 feet=(-12.409008, 5816.000000, 760.000000) on_platform=0
  step off end: feet=(269.790992, 5816.000000, -411.682164) on_platform=0 delta_z=-1171.682165 plate_x=-243..-13
  after step off: 30 idle ticks z -411.682164 -> -871.952663 (dz=-460.270499) on_platform=0 carried=0.000000
platform_carry off: rest z=760.000001 after cable raise z=720.69315400084508 dz=-39.306846999154914 on_platform=0 carried=0.000000 panel_top=1020.000000
wall: static=54 dynamic=52 suppressed=1 wall_x=160.0
  settle: feet=(-128.000000, 5816.000000, 760.000001) on_platform=1
  wall: feet x -128.000000 -> 151.996948 (moved=279.996948, max_x=151.996948) blocked_ticks=9 capsule_limit=157.000000 on_platform=0 z=759.915470
platform_carry: ok
```

Что именно закреплено:

1. **Покой не меняется.** Игрок садится на панель за 30 тиков:
   `z = 760.000001` (верх кабины `760`), `on_ground`, `on_platform = true`,
   `platform_delta = 0`. То же число, что у `lift_collision`.
2. **Подъём.** Панель `760 → 1020` (`+260`), игрок `760.000001 →
   1020.000001`, `dz = 260.000000`, сумма `platform_delta().z = 260.000000`,
   `on_platform` на **30/30** тиках, `on_ground` всё время.
3. **Спуск.** Обратно `−260.000000`, снова 30/30, игрок возвращается на
   `760.000001` (в пределах 1e-3 от старта).
4. **Сход.** Шаг вбок (`strafe = 1`, без прыжка): на 73-м тике капсула уходит
   за край плиты (`x = -12.409008 > -13`), `on_platform = false`; за 240 тиков
   игрок падает до `z = -411.682164`, `platform_delta = 0` — переноса больше
   нет, дальше 30 тиков обычного падения (`−460.27`).
5. **Стена.** Панель с `pos_delta = (400,0,0)` едет в статическую стену
   `x = 160`: игрок едет вместе с ней `279.996948` юнита и останавливается на
   `x = 151.996948`; предел неуязвимой позиции `x = 157` (`стена − radius`),
   `max_x` за прогон `151.996948`, 9 тиков перенос отменён
   (`platform_delta().x = 0`), внутрь стены игрок не попал. Панель при этом
   продолжает ехать (перенос отменяется у игрока, а не у панели) и в конце
   уходит из-под ног: `on_platform = false`, `z = 759.915470` — один тик
   свободного падения после того, как плита уехала.
6. **Паритет выключенного правила.** Тот же стенд, тот же подъём на 260, но
   без `set_platform_carry(true)`: `dz = −39.306846999154914` — прежний
   голден `lift_collision` (`−39.306847`), `on_platform = false`,
   `platform_delta = 0`.
7. **Сброс.** `set_platform_carry(false)` очищает панель и дельту
   (`on_platform = false`, `platform_delta = 0`).

## 3. Что здесь гипотеза

* **Порядок в оригинале не снят.** Этот срез — модель, а не декомпиляция:
  Ghidra не использовалась, адресов контакт-резолва в доке нет. Выбранный
  порядок («сдвинуть на дельту панели до шага физики, шаг контроллера
  удерживает на полу») физически корректен и, что важнее, обратно совместим:
  при выключенном правиле числа прежние.
* **Правило отмены — наше.** «Если после переноса есть пересечение со статикой,
  перенос отменяется целиком» — безопасный выбор; в оригинале возможен
  частичный сдвиг/выталкивание. Проверено только то, что игрок не оказывается
  внутри стены.
* **Идентичность панели** установлена по `(sector, object, source_poly)` +
  неизменности нормалей, т.е. предполагается, что панель — жёсткая трансляция
  одного объекта `.sbw`. Для кабины лифта и скользящей двери это верно
  (`MovingCollider`).
* **Вертикальность переноса** не постулируется: переносится весь `delta`
  (у пола он и так вертикальный, у панели с горизонтальным ходом — по её
  ходу). Ограничение — не «только Z», а «только трансляция».

## 4. Ограничения

* **Только перенос.** Поворот панели (`DoorAxis::Rotating`, распашные створки,
  поворотные кабины `basis[3..5] != 0`) не везётся: нормали меняются, панель
  забывается. Хорда дуги поставила бы игрока туда, где панели не было.
* **Только «стоит на панели».** Боковой контакт (створка двери толкает
  капсулу) не моделируется: детект — зонд пола вниз. Это следующий срез, если
  понадобится.
* **Одна панель.** Запоминается один треугольник; две стопки панелей, кабина
  на платформе, тряска/качание не поддержаны.
* **Блокирует только статика.** Динамические объекты (другая панель, створка)
  перенос не отменяют — object-vs-object в движке нет
  (`docs/MOVING_COLLIDERS.md` §6).
* **Шаг дискретизации.** Перенос проверяется с шагом `radius/2`; панель,
  прыгающая больше чем на радиус за тик, может «переставить» игрока на
  несколько радиусов, но сквозь стену он всё равно не пройдёт.
* **Опускание в статический пол.** Если панель уезжает вниз в статическую
  геометрию (пол шахты), перенос блокируется и игрок остаётся на прежней
  высоте. Тест подъёма/спуска использует изолированный мир из одной плиты
  (как `lift_collision` §4), поэтому там спуск чистый.
* **Источник — рантайм.** Панель читается из `runtime.collision()`; отдельная
  копия `CollisionWorld` у вызывающего (как в `lift_collision` §4) не видна.
  Без привязки кабины (`Lift::cabin_sector/cabin_object`) на поставке панели
  нет вовсе — 45/45 лифтов не привязаны (`docs/LIFT_COLLISION.md` §2).
* **Нет вертикального «толчка».** Перенос меняет позицию, но не скорость:
  панель, уехавшая из-под ног, оставляет обычное падение.
