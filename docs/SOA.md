# `.soa` — анимации спрайтовых текстур

**Статус:** семантика закрыта (2026-10-20). Разобраны загрузчик `0x42b81b`,
селектор кадра `0x41de7d`, проверка конца `0x41df86`, специальные режимы
`0x44dc50` и часы движка. Проверены все 104 файла поставки, добавлены
`Soa.timeline()` / `Soa.frame_at(ms)` и инструмент
`tools/re/soa_semantics.py`.

**Коротко:**

| что | результат |
|---|---|
| файлов | **104**: `anims/` 77, `spritani/` 26, `Sobanim/` 1 |
| `mode` | 0 × 23, 1 × 77, 100 × 2, 101 × 1, 102 × 1 |
| `period` | 20…600 (сотые доли секунды); после пересчёта 18…546 тиков |
| длительность | 200…6000 мс (авторская), 1 кадр = 13…1000 мс |
| `declared` | 1…32; у 2 файлов имён меньше, чем объявлено → движок их не грузит |
| загрузятся | **102 из 104** (`copltBLU`, `copltRED` — объявлено 10, имён 6) |
| имена | 839 строк, движок читает 825; 152 кадра ссылаются на имена, которых нет ни в одном архиве |
| `loop` | **мёртвое поле**: читается загрузчиком, но в рантайме не используется |

---

## 1. Формат

`anims/<name>.soa`, `spritani/<name>.soa`, `Sobanim/<name>.soa` — обычный
текст (CRLF), первая строка — 4 числа, далее по одному имени на строку:

```
<mode> <period> <declared> <loop>
<sprite name>
...
```

* `mode` — 0 (один раз), 1 (цикл), 100/101/102 (часы/фильм, см. §6).
* `period` — **длительность всего цикла в сотых долях секунды**, не шаг
  кадра. Движок хранит `period * 91 / 100` тиков (§3).
* `declared` — сколько имён читает загрузчик (1…32), авторитетно.
* `loop` — 0/1, но на поведение не влияет (§7).
* Имя — это спрайт/текстура (`pics/<name>.sbm`, `sprites/<name>.sbm` или
  `flag/<name>.sbm`), а не файл рядом с `.soa` (§9).

Раскладка (CRLF, лишние/недостающие строки, хвостовые пустые строки)
сохраняется в `Soa.to_bytes()`; round-trip 104/104 побайтово.

## 2. Загрузчик `0x42b81b` (доказано)

Вызов: `load(name, kind)`. `kind` задаёт **каталог с .soa** и **каталог с
картинками**:

| `kind` | каталог `.soa` | каталог `.sbm` | кто вызывает |
|---:|---|---|---|
| 0 | `anims\` | `pics\` | грани `.sob`, thing-типы уровней |
| 1 | `spritani\` | `sprites\` | скрипты (эффекты), `0x461f05` |
| 3 | — (реестр `0x76ed40`) | — | вторая текстура грани `.sob`, `0x425315` |
| 4 | `flaganim\` | `flag\` | сейв/флаги, `0x453279`, `0x4682b4` |

Порядок (адреса — VMA):

1. Пустое имя → `0` (`0x42b821`); имя `none` (`0x4a9a1c`) → `0` (`0x42b832`).
2. `kind == 3` — не анимация: `0x414dd0(name)` ищет уже загруженный спрайт и
   возвращает его id (`0x42b84e`).
3. Поиск в таблице анимаций `0x5642c8` (записей `0x5670cc`, шаг `0x5c`) по
   имени `record+0x4c` (`0x42b8cc`). Найденную анимацию переиспользует и
   увеличивает refcount каждого кадра (`0x42b924`).
4. Не больше `0x80` анимаций (`0x42b955`), иначе `0`.
5. Выбор каталога (`0x42b968`…`0x42b9cc`), расширение — `soa` (`0x4a9a40`):
   `spritani` (`0x4a9a44`), `flaganim` (`0x4a9a54`), иначе `anims`
   (`0x4a9a64`); путь собирает `0x40d1a0` (умеет BIGFILE).
6. **Если файла нет** — это не ошибка: `0x424eab(name, kind)` регистрирует
   статический спрайт с тем же именем и возвращает **положительный** id
   (`0x42b9d8`…`0x42b9f4`). Только если и это не удалось — `"Error loading
   %s"` (`0x4a9a6c`) и `0`.
7. Запись: `rec = 0x5642c8 + n*0x5c`, `strncpy(rec+0x4c, name, 16)`
   (`0x42ba21`).
8. `fscanf("%ld")` ×4 → `rec+0x00` mode, `rec+0x04` period, `rec+0x08`
   declared, `[ebp-4]` loop (`0x42ba36`…`0x42baab`); форматы — `0x4a9a80`,
   `0x4a9a84`, `0x4a9a88`, `0x4a9a8c`.
9. Для `kind != 0 && kind != 4` (т.е. для `spritani`) **`loop = 0`**
   принудительно (`0x42bad2`).
10. `period = period * 0x5b / 0x64` = `period * 91 / 100`, знаковое деление
    (`0x42bad9`…`0x42baea`).
11. `declared > 0x20` → файл закрывается, возврат `0` (`0x42baf3`).
12. Цикл `i = 0..declared-1`: `fscanf("%s")` (`0x4a9a90`) → `0x424eab(name,
    kind)` → `word rec+0xc+2i` (`0x42bb1f`…`0x42bb4a`). Если id == 0 —
    `"Error adding %s animation frame"` (`0x4a9a94`), кадр остаётся нулевым,
    загрузка продолжается.
13. Если запись новая (`[entry] == 0`), в неё пишется `loop`
    (`entry+0x6`); для уже существующего имени значение не перезаписывается
    (`0x42bb71`…`0x42bba1`).
14. `fclose`, `n++`, возврат `-n` (`0x42bbaa`…`0x42bbc6`). Отрицательный id —
    это id анимации; положительный — статический спрайт.

Структура записи (база `0x5642c8`, шаг `0x5c`):

| смещение | поле |
|---|---|
| `+0x00` | `mode` (i32) |
| `+0x04` | `period` в тиках (= `period*91/100`) |
| `+0x08` | `declared` (1..32) |
| `+0x0c + 2i` | id спрайта кадра `i` (word, 1-based) |
| `+0x4c` | `char name[16]` |

Реестр спрайтов — база `0x76ed40`, `0x800` записей по 16 байт: `+0` указатель
на загруженную картинку, `+5` `kind`, `+6` `loop`, `+7` `char name[9]`;
refcount — `0x5310c0`, текущий кадр — `0x5350c0` (word). Вторая таблица
`0x55a0c0` (тоже 16 байт) — записи кадров/подстановок `.sub`; в неё
копируется `kind`/`loop` (`0x4233ec`…`0x423404`).

Итого: **`declared` — не подсказка, а точное число читаемых имён**; лишние
строки не читаются, недостающие делают загрузку невозможной (fscanf не
вернёт 1).

## 3. Часы движка: 91 Гц, `period` — сотые доли секунды

Несколько независимых мест задают одну и ту же частоту:

* **Ограничитель кадра** `0x4074e0`: замер `0x40db00` (мс из `GetSystemTime`),
  затем `Sleep(elapsed + 11)` (`0x407504`: `mov ecx,0xb`; импорт `Sleep` —
  `0x841344`). Цель — 11 мс на кадр, т.е. ≈90.9 кадра/с.
* **Счётчик кадров** `0x5a4a74` инкрементируется раз за итерацию главного
  цикла (`0x44bdc0`, вызов из `0x40752d`).
* **Часы уровня** `0x5a46e4` (`0x44d4c0`): по умолчанию
  `delta = 0x5a4a74 - 0x5a46e8`, т.е. **прибавка в кадрах**, а не в мс;
  затем `0x5a46e4 += delta`. Альтернативная ветка — `delta = 91 /
  [0x5a4720]` (фиксированный шаг).
* **Мировые часы** `0x44db80`: аккумулятор `[0x5a4ae8] += delta`, и каждые
  **91** единиц (`0x44db8d: cmp ecx,0x5b`) добавляется одна секунда; далее
  60 с → минута, 60 мин → час. Значит 91 тик = 1 секунда.

Отсюда: `1 тик = 1000/91 ≈ 10.99 мс`, а `period` авторится в **сотых долях
секунды** и переводится в тики ровно тем же коэффициентом `91/100`. Реальная
длительность ≈ `period * 10 мс` (с точностью до одного тика):

```
period_ticks = trunc(period_cs * 91 / 100)
duration_ms  ≈ period_cs * 10
```

Проверка на данных: `period` 20…600 → 0.2…6.0 с; при 32 кадрах `gkscrn`
512 → 5.12 с (160 мс/кадр), `pulsar` 32 → 0.32 с (13 мс/кадр) — правдоподобно.
Версия «period в миллисекундах» дала бы 1.3 мс/кадр у `pulsar` и 4 мс/кадр у
`x.SOA`, что для спрайтовой анимации бессмысленно (см. §13).

`0x9e82d8` — «текущее время» для рендера (читается в `0x41a9b7`, `0x41bdb8`,
`0x41c7df`, `0x9fdf0b`). В `gundx.exe` его **никто не записывает** (все 6
вхождений — чтения); значение обновляет таймер/оверлей движка. Что это те же
единицы, видно по времени спавна: `0x45616e` кладёт в запись спавна
`[0x5a46e4]`, а рендер вычитает это из `0x9e82d8` (`0x41c7f4`, `0x41c83f`).

## 4. Выбор кадра `0x41de7d` (доказано)

Аргументы: `(anim_id, t_start, t_now)`, `t = t_now - t_start`.

```c
rec = &anim[0x5642c8 + (-1 - anim_id) * 0x5c];
t   = t_now - t_start;

if (mode == 0) {
    if (t >= period_ticks) return rec->frame[declared - 1];   // 0x41ded9
} else if (mode != 1) {
    return special_0x44dc50(...);                             // 0x44dc50
}
rem = t % period_ticks;                 // idiv, 0x41dee7
return rec->frame[rem * declared / period_ticks];  // 0x41defb..0x41df01
```

Точная формула для обоих нормальных режимов:

```
frame(t) = (t % period_ticks) * declared / period_ticks      (целочисленно)
```

* `mode 0`: при `t >= period_ticks` — **последний кадр навсегда**
  (`frame[declared-1]`, адрес `rec+0xa+2*declared`).
* `mode 1`: `t % period_ticks`, цикл бесконечный.
* В пределах первого периода формулы **совпадают** — различие только в
  поведении на границе.
* Кадр `i` занимает `period_ticks/declared` тиков; при `declared > period_ticks`
  часть кадров имеет нулевую длительность и не показывается.
* `period` — длительность **всего цикла**, а не шага кадра.

**Граница.** При `t == period_ticks` mode 0 отдаёт последний кадр, mode 1 —
нулевой. Внутри: `t < period_ticks` → `floor(t*declared/period)`.

**Отрицательное время.** В отличие от `.soo` (`0x433e84` прижимает к 0), у
`.soa` клампа нет: отрицательный `t` даёт отрицательный остаток `idiv` и
чтение до массива. `Soa.frame_at()` в `gm/soa.py` на отрицательных мс
бросает `ValueError`, а не воспроизводит OOB.

**Потребитель.** `0x41c78b` (рендер спрайтового объекта): берёт
`id = word[obj+0x20]`, `start = [obj+0x30]`, `now = [0x9e82d8]`, вызывает
`0x41de7d`, затем индексирует таблицу картинок
`0x9e82c8 + (id-1)*16` (`0x41c883`…`0x41c88c`). Если вернулся 0 — кадр
не рисуется (`0x41c802`).

## 5. Время жизни: `0x41df86` и `0x4565c0`

```c
// 0x41df86(id, t_start, t_now): 0 = анимация закончилась
if (id >= 0) return -1;                // это статический спрайт
if (mode != 0) return -1;              // цикл не заканчивается
return (t_now - t_start >= period_ticks) ? 0 : -1;
```

Вызывается раз в кадр из `0x4565c0` (обход таблицы спавнов `0x5ab808`, шаг
`0x2c`): для спрайта с `anim_id != 0` и `mode 0`, у которого истёк период,
объект удаляется (`0x456615`). Спрайты с `mode != 0` автоматически не
удаляются — их убирает только скрипт/уровень.

То есть `mode` — это и цикличность, и время жизни эффекта.

## 6. Специальные режимы 100/101/102 (`0x44dc50`)

Селектор отправляет сюда всё, что не 0/1. Функция вызывается как
`(anim_id, t_start, t_now, rec)` и работает с `rec->frame[0]`:

| mode | файлы | что делает |
|---:|---|---|
| 100 | `DCLOCK1.SOA`, `dclocksm.soa` | рисует в текстуру кадра 0 текущее время `%02d:%02d:%02d` (`0x4ac1c0`), часы/минуты/секунды — `0x5a4adc/e0/e4`; буфер 512 Б (64×8, 6+3 бита), цель — текстура `0x5a4660` |
| 101 | `dclocklg.soa` | то же, но 1024 Б (64×16, 6+4), цель — `0x5a4664` |
| 102 | `FILM.SOA` | видеокадр 128×64 (6+7) через `0x44de30` (буфер `0x5a4aec`, номер кадра `0x5a4ad4`, зацикливание `0x5a4ad0/0x5a4ad8`) |

Во всех трёх `period = 1` (тиков 0), но деления на period нет — режим обходит
формулу. Возвращается всегда `frame[0]`; текстура перерисовывается каждый тик.
Для прочих значений (2…99, <0, >102) `0x44dc50` просто возвращает `frame[0]`
без перерисовки — поэтому `gm/soa.py` для любого `mode ∉ {0,1}` отдаёт кадр 0.

`0x44db80` — счётчик времени суток, который рисуют режимы 100/101: он
прибавляет дельту и каждые 91 тик добавляет секунду (см. §3). То есть
`DCLOCK*` — это настоящие часы в HUD/на панели, а не «анимация с периодом 1»;
`FILM` — проигрывание ролика в текстуру (свой счётчик кадров).

## 7. `loop` — мёртвое поле (доказано)

* Загрузчик читает его (`0x42ba99`) и пишет в запись спрайта `entry+6`
  (`0x42bba1`), но **только** для `kind 0`/`4`; для `spritani` принудительно
  `0` (`0x42bad2`).
* Все обращения к `0x76ed46` в `gundx.exe` — записи/копирования
  (`0x423400` копирует в запись кадра `0x55a0c6`; `0x424f8f/9e` — начальные
  значения; `0x42ab62` — загрузка сейва). **Ни одного чтения** нет, как нет
  и чтений `0x55a0c6`.
* Поведение «один раз / цикл» целиком определяется `mode` (селектор
  `0x41de7d` и `0x41df86` поле `loop` не трогают).

Следствие: у всех 26 `spritani/*.soa` в файле стоит `loop = 1`, но движок
всё равно играет их один раз (`kind 1` → `loop = 0`) — и это правильно, это
эффекты. `loop = 0` в поставке только у четырёх файлов с `mode 100..102`.
Поле, вероятно, осталось от редактора/ранней сборки.

## 8. `declared` против списка имён

Загрузчик читает ровно `declared` имён. Проверка всех 104 файлов:

| файл | declared | имён | что делает движок |
|---|---:|---:|---|
| `anims/copltBLU.soa` | 10 | 6 | **не грузится**: `fscanf` на 7-м имени не вернёт 1 → `0` (`0x42bbce`) |
| `anims/copltRED.soa` | 10 | 6 | то же |
| `anims/watsurf.soa` | 7 | 8 | играет 7, 8-е имя не читается |
| `anims/wrnlit.SOA` | 2 | 3 | играет 2, 3-е (`blank`) не читается |

У `copltBLU/RED` при этом все 6 имён существуют — файл сломан именно
счётчиком, а не картинками. Это единственные две анимации, которые движок
не зарегистрирует.

## 9. Имена → файлы: `pics`/`sprites`/`flag`, BIGFILE, `.sub`

`0x424eab` **не открывает файлы** — он только регистрирует имя в таблице
`0x76ed40` и возвращает 1-based id. Картинка грузится лениво, при первой
отрисовке: `0x423d31` выбирает каталог по `kind` и собирает путь

| kind | строка | адрес |
|---:|---|---|
| 0 | `pics\%s.sbm` | `0x4a8db4` |
| 4 | `flag\%s.sbm` | `0x4a8dc0` |
| 1 | `sprites\%s.sbm` | `0x4a8dcc` |

и вызывает `0x440344` (загрузчик `.sbm`, `gm/sbm.py`). В отличие от `.soo`,
имена `.soa` — это **не** `SOBS/*.sob`, а плоские `.sbm`-картинки из
BIGFILE-архивов. `0x40d1a0` умеет
читать из BIGFILE, поэтому реально это `PICS/SBM.DAT` (1648 записей) и
`sprites/SBM.DAT` (179 записей); `FLAG/` содержит только `.bmp`, ни одного
`flaganim/*.soa` в поставке нет — ветка `kind 4` мертва.

* Имена в индексах BIGFILE обрезаны до 8 символов; поиск регистронезависим
  (Windows). Поэтому `j'sit6a` не находится: в `PICS` есть только `J'SIT6`.
* Пропущенная картинка — **отложенная** ошибка: загрузка `.soa` успешна, при
  отрисовке кадр просто не появится (`0x423e1c`, сообщение о памяти).
* `.sub` (`PICS/textures.sub`, `sprites/sprites.sub`) — таблица
  вероятностных подстановок `вес <база> <вариант>`; загрузчик `0x422f75`
  читает её и `0x42307a`/`0x4232b7` связывают варианты с записями кадров.
  К самой семантике `.soa` она отношения не имеет, но объясняет, почему у
  части имён есть «двойники».

Итог по 104 файлам (проверка `tools/re/soa_semantics.py`):

* **88** файлов полностью резолвятся в «своём» каталоге;
* **12** имеют хотя бы одно имя, которого нет ни в `PICS`, ни в `sprites`
  (мёртвый/вырезанный контент): `J'SITL`, `J'SITR`, `arc-3` (13 из 23),
  `arc-4` (все 23), `arc-zap` (все 23), `pamkel` (29), `power` (6),
  `splash_g` (12), `splash_h` (12), `Puff` (8), `Pulse` (13), `foam` (5);
* **4** имени есть только в «чужом» каталоге: `anims/earthtgt` и `anims/x`
  (кадры в `sprites/`), `spritani/Flash3` и `spritani/PLSBLST` (кадры в
  `PICS/`). `anims/x.SOA` и `anims/earthtgt.soa` — дубликаты `spritani`-версий
  (у `earthtgt` рабочий только `spritani/`), `x.SOA` целиком мёртв — его
  взрывы живут в `spritani/Expl2.SOA`;
* `Sobanim/pulsnuke.SOA` лежит не там: загрузчик для kind 0 ищет
  `anims\pulsnuke.soa`, поэтому файл никогда не найдётся (сработает откат на
  статический спрайт). Рабочая копия — `anims/pulsnuke.SOA`.

## 10. Где используется

| потребитель | адрес | kind | что это |
|---|---:|---:|---|
| грани моделей `.sob` (1-е имя текстуры) | `0x424fd1`, вызов `0x42b81b` на `0x4252d9` | 0 | анимированная текстура грани |
| 5-е имя грани `.sob` (флаг) | `0x4253af` | 0 | тоже резолвится как kind 0 (у флагов — откат в статический спрайт) |
| 2-е имя грани `.sob` (флаг) | `0x425315` | 3 | прямой спрайт без анимации |
| скриптовые спрайты/эффекты | `0x461f05` | 1 | `ADD_SPRITE*` в скомпилированных скриптах |
| thing-типы уровня | `0x47d1c6`, `0x47d1f9` | переменный | две анимации на тип объекта (`%s %s`) |
| флаги (сейв/уровень) | `0x453279`, `0x4682b4` | 4 | `flaganim\`, в поставке нет |
| рендер | `0x41c78b` → `0x41de7d` | — | выбор кадра по времени |
| время жизни | `0x4565c0` → `0x41df86` | — | удаление one-shot спрайтов |
| часы/фильм | `0x44dc50` | — | modes 100..102 |

То есть `anims/*.soa` — это в первую очередь **анимированные текстуры
моделей и thing-типов** (поэтому их имена лежат в `PICS`), а
`spritani/*.soa` — **билборды эффектов** (имена в `sprites`). UI-экраны
(`Brief`, `Compgt*`, `DNA`, `Molec*`, `gkscrn`, `hglass`, `static`, `tek`,
`earthtgt`) — обычные `anims`-анимации, которые вешает на грани модель или
thing-тип; отдельного «UI-режима» у `.soa` нет. `SML`-скрипты ссылаются на
картинки по `f="..."`; имён `.soa` в них нет. `SOB_TABLE` (`.sbt`) —
таблица моделей `.sob`/`.soo` (`0x47c7c0`, `0x42b4e1`); к `.soa` она
отношения не имеет, совпадают только имена некоторых анимаций.

## 11. Инструмент

```
python3 tools/re/soa_semantics.py                # таблица всех 104
python3 tools/re/soa_semantics.py --json
python3 tools/re/soa_semantics.py --check        # exit 1 на «жёстких» ошибках
python3 tools/re/soa_semantics.py --strict       # + предупреждения
python3 tools/re/soa_semantics.py --only baby --frame-at 720
python3 tools/re/soa_semantics.py --self-test    # без установленной игры
```

`--frame-at MS` переводит миллисекунды в тики (`ms*91/1000`) и печатает
кадр так, как его выбрал бы `0x41de7d`. `--check` падает на: parse error,
`declared < 1`, `declared > 32`, нехватке имён, нулевом периоде после
пересчёта (деление на ноль). Отсутствующие картинки — предупреждение (движок
их переживает). `--self-test` проверяет 29 граничных случаев модели, включая
негативные: короткий файл, `declared > 32`, `period = 1`, нулевая длина
кадра, границу периода и спецрежим.

В `gm/soa.py` добавлены (API не менялся):

* `ENGINE_TICK_HZ`, `ticks_at(ms)`, `ms_at(tick)`;
* `Soa.period_ticks`, `.looped`, `.special`, `.short`, `.truncated`,
  `.loadable`, `.engine_names()`;
* `Soa.timeline()` — интервалы кадров в тиках/мс (у one-shot последний
  интервал открытый);
* `Soa.frame_at(ms)` → `Pose(index, name, tick, period_ticks, loop, mode)`
  и `Soa.frame_name_at(ms)`.

## 13. Опровергнутые гипотезы

| гипотеза | почему неверна |
|---|---|
| `period` — шаг одного кадра | формула делит на `period` и умножает на `declared`: это длительность **всего цикла**; кадр = `period/declared` |
| `period` в миллисекундах | загрузчик делает `*91/100`, а часы считают 91 тик в секунду; `period` — сотые доли секунды. В мс у `pulsar` было бы 1.3 мс/кадр |
| `loop` управляет циклом | поле читается, но ни разу не читается рантаймом; цикл задаёт `mode`; для `spritani` загрузчик вообще обнуляет `loop` |
| `mode` бывает только 0/1 | есть 100/101/102 (часы и фильм), `0x44dc50` |
| `mode 0` и `mode 1` по-разному считают кадр внутри периода | формулы идентичны; различие только в `t >= period` |
| `declared` — «подсказка», играются все строки | читается ровно `declared`; лишние строки игнорируются, недостающие ломают загрузку |
| отсутствующий кадр ломает загрузку `.soa` | `0x424eab` только регистрирует имя; `.sbm` грузится лениво при отрисовке |
| отсутствующий `.soa` — ошибка | откат на статический спрайт с тем же именем (`0x42b9d8`) |
| имена кадров — файлы рядом с `.soa` | это спрайты из `PICS`/`sprites`/`flag` (BIGFILE) |
| `period` — «тики» таймера в мс | тик = 1/91 с ≈ 10.99 мс; мс-гипотеза несовместима с `*91/100` |

**Устаревшие формулировки.** В `docs/FORMATS.md` §8 `period` назван «шагом
кадра» и указано «все 77 файлов»; верно: `period` — длительность всего цикла
в сотых секунды, файлов 104. Также `loop` там описан как реальный переключатель
цикла — это не так (§7).

## 14. Остаток

* **Кто пишет `0x9e82d8`.** В `gundx.exe` только чтения; значение приходит от
  таймера/оверлея. Единицы доказаны косвенно (время спавна из `0x5a46e4`,
  ограничитель 11 мс, `cmp 0x5b` в часах). Точное равенство
  `0x9e82d8 == 0x5a46e4` (или смещение) не доказано.
* **Пиксельные форматы mode 100/101/102** (6+3/6+4/6+7) и то, куда именно
  блитится время (`0x47fa50`/`0x47faf0`), разобраны поверхностно.
* **`kind 4` / `flaganim`**: ни одного `.soa`, `FLAG/*.bmp` вместо `.sbm`;
  ветка выглядит унаследованной.
* **`.sub`**: вес 16/20 и точный порядок применения вариантов не закрыты.
* **`loop`**: не используется в `gundx.exe`; возможно, читается редактором
  или другой сборкой (`gun.exe`).
* **Единицы `.soo` — закрыто:** тот же `0x9e82d8`/`0x5a46e4`, т.е. 91-Гц
  тики, а не мс. `docs/SOO.md` исправлен: `frame_at(ms)` переводит мс в тики
  (`ms*91/1000`), длительности в файле — тики.
