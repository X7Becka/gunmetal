## 1. Формат: что доказано

| файл | байт | записей | счётчик | поле-число | EOL |
|---|---:|---:|---:|---|---|
| `PICS/textures.sub` | 2156 | 119 | `119` | `20` × 119 | CRLF |
| `sprites/sprites.sub` | 1336 | 64 | `64` | `16` × 64 | CRLF |
| `sounds/sounds.sub` | 2658 | 161 | нет | нет | CRLF |

Раскладки (доказаны round-trip **6/6** в `gm/small.py`,
`tools/re/sub.py --check`, и подтверждены данными всех трёх файлов):

```
textures/sprites : <count>                      одна строка-счётчик
                   <weight> <from> <to>         ровно count строк
sounds           : <from><TAB><to>              без счётчика и без веса
```

**Важно:** поля — это **имена**, а не числа. `20 alumnm4 alumnm5` значит
«спрайт `alumnm5` рисуется картинкой `alumnm4`» (левое поле — то, что
рисуется; правое — то, что подменяется, `0x42307a`). Поэтому
`SubEntry` хранит `{int weight, std::string from, std::string to}`, а не
`pair<int,int>`: числовых пар в поставочных файлах нет вообще.

Число в начале строки — **не** «вес/частота подстановки» (как предполагалось
в постановке среза): это **класс RAM** из `GlobalMemoryStatus`,
`(dwTotalPhys − 4 000 000) / 1 048 576` (`0x404630`), и строка применяется
только при `ram_class <= weight` (`0x42302c`..`0x423035`, `docs/SUB.md` §3).
На любой современной машине класс — тысячи, поэтому обе таблицы фактически
мертвы; это low-memory fallback. Числа 20 и 16 — классы для машин ≈24 и
≈20 МБ, не вероятность.

Числа по данным (печатает тест, `sub: <файл> ...`):

| файл | declared | pairs | uniq from | uniq to | dup-from строк | dup-to строк | max len from/to |
|---|---:|---:|---:|---:|---:|---:|---:|
| `textures.sub` | 119 | 119 | 103 | 116 | 16 | 3 | 8 / 8 |
| `sprites.sub` | 64 | 64 | 64 | 60 | 0 | 4 | 8 / 8 |
| `sounds.sub` | 0 (нет) | 161 | 161 | 51 | 0 | 110 | 8 / 9 |

`textures.sub`: три имени `to` встречаются дважды (`alumnm5`, `alumnm6`,
`tile1`); `sprites.sub`: пять строк подменяют `Blksmk`
(первая — `Blksmk2b`); `sounds.sub`: 51 разное `to` на 161 строку.

## 2. Модель: решения, которых нет в файле

Всё ниже — **модель**, а не доказанный код игры; каждое решение закреплено
тестом.

1. **Дубли `to` (и `from`) — первая строка побеждает.** `0x42307a` не
   перезаписывает уже отображённое имя и возвращает 0, поэтому из дубликатов
   действует только первый (`docs/SUB.md` §4). `resolve()` идёт по строкам в
   порядке файла и возвращает первое совпадение; `pairs` хранит все строки,
   так что потерю видно (`pairs.size() − unique_to`).
2. **Отсутствующая подстановка — тождество, а не `-1`.** Движок оставляет
   исходную картинку; для `int`-версии `-1` означает только «таблица не
   привязана / индекс вне списка / картинки-замены нет в списке имён».
3. **Ключ сравнения — первые 8 байт, ASCII-верхний регистр** (`sub_key`).
   Слот имени в движке — `char name[9]` + `strncpy(..., 9)` (`0x423244`,
   `0x4233d2`), то есть значимы 8 символов. `.sub` пишет имена строчными, а
   `.sbw` — смешанно (`ALUMNM4` и `comp2a`), поэтому без fold таблицы не
   совпадают: на `level0` точное совпадение даёт **11** имён, fold —
   **15** (оба числа закреплены тестом). Регистронезависимость самого
   `strcmp` в реестре `0x76ed40` не декомпилировалась — это часть модели.
4. **Расхождение счётчика и строк — предупреждение, данные остаются.**
   `load_sub` возвращает `true`, а в `*error` кладёт текст с префиксом
   `warning:`:
   * строк **больше** счётчика — лишние отбрасываются (загрузчик читает
     ровно `count` записей, `0x422fe1`,`0x422fff`), в тексте
     `extra rows are ignored`;
   * строк **меньше** — сохраняются все, в тексте
     `the loader would abort the whole table` (оригинал в этом случае
     отменяет загрузку целиком, `0x422fff`).

   Отказом (`false`) считаются только нечитаемые данные: не `.sub`-путь,
   отсутствующий/пустой файл, нечисловой или отрицательный счётчик/вес,
   строка не той арности, пустое имя, имя длиннее 255 Б (`%s` в буфер 256 Б,
   `0x422ff1`), а также чужой расклад (счётный файл как `sounds` и наоборот).
   При отказе `out` не изменяется.
5. **`from == to`** — валидная, но бесполезная строка: сохраняется, в
   `*error` попадает `from == to (...) is a no-op`. В поставочных файлах
   таких строк нет (тест это проверяет).

## 3. API (`res/sub.h`)

```cpp
enum class SubKind { textures, sprites, sounds };

struct SubEntry { int weight; std::string from, to; };

struct SubTable {
    SubKind kind; std::size_t declared; std::vector<SubEntry> pairs;
    std::string source;
    bool bound; std::size_t bound_size;         // после bind_indices()
    std::vector<int> from_index, to_index;      // параллельно pairs, -1 = нет
};

bool load_sub(const std::filesystem::path&, SubKind, SubTable&, std::string* error);
std::string sub_key(const std::string&);        // первые 8 Б, верхний регистр
bool has(const SubTable&, const std::string&);
std::string resolve(const SubTable&, const std::string&);   // имя → имя
void bind_indices(SubTable&, const std::vector<std::string>& names);
bool has(const SubTable&, int index);
int  resolve(const SubTable&, int index);       // индекс → индекс (§2.2)
bool applies(const SubEntry&, int ram_class);   // ram_class <= weight
```

Индексный слой — это ответ на требование «`resolve(from) → to` по индексам»:
в файле индексов нет, поэтому таблица один раз привязывается к списку имён
(`bind_indices(table, names)` — например, к `SbwHeader::textures`), а дальше
`resolve(table, 28) == 0` уже без строк. `bound`/`bound_size` позволяют
отличить «нет подстановки» (тождество) от «таблица не привязана» (`-1`).

Фильтр `applies()` — про `ram_class`; по умолчанию тест берёт класс `20`
(текстуры) и `16` (спрайты), при `21`/`17` не применяется ни одна строка.

Применение к реальному уровню (`textures.sub` × `level0.sbw`, класс 20):

| величина | число | смысл |
|---|---:|---|
| ссылок на текстуры в `level0.sbw` | 381 | 378 уникальных имён |
| строк, чьё `to` есть в уровне | 16 | 15 различных имён |
| из них с `from` тоже в уровне | 8 | индексная замена разрешима |
| изменённых слотов | 15 | `substituted` (первая строка побеждает) |
| уникальных имён до / после | 378 / 373 | 15 подмен, 10 слияний с существующими |

Контрольные точки: `names[28] == "ALUMNM5"` → `resolve(28) == 0` (`ALUMNM4`);
`resolve(10) == -1`, но `has(10) == true` (`bulkh3` подменяется `bulkh2d`,
которого в списке текстур уровня нет); `resolve(name, 5) == 5`.

Синтетическая половина (без игры) проверяет оба расклада, first-wins, fold,
8-байтовый ключ, `applies` на 12/16/17/20/21/28, привязку с дубликатом имени
и отказы: пустой/пробельный файл, счётчик не число, отрицательный счётчик и
вес, нечисловой вес, 2 и 4 поля в счётном файле, строка через пробел в
`sounds`, имя 256 Б, чужой расклад в обе стороны, расширение не `.sub`,
отсутствующий файл. Предупреждения печатаются текстом (`synthetic short`,
`synthetic long`, `synthetic self`).

## 5. Ограничения

* **Не подключено к загрузчику.** `res/sbw.*` (текстуры уровня) и SBT/SBM
  ничего не знают о `res/sub.*`: таблица читается и привязывается вручную.
  Подключение — отдельный срез (нужен реестр спрайтов `0x76ed40` и момент
  загрузки, `docs/SUB.md` §9 «остаток»).
* **`sounds.sub` в этом билде не загружается вообще.** Единственный
  потребитель `0x40b510` сначала читает `%ld`, первая строка поставки —
  `alarmk\talarmkbig`, `fscanf` возвращает −2, вызывающий результат
  игнорирует (`docs/SUB.md` §5). Файл парсится как данные, но поведения в
  оригинале у него нет.
* **Порядок загрузки не воспроизведён.** «Строка теряется, если `to` ещё не
  зарегистрирован» (`0x42307a`, п.3) зависит от того, что успели
  зарегистрировать `.sob`/`.sbt`; наш `has/resolve` отвечает по таблице, а не
  по состоянию реестра.
* **Регистр — модель** (§2.3): сравниваются folded-ключи, а не `strcmp`
  декомпилированного реестра.
* **21/119 и 5/64 «мёртвых» строк** (имена, которых нет ни в одном SBM-архиве,
  `docs/SUB.md` §1) не проверяются: тест не открывает `PICS/SBM.IDX` и
  `sprites/SBM.IDX`. Проверяется только совпадение с именами конкретного
  уровня.
* **Визуальная сверка** на машине с эмуляцией `ram_class = 12/20` — вне
  рамок read-only репозитория; картинка не проверялась, только данные.
