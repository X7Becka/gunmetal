# Gunmetal — объёмные запросы к статике (`collide_overlap`)

Что здесь: `engine/src/render/collide_overlap.{h,cpp}` — запросы «какие
**статические** треугольники `CollisionWorld` пересекает эта коробка / этот
шар». Три функции: `overlap_triangles`, `overlaps_static`, `overlap_sphere`.
`CollisionWorld` не меняется: модуль читает `triangles()`, `sector_bounds()`,
`is_suppressed()` и `CollideFilter`, а пишет только в свой выходной вектор.

Статус: CTest `collide_overlap` (label `quick`, ~1.6 с) зелёный на
`level0.sbw` и `dm1.sbw`. Паритет с независимым полным перебором: коробки
**240/240** и **240/240**, сферы **120/120** и **120/120**; синтетика
**2000/2000**. Изменены только новые `collide_overlap.{h,cpp}`,
`engine/tests/test_collide_overlap.cpp`, этот документ и две строки в
`engine/CMakeLists.txt` / `engine/tests/CMakeLists.txt`.

---

## 0. Коротко

| что | значение |
|---|---|
| модуль | `render/collide_overlap.{h,cpp}`, ничего не меняет в `CollisionWorld` |
| бокс | `gm::Aabb` из `render/collide.h`: поля `lo`/`hi`, границы включительно; `aabb_of(min, max)` — удобная сборка из углов |
| broad-phase | AABB сектора (один тест на серию подряд идущих треугольников), затем AABB треугольника |
| узкая фаза, бокс | SAT по 13 осям (3 оси коробки, плоскость треугольника, 9 векторных произведений «ось × ребро»), **включительно**: касание гранью/ребром/углом считается пересечением |
| узкая фаза, сфера | точное расстояние «центр–треугольник» (`closest_point_on_triangle`), допуск `1e-9` мировых единиц |
| фильтры | `CollideFilter` целиком: полы/стены/потолки, `backfaces`, `sectors`, плюс подавление `(sector, object)` из `set_dynamic` |
| динамика | **нет**: только статические треугольники (`triangles()`) |
| точность | `double`, мировые единицы `.sbw`; никаких допусков в SAT, кроме включительных сравнений |
| аллокации | только caller-owned выходной вектор; `overlaps_static` не аллоцирует вовсе |
| проверка | `ctest -R collide_overlap`, 1.6 с; паритет с перебором 240/240 на каждом уровне |

## 1. API

```cpp
#include "render/collide_overlap.h"

// Точный тест «треугольник × коробка» (SAT, 13 осей, включительно).
bool triangle_intersects_box(const Triangle& triangle, const Aabb& box);

// Треугольник в пределах radius от centre (расстояние до поверхности).
bool triangle_within_sphere(const Triangle& triangle, Vec3d centre, double radius);

// Индексы статических треугольников, пересекающих коробку (по возрастанию).
bool overlap_triangles(const CollisionWorld&, const Aabb&, std::vector<std::uint32_t>& out,
                       const CollideFilter& = {}, std::string* error = nullptr);
std::vector<std::uint32_t> overlap_triangles(const CollisionWorld&, const Aabb&,
                                             const CollideFilter& = {});

// Есть ли хоть один такой треугольник (ранний выход, без аллокаций).
bool overlaps_static(const CollisionWorld&, const Aabb&, const CollideFilter& = {},
                     std::string* error = nullptr);

// Индексы статических треугольников в пределах radius от centre.
bool overlap_sphere(const CollisionWorld&, Vec3d centre, double radius,
                    std::vector<std::uint32_t>& out, const CollideFilter& = {},
                    std::string* error = nullptr);
std::vector<std::uint32_t> overlap_sphere(const CollisionWorld&, Vec3d centre, double radius,
                                          const CollideFilter& = {});
```

Семантика:

* индексы — в `world.triangles()`, в порядке сборки (sector-major, затем
  порядок полигонов); вектор очищается до валидации, поэтому после отказа в нём
  не остаётся старых чисел;
* `overlaps_static` отвечает ровно `!overlap_triangles(...).empty()`, но
  останавливается на первом попадании;
* фильтр `CollideFilter` применяется целиком: класс поверхности считается по
  `data_normal`/обходу (`surface_of`), `sectors` ограничивает список секторов,
  `backfaces` на объёмный запрос не влияет (объём двусторонний по построению, но
  поле остаётся в структуре и просто не участвует);
* статические треугольники подавленной пары `(sector, object)` пропускаются —
  ровно так же, как в `raycast`/`overlap_aabb`: мир уже объявил их устаревшими
  (`docs/DOOR_COLLISION.md`).

Отказы (возврат `false`, `out` пуст, `error` — одна строка):

| вход | текст |
|---|---|
| пустой мир | `overlap_triangles: empty world: nothing to query` |
| `min > max` по любой оси | `overlap_triangles: box is empty: min > max on some axis` |
| NaN/inf в углах коробки | `overlap_triangles: box is not finite: min/max must be finite` |
| NaN/inf центр сферы | `overlap_sphere: sphere centre is not finite` |
| NaN/inf радиус | `overlap_sphere: sphere radius is not finite` |
| `radius < 0` | `overlap_sphere: sphere radius is negative` |

Вырожденная коробка (`lo == hi` по оси) — **валидна**: это плоскость/отрезок/точка.
Именно поэтому «точечный» запрос делается коробкой `±1e-3` вокруг точки, а не
`±0` (см. §2.3).

## 2. Модель и точность

### 2.1. Broad-phase

1. Если у мира есть подавленные пары — треугольник с такой парой сразу
   пропускается.
2. `filter.allows(triangle)` (класс поверхности + список секторов).
3. AABB сектора против коробки запроса — **один раз** на серию подряд идущих
   треугольников одного сектора: массив треугольников sector-major, так что
   сектор — непрерывный диапазон. (Если бы порядок когда-нибудь перестал быть
   sector-major, запрос остался бы верным, просто пересчитывал бы тест чаще.)
4. AABB треугольника против коробки запроса.
5. Точный тест.

Сетка `CollideGrid` **не переиспользуется**: она индексирует треугольники для
обхода лучом (3D-DDA) и не умеет обход коробкой. Чтобы ей воспользоваться,
пришлось бы писать второй обход (перебор ячеек AABB) и доказывать его
эквивалентность — выигрыш при 3–12 тысячах треугольников не стоит новой
поверхности ошибок. См. §4.

Для сферы broad-phase — AABB шара (`centre ± radius`), поэтому треугольник, чей
AABB далеко, до точного расстояния не доходит.

### 2.2. Узкая фаза: треугольник × коробка (SAT)

Классический тест разделяющих осей в системе координат коробки (центр `c`,
полуразмеры `h`), вершины треугольника `v0, v1, v2` сдвинуты на `-c`:

1. **3 оси коробки.** Если проекции всех вершин на ось лежат вне `[-h, h]` —
   коробка разделяет.
2. **Плоскость треугольника.** `n = cross(v1-v0, v2-v0)`,
   `d = dot(n, v0)`, радиус опоры коробки `r = |n.x|·h.x + |n.y|·h.y + |n.z|·h.z`.
   Если `|d| > r` — разделяет. Нормаль не нормируется: сравнение
   масштабно-инвариантно. У вырожденного (нулевой площади) треугольника `n = 0`,
   и ось плоскости ничего не разделяет — это безопасно.
3. **9 осей «ось коробки × ребро».** Для каждого из трёх рёбер и трёх осей
   `a = cross(unit_axis, edge)`; нулевой `a` (ребро параллельно оси) пропускается;
   иначе проекции вершин против радиуса `|a.x|·h.x + |a.y|·h.y + |a.z|·h.z`.

Границы **включительные** (`>` / `<`, а не `>=` / `<=`): треугольник, который
только касается грани, ребра или угла коробки, считается пересекающимся. Это
согласовано с `Aabb::contains()`/`overlaps()` в `render/collide.h`, где граница
тоже внутри.

Численная устойчивость: центр и полуразмеры считаются как
`lo*0.5 + hi*0.5` и `hi*0.5 - lo*0.5`, поэтому даже коробка у предела `double`
не даёт переполнения `lo + hi`.

### 2.3. Узкая фаза: треугольник × шар

`distance(centre, closest_point_on_triangle(centre, triangle)) <= radius + 1e-9`.
Треугольник — бесконечно тонкий лист, как и во всём модуле: шар «внутри»
замкнутой комнаты видит её стены (расстояние до поверхности), а не «объём
снаружи». Допуск `1e-9` нужен, чтобы точка, лежащая на грани **точно**, попала
в шар радиуса 0: `closest_point_on_triangle` восстанавливает точку внутри
треугольника с ошибкой ~1e-13 при координатах ~1e4. Тот же допуск (1e-9)
используется в эталонном переборе, поэтому паритет не зависит от него.

Поэтому «точечный» запрос коробкой делается как `±1e-3`: у коробки `±0` ось
плоскости требует `|d| == 0` бит-в-бит, а `d` для центра масс треугольника —
это результат округления (`~1e-10`), и запрос честно, но бесполезно отвечал бы
«нет». Это ограничение SAT с включительными границами, а не ошибка: сама
коробка `±0` валидна и просто описывает точку.

### 2.4. Эталон в тесте — независимый алгоритм

Паритет проверяется не копией SAT, а другим решением той же задачи: контакт
есть, если

* (a) вершина треугольника внутри коробки, **или**
* (b) угол коробки лежит на треугольнике (расстояние до плоскости `<= 1e-9` и
  барицентрически внутри проекции), **или**
* (c) ребро треугольника пересекает коробку (slab-клип отрезка), **или**
* (d) ребро коробки пересекает треугольник.

Полнота: если плоскость не рассекает коробку, треугольник может её касаться
только вершиной внутри коробки — (a). Если рассекает, сечение плоскости и
коробки `P` — выпуклый многоугольник в плоскости треугольника; из `T ∩ P ≠ ∅`
следует либо вершина `T` в коробке (a), либо вершина `P` (это пересечение ребра
коробки с плоскостью) внутри `T` (d), либо ребро `T` пересекает границу `P`,
то есть входит в коробку (c). Для шара эталон — расстояние по трём рёбрам плюс
высота до плоскости, если проекция внутри (другой алгоритм, чем региональный
`closest_point_on_triangle`).

**Опровергнутая гипотеза (стоила отладки).** Первая версия эталона искала
пересечение «ребро коробки × треугольник» через Мёллера–Трамбура. На `level0`
она дала одно ложное срабатывание: ребро коробки лежало **в плоскости**
треугольника (обе вершины ребра на расстоянии 0 от плоскости), детерминант был
не нулём, а шумом округления `7.3e-12 > 1e-12`, и тест «попал» в точку далеко
за пределами треугольника. Исправление: пересечение ищется по **расстояниям
концов до плоскости** (устойчиво к параллельности), а случай «отрезок лежит в
плоскости» уходит в 2D-тест «отрезок × треугольник» с проекцией по
наибольшей компоненте нормали. После этого паритет стал 240/240.

## 3. Тест

`engine/tests/test_collide_overlap.cpp`, CTest `collide_overlap`, label `quick`,
~1.6 с. Что проверяется:

* синтетика: 2000 SAT-случаев против эталона §2.4 + ручные граничные случаи;
* паритет коробок 240/240 на `level0` и `dm1` (векторное равенство, не размер);
* паритет сфер 120/120 на обоих уровнях;
* известные запросы: origin, спавн (пустая комната), пустота, весь мир
  (`== triangle_count()`), фильтры полы/стены/потолки (для `level0` ещё и
  сверка с 558/2082/522), ограничение одним сектором, точечная коробка, шары
  r=0/1/100, шар в пустоте, шар на весь мир;
* `overlap_aabb` — надмножество точного ответа; `overlaps_static` совпадает с
  `!empty()`; удобные overload'ы возвращают тот же вектор;
* подавление пары `(sector, object)`;
* отказы: `min > max`, NaN/inf коробки, `radius = −1`, NaN/inf центра и
  радиуса, пустой мир — текст ошибки, пустой выход;
* детерминизм повторного запроса.

Без установленной игры реальная часть печатает «not installed, skipped» и не
падает: синтетика и отказы проверяются всегда.

## 4. Ограничения

1. **Только статика.** Динамический набор (`CollisionWorld::set_dynamic`,
   движущиеся створки/кабины) не возвращается: у него свои индексы и своя
   жизнь. Для него есть `MovingCollider::raycast/sphere_cast`
   (`docs/MOVING_COLLIDERS.md`); объёмного запроса по динамике пока нет.
2. **Нет объект-объект и выталкиваний.** Модуль отвечает «что задето», но не
   «на сколько и куда вытолкнуть»: нет глубины проникновения, нет
   `contact normal`, нет `sweep`/CCD. Это следующие срезы `M6.4.1`.
3. **Нет `sweep`.** Объём — статическая коробка/шар в текущей позе. Движение —
   это `raycast`/`sphere_cast` (луч/сфера по траектории), которые уже есть в
   `CollisionWorld`.
4. **Не подключено к рантайму.** Ни `main.cpp`, ни игрок/AI/двери этот модуль
   пока не вызывают: это библиотечный слой с тестом, как `collide_grid` до
   интеграции.
5. **Ускорение только секторами и AABB треугольника.** Для 3–12 тысяч
   треугольников запрос — линейный проход с дешёвыми тестами (AABB сектора и
   AABB треугольника отсекают почти всё). Если понадобится объёмный запрос в
   горячем цикле на всех 36 уровнях, следующий шаг — переиспользовать CSR-сетку
   `CollideGrid` (нужен обход ячеек по AABB, сейчас его нет) или строить
   BVH; до измерений этого не делалось.
6. **Треугольники — листы.** Шар/коробка «внутри» замкнутой геометрии видят её
   поверхности; «замкнутый объём» и «солид» здесь не моделируются (так же, как
   в `sphere_cast`).
7. **`backfaces` не влияет** на объёмный запрос: пересечение объёма с
   двусторонним листом не зависит от стороны. Поле остаётся в `CollideFilter`,
   потому что это общий тип фильтра.
8. **Порядок — порядок сборки.** Индексы возрастают, при равных условиях
   никакой «ближайший» не выбирается: это множество, а не hit.

```sh

cmake --build build/sandbox --target gm_collide_overlap_tests -j 4
```
