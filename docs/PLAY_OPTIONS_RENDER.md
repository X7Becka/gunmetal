# Рендер экрана 32 `PLAY OPTIONS` (`engine/src/ui/play_options_render.h`)

Срез 20 пункта `M8.8`: один кадр экрана **32** фронтенда (`gundx.exe`,
ImageBase `0x400000`) в RGBA-буфер 320×200. Модуль без состояния — рисует то,
что ему передали в `PlayOptionsRenderOptions`, и отдаёт числа (`rows`, `checks`,
`sliders`, `arrows`, `ink_pixels`, `missing_glyphs`). Шрифты, метрики и атласы —
из `render/text_layout` (`FONTS4` в `FRONTEND/BMP.IDX`), точный fade — из
`render/hud_lut`. Ничего не измеряется заново.

Код: `engine/src/ui/play_options_render.h/.cpp`; тест —
`engine/tests/test_play_options_render.cpp` (CTest `play_options_render`, label
`quick`). Соседние срезы — `SOUND_OPTIONS_RENDER.md` (11),
`MATCH_SETUP_RENDER.md` (27), `MOUSE_SETUP_RENDER.md` (22), `MENU_RENDER.md`
(общая механика `0x485dd0` и виджетов), `CONFIG.md` §3.1 (биты `play_flags`).

## 1. API

```cpp
#include "ui/play_options_render.h"

gm::PlayOptionsRenderOptions options;    // defaults = .data/.bss движка (§2.5)
options.cursor = 2;                      // [0x68ccf4], id пункта 0..7
options.flags = 0x10400;                 // [0x5a46f8], биты kPlayOptionsFlag*
options.dynamic_camera = 2;              // [0x4aac8c], кламп 0..2
options.in_game = false;                 // [0x6e89c0] != 0
options.background = "PLATE";            // "" = чёрный холст

std::vector<std::uint32_t> rgba;         // 0xRRGGBBAA
int width = 0, height = 0;
gm::PlayOptionsRenderStats stats;
std::string error;
if (!gm::render_play_options(game, options, rgba, width, height, &stats, &error)) {
    // error: текст с префиксом "play_options_render: "
}
// width=320 height=200, rgba.size()==64000
// stats: rows=8 checks=6 sliders=0 ink_pixels=2765 missing_glyphs=0 arrows=0
```

| Поле `PlayOptionsRenderOptions` | По умолчанию | Смысл |
|---|---|---|
| `std::string background` | `""` | запись `FRONTEND/BMP.IDX`, рисуется в (0,0); пусто — чёрный холст |
| `int cursor` | `0` | `[0x68ccf4]`, **id пункта** 0..7; вне нарисованных id ничего не подсвечивает (`-1` — кадр без подсветки) |
| `int flags` | `0` | `[0x5a46f8]` (`.bss` = 0; поставочный CFG — `0x10400`); читаются только биты `kPlayOptionsFlag*`, маска `0x11D400` |
| `int dynamic_camera` | `1` | `[0x4aac8c]` (`.data` = 1), кламп 0..2 = None/Some/Full |
| `bool in_game` | `false` | `[0x6e89c0] != 0`; `true` — строка `DYNAMIC CAMERA: HUMAN` шрифтом 8 |
| `bool fade_lut` | `false` | точный fade `0x682f90` по палитровым индексам |
| `int fade_lut_level` | `11` | 0..15; 11 — тождество, 12..15 светлеют |
| `std::string fade_lut_dump` | `""` | дамп 4096 Б (`load_hud_lut`) |
| `const HudLut* fade_lut_table` | `nullptr` | готовая таблица, приоритетнее дампа |

Публичные помощники (нужны тесту и будущему CLI): `play_options_item_row(item)`,
`play_options_item_y(item)`, `play_options_second_y(item)`,
`play_options_item_x(item)`, `play_options_flag_bit(item)`,
`play_options_checked(item, flags)`, `play_options_check_y(item)`,
`play_options_camera(int)`, `play_options_label(item, options)`,
`play_options_second_label(item)`, `play_options_item_font(item, options)`.

`PlayOptionsRenderStats`: `rows` (`0x67f10c`: всегда 8), `checks` (рамка
`CHECK`/`NOCHECK`: всегда 6 — по одной на пункт 0..5, в обоих состояниях),
`sliders` (`SLIDE`/`KNOB` на этом экране нет — всегда 0), `arrows` (`MENUARRW`
нет — всегда 0), `ink_pixels` (уникальные пиксели глифов и спрайтов; фоновая
плата не считается — как в `menu_render`/`sound_options_render`),
`missing_glyphs` (байты без глифа, не фатальны).

Контракт буфера: при отказе `rgba` очищается, `width`/`height` = 0,
статистика обнуляется; `stats`/`error` могут быть `nullptr`. Функция только
читает установку, детерминирована, не зависит от текущего каталога.

## 2. Доказано (листинг + данные)

Инструмент: `python3 tools/re/disrange.py`, данные — `tools/re/exelib.py`.
**Обработчик — `0x486170`**: таблица `0x4883d8`, id 32 → вход 27 (`0x488444`)
= stub `0x487ed4` (`call 0x486170`), `ret` на `0x486390`; пролога и локалов
нет, других вызовов рисования тоже.

### 2.1. Пролог, заголовок

| Факт | Где |
|---|---|
| `rows = 8` (`0x67f10c`) | `0x486170` |
| `step = 15` (`0x662d58`) | `0x48617a` |
| копия `PLATE` 196×131 в `0x6865f8` | `0x486184` → `0x486050` (`rep movsd 0x1913`) |
| заголовок: шрифт 5, текст `0x4bd040`, `centered=1`, `x=13`, `row=11`, `item=-1` | `0x486189`..`0x486198` |

`0x485dd0` (`0x485dd0`..`0x485e70`) при `item == -1` считает `row` абсолютным
`y`, при `centered=1` заменяет `x` на `(196 - width)/2`, а шрифт 4 подставляет
только если `item == [0x68ccf4]` **и** вызывающий передал шрифт 0
(`0x485e0d`..`0x485e19`). Поэтому заголовок стоит на **строке 11**, а текст
пишется в копию платы — **клип 196×131**.

### 2.2. Строки, `x` и `y`

`y = row + 15*item`; вторые строки пунктов 2/3/4 передают свой `row` с тем же
`item`.

| item | текст | VA | x | row | y |
|---:|---|---|---:|---:|---:|
| 0 | `Skip Empty Weapons` | `0x4bd02c` | 25 | 21 | 21 |
| 1 | `Skip Deadly Weapons` | `0x4bd018` | 25 | 17 | 32 |
| 2 | `Switch Weapon To Picked-Up` | `0x4bcffc` | 25 | 13 | 43 |
| 2 | `Ammo` | `0x4bcff4` | 25 | 21 | 51 |
| 3 | `Auto Switch Weapons When` | `0x4bcfd8` | 25 | 15 | 60 |
| 3 | `Ammo Depleted` | `0x4bcfc8` | 25 | 23 | 68 |
| 4 | `Don't Auto-Target when` | `0x4bcfb0` | 25 | 18 | 78 |
| 4 | `Looking` | `0x4bcfa8` | 25 | 26 | 86 |
| 5 | `Mouse Cheating` | `0x4bcf98` | 25 | 20 | 95 |
| 6 | `Dynamic Camera: None/Some/Full` | `0x4bcf38`/`0x4bcf50`/`0x4bcf68` | 13 | 15 | 105 |
| 6 | `DYNAMIC CAMERA: HUMAN` (только при `[0x6e89c0] != 0`) | `0x4bcf80` | 13 | 15 | 105 |
| 7 | `Done` | `0x4bceb4` | 13 | 9 | 114 |

Адреса вызовов `0x485dd0`: `0x4861cc` (item 0), `0x486202` (1), `0x486238` и
`0x48624f` (2), `0x486283` и `0x48629a` (3), `0x4862d0` и `0x4862e7` (4),
`0x48631d` (5), `0x486371` (6, ветки камеры `0x48632e`..`0x48636f`), `0x486388`
(`Done`).

Камера (`0x486322`..`0x486371`): при `[0x6e89c0] != 0` — текст `0x4bcf80`
шрифтом **8** (короткий `jmp` на общий вызов); иначе по `[0x4aac8c]`:
0 → `0x4bcf38`, 1 → `0x4bcf50`, остальное → `0x4bcf68`, шрифт 0. Именно
поэтому строка в игре не подсвечивается: шрифт 8 не равно 0, и подстановки
шрифта 4 не происходит.

### 2.3. Чекбоксы

`0x4833e0(dst, 196, value)`: при ненулевом `value` копируется 16-строчный
`CHECK` 8×16 в `dst`, при нуле — 8-строчный `NOCHECK` 8×8 **на 8 строк ниже**
(`lea ecx,[ecx+edi*8]` в `0x483403`); индекс палитры 0 прозрачен
(`test dl,dl; je` в `0x483413`). Аргумент — адрес внутри копии платы, поэтому
`dst - 0x6865f8 = y*196 + x`:

| item | аргумент `0x4833e0` | x | anchor y | вызов |
|---:|---|---:|---:|---|
| 0 | `0x686ffc` | 16 | 13 | `0x4861b5` |
| 1 | `0x687868` | 16 | 24 | `0x4861eb` |
| 2 | `0x6880d4` | 16 | 35 | `0x486221` |
| 3 | `0x688dd8` | 16 | 52 | `0x48626c` |
| 4 | `0x689ba0` | 16 | 70 | `0x4862b9` |
| 5 | `0x68a8a4` | 16 | 87 | `0x486306` |

Все шесть якорей ровно на 8 строк выше своей подписи, то есть низ рамки всегда
на строке текста. Из-за шага 15 и высоты `CHECK` 16 прямоугольники соседних
пунктов перекрываются по строкам (например, `CHECK` пункта 1 занимает 24..39,
а `NOCHECK` пункта 0 — 21..28), поэтому порядок отрисовки важен: обработчик
рисует рамку и текст каждого пункта подряд, и рамка следующего пункта ложится
поверх предыдущей. Модуль воспроизводит этот порядок.

### 2.4. Биты `[0x5a46f8]`

| item | бит | опция |
|---:|---:|---|
| 0 | `0x00400` | Skip Empty Weapons |
| 1 | `0x04000` | Skip Deadly Weapons |
| 2 | `0x08000` | Switch Weapon To Picked-Up Ammo |
| 3 | `0x10000` | Auto Switch Weapons When Ammo Depleted |
| 4 | `0x01000` | Don't Auto-Target when Looking |
| 5 | `0x100000` | Mouse Cheating |

Чтение — `and eax,imm` перед каждым вызовом (`0x48619d`, `0x4861d1`,
`0x486207`, `0x486254`, `0x48629f`, `0x4862ec`). Клики `0x48d816`, `0x48d83c`,
`0x48d862`, `0x48d888`, `0x48d8ae`, `0x48d8d4` ксорят бит сразу в `0x5a46f8` и
`0x5a46fc` (обе копии игроков), `0x48d8fa` — камера: при `[0x6e89c0] != 0`
выходит, иначе `[0x4aac8c] = ([0x4aac8c]+1) mod 3`. Маска `0x11D400` в
`0x44d68c` подтверждает, что других битов у слова нет (`docs/CONFIG.md` §3.1).

### 2.5. Значения по умолчанию

| поле | до загрузки CFG | где |
|---|---|---|
| `0x5a46f8` / `0x5a46fc` | `0` | `.bss`; в поставочном `GUNMETAL.CFG` — `0x10400` (пункты 0 и 3 включены) |
| `0x4aac8c` (камера) | `1` | `.data`; в поставочном CFG — 1 (`Some`) |
| `0x6e89c0` (идёт игра) | `0` | `.bss` |
| `0x68ccf4` (курсор) | `0` | `.bss`; вход в состояние 32 (`0x48d005`) его не пишет |

### 2.6. Ассеты, цвета, fade

`FRONTEND/BMP.IDX` (`docs/UI_SCREENS.md` §9): `PLATE` 196×131, `CHECK` 8×16,
`NOCHECK` 8×8, `FONTS4` 512×168 (грани 5/0/4/8). Размеры проверяются при
загрузке; расхождение — текстовый отказ.

Цвета — из палитры атласа: заголовок (шрифт 5) — (155,15,15) тёмно-красный,
пункты (шрифт 0) — (19,15,15) тёмно-серый, подсветка (шрифт 4) — (239,239,239)
белый, строка камеры в игре (шрифт 8) — (75,75,75) серый
(`docs/MENU_RENDER.md` §3; грани проверены по палитре `FONTS4`). `PLATE` и
чекбоксы используют собственные палитры BMP; индекс 0 — прозрачный ключ
спрайтов.

Точный fade `0x682f90`: каждый нарисованный палитровый индекс проходит через
`render/hud_lut.h::map(level, index)` **до** выборки цвета (как в
`sound_options_render`/`mouse_setup_render`). Таблица — готовая
(`fade_lut_table`) или из дампа 4096 Б (`fade_lut_dump`, `docs/HUD_LUT.md` §2);
без обеих — текстовый отказ, а не «молча без fade».

## 4. Модель (не доказано кодом)

* **Плата на экране.** Оригинал копирует `PLATE` в `0x6865f8` как буфер
  композиции; куда этот буфер блитится на 320×200, в документации не
  зафиксировано (`docs/MENU_RENDER.md` §2). Поэтому `PLATE` не рисуется
  неявно: `background` — выбор вызывающего, по умолчанию чёрный холст. Текст и
  спрайты клипаются к 196×131 — это доказано адресами назначения.
* **Значения по умолчанию** `flags = 0` взяты из `.bss`, а не из поставочного
  CFG (`0x10400`): модуль не читает конфиг, как и соседние рендереры. Оба числа
  вынесены в константы (`kPlayOptionsFlagsBssDefault`,
  `kPlayOptionsFlagsShippedCfg`).
* **Курсор по умолчанию 0** — `.bss`; вход в состояние 32 его не пишет, поэтому
  «первый кадр» зависит от предыдущего экрана. API даёт нейтральные 0.
* **Шрифт 8** для строки `DYNAMIC CAMERA: HUMAN` — вывод из `push 0x8` в ветке
  `0x48632e`; что игра запускается именно так, проверено листингом (в игре тест
  не запускается).
* **Цвета** (155,15,15)/(19,15,15)/(239,239,239)/(75,75,75) — палитра `FONTS4` и
  `docs/MENU_RENDER.md` §3; сами значения не пересчитываются, а берутся из BMP.

## 5. Ограничения

* Нет ввода: шесть переключателей (`0x48d816`..`0x48d8e9`), цикл камеры
  `0x48d8fa`, `Esc`/выход, навигация курсором и таблица диспетчера пунктов
  `0x48e8f8` не реализованы и не читаются.
* Нет звука: UI-звуки (`docs/UI_SOUNDS.md` §3.2) не проигрываются.
* Нет `GUNMETAL.CFG`: `0x1CC`/`0x1D0` (биты) и `0x1C8` (камера) не читаются и не
  пишутся; значения из `options` **никуда не применяются** — это только
  пиксели кадра. Вторая копия `0x5a46fc` и копия в структуру игрока (`0x44d68c`)
  не моделируются.
* **CLI — есть (срез 21).** `--play-options [--play-options-cursor N]
  [--play-options-flags HEX] [--play-options-camera N] [--play-options-in-game]
  [--no-plate] [--png OUT] [--fade-lut N]`: по умолчанию (камера 1 = `Some`,
  `.data`-значение) `play_options: rows=8 sliders=0 checks=6 cursor=0
  arrows=0 ink=2765 missing=0`; `--play-options-flags 0xff`, камера 2,
  курсор 7 — `ink=2737`; `--play-options-in-game` — `ink=2854`. CTest
  `cli_play_options*`; `cli_fade_lut` (11 = без fade).
* `sliders` и `arrows` всегда 0: в `0x486170` нет вызовов `SLIDE`/`KNOB`/
  `MENUARRW`/`MENULIT`; поля оставлены ради единой формы статистики соседних
  рендереров.
* Шрифты/палитры — только из поставочных `FONTS4`; синтетических атласов модуль
  не принимает.
