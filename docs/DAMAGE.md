# Урон, броня и щиты (`M6.5.2`)

**Статус:** математика снята по коду `gundx.exe` 1.36 (только чтение) и по 36
`.sbt`; модель и числа — `tools/re/damage.py` (`--self-test` 63/63,
`--fields`, `--calc`, `--corpus`, `--json`, `--anchors`; Ghidra не нужна).
Всё, что помечено «код», проверено дизассемблером `tools/re/disrange.py` и
байтовыми якорями (`--anchors`, 33/33 при SHA exe `929ffa72…`), константы
`.rdata` — чтением double'ов (`--self-test`, 8/8).

Смежные документы (не пересказываются): `docs/PLAYER_FIELDS.md` §11 (поля
виталов), `docs/DM_RULES.md` §3–4 (фраги, смерть, респавн), `docs/PICKUP.md`
§8–9 (вирус, щиты), `docs/RECORDS.md` §3 (`SET_*SECTOR_DAMAGE`),
`docs/PROJECTILE_CPP.md` §7 (снаряды), `docs/WEAPONS_CPP.md` §5–6 (оружие),
`docs/EVENTS.md` §4.1 (события `-12…-18`), `docs/ECONOMY.md` §4/§8 (цена и
вес щитов).

## 0. Итог

1. **Отдельного «здоровья» у игрока нет.** HP — это `armor`
   (`player+0x3248`), максимум — `armor_max` (`+0x3244`); обе шкалы в сотых
   (`10000` = 100.00). Смерть — `armor <= 0` (`0x453e6f` → `0x4536e0`).
2. **Щиты — четыре плиты** `player+0x3250` (front/right/back/left) с одним
   максимумом `shield_max` (`+0x324c`). В задаче указано `+0x3224` — это
   **не щиты**, а таймер вспышки попадания в мс (`docs/SCREEN_FX.md` §2.1,
   `0x453f8a`).
3. **Порядок поглощения: плита → броня.** `arg6` (`plate`) бьёт по плитам,
   `arg7` (`hull`) — сразу по броне; недостача плиты переливается в броню.
   Без направления плита получает `plate/4`, с флагом `2` — полный `plate`.
4. **Смерть** (`0x4536e0`): `armor = 0`, `action_state (+0x3210) = 7`,
   `+0x33c8 = 0xC0000`, таймер респавна `+0x33d4 = 0`, `event -7`,
   фраг убийце; через `0x88` (136 тиков) — `0x452670` → респавн, виталы
   восстанавливаются (`armor = armor_max`, все 4 плиты `= shield_max`).
5. **Вещи:** `health +0x398`, `max_health +0x39c`, `shields[4] +0x3a0`,
   `shield_max[4] +0x3b0`; тот же порядок «плиты → HP», `health <= 0` →
   `0x470290` (destroy).
6. **Взрыв** `0x477280` (опкод 75) масштабирует оба гейджа на
   `(radius − dist)/radius` (целочисленно) и зовёт `0x453b50`/`0x470500`.
   `0x4698b0` — не урон, а цепной подрыв **предметов** в радиусе `arg/2`.
7. **`god_mode` урон не меняет.** Урон отменяют только бит `0x10` в
   `player+0x3200` (неуязвимость) и `ds:0x83d620 == 1` (отладочный кадр).
   Гандикап (`mp_flags & 0x20`) — только деньги на респавне.

## 2. Игрок: `0x453b50` — `damage_player`

Сигнатура (по кадрам стека `[esp+0x58]`…`[esp+0x80]`):

```
damage_player(int player, u32 flags,
              double x, double y, double z,
              int plate, int hull, int attacker)
```

`player` — индекс слота 0..7 (база `0x819040`, шаг `0x3510`); `attacker` —
индекс игрока, индекс вещи `+8` (8..0x10b) или `-1` (мир). Возврата нет
(`void`), все эффекты — через поля и `event_post`.

### 2.1. Ранние выходы

| проверка | адрес | что значит |
|---|---|---|
| `ds:0x83d620 == 1` | `0x453b53`/`0x453b78` | отладочный/трассировочный кадр (в нём ВМ только валидирует команды, `docs/VM_EXEC.md` §1) — урона нет |
| `player+0x3200 & 0x10` | `0x453b94` | неуязвимость (`SOURCEPLAYER_INVINCIBLE`, таймер `+0x3220`) |
| `player+0x3178 == 0` | `0x453bdb` | слот пуст (нет объекта) |
| `0x4277cd(body_object_id) == 0` | `0x453be9` | объекта нет |
| `attacker` — вещь с `flags_b & 0x800` | `0x453ba1`…`0x453bd4` | атакующий заменяется на `thing+0x47c` (владелец снаряда) |

### 2.2. Статусы: `plate < 0`

| `plate` | эффект | адрес |
|---:|---|---|
| `-1` | `player+0x3224 += hull*91/100` (мс); если `> 0`, `flags |= 0x20` и `0x4538d0` | `0x453f5d`…`0x453fa8` |
| `-2` | `flags |= 0xc0` (заражение), `0x4538d0` | `0x453faa`…`0x453fc3` |
| иное | ничего | `0x453fcb` |

`hull` здесь — **операнд**, а не спад: `0x453f62` берёт `[esp+0x7c]` (arg7).

### 2.3. Множители (`FORCE SHIELD`, опкод 132)

```
если !(flags & 4):
    plate = ftol(plate * double[player+0x2fb0])     ; 0x453c13
    hull  = ftol(hull  * double[player+0x2fb8])     ; 0x453c24
    если plate == 0 и hull == 0 -> выйти            ; 0x453c3b
```

`ftol` — `0x40e0e0`: смена управляющего слова x87 на усечение и `fistp`
(отбрасывание дробной части, не округление). Значения по умолчанию — `1.0`
(`0x452cd0` кладёт `0x3FF00000`, `0x452d7e`/`0x452d8a` — нули в младшие
полуслова). Пишет их опкод 132 (`0x45a79d`/`0x45a7b1`, 16 байт = две
`double`).

**Сложности (difficulty) в `0x453b50` нет** — вопреки строке в
`docs/SECTOR_STUFF.md` §4.2; единственные множители — эти две `double`.

### 2.4. Тряска/«hitstun» `player+0x33c8`

```
S     = shield_max(+0x324c) + armor(+0x3248)          ; 0x453c47
scale = max(S * (1/64), 1.0)                          ; 0x453c5d, 0x4a2518, 0x4a2498
v     = ftol((plate + hull) / scale * 524288)         ; 0x453c7e..0x453c8a, 0x4a2520
v     = clamp(v, 0x10000, 0x80000)                    ; 0x453c8f, 0x453c9d
если player+0x33c8 < v: player+0x33c8 = v             ; 0x453ca9
```

Тик `0x443716`: `+0x33c8 -= ticks*0x4000`, пол 0. Читают рендер/камера
(`0x447140`, `0x447e21`, `0x4480ee`, `0x44887a`, …). При смерти пишется
`0xC0000` (`0x453724`). Для типичного LIGHT-шасси (`shield_max 8000`,
`armor 10000`) порог `0x10000` достигается уже при 1 единице урона, а потолок
`0x80000` — при 400, т.е. почти любое попадание даёт максимальную тряску.

### 2.5. Выбор плиты (направление)

Если `flags & 1` — сразу `side = -1` («без направления», `0x453cb7`).
Иначе (`0x453cc2`…`0x453d6c`):

```
если |x - player.x| > 0.1 или |y - player.y| > 0.1:     ; 0x4a2528 = 0.1
    out = 0x437909(obj, точка_попадания)               ; проекция на базис
    если |out0| > |out1|:  side = (out0 > 0) ? 1 : 3
    иначе:                 side = (out1 > 0) ? 0 : 2
иначе side = -1                                        ; «точка внутри игрока»
```

Сравнения строгие: при `|dx| == 0.1` направление **не** считается (x87
`C3` → `test ah,0x41` не ноль). Стороны: `0` front, `1` right, `2` back,
`3` left (имена — `docs/PLAYER_FIELDS.md` §11).

Взрыв с `no_direction != 0` (опкод 75) передаёт в урон **позицию самой цели**
(`0x477396`…`0x4773d2` собирает `x,y,z` из записи игрока), поэтому всегда
попадает в ветку `side = -1`. В поставе так делает только DISRUPTORFIELD. У
остальных взрывов `no_direction = 0` — в урон идёт центр взрыва
(`0x4773d4`), т.е. удар направленный.

### 2.6. Поглощение щитами

`flags` = `arg2`; значащие биты: `0x1` — без направления, `0x2` — «полный
урон в каждую плиту», `0x4` — без множителей.

**Направленный удар** (`0x453d91`…`0x453da5`), если `shields[side] > 0`:

```
shields[side] -= plate        ; может уйти в минус
spill = hull                  ; броня получит hull
```

Если `shields[side] <= 0`, плита не трогается, и `spill = plate + hull`
(`0x453da7`: `ebp = [esp+0x78]`, куда ранее положено `hull + plate`).

**Без направления** (`0x453db9`…`0x453ded`):

```
per = (flags & 2) ? plate : (plate >> 2)      ; sar, 0x453db6
для i = 0..3:
    если shields[i] > 0: shields[i] -= per
    иначе:               spill += (plate >> 2)   ; четверть — всегда
```

**Сбор отрицательных плит** (`0x453e0d`…`0x453e38`) — общий для обеих ветвей:

```
для i = 0..3:
    если shields[i] < 0:
        neg = (flags & 2) ? (shields[i] >> 2) : shields[i]   ; sar, 0x453e18
        spill -= neg          ; т.е. += |neg|
        shields[i] = 0
        broken[i] = true
```

Важно: **ровно ноль — не «пробита»** (проверка `< 0`). Событие
`*_SHIELD_GONE` приходит только на перелёте через ноль.

### 2.7. Броня (HP) и смерть

```
armor -= spill                          ; 0x453e58
если armor > 0  -> события половины и пробитых плит
иначе           -> 0x4536e0(player, attacker)   ; 0x453e73..0x453e8e
```

`armor` в `0x453b50` **не обрезается до нуля**: в поле остаётся отрицательное
значение до `0x4536e0`, который пишет `0` (`0x453718`). Для игры разницы нет,
для сохранений/дампов — есть.

### 2.8. События (`event_post`)

| событие | когда | адрес |
|---:|---|---|
| `-17` `LIFE_HALF_GONE` | до удара `armor >= armor_max/2`, после `< armor_max/2`, жив | `0x453eaa`, `0x453ef4` |
| `-18` `ABOVE_HALF_LIFE` | обратный переход (по коду достижим только при отрицательном уроне: `edi=0` — «броня была ниже половины», а после урона `>= половины`) | `0x453f09`, `0x453f51` |
| `-12/-15/-13/-14` | пробиты плиты `0(front)/1(right)/2(back)/3(left)` — **именно в таком порядке** | `0x454013`, `0x454061`, `0x4540af`, `0x4540fd` |

Координаты события — позиция игрока как есть, а в числовом хвосте стоит
`-0x10000 + i` (`lea eax,[ebx-0x10000]`), т.е. «убийца = мир» (`-1 << 16`).
При смерти события плит постятся всё равно (ветка `0x453e73` → `0x453fcf`),
`-17` — нет.

## 3. Смерть и респавн

`0x4536e0(victim, killer)` (полный разбор — `docs/DM_RULES.md` §3.2):

```
если action_state == 0 или == 7: выход              ; 0x453700
armor = 0                                           ; 0x453718
+0x33c8 = 0xC0000                                   ; 0x453724
+0x33d4 = 0                                         ; 0x45372f
0x4569d0(victim, 0)                                 ; эффект/взрыв
event_post(-7, source = (killer<<16)|victim)        ; 0x453755
action_state = 7                                    ; 0x453763
фраги: +1 убийце (в TEAM — только если команды разные), иначе -1 жертве
kills_by_victim[killer][victim] += 1
```

Респавн: `+0x33d4 >= 0x88` → `0x452670` → `0x452730(player, 0, 1)`:
`flags = 0`, `action_state = 1`, **виталы восстанавливаются**:

```
armor        = armor_max            ; 0x452dd8
shields[i]   = shield_max (все 4)   ; 0x452de4..0x452e0e
shields_spawn[i] = shield_max       ; 0x452e1a..0x452e43
```

плюс `0x47a980` (loadout), деньги и гандикап. Неуязвимость (`flags & 0x10`)
после респавна **не** ставится (в этой сборке это делает только скрипт
`SOURCEPLAYER_INVINCIBLE`).

## 4. Вещи: `0x470500` — `damage_thing`

Та же сигнатура, `player` → индекс вещи (база `0x7ac080`, шаг `0x528`,
260 слотов).

| поле | смещение | смысл |
|---|---|---|
| `object` | `+0x33c` | `0` → выход (`0x470522`) |
| `health` | `+0x398` | текущее HP; `<= 0` → выход (`0x470633`) |
| `max_health` | `+0x39c` | из `THING_TYPES+0x1d4` |
| `flags_b` | `+0x364` | бит `0x2` → `plate = 0`, бит `0x4` → `hull = 0` (`0x4705f7`); бит `0x800` → атакующий из `+0x47c` (`0x47053b`); бит `0x1000` → событие `-17` (`0x470824`); бит `0x200` → «взорваться от попадания» (`0x470888`: событие `+0x394`, `flags_a &= ~2`, `+0x378 = 0x38e`) |
| `flags_c` | `+0x368` | бит `0x20000` + `game_mode == 0` → `frags[attacker]++` при destroy (`0x4707c6`) |
| `shields[4]` | `+0x3a0` | текущие плиты |
| `shield_max[4]` | `+0x3b0` | максимумы (по плитам, не одно число) |
| `mult_plate`/`mult_hull` | `+0x0e0`/`+0x0e8` | `double`, умножаются через `ftol` (`0x470611`/`0x470626`) |
| `damaged_event` | `+0x518` | `event_post` после несмертельного попадания (`0x470995`) |

Алгоритм: тот же, что у игрока, плюс два отличия:

1. **Плита вычитается всегда**, даже если уже `<= 0` (`0x47076c`:
   `sub` без проверки) — перелив считается по отрицательному остатку: без
   флага `2` это `|x|`, с флагом `2` — `|x|/4` с округлением к нулю
   (`0x470784`: `cdq/and 3/add/sar 2/neg`).
2. **Смерть** — `health <= 0` → `0x470290` (destroy), и только тогда
   `frags[attacker]++` (если `flags_c & 0x20000` и `game_mode == 0`).

Статусы вещи идут в `flags_a` (`+0x360`), а не в `player+0x3200`:

* `plate == -1` — `thing+0x388` (таймер горения) `+= hull*91/100`; если стал
  `> 0`, `flags_a |= 0x40` (`0x4709bb`…`0x4709fb`);
* `plate == -2` — `flags_a |= 0x18`, но только если нет `flags_b & 0x40`
  (`0x470a02`…`0x470a11`).

Событие `-17` для вещей — не «половина жизни игрока», а «переход через
половину HP» и только при `flags_b & 0x1000` (`0x47081a`). После
несмертельного попадания постится `damaged_event` (`+0x518`).

`max_health == 0` как «маркер неуязвимости» в `0x470500` **не виден**: там
проверяется только текущий `health <= 0`. Правило `max_hp <= 0` есть в
`engine/src/game/weapons.cpp`, но адрес `0x470633`, на который он ссылается,
— это проверка `health`. **Гипотеза C++**, в игре не подтверждена.

## 5. Взрыв и урон по площади

### 5.1. `0x477280` — `blast_radius_damage` (опкод 75)

Опкод 75 `CAUSE_BLAST_RADIUS_DAMAGE` (`0x45775b`) имеет операнды
`(flags, no_direction, plate, hull, radius, event)` и передаёт в `0x477280`
ещё `source` (handle игрока/вещи) и точку.

```
для каждого живого игрока i (action_state != 0 и != 7) и вещи:
    dist = ftol(0x4344df(центр - позиция цели))       ; приближение, не евклид
    если dist > radius: пропустить                    ; 0x477342
    plate' = plate * (radius - dist) / radius         ; idiv, 0x4773a3
    hull'  = hull  * (radius - dist) / radius         ; idiv
    damage_player(i, flags & 2, точка, plate', hull', source<<16 | i)
```

* Фильтры — по битам `flags`: `0x1` — источник-игрок (номер слота),
  `0x4` — не бить игроков, `0x8` — не бить вещи (`0x47729c`, `0x477480`).
* В урон идёт только `flags & 2` (флаг «полный урон в каждую плиту»).
  В поставе этот бит **не встречается ни разу** (`--corpus --all`: все
  взрывы `flags` 0 или 1, `flags & 2 == 0`), поэтому «полный урон в плиту»
  в игре не включается никогда.
* `flags & 1` — «источник-игрок» (номер слота); `no_direction = 1` есть
  только у DISRUPTORFIELD (тогда `plate/4` на каждую из 4 плит), у
  остальных удар направленный (полный `plate` в одну плиту).
* `plate < 0` (−1/−2) не масштабируется — это статус (см. §2.2); так,
  TAC NUKE несёт `plate = -1` с `hull = 150` (остаточное горение).

### 5.2. `0x4698b0` — цепной подрыв предметов

Это **не** урон: `if (ds:0x83d620 == 1) return` (`0x4698b3`), затем
`radius = arg * 0.5` (`0x4a2608`) и для каждого предмета с `state == -4`
(взведённая мина), попавшего в радиус, постится его триггер `item+0x4c`
(`0x469921`…`0x46994a`). Дальше срабатывает скрипт предмета (обычно опкод
75) — вот он и наносит урон.

### 5.3. Урон сектора

`SET_SOURCESECTOR_DAMAGE` (31, `L`) и `SET_HANDLESECTOR_DAMAGE` (43, `EL`)
пишут в слот `0x800b60` (`0x45798a`):

```
slot.damage_a (+0x40) = value & 0xffff        ; 0x45799a
slot.damage_b (+0x44) = value >> 16 (sar)     ; 0x4579a0  — знаковое!
```

Потребитель `0x4450f6`: `plate = damage_a * dt`, `hull = damage_b * dt`
(`imul`), затем `damage_player(player, 0 или 4, позиция игрока, …)`
(`0x445133` — флаги `0`, `0x44525d` — флаги `4`, т.е. без множителей).
Точка = позиция игрока, поэтому урон всегда «без направления».

В поставе: `dm1` — 4 команды по handle 300 (`100`, `9999`, `0`, `0`),
`level15` — handle 99 со `200`; `level0` — ни одной. Отрицательный `damage_b`
(бит 15 в старшем полуслове) даёт **лечение** — в поставке не встречается.

## 6. Что реально меняет урон

| механизм | адрес | эффект на урон |
|---|---|---|
| вирус (`DEFINE_VIRUS`, `SOURCEPLAYER_INFECT`) | `0x443c7d`…`0x443e03` | каждая из 4 плит `-= dt * [0x80d8b4]` (в поставе `L0 = 16`); при `<= 0` плита = 0, побочный эффект `0x4452f0`; когда все 4 нуля — снимается бит `0x40`. Вирус **сливает те же плиты**, что и урон |
| регенерация (`DEFINE_REGENERATION_MARKER`, 174) | `0x45c375` | **не работает**: `0x80f9e0`/`0x80f830` пишет только опкод 174 (`0x45c38a`/`0x45c399`) и обнуляет загрузка уровня (`0x45713f`/`0x457153`); читателей нет (`grep` по листингу) |
| гандикап (`mp_flags & 0x20`) | `0x452e67` | только стартовые деньги на респавне (`docs/DM_RULES.md` §5); урон не трогает |
| `god_mode` (`/god` → `0x62cad4`, условие 26) | `0x44a9e8`, `0x45eb3f` | **урон не меняет**: все чтения `0x62cad4` — условие 26 и функция переключения вида (`0x44cdf6`…`0x44d1ff`, индекс вида `0x83d628`); в `0x453b50`/`0x470500`/`0x477280` его нет |
| неуязвимость (`flags & 0x10`) | `0x453b94` | полная отмена урона игроку |
| `ds:0x83d620 == 1` | `0x453b53`, `0x4698b3` | полная отмена урона и цепного подрыва (отладочный кадр) |
| `FORCE SHIELD` (опкод 132) | `0x453c13`/`0x453c24` | множители `plate`/`hull`; флаг `4` их обходит (урон сектора, столкновения `0x44490d`/`0x44525d`) |

## 7. Ручные примеры (все воспроизводятся `--calc`)

Шасси LIGHT (`dm1`/`level0`, `--corpus`): `shield_max = 8000`,
`armor_max = 10000`, плиты `8000/8000/8000/8000`. Все числа — сотые.

### 7.1. Пулемёт, 4.00 за пулю (`--plate 400 --side 0`)

```
python3 tools/re/damage.py --calc --plate 400 --side 0
  front 8000 -> 7600 (-400), остальные без изменений, spill 0, armor 10000
```

`--repeat 0` → **45 попаданий** в одну и ту же плиту: 20 (8000/400) снимают
плиту ровно в 0, затем 25 × 400 = 10000 добивают броню. По разным сторонам
— 105 (4·8000/400 + 25).

### 7.2. Пушка, 15.00 (`--plate 1500 --side 0 --repeat 0`)

6-е попадание: `8000 − 6·1500 = −1000` → плита 0, `spill = 1000`, броня
`10000 → 9000` (событие `-12`). Дальше по 1500 в броню → ещё 6 попаданий,
итого **12**.

### 7.3. Рельса, 60.00 (`--plate 6000 --side 0 --repeat 0`)

`8000→2000`, `2000−6000 = −4000` → `spill 4000` (броня 6000), третье
попадание — `spill 6000` → броня `0` → смерть. **3 попадания**.

### 7.4. Граната и ракета: направленный взрыв 80.00

Граната (`plate 8000`, радиус 500, `no_direction = 0`) в упор:

```
python3 tools/re/damage.py --calc --plate 8000 --side 0
  front 8000 -> 0 ровно, spill 0, armor 10000; события нет (ноль — не «пробита»)
```

На половине радиуса (`--calc --plate 4000 --side 0`) — `front 8000 -> 4000`.
Ракета (`plate 8000`, радиус 80) в упор даёт то же: `front 8000 → 0`.

DISRUPTORFIELD — единственный взрыв с `no_direction = 1`
(`--calc --plate 12000 --flags 1`): `per = 12000>>2 = 3000`, все четыре
плиты `8000 → 5000`, `spill 0`.

### 7.5. TAC NUKE (`plate 60000`, радиус 3000) на дистанции 1500

`plate' = 60000·(3000−1500)/3000 = 30000`:

```
python3 tools/re/damage.py --calc --plate 30000 --side 0
  front 8000 -> 0 (-8000) BROKEN, spill 22000, armor 10000 -> -12000 DEAD
  events: -12
```

В центре (`--plate 60000`): `spill = 60000 − 8000 = 52000`, броня `−42000`.

### 7.6. Урон только по корпусу (MICROWAVE GUN, `hull = 500`)

```
python3 tools/re/damage.py --calc --plate 0 --hull 500
  плиты не меняются, spill 500, armor 10000 -> 9500
```

Что поправить/добавить в C++:

1. `kHitscanMinDepth = 0.32` (`engine/src/game/weapons.h:433`) — **в
   оригинале 0.0** (`0x4a2658`, проверено чтением double'а; сравнение
   `depth > 0` строгое, `0x4781c1`). Наш конус отбрасывает цели ближе 0.32
   по глубине — расхождение с оригиналом.
2. `apply_damage_gauge` обрезает `armor` до 0; оригинал оставляет минус до
   `0x4536e0`. На смерть не влияет, но если значение уходит в сейв/дамп —
   будет расхождение.
3. Нет ранних выходов `player+0x3200 & 0x10` и `ds:0x83d620 == 1`
   (для паритета нужны оба; второй — глобальный флаг кадра).
4. Нет смерти игрока (`0x4536e0`): `action_state = 7`, `armor = 0`,
   `+0x33c8 = 0xC0000`, `+0x33d4 = 0`, фраги, событие `-7`; и респавна
   с восстановлением виталов (§3).
5. Нет событий `-12/-15/-13/-14` (порядок именно такой) и `-17`
   на переходе через половину.
6. Нет атрибуции снаряда владельцу: при `flags_b & 0x800` урон идёт
   `thing+0x47c` (`0x453ba1`), иначе дробь-убийство попадёт в саму вещь.
7. `apply_thing_damage`: (а) спред-ветка с `flags & 2` должна делить
   **отрицательный остаток** на 4 (`0x470784`), а не отдавать весь дефицит
   в HP; (б) нет `flags_b & 0x2/0x4` (обнуление `plate`/`hull`);
   (в) нет `damaged_event +0x518` и `frags++` при destroy
   (`flags_c & 0x20000`); (г) `max_hp <= 0` — гипотеза, а не факт.
8. Урон сектора: `damage_a = value & 0xffff`, `damage_b = (signed)value >> 16`
   и умножение на `dt` **до** вызова урона; точка — позиция игрока
   (⇒ всегда «без направления»).
9. Числа для тестов: MG 400 → 45 попаданий в одну плиту / 105 в разные;
   CANNON 1500 → 12; RAILGUN 6000 → 3; граната/ракета 8000 в упор → ровно
   0 у плиты и 0 перелива; DISRUPTORFIELD 12000 (`no_direction`) → −3000
   каждой из 4 плит.

## 9. Доказано / гипотезы / остатки

### 9.1. Новое и поправки к существующим докам

1. **`+0x3224` — не щиты.** Это таймер вспышки (мс), щиты — `+0x3250[4]`
   (`0x453d91`), максимум — `+0x324c`.
2. **`+0x14c`/`+0x150` записи `DEFINE_PLAYER_TYPES`.** По адресам записи:
   `+0x14c → player+0x324c` (shield_max), `+0x150 → player+0x3244`
   (armor_max) — `0x47acce` и `0x47ace0`. В
   `tools/re/weapon_fields.py` ярлыки обратные («armor_x100» /
   «armor_cap_x100»); данные подтверждают мою раскладку: `LIGHT` даёт
   `8000/10000`, а `saved0` в `docs/PLAYER_FIELDS.md` §11 имеет броню
   `10000/10000` и щиты `8000×4`.
3. **`0x4a2658 = 0.0`, а не 0.32.** `docs/WEAPONS_CPP.md` §6 называет этот
   адрес порогом `depth > 0.32`; фактически там `0.0` и сравнение
   `depth > 0`.
4. **«Сложность» в `0x453b50` отсутствует** (поправка к
   `docs/SECTOR_STUFF.md` §4.2): только множители FORCE SHIELD.
5. **`flags_b & 0x800` = «урон принадлежит владельцу `+0x47c`»**
   (`0x453ba1`, `0x47053b`); в `docs/THING_FIELDS.md` §6 этого бита нет.
6. **Регенерация (`DEFINE_REGENERATION_MARKER`) в 1.36 мертва** — два
   `double` только пишутся; потребителей нет.
7. **`-18` практически недостижим**: ветка требует «броня была ниже
   половины, а после урона стала не ниже» — при положительном уроне
   невозможно (нужен отрицательный `hull`).

### 9.2. Гипотезы

* `ds:0x83d620 == 1` — отладочный/трассировочный кадр (по `0x457412`:
  команды ВМ не исполняются, а сверяются с таблицей). Что это за режим
  в игре (пауза/фильм/`/log`) — **не проверено**.
* `flags_b & 0x2/0x4` у вещей — «иммунитет к типу урона» (какому именно —
  не установлено).
* RGM: hitscan-ветка несёт `plate = 3` (0.03), а цепочка событий —
  `plate 14000/15000`; похоже, что hitscan-значение для RGM — заглушка,
  а урон идёт взрывом. Требует проверки в игре.
* `-18` и «лечение отрицательным уроном» — механизм есть, применений в
  поставе нет.

### 9.3. Остатки

* `0x437909` (проекция на базис) разобрана только по результату
  (`out = delta·b`); для точного воспроизведения сторон нужен её
  собственный разбор (сейчас стороны проверены косвенно, через
  `docs/WEAPONS_CPP.md` §6 и `--corpus`).
* Не проверено в игре: момент снятия бита `0x8000` `flags2` (признак
  «мёртв», `docs/DM_RULES.md` §10.4) — от него зависит, когда именно
  запускается респавн.
* Таблицы `THING_TYPES+0x1d8` (щиты вещи) читаются как максимумы; как они
  соотносятся с `shield_max[4]` у разных типов — проверено только на
  `ROCKET` (`0/500/0/500`, совпадает с `docs/THING_FIELDS.md` §7).
