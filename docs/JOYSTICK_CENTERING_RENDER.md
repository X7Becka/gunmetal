# Рендер экрана 26 `JOYSTICK CENTERING` (`engine/src/ui/joystick_centering_render.h`)

Срез 10 пункта `M8.8`: модуль **рисует экран 26** в RGBA-буфер 320×200 из
реальной установки: заголовок `JOYSTICK CENTERING`, пять информационных строк
(25/35/45 и 86/97, `x` 36/41), плату `PLATE`. Геометрия — из обработчика
`0x488f70` (`docs/UI_SCREENS.md` §2/§3.8), атласы — из `render/text_layout`
(`FONTS4` в `FRONTEND/BMP.IDX`), вход — из CONTROL OPTIONS (10), пункт 7
(`0x48d22e`).

Экран **полностью статический**: все шесть строк — литералы exe, `%s`-подстановок
нет (см. §1.2). Поэтому у модели кадра нет полей подстановок, и это не
упущение, а доказанный факт.

Код: `engine/src/ui/joystick_centering_render.h/.cpp`; тест —
`engine/tests/test_joystick_centering_render.cpp` (CTest `joystick_centering_render`, label
`quick`). Канон поведения — `docs/UI_SCREENS.md` §2/§3.8 и этот документ;
образцы того же класса задач — `docs/VIDEO_MODE_RENDER.md` (37),
`docs/GAME_TYPE_RENDER.md` (19), `docs/DIFFICULTY_RENDER.md` (23).

Проверка:

```sh
export PATH=$HOME/tools/cmake-4.4.4-linux-x86_64/bin:$HOME/tools/bin:$PATH
cmake --build build/sandbox --target gm_joystick_centering_render_tests -j 4
./build/sandbox/engine/tests/gm_joystick_centering_render_tests
ctest --test-dir build/sandbox -R '^joystick_centering_render$' --output-on-failure
python3 regress.py --mirror --json
```

## 1. Что доказано (`0x488f70`, docs/UI_SCREENS.md §2/§3.8)

Обработчик занимает `0x488f70`..`0x489013` (последний `ret`; дальше `nop` до
`0x489020`, где начинается `LOCAL PLAYER ONE/TWO NAME`). Таблица диспетчера
`0x4883d8` для id 26 указывает на stub `0x487f08` =
`call 0x488f70; jmp 0x487f64` (слот `0x48842c`); CONTROL OPTIONS вызывает
обработчик напрямую (`0x48d274`). Всё в таблицах ниже — сайты обработчика и
общего отрисовщика `0x485dd0`
(листинг: `python3 tools/re/disrange.py 488f70 489020` и `485dd0 485e80`).

| факт | значение | источник |
|---|---|---|
| длина «списка» | **1** (`0x67f10c = 1`): один item (id 0) на все пять строк | `0x488f70` |
| шаг item | **0** (`0x662d58 = 0`): `y` каждой строки равно её `row` | `0x488f7a` |
| плата | `0x486050` копирует `PLATE` 196×131 в `0x6865f8` (6419 dword = 25676 байт); весь текст пишется в эту копию (клип 196×131) | `0x488f84`; §3, §9 |
| заголовок | `JOYSTICK CENTERING` (`0x4bd6ac`), шрифт **5**, `centered=1`, `x 38`, `row 14`, `item -1` → **y 14**, x = (196 − measure)/2 = **50** | `0x488f89`..`0x488f9d`; `0x485de2`..`0x485dfa` |
| `centered` | `x = (196 − measure(text)) / 2`, целочисленно | `0x485de2`..`0x485dfa` |
| `item == -1` | обнуляет `item·step` **и** пропускает сравнение с курсором — заголовок не подсвечивается никогда | `0x485e04`..`0x485e09` |
| пять строк | `Spiral the stick of the` / `joystick through all of` / `it's positions.` / `Press Esc or Enter` / `to close`, шрифт **0**, `centered=0`, `item **0**`, `x` 36/36/36/41/41, `row` 25/35/45/86/97 | `0x488fa0`..`0x489010` |
| `y` при `row >= 0` | `y = row + item·[0x662d58] = row + 0` | `0x485e4b`..`0x485e5c` |
| подсветка | `item == [0x68ccf4]` **и** вызывающий передал шрифт 0 (`test esi,esi`) → шрифт **4**. Все пять строк — item 0, поэтому `[0x68ccf4] == 0` белит **весь текст сразу**; других item на экране нет | `0x485e0d`..`0x485e19` |
| вход | CONTROL OPTIONS (10), пункт 7 `Joystick Centering` (таблица `0x48e888`, слот 7 → `0x48d22e`): `0x48d22e`..`0x48d25a` кладёт -1 в восемь dword `0x4a5ae8`..`0x4a5b04` (состояние центрирования; имена полей не доказаны), `0x48d260` пишет 7 в `0x660788`, `0x48d26a` — state `0x1a`, `0x48d274` сразу вызывает `0x488f70`, затем прыжок в общий ввод `0x48e4a6` | `0x48d22e`..`0x48d279`; §3.1 |
| курсор при входе | **не пишется**: `0x48d22e`..`0x48d279` не трогает `0x68ccf4`, значит на экране 26 остаётся курсор экрана 10 — item **7**. Ни одна строка не имеет item 7 → в оригинале подсветки нет | `0x48d22e`..`0x48d279` (нет записи), §3.1 |
| стрелки | обработчик не вызывает `0x485cc0`/`0x485d00`; последняя строка кончается на y 103 в полосе 131 px | листинг `0x488f70..0x489013` |
| порядок | заголовок → строка 1 → 2 → 3 → подсказка 1 → подсказка 2 | порядок вызовов `0x488f9d`, `0x488fb4`, `0x488fcb`, `0x488fe2`, `0x488ff9`, `0x489010` |

Ассеты экрана (`python3 tools/re/ui_screens.py --assets`, поле
`screens[].assets`): `plate` + шрифты. Ни `MENUARRW`, ни `MENULIT`, ни
`SLIDE`/`KNOB` — центрирование джойстика не имеет элементов ввода.

### 1.1. Пять строк и геометрия

| # | строка | VA | x | y | шрифт |
|---:|---|---|---:|---:|---:|
| — | `JOYSTICK CENTERING` | `0x4bd6ac` | (196−96)/2 = **50** | **14** | 5 |
| 1 | `Spiral the stick of the` | `0x4bd694` | 36 | 25 | 0 |
| 2 | `joystick through all of` | `0x4bd67c` | 36 | 35 | 0 |
| 3 | `it's positions.` | `0x4bd66c` | 36 | 45 | 0 |
| 4 | `Press Esc or Enter` | `0x4bd658` | 41 | 86 | 0 |
| 5 | `to close` | `0x4bd64c` | 41 | 97 | 0 |

`36 = 0x24`, `41 = 0x29`, `25 = 0x19`, `35 = 0x23`, `45 = 0x2d`,
`86 = 0x56`, `97 = 0x61` — это `push`-иммедиаты вызовов
(`0x488fa0`..`0x489004`), а не результат измерения: строки не центрируются.
Абзац идёт с шагом 10 px (25/35/45), подсказка — с шагом 9 (86/97); разрыв
45 → 86 (41 px) принадлежит раскладке, пустой строки там нет. Апостроф в
`it's positions.` — из exe (строка `0x4bd66c`), тест его пинит.

### 1.2. Данных нет: строки статические

В `0x488f70`..`0x489013` нет ни одного `push` подстановки: только шесть
наборов аргументов `0x485dd0` (текст/шрифт/центрирование/x/row/item) и `ret`.
Ни `%s`, ни `%d`, ни буфера, ни чтения `0x6c2058` (имя набора), `0x5a4910`
(выбранный набор), статистики уровня или имени миссии. В отличие от экрана 10
(`Player 1: %s`, `Assign %s`), 24/25 (имена игроков) и 17 (имена уровней),
экран 26 ничего не читает — все пять строк и заголовок статичны.

Поэтому `JoystickRenderOptions` **не имеет полей подстановок**: любое такое
поле было бы моделью, которую бинарь не поддерживает. Тест проверяет, что ни
одна строка не содержит `%` (это и есть проверка «нет printf-подстановок»), и
печатает пять строк с их `x`/`y`.

### 1.3. Курсор и «квирк» подсветки

Вход в 26 не пишет `0x68ccf4` (`0x48d22e`..`0x48d279`) — в отличие от входа в
37, где `0x48e1c6` обнуляет курсор. Значение, которое видит обработчик, —
курсор экрана 10, то есть **7** (`Joystick Centering` — седьмой пункт §3.1).
Так как все пять строк передают `item 0`, сравнение `0x485e0d` не совпадает и
оригинальный кадр рисует текст шрифтом 0.

Если же вызвать отрисовщик с `[0x68ccf4] == 0`, `0x485e19` подменит шрифт на 4
для **всех пяти** строк: item у них общий. Это поведение обработчика, а не
«курсор списка» (выбирать на экране нечего), и модуль его моделирует:
`options.cursor = 0` → весь текст белый; `-1` (по умолчанию), `7` (как в
оригинале), `1`, `99` → шрифт 0. Заголовок (`item -1`) не подсвечивается ни
при каком курсоре.

## 2. Модель кадра

* Холст — 320×200 (`0x6d8fc0`, mode 13h), по умолчанию непрозрачный чёрный
  `#000000FF`. `options.background` — имя записи `FRONTEND/BMP.IDX`,
  нарисованной в (0,0) **до** текста; пустая строка = чёрный холст.
  Доказанная плата экрана — `PLATE` 196×131 (`0x486050`), но она не рисуется
  неявно (как у экранов 13/14/17/19/21/23/30/37).
* Текст клипается к полосе 196×131: `0x485dd0` пишет в копию `PLATE`
  `0x6865f8`, за её пределы пиксель не попадает. Холст вне платы остаётся
  чёрным.
* Шрифты — три грани `FONTS4`: заголовок 5, строки 0, подсветка 4 (§3).
  Цвета из палитры атласа: заголовок (155,15,15), строки (19,15,15),
  подсветка (239,239,239). Ячейка 8×8; строка `y` занимает `y..y+7`.
* Заголовок центрируется по ширине **advance**-сумм (`0x47fa50`), а не по
  чернилам: при поставочном `FONTS4` measure = 96, `x = (196 − 96)/2 = 50`,
  чернила заголовка занимают x 50..144 (ширина 95 — трейлинг последней
  литеры в advance не входит).
* Подсветка — только смена грани на 4 (`0x485e0d`..`0x485e19`): ни полосы,
  ни рамки, ни `MENULIT` на этом экране нет.
* Точный fade (`fade_lut*`) — тот же индексный слой `0x682f90`, что у
  `ui/video_mode_render`/`ui/game_type_render`: таблица применяется к индексу
  палитры **до** поиска цвета, поэтому видит индекс, которым пиксель нарисован.
  Без таблицы и дампа — отказ, не «молча без fade».

## 3. API

```cpp
struct JoystickRenderOptions {
    std::string background;              // "" = чёрный; "PLATE" = плата экрана
    int cursor = -1;                     // [0x68ccf4]; 0 = все пять строк шрифтом 4
    bool fade_lut = false;
    int fade_lut_level = 11;             // 0..15
    std::string fade_lut_dump;           // 4096 байт, docs/HUD_LUT.md §2
    const HudLut* fade_lut_table = nullptr;
};

struct JoystickRenderStats {
    int rows;             // 0x67f10c = 1 (item), не число строк текста
    int ink_pixels;       // уникальные пиксели чернил глифов
    int missing_glyphs;
    int arrows;           // всегда 0 (на экране нет прокрутки)
};

bool render_joystick_centering(const std::filesystem::path& game,
                         const JoystickRenderOptions&,
                         std::vector<std::uint32_t>& rgba,
                         int& width, int& height,
                         JoystickRenderStats* = nullptr,
                         std::string* error = nullptr);
```

Вспомогательные (для UI и тестов): `kJoystickLines[5]`
(`{text, x, y, item}`), `kJoystickTitle`, `kJoystickLineOne..Five`,
`kJoystickPanelName`, `kJoystickBodyX = 36`, `kJoystickHintX = 41`,
`kJoystickRows = 1`, `kJoystickItemStep = 0`,
`kJoystickShippedCursor = 7`, `kJoystickNoHighlight = -1`.

Отказы (префикс `joystick_centering_render:`): пустой путь игры; нет/битый
`FRONTEND/BMP.IDX`; нет атласа `FONTS4` (шрифты 5/0/4); неизвестная/битая/
не-8-bpp запись фона; `fade_lut` без таблицы и дампа или с нечитаемым дампом.
При отказе `rgba` очищен, `width = height = 0`, статистика обнулена.

## 4. Числа (поставочная установка, `joystick_centering_render: ok (228 checks)`)

Чёрный холст, курсор по умолчанию (`-1`; кадр совпадает с оригинальным
курсором 7):

| величина | значение |
|---|---|
| `rows` / `arrows` / `missing_glyphs` | 1 / 0 / 0 |
| `ink_pixels` | **1141** = 267 + 226 + 234 + 136 + 193 + 85 |
| непрозрачных пикселей | 64000 / 64000 |
| заголовок | x 50 (центр), bbox (50,14)-(144,20), 95×7, 267 px |
| строка 1 | bbox (36,25)-(133,32), 98×8, 226 px |
| строка 2 | bbox (36,35)-(132,42), 97×8, 234 px |
| строка 3 | bbox (36,45)-(91,52), 56×8, 136 px |
| подсказка 1 | bbox (41,86)-(125,92), 85×7, 193 px |
| подсказка 2 | bbox (41,97)-(74,103), 34×7, 85 px |

Каждый bbox и каждая полоса сверены с независимым блинком атласа (0
отличающихся пикселей); `ink` равен сумме шести полос, полосы не пересекаются.

Шаг и `x`:

| проверка | значение |
|---|---|
| 25 → 35 → 45 | 10 / 10 px |
| 45 → 86 | 41 px (разрыв раскладки) |
| 86 → 97 | 11 px |
| x абзаца → x подсказки | 36 → 41 (+5 px) |
| `0x662d58` | 0 (шага строк нет) |

Подсветка (item 0 у всех пяти строк):

| cursor | отличается от кадра `-1` | `ink` |
|---:|---:|---:|
| **0** | **874 px** (все пять текстовых полос) | 1141 |
| 7 (оригинал) | 0 px | 1141 |
| 1 / 99 | 0 px | 1141 |

`background = "PLATE"`: кадр совпадает с независимо декодированной платой +
глифами (0 отличий), от чёрного кадра отличаются **24535** пикселей, **38324**
пикселя вне платы остаются чёрными, панель 25676 = 196×131, под глифами 1141
пиксель (равен `ink`), `ink_pixels` не меняется.

Fade (`background = "PLATE"`, курсор `-1`): уровень 11 — **0/64000** отличий
от кадра без fade; уровень 0 меняет 25676 пикселей (вся панель уходит в
чёрный; чёрных пикселей в кадре 64000 против 38324 без fade), `ink_pixels`
не меняется; уровни 12/13/14/15 различаются попарно (17721 / 23244 / 20892 px)
и каждый отличается от 11 (16379 / 24636 / 24875 / 25560 px); вне платы
нечёрных 0 на всех уровнях; уровень 99 клампится к 15 (`map`).

## 5. Ограничения

* **Нет ввода**: модуль не читает клавиатуру и не обрабатывает Esc/Enter;
  закрытие экрана назад в состояние 10 (`0x48e599`) — дело вызывающего.
* **Нет самой калибровки джойстика**: за пунктом `Joystick Centering` в
  оригинале стоит проход центрирования (чтение осей); здесь рисуется только
  информационный кадр.
* **Нет звука**: `updown`/`select` (`docs/UI_SOUNDS.md`) не моделируются.
* **CLI — есть (срез 11).** `--joystick-centering [--joystick-centering-cursor N]
  [--no-plate] [--png OUT] [--fade-lut N]`:
  `joystick_centering: rows=1 cursor=-1 ink=1141 missing=0 arrows=0`; курсор 0
  (белит весь текст — квирк `0x485dd0`) — `cursor=0 ink=1141`. CTest
  `cli_joystick_centering`, `_png`; `cli_fade_lut` (11 = без fade).
* **Все строки статические**: подстановок нет (§1.2), поэтому кадр меняют
  только `background`, `cursor` и `fade_lut*`.
* **Курсор — наследство экрана 10**: значение по умолчанию `-1` рисует тот же
  кадр, что оригинальные 7; «правильный» курсор как таковой у экрана
  отсутствует, это доказанный квирк `0x485dd0`.
* **Соответствие «номер шрифта → атлас»** для 0/4/5 взято из
  `docs/UI.md` §10.3/`docs/MENU_RENDER.md` §3; независимой привязки номеров в
  коде нет — это общее открытое место фронтенда, не специфика экрана 26.
