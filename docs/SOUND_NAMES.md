# Имена сэмплов: `SOUND_SAMPLE_TABLE` → `SOU.IDX`, поведение при промахе (M7.6)

Статус: **разобрано кодом и данными**. Инструмент — `tools/re/sound_names.py`
(`--report`, `--resolve`, `--self-test`). Ghidra не нужна: адреса проверены по
листингу `gundx.exe` (`tools/re/disrange.py`), формат каталога — по
`gm/bigfile.py`, таблица уровня — по `gm/sbt.py`.

Короткий итог:

| вопрос | ответ |
|---|---|
| сколько имён таблиц не разрешается в `SOU.IDX` | **0 из 528** (после приведения регистра, как в игре) |
| откуда «95» в `ROADMAP.md` | это число имён, у которых есть строка в `Sounds/sounds.sub`; **не** «ненайденные» |
| работают ли алиасы `sounds.sub` в v1.36 | **нет**: `0x40b510` ждёт счётчик, файл — пары без счётчика |
| что делает игра при промахе | тишина; `-1`/`-2` в хэндле слота; лог только у жёстко зашитых имён; падения нет |
| фолбэк на другой каталог | да, `sounds` → `music` (`0x40ae10…0x40ae51`); в поставке не срабатывает ни разу |

```sh
  имён в 1-й колонке: 95; во 2-й: 42; ни в одной: 391; алиасы применены: нет
  если применить: 95 имён; целей нет в каталоге у 2 (ALARMK->alarmkbig, PICKSAL->picksalv); та же запись у 0; другая запись у 93
```

Те же числа на зеркале (`--dir ~/.cache/gunmetal-re/game`) — данные не зависят
от drvfs-латентности; каталог `sounds.sub` ищется в обоих написаниях
(`sounds`/`Sounds`), потому что в установке он лежит рядом с `SOU.IDX`.

То есть `528 = 137 + 391`, а `137 = 95 + 42`: 95 — имена, для которых в
`sounds.sub` есть **левая** колонка (алиас), 42 — только правая, 391 не
упомянуто вовсе. Все 528 при этом находятся в каталоге напрямую, поэтому
«отсутствующих имён» в поставке нет. Число «95» в `ROADMAP.md` описывало
именно строки `sounds.sub` (и было прочитано как «ненайденные»).

## 1. Каталог: `sounds/SOU.IDX` + `SOU.DAT`

`SOU.IDX` — обычный BIGFILE (`docs/FORMATS.md` §1, `gm/bigfile.py`):

```
char magic[7] "BIGFILE"; u8 0x1a; u32 count;
count * { char name[8];  u32 offset; }      // имя NUL-дополненное
```

Размер блоба — разность соседних смещений, последний — до конца `.dat`.
В поставке:

| | значение | проверка |
|---|---:|---|
| записей | 999 | `gm.bigfile.BigFile` = `sound_names.load_index` |
| имена | уникальны, `A-Z0-9_+-.`, 3…8 байт | `--self-test` |
| смещения | с 0, строго возрастают, без дыр | `sum(size) == .dat` |
| `SOU.DAT` | 26 738 998 байт | `os.path.getsize` |
| блоб | 416 … 3 126 040 байт | `SOU0/SOU1/SOU2` (`docs/SOU_CONTAINER.md`) |

**Имя записи каталога — и есть разрешённое имя сэмпла.** Отдельного поля
«имя» внутри `.sou` нет; внутри — только кодек-заголовок.

`MUSIC/SOU.IDX` (3092 записи, все `SOU2`) — отдельный каталог для музыки.
Уровневое имя ищется сначала в `sounds`, при промахе — в `music` (§3.1); в
поставке фолбэк не срабатывает ни для одного из 528 имён (`--report`:
`через music: 0`), потому что все они есть в `sounds`.
528 из 999 записей `sounds` используются именами хотя бы одного уровня;
остальные 471 — UI/скриптовые/неиспользуемые (вероятно; отдельно не считались).

## 2. Таблица уровня: запись 12 `.sbt`

`SOUND_SAMPLE_TABLE` (`gm/sbt.py`, `docs/SBT_RECORDS.md`):

```
u32 counts[300];        // 0x4b0 байт — счётчики ссылок
char names[300][9];     // 0xa8c байт — NUL-дополненные имена
```

Загрузчик `0x40b670` (вызов из диспетчера записей `.sbt` — `0x45522e`):

```
0x40b677 call 0x40bcf0        ; сброс: все хэндлы 0x4ca720[i] = -1, имена пусты
0x40b68d fread(0x4cebd8, 1, 0x4b0, f)      ; счётчики (0x40dc70)
0x40b6aa fread(0x4c9c90, 1, 0xa8c, f)      ; имена (9 байт * 300)
```

Соответствие «слот имени → данные»:

| что | база | шаг | записей | адрес в коде |
|---|---|---:|---:|---|
| имена таблицы | `0x4c9c90` | 9 | 300 | `0x40b6aa`, конец `0x4ca71c` |
| хэндлы (номер записи сэмпла) | `0x4ca720` | 4 | 300 | `0x40b6f1`, `0x40bece`, `0x40bd8d` |
| счётчики ссылок (из `.sbt`) | `0x4cebd8` | 4 | 300 | `0x40b68d` |
| второй счётчик (дубликаты имён) | `0x4cf1a8` | 4 | 300 | `0x40b786` |

Предзагрузка (`0x40b6c2…0x40b703`): для каждого слота, у которого
`counts[i] > 0` **и** имя непустое, зовётся `0x40ade0(name)`; результат
кладётся в `0x4ca720[i]`. Второй проход (`0x40b70c…0x40b7b5`) обрабатывает
дубликаты имён: находит уже загруженный слот через `0x40b9c0` и переиспользует
его номер записи (счётчик ссылок уменьшается/увеличивается).

В поставке: имена занимают слоты `0..k-1` без дыр, `counts[i] >= 1` у каждого
имени (максимум 109), хвост — нули. Поэтому предзагружаются **все** имена
уровня: 5800 слотов на 36 уровней, дубликатов внутри уровня нет.

Та же раскладка пишется и в сейв: `0x40b620` — симметричный писатель
(`fwrite` `0x40ddf0` вместо `fread` `0x40dc70`), вызов `0x455ab6`; ошибки —
строки `0x4a6918` «Error saving…» / `0x4a6940` «Error loading…». Обратное
чтение таблицы из сейва не прослежено (для отчёта не нужно).

## 3. Как игра ищет сэмпл по имени

### 3.1. Цепочка вызовов

```
0x40b670 (запись 12)  ->  0x40ade0(name)
0x40ade0: [0x4c876c] == 0 -> -1                      ; звук не инициализирован
          [0x4a6820] != 0 -> 0x40af30({sounds,music}[i], name), i = [0x4c8774]
                             при неудаче i = 1 - i и повтор (0x40ae3c)
                             (i хранится между вызовами; в образе 0 = sounds)
          иначе            -> 0x40af30("sounds", name)   ; 0x4a6894
          если обе неудачны: split по последнему ':' или '\' -> dir/base
          0x40af30(dir, base)
0x40af30: ищет свободную запись 0x83d960 с 1 по 299 (ebx = 1, 0x83d97c..);
          нет свободной -> -2
          fopen(dir, base + "SOU") -> 0x40d1a0; не открылось -> -1
          читает magic, требует "SOU" + '0'/'1'/'2'; иначе -1
0x40d1a0: имя (arg2) копируется в 0x4d2ad8, обнулённые первые 8 байт,
          верхний регистр -> 0x480180 (0x40d1e6)
          ключ = первые 8 байт (0x40d1f0, 0x40d1f6 -> [esp+0x18], [esp+0x1c])
          поиск по загруженному индексу: 8 байт сравниваются как два dword
          (0x40d6b3: cmp [ecx-4],esi; cmp [ecx],edi; шаг 0xc)
          найдено -> fseek на offset записи (0x40d80e), иначе ищет в следующей
          порции индекса (по 0x400 записей)
```

### 3.2. Регистр и длина — доказано

* `0x480180` на ветке `[0x4bf120] == 0` поднимает регистр латиницы **на месте**
  (`0x480190…0x4801b8`: `cmp cl,0x61 / cmp cl,0x7a / sub cl,0x20`).
* `[0x4bf120]` **не имеет писателя** во всём образе (все 16 ссылок — чтения:
  `0x410e39`, `0x481181`, `0x4a0200`, …) и лежит в нулевой части `.data`
  (VA `0x4bf120`; `.data` = RVA `0xa3000`, VirtualSize `0x39db70`, сырых
  байт только `0x1c000`, т.е. до `0x4bf000`) — значит всегда 0, ветка
  Win32-поиска файла (`0x413670`) не выполняется.
* Ключ — ровно 8 байт и NUL-дополнение: буфер имени обнуляется
  (`0x40d1b2`, `0x40d1b8`), строка копируется целиком, но в поиск идут первые
  две dword-пары. Поэтому `ALAR` ≠ `ALARMK`, а `ABCDEFGHI` даёт ключ
  `ABCDEFGH` (в поставке имён длиннее 8 нет).
* Независимое подтверждение из данных: жёстко зашитые имена UI в коде —
  в нижнем регистре (`updown` `0x4bdf7c`, `select` `0x4bdf4c`, `vleft`,
  `vfront`, `vback`, `menuon`), а в каталоге есть только `UPDOWN`, `SELECT`,
  …; играть они могут лишь при нечувствительном к регистру поиске.

### 3.3. Индекс слота имени (`0x40b9c0`) — для «динамических» имён

`0x40b9c0(name)` (нормализация `0x40b9c2…0x40b9f1`: хвост после последнего
`\`, не больше 8 символов) ищет имя в таблице `0x4c9c90` сравнением
`0x416850` — это **регистронезависимый** `strcmp` (`0x416876…0x416898`
поднимает регистр обоих операндов). Если имени нет — занимает свободный слот
(оба счётчика `<= 0`) и подгружает сэмпл; если свободных нет — `-3`.

Коды возврата `0x40b9c0`: `>= 0` — индекс слота; `-1` — имя не влезло в 8
символов (недостижимо, обрезка идёт раньше); `-2` — `0x40ade0` не смог
загрузить (в т.ч. алиас, который сам не разрешился, `0x40bb68`); `-3` — нет
свободного слота (`0x40ba74`). `0x40b940` возвращает имя слота или строку
`"none"` (`0x4a6968`), если хэндл отрицательный.

### 3.4. Пространства имён: слот таблицы ≠ номер записи

Скрипты/двери/3D-источники передают **индекс слота** `0..299`
(`0x46b840` пишет его в 3D-очередь `+0x18` = `0x62ce30` без преобразования).
Номер записи `0x83d960` игра получает только через `0x4ca720`:

```
0x40bec0 QueueSound(idx, class, volume, pan, rate):
    idx < 0                -> выход (тишина)
    esi = [0x4ca720 + idx*4]              ; 0x40bece
    esi < 0                -> выход (тишина)   ; 0x40bed7
    request[+0x08] = esi                  ; 0x40be85 (это уже номер записи)
0x40bd80 (3D-очередь): то же, 0x40bd8d / 0x40bd94, -> 0x4cf0a8 (16 входов)
0x40ace0 PlayRecord(id, ...): id <= 0 -> выход ; 0x40ace9
0x40a4b0 PlayRecord(id, ...): id >= 300 -> -1  ; 0x40a4b7
                               size[id] <= 0 -> -1 ; 0x40a4df
```

Записи `0x83d960` выдаются по одной: `0x40af30` каждый раз берёт первую
свободную, начиная с 1 (слот 0 не используется никогда). Значит при полном
успехе загрузки `запись(i) = i + 1`; если какое-то имя не загрузилось,
нумерация следующих записей сдвигается на 1. Прямых потребителей формулы
«индекс+1» в коде не найдено — все пути идут через `0x4ca720`, поэтому сдвиг
не должен ломать воспроизведение (гипотеза, см. §7).

## 4. `sounds.sub`: алиасы, которые не работают

Формат DOS-версии (`docs/SUB.md` §5): пары `replaced<TAB>replacement`, без
счётчика и веса, 161 пара, CRLF, `latin1`.

Загрузчик v1.36 — `0x40b510` (`sounds\sounds.sub`, вызов `0x44b0a5`):

```
0x40b54d fscanf(f, "%ld", &[0x4cf6b8])      ; счётчик, формат 0x4a6910
      != 1 -> [0x4cf6b8] = 0; return -2     ; 0x40b55b
0x40b5b0 fscanf(f, "%ld %s %s", &thr, n1, n2) ; формат 0x4a68c0, 0x3 аргумента
      != 3 -> return -3                      ; 0x40b5e8
      больше 150 (0x96) -> обрезается с предупреждением 0x4a68cc
```

Первая строка поставки — `alarmk\talarmkbig`: `%ld` не сматчится, функция
возвращает `-2`, таблица пуста, вызывающий `0x44b0a5` результат игнорирует и
сразу зовёт `0x48f770` (предзагрузка жёстко зашитых UI-имён). **Алиасы в этом
билде не применяются ни для одного имени.**

Устройство таблицы (если бы загрузилась): запись 0x24 = порог (dword) +
`name1[16]` + `name2[16]`, база `0x4c8778`;
`0x40b800(name1)` возвращает `name2`, если `strcmpi` совпал **и**
`порог > [0x4bf290]` (`0x40b82a…0x40b846`; `[0x4bf290]` — класс RAM из
`0x404630`). Порогов в поставочном файле нет вовсе, так что даже с настоящим
парсером строки нечем взвесить.

Следствие для нас: 95 имён с алиасом (`alarmk`, `amboilr2`, …) не нуждаются в
подстановке — их собственные записи есть в `SOU.IDX` (`ALARMK`, `AMBOILR2`, …).
Поэтому «тишина из-за отсутствия алиаса» в поставке невозможна.

Более того, применять `sounds.sub` было бы **вредно**: из 95 имён 93 получили
бы *другую* запись, чем прямое совпадение (ни одна подстановка не совпадает с
прямой), а 2 повели бы на несуществующую цель — `alarmk` -> `alarmkbig`
(9 символов, ключ обрезается до `ALARMKBI`; в каталоге есть `ALARMBIG`, но это
другое имя) и `picksal` -> `picksalv`; в обоих случаях оригинал молчал бы.
Числа печатает `--report` (`если применить: …`), проверяет `--self-test`.

## 5. Промах: что именно делает оригинал

| этап | код | результат | падение? |
|---|---|---|---|
| имя нет в каталоге | `0x40af30` → `0x40b3f5` | `-1` | нет |
| запись не `SOU0/1/2` | `0x40b3ec` | закрыть, `-1` | нет |
| нет свободной записи | `0x40af61` | `-2` | нет |
| обрыв чтения заголовка | `0x40afa6`, `0x40b007`, `0x40b03b` | `-2` | нет |
| режим без музыки (`[0x4a6820] == 0`) | `0x40af16` | `0`, а не `-1` (номер записи 0 не выдаётся никогда) | нет |
| предзагрузка слота | `0x40b6e9` | `0x4ca720[i]` = отрицательный/0 | нет |
| имя есть только в `music` | `0x40ae3c` → `0x40af30` | грузится оттуда (тот же номер записи) | нет |
| нет ни в `sounds`, ни в `music` | `0x40af0c` | `-1` (или `0`, см. ниже) | нет |
| проигрывание по индексу слота | `0x40bec0` / `0x40bd80` | `idx < 0` или `хэндл < 0` → выход | нет |
| проигрывание по номеру записи | `0x40ace0` / `0x40a4b0` | `id <= 0`, `id >= 300`, `size == 0` → выход | нет |

Лог при промахе есть **только** у жёстко зашитых имён:

* `Warning:  Unable to load sample UPDOWN` (`0x4bdf54`, вызов `0x48f78e`;
  аналогично `SELECT`, `VLEFT`, `VFRONT`, `VBACK` — `0x48f7b6`, `0x48f7da`,
  `0x48f7fe`, `0x48f822`). Список предзагрузки — 7 имён: `updown`, `select`,
  `vleft`, `vfront`, `vback`, `menuon`, `selectm` (`0x48f770`); у последних
  двух своих сообщений нет: `0x48f846`/`0x48f86f` проверяют чужой хэндл
  (`0x4bc464`, VBACK) и печатают текст VBACK — копипаст-баг оригинала;
* `Unable to load sample '%s' for song '%s'` (`0x4a6848`, `0x40ac55`) — сэмплы
  песни `.sog` (`0x40ab20`);
* `Error loading sound sample table info.` (`0x4a6940`, `0x40b7c6`) — не
  прочиталась сама запись 12.

У имён из `SOUND_SAMPLE_TABLE` **своего сообщения нет**: `0x40b6e9` просто
сохраняет код. То есть в оригинале промах уровня — молчаливая тишина
(«не падение» подтверждено, «лог» — нет).

## 6. Контракт для движка (M7.6)

Что должен делать наш загрузчик (C++/Python), чтобы совпасть по поведению и
при этом быть диагностируемым:

1. **Ключ имени.** Взять имя слота как есть (≤ 8 байт), отрезать каталог по
   последнему `\`/`:` (как `0x40ade0`), привести к верхнему регистру ASCII и
   дополнить NUL до 8 байт. Сравнивать с именами записей каталога как 8 байт
   (не как C-строку): `ALAR` не должен совпадать с `ALARMK`.
2. **Обрезка.** Имя длиннее 8 байт обрезается (в поставке таких нет; в нашем
   движке — предупреждение, потому что это почти наверняка ошибка данных).
3. **Алиасы.** `sounds.sub` **не загружать** (в v1.36 он мёртв); если появится
   файл с счётчиком и порогами — читать `count`, затем `threshold name1 name2`
   и применять при `threshold > ram_class`.
4. **Промах.** Не исключение и не падение:
   * резолвер возвращает `-1` (имя не найдено) или `-2` (нет свободной записи /
     битый заголовок) — как `0x40af30`; вызывающему отдаём `std::optional`
     либо `int` с отрицательным значением;
   * `log(WARN)` один раз на пару `(уровень, слот, имя)`, с полями
     `level`, `slot` (0…299), `name`, `code`, `reason` — это **наше**
     улучшение: оригинал для имён таблицы молчит (см. §5), поэтому лог не
     ломает паритет по поведению (звука всё равно нет), но объясняет тишину;
   * слот помечается «нет сэмпла», повторных попыток загрузки нет.
5. **Проигрывание.** `sample(slot)`: `slot < 0 || slot >= 300` → выход;
   хэндл слота `< 0` → выход; `size == 0` → выход. Возвращаем `false`
   (оригинал: `-1` из `0x40a4b0`, `0` из `0x40ace0`). Фолбэк на другой
   *индекс/имя* оригинал не делает; единственный фолбэк — другой каталог
   (`sounds` → `music`), его и повторяем (п. 1: если имени нет в `sounds`,
   проверить `MUSIC/SOU.IDX`; при попадании — лог `INFO` «взято из music»).
6. **Индекс слота ≠ номер записи.** Наружу (скрипты, двери, 3D) отдаём индекс
   слота `0..299`; номер записи — внутренний, через таблицу хэндлов.

Инструмент (`sound_names.load_index` / `resolve`) реализует пункты 1–3 и
печатает коды так же, как оригинал (`-1` при промахе).

## 7. Доказано / гипотеза / осталось

**Доказано (код):**

* формат записи 12 и её загрузка: `0x40b670` (размеры `0x4b0`/`0xa8c`,
  базы `0x4cebd8`/`0x4c9c90`/`0x4ca720`);
* поиск записи в каталоге: `0x40d1a0` → `0x480180` (верхний регистр) →
  ключ 8 байт (`0x40d1f0`) → сравнение dword-парами (`0x40d6b3`);
* фолбэк каталогов: `0x40ae10` читает `[0x4c8774]` (в образе 0), берёт
  `{sounds, music}[i]` из массива `0x4a6828` (два 16-байтных имени), при
  неудаче `0x40ae3c` пишет `1 - i` и пробует второй;
* `[0x4bf120] == 0` в образе (нет писателя, нулевая часть `.data`) — ветка
  `FindFirstFile` не выполняется;
* свободные записи выдаются с 1 (`0x40af3c…0x40af5f`), предел 300
  (`0x40af55`, `0x40a4b7`), `-2` при отсутствии свободных;
* `sounds.sub` не загружается: формат `0x40b510` против данных
  (`--self-test`, `parse_sub_v136`);
* все точки «промаха» возвращают управление без падения (§5);
* хэндл слота используется как номер записи только через `0x4ca720`
  (`0x40bece`, `0x40bd8d`), а проигрывание отвергает `id <= 0` / `size == 0`.

**Доказано (данные, `--self-test`):**

* 36 уровней, 5800 слотов с именем, 639 написаний, 528 имён без регистра,
  **0** ненайденных; 228 написаний совпадают с каталогом по регистру;
* 999 записей `SOU.IDX`, имена уникальны, в верхнем регистре, ≤ 8 байт;
  размеры покрывают `.dat` без дыр;
* 95/42/391 — разбиение 528 имён по колонкам `sounds.sub`;
* ни одно имя уровня не разрешается через `music` (все 5800 ссылок — `sounds`);
* ни одного имени вне `^[A-Za-z0-9_+.\-]{1,8}$` и ни одного длиннее 8 байт.

**Гипотеза:**

* `запись(i) = i + 1` при отсутствии промахов и сдвиг номеров после промаха
  (§3.4): формула выведена из порядка выдачи записей, но ни один потребитель
  «индекс+1» в коде не найден — все идут через `0x4ca720`, так что сдвиг,
  скорее всего, безвреден. Проверять эмуляцией/трассой, не нужно для M7.6.
* 471 запись каталога, не упомянутая ни в одном `.sbt`, — UI/скриптовые
  звуки; поимённо не сверялось.

**Осталось:**

* точная роль `[0x4a6820]` (флаг читают `0x40aa10`/`0x40aa40` и `0x40ade0`;
  пишется один раз из `0x40c420` → `0x40a970` как `arg == 0`): при 0 промах
  даёт `0` вместо `-1`. На поведение (тишина) не влияет;
* алиасы, если понадобится поддержать другой билд: сверить пороги
  `sounds.sub` с `[0x4bf290]` (класс RAM, `0x404630`) — в поставке порогов нет;
* строка «95» в `ROADMAP.md` — переформулировать в «95 имён имеют строку в
  `sounds.sub`, который не загружается» (делает основной агент: `ROADMAP.md`
  сабагенту не принадлежит).
