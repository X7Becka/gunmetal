# `.sbv` — видео/анимации Gunmetal

Статус: **контейнер, декодер и энкодер пиксельного кодека разобраны**.
Реализация: `gm/sbv.py` (контейнер + декодер + энкодер), проверка:
`tools/re/sbv_codec.py`, C++-порт декодера: `engine/src/res/sbv_video.cpp`
(сверен с Python на выборочных кадрах всех трёх клипов).

Дизасм — `gundx.exe` (загрузчик `0x49e1e8`, плоскости `0x49ee8c`, блоки
`0x49f4db`, лифтинг `0xa1d940`/`0x49f1e3`, раздвижка `0x49f43a`,
энтропийный декодер `0xa1d000`, YUV→RGB `0x49e33b`). Транслитерация
1:1 — `gm/sbv.py`; здесь описаны структура, кодирование и round-trip.

## 1. Поставка

Все клипы лежат в `Vid/`, геометрия у всех одна — **320×160**, 15 fps
(шаг метки ≈ `1000/15` = 66.67 мс, первая метка 67, последняя
`frames * 200/3`), блоки внутрикадровые, без кросс-кадрового состояния.

| файл | размер | кадров | `data_start` | метки, мс | размер блока, байт |
|---|---:|---:|---:|---|---:|
| `Intro.sbv` | 2 811 092 | 500 | 4 016 | 67 … 33 333 | 1 572 … 13 928 |
| `orient.sbv` | 35 005 220 | 4 523 | 36 200 | 67 … 301 533 | 1 456 … 13 560 |
| `winner.sbv` | 15 343 896 | 1 820 | 14 576 | 67 … 121 333 | 1 456 … 14 732 |

Итого 6 843 кадра, 53.2 МБ. Вариантов контейнера один (`SBV0`), палитры нет
(см. §4), «сырые»/RLE-кадры и копии кадров не встречаются — все кадры
самостоятельные, чисто внутрикадровые.

Минимальный блок (1 456 байт) — полностью статичный кадр: три заголовка
плоскостей (по 8 байт), три базовые сетки (800 + 200 + 200 байт) и
энтропийный поток из одних «нулевых» блоков.

## 2. Контейнер

```
char magic[4];      // "SBV0"
u32  width;         // 1..0x140 (320): загрузчик 0x49e1e8 отвергает шире
u32  height;
u32  frame_count;
frame_count * {
    u32 timestamp_ms;   // метка воспроизведения
    u32 end_offset;     // кумулятивный конец блока от data_start
};
data...
```

`data_start = 16 + 8*frame_count`. Кадр *i* занимает
`[data_start + end[i-1], data_start + end[i])` (`end[-1] = 0`), последний
`end` точно равен размеру файла — проверено на всех трёх клипах
(`gm.sbv.validate`). Смещения монотонны; отрицательный размер блока и
выход за EOF отвергаются при разборе.

`gm/sbv.py:build()` собирает контейнер обратно из блоков, а
`Sbv.to_bytes()`/`Sbv.rebuild()` — обратная операция к `parse()`.
Пересборка всех трёх файлов **побайтово точна** (таблица пересчитывается
из длин блоков, блоки переносятся как есть).

## 3. Пиксельный кодек

### 3.1. Плоскости

Кадр — три плоскости **знаковых 16-битных** сэмплов:

* яркость `Y`: `W×H`;
* две цветности `C0`, `C1`: `(W/2)×(H/2)`.

Никаких 8-битных индексов и палитры в потоке нет. YUV→RGB (`0x49e33b`),
`clamp` в 0..255, `C0`/`C1` берутся в `(x>>1, y>>1)`:

```
r = clamp((Y + C0      + 8) >> 4)
g = clamp((Y - C0 - C1 + 8) >> 4)
b = clamp((Y + C1      + 8) >> 4)
```

Движок прогоняет эти байты через три таблицы по 256 dword
(`0x4a6a40`/`0x4a6e40`/`0x4a7240`) — судя по всему, гамма-рампа вывода; в
toolkit отдаётся естественный 8-битный RGB (так же поступает C++-порт).

### 3.2. Пирамида

Каждая плоскость реконструируется «снизу вверх» тремя уровнями. Уровни
одинаковы для яркости и цветности, если считать в координатах самой
плоскости: `(W/4, H/4)` → `(W/2, H/2)` → `(W, H)`.

1. **База.** Из потока читаются `i32 lo`, `i32 hi`, затем по байту на
   сэмпл самой грубой сетки `(W/4)×(H/4)` — только на чётные позиции
   (чётная строка, чётный столбец), т.е. `(W/8)×(H/8)` байт. Сэмпл:
   `(int)(byte * (hi - lo) / 256.0 + lo)` (усечение к нулю; деление на
   double `256.0`, `0x4a2ac0`).
2. **Блоки.** Энтропийный поток заполняет **3/4** сэмплов сетки: в
   каждом блоке `factor×factor` (`factor = 4` на первом уровне, далее 8)
   передаются нечётные столбцы чётных строк и все столбцы нечётных строк.
   Оставшаяся 1/4 (чётное/чётное) — вход с более грубого уровня.
3. **Лифтинг** `_filt_edges` = `_lift_2d` + правка нижних двух строк и
   правого края. Обратимый целочисленный (u16) лифтинг.
4. **Раздвижка** `_spread`: сэмплы уровня `S` кладутся в чётные/чётные
   позиции уровня `2S`; остальное заполнит следующий шаг блоков.

Порядок вызовов (совпадает для обеих цветностных плоскостей и для
яркости, только с разными стартовыми размерами):

```
scatter(W/4,H/4,4) -> filt(W/4,H/4) -> spread(W/4,H/4)
scatter(W/2,H/2,8) -> filt(W/2,H/2) -> spread(W/2,H/2)
scatter(W,H,8)     -> filt(W,H)
```

### 3.3. Энтропийный поток (`0xa1d000`)

Биты читаются MSB-first из 32-битных little-endian слов. На блок:

* унарный код **класса** + (если код ненулевой) бит знака, DPCM от
  предиктора `pred1`; класс `0` — блок целиком нулевой; класс `>= 0x11` —
  «конец плоскости» (в поставке не встречается);
* если класс не 0: унарный код **экспоненты** + бит знака, DPCM от
  `pred2`; `step = 1 << (e & 31)`; затем бит знака блока;
* полезная нагрузка класса:
  * **класс 1**: на слот — бит «ненулевой?», при 1 знак: значение `±step`;
    если курсор выровнен на 4 слота (16 байт), один бит `0` кодирует
    сразу четыре нуля;
  * **класс 3**: как класс 1, но значение `(1 + число единиц) * step`,
    бит знака читается **до** серии единиц;
  * классы 2 и 4..16 — «семейные» обработчики, в поставке не встречаются.

Классы в поставочных файлах: `{0: 6 526 044, 1: 3 001 203, 3: 2 790 153}`
на 12.3 млн блоков; `FAMILY_BLOCKS = 0`.

Битовая раскладка кадра: каждая плоскость начинает **своё** 32-битное
слово (`st.bc = 0`), после последнего блока плоскости остаток слова
отбрасывается. Поэтому энкодер дописывает неполное слово нулями в конце
каждой плоскости; байты заголовка/base-сетки идут подряд, без выравнивания.

## 4. Палитры нет

Требование «8-битные индексы + палитра» к `.sbv` **неприменимо**: поток
кодирует знаковые 16-битные Y/C-сэмплы, а не индексы. Поэтому:

* `Sbv.to_png(index, palette)` принимает `palette` только для совместимости
  сигнатуры (валидируется как 256 BGRA = 1024 байта) и **игнорирует** его;
* `decode_frame(index)` возвращает упакованный 8-битный RGB;
* `encode_frame(planes)` принимает именно plane-буфер (формат
  `decode_frame_planes`), а не индексы.

## 5. Энкодер (`encode_frame`)

Энкодер — точная инверсия декодера, а не клон «оригинального»
компрессора (в `gundx.exe` его нет):

1. `_inv_filt_edges` — обратный лифтинг. Расписание: полосы по две строки
   сверху вниз, в каждой сначала вертикальный проход (строки `r..r+3`,
   пишутся `r+1` и `r+2`), затем горизонтальный по строкам `r`, `r+1`.
   Инверсия идёт в обратном порядке: горизонтальный проход полосы
   (справа налево), затем вертикальный. Формулы:
   * вертикаль: `B -= (A + C + 1) >> 1`, затем `C += (D + B + 2) >> 2`;
   * горизонталь (для `i` справа налево): `X[i-1] -= (X[i-2] + X[i] + 1) >> 1`,
     затем `X[i] += (X[i-1] + X[i+1] + 2) >> 2`;
   * плюс обратные правки нижних двух строк/правого края (`_filt_edges`).
   Все операции — u16 с обёрткой по модулю `2^16`, поэтому обратимы
   побитово.
2. **3/4** сэмплов каждого уровня считываются в порядке раскладки
   `_scatter_blocks`, путь **B** (row-major): для `k = 0, 2, …` — нечётные
   столбцы строки `i+k`, затем все столбцы строки `i+k+1`.
3. **1/4** (чётное/чётное) становится входом следующего, более грубого
   уровня; после трёх шагов это базовая сетка.
4. Базовая сетка квантуется обратно в 8 бит. Референсный компрессор
   брал `lo = min(sample)` и `hi` так, чтобы код 255 попадал в максимум;
   энкодер ищет `span = hi - lo` небольшим ограниченным перебором
   (`span_dec … span_dec + 700`) и проверяет, что каждый сэмпл точно
   представим. Если точной сетки нет (шум на весь 16-битный диапазон),
   включается равномерный fallback и счётчик `gm.sbv.LOSSY_PLANES`
   увеличивается — такой кадр честно помечается как приближённый.
5. Блоки кодируются только классами **0** и **3**: класс 0 — весь блок
   нулей (один унарный код), класс 3 — любые остатки
   `±(1 + run) * step`, где `step` — наибольшая степень двойки, делящая
   все ненулевые значения блока. Бит знака блока всегда `0`, поэтому
   декодер всегда идёт по пути B. Предикторы `pred1`/`pred2`
   сбрасываются на каждом уровне, как в `_scatter_blocks`.

Валидность потока подтверждается независимо: C++-порт
(`engine/src/res/sbv_video.cpp`) декодирует пересобранные блоки в тот же
RGB (см. §7).

## 6. API `gm/sbv.py`

Существующий API сохранён (`parse_file`, `parse`, `validate`, `build`,
`frames(blob)`, `frame(blob, i)`, `to_bytes(blob)`, `decode_frame_planes`,
`planes_to_rgb`, `decode_frame_rgb`); добавлено:

```python
clip, blob = sbv.parse_file(path)
clip.frames()                  # -> [Frame] (blob запоминается в parse())
clip.frame(i)                  # -> Frame
clip.decode_planes(i)          # сырой signed-16 plane-буфер
clip.decode_frame(i)           # RGB (top-down, 3 байта/пиксель)
clip.to_png(i, palette=None)   # PNG-байты
clip.to_bytes()                # == blob для поставочных клипов
clip.rebuild()                 # алиас to_bytes

block = sbv.encode_frame(planes, width, height)   # точный round-trip
block = sbv.encode_frame_rgb(rgb, width, height)  # приближённо (Y/C-матрица
                                                  # в exe не хранится)
```

Диагностика: `sbv.FAMILY_BLOCKS` (декодер, приближённые классы) и
`sbv.LOSSY_PLANES` (энкодер, базовая сетка не влезла в 8 бит).

## 7. Round-trip и проверки

`tools/re/sbv_codec.py`:

```sh
python3 tools/re/sbv_codec.py --check                 # весь Vid/*.sbv
python3 tools/re/sbv_codec.py --check --jobs 16 --json
python3 tools/re/sbv_codec.py Intro.sbv --png 42 --out frame.png
python3 tools/re/sbv_codec.py --self-test
```

`--check` по каждому кадру считает: декодирование, `decode(encode(decode))`
(попиксельно), побайтовое совпадение пересобранного блока с поставочным и
пересборку контейнера целиком.

### 7.3. `encode_frame_rgb`

Обратная Y/C-матрица в `gundx.exe` не хранится (движок идёт Y/C → RGB),
поэтому RGB→плоскости — алгебраическое приближение: на кадре 250 `Intro`
средняя абсолютная ошибка после `encode_frame_rgb` → decode = **0.59**
уровня, максимум 3, p99 = 2. Для точного round-trip используйте
`encode_frame` на декодированных плоскостях.

## 8. Ограничения

* Геометрия: ширина ≤ 320, высота ≤ 1024 (границы загрузчика). Энкодер
  требует **кратности 32** обеих сторон — иначе какой-то уровень
  пирамиды не делится на `factor` и раскладка блоков выходит за плоскость.
  Декодер исторически проверяет только `%16`/`height >= 32`: для кадров
  вроде 320×48 раскладка блоков цветностной плоскости выходит за её
  пределы (результат не определён — записи уходят в соседнюю плоскость).
  В поставочном корпусе таких нет, все кадры 320×160; энкодер их отвергает.
* Базовая сетка — 8-битная: произвольный 16-битный шум кодируется с
  потерями (`LOSSY_PLANES`); поставочные кадры кодируются без потерь.
* Энкодер не воспроизводит **биты** оригинального компрессора: классы
  (0/3 вместо 0/1/3) и экспоненты выбираются иначе, поэтому блок обычно
  на 1–5 % больше. Побайтовое совпадение блоков достигается только там,
  где поток тривиален (полностью статичные кадры — все блоки класса 0).
  Это не ошибка кодека: обратное преобразование из декодированных
  плоскостей неоднозначно.
* `decode_frame_rgb`/C++ не применяют таблицы гаммы `0x4a6a40`/…: цвет
  соответствует «естественному» RGB, а не тому, что видно в игре.
* Энкодер — Python. Полный прогон `--check` по корпусу — примерно **57
  минут на одно ядро** (декодирование доминирует: ~0.2–0.35 с на кадр,
  кодирование ~0.06–0.08 с); `--check --jobs 16` на этой машине — 3m41s
  изолированно (до ~5 мин при фоновой нагрузке).

## 9. Интеграция в `gm.py` (не меняя файл)

`gm.py` уже умеет `sbv FILE [OUT] [--png DIR] [--frames SPEC] [--scale N]
[--rebuild DIR]`. Точечные строки, если понадобится расширить команду:

1. PNG одного кадра через новый API (вместо ручного `decode_frame_rgb`):

   ```python
   # в cmd_sbv, ветка opts.png
   with _wopen(out, opts) as f:
       f.write(clip.to_png(i))          # вместо png.rgb(W, H, rgb)
   ```

2. Проверка кодека без внешнего скрипта:

   ```python
   # новая подкоманда или флаг --verify
   planes = clip.decode_planes(i)
   again = sbv.decode_frame_planes(
       sbv.encode_frame(planes, clip.width, clip.height),
       clip.width, clip.height)
   assert again == planes
   ```

3. Запись клипа из RGB-кадров (энкодер пикселей):

   ```python
   blocks = [(i * 1000 // 15, sbv.encode_frame_rgb(rgb, clip.width, clip.height))
             for i, rgb in enumerate(frames)]
   blob = sbv.build(clip.width, clip.height, blocks)
   ```

4. Диагностика после `--png`:

   ```python
   if sbv.LOSSY_PLANES:
       print(f"warning: {sbv.LOSSY_PLANES} plane(s) re-quantised", file=sys.stderr)
   ```
