# Экран сообщений об убийстве (`KILLED.skb` / `.skk`) — `M8.4`, срез 3

**Статус:** модуль `engine/src/ui/killed.{h,cpp}` + тест `killed`
(`engine/tests/test_killed.cpp`, CTest label `quick`, **133 проверки**).
Сторона данных экрана: файл читается построчно, применяется фильтр строк
загрузчика игры, `%S` заменяется именем игрока, выбор строки — детерминированный.
**Без** отрисовки, шрифтов, пагера, состояния экрана и `GameRuntime`
(CLI `--killed` добавлен в срезе 4).

Канон поведения — `docs/SUB.md` §7 (загрузчики `0x485a00`/`0x485b2f`), формат —
`docs/FORMATS.md` §8.2. Python-оракул (`gm/small.py::parse_kill`,
`gm.py misc`) читает те же файлы, но **не** применяет фильтр длины; его числа
(73 и 91 «сообщений») — это все непустые строки, а не то, что попадает в
массивы игры (см. §1).

Проверка:

```sh
cmake --build build/sandbox --target gm_killed_tests -j 4
./build/sandbox/engine/tests/gm_killed_tests
ctest --test-dir build/sandbox -R '^killed$' --output-on-failure
python3 regress.py --mirror --json
```

## 1. Что доказано (код игры и данные поставки)

| факт | значение | источник |
|---|---|---|
| один загрузчик на два файла | `0x485a00` (`.skk`) и `0x485b2f` (`.skb`) в одной функции | `SUB.md` §7 |
| открытие | `fopen(..., "r")` — **текстовый** режим, строка `0x4a6888` | `SUB.md` §7 |
| чтение | `fgets(buf, 0x400, f)` (`0x40e050`), то есть построчно, до 1023 байт за раз | `SUB.md` §7 |
| фильтр строки | `0 < strlen(line) < 0x20` (`0x485a7d`); в текстовом режиме CRLF уже `LF`, а `fgets` оставляет `\n`, поэтому видимый текст — **1..30 байт** | `SUB.md` §7 |
| предел сообщений | `0x80` = 128 на массив, счётчики `0x68ddb8` (`.skk`) и `0x68ddb4` (`.skb`) | `SUB.md` §7 |
| массивы сообщений | `0x662d60` (`.skk`) и `0x67fd38` (`.skb`) | `SUB.md` §7 |
| подстановка | любой `%<символ>` нормализуется в `%s` (`0x485ad6`..`0x485ae1`), значит `%S` файла — плейсхолдер | `SUB.md` §7 |
| поставка `.skb` | 2338 Б, FNV-1a64 `0xcbcf7b50e7241960`, 92 строки CRLF, 91 непустая | файл, 1/1 |
| поставка `.skk` | 1967 Б, FNV-1a64 `0xe1eeeb2572c7b0e1`, 74 строки CRLF, 73 непустых | файл, 1/1 |
| проходит фильтр `.skb` | **69 из 91** (22 строки длиннее 30 байт) | `SUB.md` §7 — совпало 69/69 |
| проходит фильтр `.skk` | **50 из 73** (23 строки длиннее 30 байт) | `SUB.md` §7 — совпало 50/50 |
| плейсхолдеры в файле | `.skb` 182 (`%S` 109 + `%s` 73), `.skk` 73 (`%S` 44 + `%s` 29) | подсчёт по байтам, 2/2 |
| плейсхолдеры в принятых строках | `.skb` **138**, `.skk` **50** | подсчёт по принятым строкам |
| первая/последняя принятая `.skb` | `%S MUTILATES %S.` … `%S KILLS %S.` (самая первая строка файла — `%S PUTS %S TO FIRE AND THE SWORD.`, 33 байта, отбрасывается) | файл |
| первая/последняя принятая `.skk` | `%S BITES THE BIG BULLET` … `%S IS DEAD.` | файл |
| EOL | CRLF в обоих файлах, файл кончается `CRLF CRLF` (пустая строка) | `file(1)`, `SUB.md` §1 |

Число принятых строк совпало с `docs/SUB.md` §7 («реально загрузятся 50 из 73
строк `.skk` и 69 из 91 строк `.skb`») — это и есть проверка фильтра: тест
считает те же числа **независимо** от модуля (свой CRLF-сплит и свой счётчик
плейсхолдеров) и сверяет с `load_killed`.

Python-оракул даёт другие числа осознанно: `parse_kill` — чистый round-trip
текста без фильтра, поэтому `gm.py misc` печатает `73 messages` и
`91 messages`. Оба набора чисел верны для своих задач.

## 2. Что модель, а не порт

1. **Какой файл читается — наш выбор.** Оригинал заполняет **оба** массива из
   двух файлов (`0x662d60` и `0x67fd38`); привязка «какой экран какой массив
   печатает» не доказана. `load_killed` предпочитает `KILLED.skb` (91 строка,
   шаблоны на два имени) и берёт `KILLED.skk`, только если `.skb` нет;
   `KilledScreen::source` называет прочитанный файл.
2. **Одно имя, не два.** Шаблоны `.skb` содержат два плейсхолдера
   (`%S KILLS %S.`) — в deathmatch это убийца и жертва. API принимает одно
   `player_name`, поэтому оба места получают одно и то же имя.
3. **`substitution_count()` считает `%S` и `%s`**, а не только верхнее
   написание: движок нормализует `%<c>` в `%s`, и в данных встречаются оба
   (`.skk` 44 + 29).
4. **Другие `%` не трогаются.** Движок превратил бы `%O` в `%s` и подставил бы
   имя; в поставке таких строк нет, поэтому модуль заменяет только `%S`/`%s`,
   а остальные `%` сохраняет (проверено на `50% OFF, %S AND %s.`).
5. **Строка из одних пробелов/табов считается пустой и пропускается.** Движок
   сохранил бы пробелы как сообщение (`strlen` = число пробелов + 1), но оно
   ничего не печатает. В поставке таких строк нет (§1: пробельных строк 0).
6. **`NUL` внутри строки обрезает её** — как `strlen` в движке: сообщение это
   байты до первого `NUL`, и фильтр длины применяется уже к ним.
7. **Размер файла ограничен 64 КиБ** — модель против случайного пути; в
   поставке 2338 и 1967 Б.
8. **Имя игрока — до 15 байт**: слот имени в сейве 16 байт
   (`0xfc`..`0x10c`, `docs/SAVE_FIELDS.md` §2.1, значение поставки `K-9`).
   `NUL` в имени — отказ.
9. **Пустое имя разрешено только без плейсхолдеров**: иначе `%S` ушёл бы в
   текст как есть, поэтому `load_killed` отказывает.
10. **`pick()` — модель.** Какой именно строкой игра отвечает на смерть
    (её ГПСЧ и точка вызова) здесь не документировано, поэтому индекс —
    `seed % lines.size()`; это детерминированно и проверяемо.
11. **Длина строки считается по байтам, не по code points** — как `strlen`.
    Файлы поставки чистый ASCII, но битые/высокие байты читаются как байты
    (тест `killed` проверяет и это).

## 3. API и числа теста

```cpp
struct KilledLine { std::string raw; std::string text; };
struct KilledScreen { std::vector<KilledLine> lines; std::string source; };

bool load_killed(const std::filesystem::path& game, const std::string& player_name,
                 KilledScreen& screen, std::string* error);
std::string pick(const KilledScreen& screen, std::uint32_t seed);
std::size_t substitution_count(const KilledScreen& screen);
```

Константы (`ui/killed.h`): `kKilledMaxLineChars = 30`, `kKilledMaxMessages = 0x80`,
`kKilledMaxNameBytes = 15`, `kKilledMaxBytes = 64 KiB`, `kKilledPlaceholder = "%S"`,
`kKilledPrimaryFile = "FRONTEND/KILLED.skb"`, `kKilledFallbackFile = "FRONTEND/KILLED.skk"`.

`raw` — строка файла без EOL и без подстановки, `text` — она же с именем.
Отказ (`false` + `error`) не меняет прежний `KilledScreen` (запись только после
всех проверок) — это проверено и для каждой негативной ветки.

Дополнительно тест проверяет: `raw` не содержит `\r` ни в одной строке; LF-only,
смешанные EOL и файл без финального перевода строки читаются; строка с `NUL`
обрезается; высокие байты (`\x80\x81\xff\xfe`) и битая UTF-8
(`\xc3\x28 … \xc3\xa9`) читаются как байты без крэша; два прогона дают те же
строки, `source` и `substitution_count`.

## 4. Ограничения

- **Экран не рисуется.** Нет ни шрифтов, ни пагера, ни фона: `ui/killed.*` —
  только строки. Плитка kill-list (`killtile` 80×16, `0x6eb820`,
  `docs/UI_SCREENS.md` §9, `docs/UI.md` §7.1), рамка, цвета
  и координаты экрана не реализованы.
- **Пагер не используется**: `FRONTEND/KILLED.skb` — не SML-документ, поэтому
  `ui/sml_pager.*` и `ui/pager_render.*` к нему не применимы; 320×200-кадр
  экрана не собирается.
- **CLI — есть (срез 4):** `--killed NAME [--killed-all] [--killed-seed N]`
  печатает `lines/subs/seed` и выбранную строку (`seed % n`); проверено:
  `--killed PLAYER --killed-seed 999` → `lines=69 subs=138`,
  `PLAYER SENDS PLAYER TO THE BONEYARD.` (строка 33). CTest `cli_killed`,
  `cli_killed_all`. Отрисовки 320×200 по-прежнему нет.
- **В `GameRuntime` не подключено**: смерть игрока (`state=7`,
  `docs/GAME_OVER.md` §2, событие `-7 SYSTEM_PLAYER_KILLED`) сообщений отсюда не
  берёт.
- **Два имени не поддержаны** (§2.2), **выбор файла — модель** (§2.1),
  **`pick` — модель** (§2.10).
- `res/*`, `ui/pager_render.*`, `main.cpp`, `config.*`, `ROADMAP.md` не
  изменялись.
