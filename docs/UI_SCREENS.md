# Экраны фронтенда: карта, переходы, load/save, options

Документ описывает **экранный автомат оболочки** Gunmetal (`gundx.exe`,
ImageBase `0x400000`): какие состояния существуют, какой код их рисует,
куда ведут переходы, как устроены загрузка/сохранение, опции, наборы
клавиш и звуки интерфейса. Всё проверяется по байтам исполняемого файла
и по эталонной установке `/mnt/d/games/Gunmetal 3dfx` (v1.36).

Инструмент: `tools/re/ui_screens.py`

```sh
python3 tools/re/ui_screens.py --map       # таблица экранов и переходов
python3 tools/re/ui_screens.py --assets    # инвентарь установки
python3 tools/re/ui_screens.py --json      # полный отчёт (включая пункты)
python3 tools/re/ui_screens.py --self-test # 498 проверок по бинарю и файлам
```

`--self-test` сверяет: таблицу переходов `0x4883d8` и все 33 записи
(stub'ы), строки заголовков, immediate-записи `rows`/`step`, каждый статический
пункт меню (label, id, x, base row), сайты переходов, save/KEYCFG-строки,
UI-звуки (имя, хендл, сайт загрузки/проигрывания) и размеры BMP.IDX.
Текущий результат — `self-test: 498/498 checks passed`.

Инструмент ничего не пишет в установку и не использует Ghidra: только
`tools/re/exelib.py` (дизассемблер + образ) и чтение файлов игры.

## 1. Автомат состояний

Состояние фронтенда — dword `0x4bc440`. Диспетчер `0x487e71`:

```
eax = [0x4bc440] - 5
if eax > 0x20: ...            ; состояния 0..4 обрабатываются отдельно
jmp [eax*4 + 0x4883d8]
```

`0x4883d8` — таблица из **33 входов** (id 5..37). Вход — либо короткий
stub (8–16 байт), либо адрес общего эпилога `0x487f64`. Stub при
необходимости кладёт аргумент и вызывает обработчик, затем прыгает на
эпилог:

```
487e8e: mov ecx,[0x68cd7c]    ; аргумент (индекс набора клавиш)
487e94: push ecx
487e95: call 0x4892d0         ; обработчик экрана
487e9d: jmp 0x487f64
```

Экран без обработчика — stub `0x487f64` (`mov eax,[state]; cmp eax,0x1c; ...`),
то есть просто общий эпилог. Такие id: **7, 8, 15, 28, 29, 31**.

Состояния 0..4 в таблицу не входят:

| id | что это | доказательство |
|---:|---|---|
| 0 | intro video | `0x499fc0`; по завершении `0x487709` ставит state 1 |
| 1 | главное меню | карусель `0x486740..0x48694f`, 7 пунктов |
| 2 | SML-пагер (help/credits/briefing) | `0x487b69` → `0x4972f0`, `0x498600/0x4986b0/0x498750` |
| 3 | переход брифинга | `0x4882d6` |
| 4 | переход брифинга | `0x4882d1` |

Состояние **34 — однофреймовый алиас 35**: обработчик ввода `0x48e212`
(`cmp ebp,0x22; mov ebp,0x23; mov [0x4bc440],ebp`) переписывает 34 в 35
до следующего кадра. Оба id смотрят на один и тот же stub `0x487e8e`,
поэтому визуально это один экран.

## 3. Как рисуется пункт

Единой таблицы «строка → действие» нет: каждый обработчик сам вызывает
отрисовщик `0x485dd0(text, font, centered, x, row, item)`. Аргументы
кладёт вызывающий (cdecl, справа налево):

* `item == -1` — невыделяемый текст, `row` — абсолютная координата y;
* `row < 0` — абсолютная координата `y = -row`;
* `row >= 0` — `y = row + item * [0x662d58]` (номер пункта задаёт строку);
* если `item == [0x68ccf4]` и текст не пуст, шрифт принудительно `4`
  (`0x485e19`) — подсветка;
* `x` — смещение внутри полосы 196 px; текст компонуется в копию
  `0x6865f8`, куда `0x486050` копирует 196×131 байт из `0x6d2b60`;
* шрифт заголовка — 5, пунктов — 0, подсветки — 4.

Слайдеры: `0x486070` копирует `SLIDE` (72×8) в копию платы, `0x4860b0` —
`KNOB` (8×8); это **маскированные блиты одного спрайта** с шагом строки
`0xc4` = 196 (ширина копии платы), а `0x67f0c8` — буфер картинки `KNOB` (не
«8 пар координат»). Уточнено 2026-10-23 по `0x486070`/`0x4860b0`/`0x4833e0`
(см. `docs/MENU_RENDER.md` §3.5). Чекбокс — `0x4833e0`
(`CHECK` 8×16 / `NOCHECK` 8×8, второй рисуется на 8 строк ниже). Полоса
слота сейва — `0x48ab90` (10 копий `FILESLOT` 124×10). Стрелки списка —
`0x485cc0`/`0x485d00` (вторая — та же `MENUARRW`, повёрнутая на 180°).

## 5. Загрузка и сохранение

### 5.1. Список слотов

Загрузчик списка — `0x48f970`. Цикл:

```
for (slot = 0; slot < 20; slot++) {
    if (read_name(slot, &table[slot], 0x13) == 0)
        strcpy(&table[slot], "::: empty slot :::");   // 0x4bc3b0
}
```

* таблица имён: `0x6c2fe0`, шаг **0x13** (19 байт), конец `0x6c315c`;
* `(0x6c315c - 0x6c2fe0) / 0x13 = 20` слотов;
* `read_name` = `0x455d90`: открывает `savegame\saved%d.sbt` (`0x4ab460`)
  и копирует имя из заголовка сейва (см. `SAVE.md`: `name[0x50]` в `+0`);
  парный мир лежит в `savegame\saved%d.sbw` (`0x4ab478`);
* пустой слот подписывается `::: empty slot :::` (`0x4bc3b0`).

Экран показывает **6** слотов, прокрутка `0x68ccdc` в диапазоне **0..13**
(условия `scroll > 0` и `scroll + 6 < 20` в `0x48aa60`/`0x48abd0`);
перерисовка — `0x485d00`/`0x485cc0`.

### 5.2. Ввод имени и запись

Состояние 15 (ветка `cmp ebp,0xf` в `0x48b691`), буфер `0x661280`:

* при входе буфер заполняется как `"-"` (пустой слот) или `"%s-"` от имени
  слота (`0x48e0e7`/`0x48e0fb`); завершающий `'-'` — курсор;
* принимаются только `A-Z`, `0-9`, пробел; строка вместе с курсором не
  длиннее **18** байт (`cmp ecx,0x12` в `0x48b6c2`), то есть имя — до
  **17** символов; ввод заменяет курсор и дописывает новый (`0x48b6cb`);
* Backspace (`0x8`), стрелки (`0xab`/`0x9b`) — правка, Esc (`0x1b`) —
  возврат в 14 и восстановление прежнего имени слота в буфер;
* Enter (`0xd`) или `0xa4`: если в буфере только курсор, подставляется
  имя по умолчанию `A SAVED GAME` (`0x4bdd44`), иначе курсор срезается;
* затем `[0x4bc274] = slot`, имя копируется в таблицу
  (`0x6c2fe0 + slot*0x13`), вызывается писатель `0x4422d0(slot, name, 0x13)`
  и ставится кулдаун `0x4bc3dc = tick + 0x12c`;
* загрузчик сейва — `0x442340`.

**Отдельного подтверждения перезаписи нет**: из 14 сразу переходят в 15,
строк overwrite/confirm в бинаре не найдено (это вывод из отсутствия, а не
из положительного байта). Единственная строка про занятость —
`%s has been used twice` (`0x4bd790`) — относится к наборам клавиш.

## 7. Наборы клавиш (KEYCFG)

* перечисление — `KEYCFG\*.KEY` (`0x4bcc74`), открытие — `KEYCFG\%s`
  (`0x4bcc68`), запись — `KEYCFG\%.8s.key` (`0x4bcdd4`);
* максимум **16** наборов (сравнение с `0x10` в `0x48d04f`/`0x48d0f5`);
* размер файла — **376** байт (`0x178`); в поставке три файла по 376 Б:
  `PERFECT.key`, `SPLIT1.KEY`, `SPLIT2.KEY`;
* имя набора — таблица `0x6c2058`, шаг `0x108`, копируется 16 байт
  (`push 0x10` в `0x48f95c`);
* имена биндингов — 31 указатель в `0x4bc558`:
  `Move Forward` … `Linear Right`;
* индексы: игрок 1 — `0x5a4910`, игрок 2 — `0x4aa488`,
  мышь — `0x5a4938`; счётчик наборов — `0x4bc5d4`;
* набор с именем `NEW SET` (`0x4bdd3c`) при входе сначала просит имя
  (состояние 31);
* текущий игрок редактора — `0x660788` (1 = P1, 3 = P2), индекс набора
  приходит аргументом через `0x68cd7c`;
* Esc из любого подэкрана 16/22/26/30/34/35/36 возвращает в 10
  (`0x48e599`), из 18 — в 12 (`0x48e55a`).

## 11. Гипотезы и остатки

* `vfront`/`vback` загружаются (`0x4bc460`/`0x4bc464`), но потребителя
  хендлов в просканированном коде нет. Возможно, это резерв или звук
  проигрывается из другого модуля — **гипотеза**.
* `GUNMETAL KEYS` (`0x4bdf84`) не пушится ни в один вызов `0x485dd0`
  из обработчиков 30/34/35; вероятно, заголовок окна/режима — **гипотеза**.
* Соответствие «номер шрифта → FONTS1..4/NUMFONTS» не установлено
  (см. `UI.md` §10.3).
* Отсутствие подтверждения перезаписи сейва — вывод из отсутствия строк
  и ветки; доказательством «положительного» байта не является.
* Порядок пунктов экрана 19 зависит от маски `0x4c1290`: при выключенных
  режимах подписи сдвигаются вверх, а не оставляют пустые строки.
* Пункты 6 (RESTART) и 17 (уровни) имеют динамические id/строки; в
  `--json` они представлены базовыми значениями и описаны в `note`.

## 12. Расхождения с `docs/UI.md`

`UI.md` §6.1 даёт общую карту и в целом совпадает, но в деталях есть
четыре расхождения (проверены байтами):

1. `0x4bc558` — **31** имя биндинга, а не 30 (`Move Forward` … `Linear Right`);
   обработчики 30/34/35 пишут в `0x67f10c` именно `0x1f = 31`.
2. id 20 — заголовок `LAY DOWN THE BUCKS` (`0x4bdb80`), а не
   `SHAREWARE VERSION`; «shareware» — это текст внутри
   (`THIS FEATURE IS NOT / AVAILABLE IN THE / SHAREWARE VERSION`).
3. id 30 — не «MOUSE SETUP», а просмотр набора клавиш: заголовок —
   имя набора из `0x6c2058 + set*0x108`, подсказка `Press Esc to close`.
4. id 33 называется `QUIT GAME?` вне игры и `QUIT OPTIONS` в игре
   (`[0x83cb7c] != 0`); в игре три пункта, вне игры — `Yes`/`No`.

Кроме того, id 34 — не отдельный «редактор игрока 1», а однофреймовый
алиас 35 (`0x48e212`); игрок редактора берётся из `0x660788`.
