# Рендер экранов 24/25, имена локальных игроков (`engine/src/ui/player_name_render.h`)

Срез 22 пункта `M8.8`: один кадр экранов **24** (`LOCAL PLAYER ONE NAME`) и
**25** (`LOCAL PLAYER TWO NAME`) фронтенда (`gundx.exe`, ImageBase `0x400000`)
в RGBA-буфер 320×200. Модуль без состояния — рисует то, что ему передали в
`PlayerNameRenderOptions` (номер игрока и содержимое буфера имени), и отдаёт
числа (`rows`, `chars`, `truncated`, `ink_pixels`, `missing_glyphs`, `arrows`,
`caret_pixels`). Шрифты и метрики — из `render/text_layout`, точный fade — из
`render/hud_lut`, плата — `PLATE` из `FRONTEND/BMP.IDX`. Ничего не измеряется
заново.

Код: `engine/src/ui/player_name_render.h/.cpp`; тест —
`engine/tests/test_player_name_render.cpp` (CTest `player_name_render`, label
`quick`). Соседние срезы и опоры: `SAVE_NAME_RENDER.md` (та же схема «строка
ввода + каретка» на экране 15), `LOCAL_PLAYERS_RENDER.md` (экран 21, откуда
приходят), `UI_SCREENS.md` §2/§3.8 (карта и обработчики), `MENU_RENDER.md` §3
(палитры граней), `HUD_LUT.md` §2 (точный fade).

## 1. API

```cpp
#include "ui/player_name_render.h"

gm::PlayerNameRenderOptions options;
options.player = 0;                   // 0 = экран 24, иначе экран 25
options.name = "JIM BOB";             // содержимое буфера (C-строка, 10 символов max)
options.caret = true;                 // полая рамка 8x17 (по умолчанию)
options.caret_pos = -1;               // [0x683f90]; -1 = за последним символом
options.caret_colour = 15;            // индекс заливки рамки (в оригинале tick & 0xFF)
options.background = "PLATE";         // "" = чёрный холст

std::vector<std::uint32_t> rgba;      // 0xRRGGBBAA, 320*200
int width = 0, height = 0;
gm::PlayerNameRenderStats stats;
std::string error;
if (!gm::render_player_name(game, options, rgba, width, height, &stats, &error))
    // error начинается с "player_name_render: "

gm::player_name_title(1);            // "LOCAL PLAYER TWO NAME"
gm::player_name_buffer(options);     // "JIM BOB" (обрезка до 10 символов)
gm::player_name_caret_pos(options);  // 7 (-1 -> конец)
gm::player_name_caret_width('M');    // 16 (M/W), 'I' -> 6, иначе 8
gm::player_name_text_x(76);          // 60 = 98 - 76/2 (центр строки имени)
```

`render_player_name` при отказе очищает `rgba`, ставит `width = height = 0` и
обнуляет `*stats`; `stats`/`error` могут быть `nullptr`. Запись в установку не
происходит: каталог игры только читается.

## 2. Доказано (листинг `gundx.exe`, данные `FRONTEND/BMP.IDX`)

### 2.1. Обработчик `0x489020(player)`

Вся отрисовка — `0x489020`..`0x4891b0` (`sub esp,0x20` в `0x489020`, `ret` в
`0x4891b0`). Аргумент — единственный, и он же выбирает игрока и заголовок:

| сайт | что видно |
|---|---|
| `0x489023` | `mov dword [0x67f10c],1` — `rows 1` |
| `0x48902d` | `mov dword [0x662d58],0` — `step 0` |
| `0x48903a` | `call 0x486050` — копия `PLATE` (`0x6d2b60` → `0x6865f8`, `0x1913` dword = 25 676 Б) |
| `0x489049` | `test esi,esi; je 0x489056` — параметр 0 → строка `0x4bd730`, иначе `0x4bd748` |
| `0x489043`..`0x48905d` | заголовок: `item -1`, `row 0xe` (y 14), `x 0x26`, `centered 1`, шрифт 5 |
| `0x489062`..`0x4890df` | строка имени: центрирование и каретка (см. §2.3) |
| `0x4890f4`..`0x4890fe` | полая рамка каретки (`0x485d40`), см. §2.4 |
| `0x489105`..`0x489118` | `0x47faf0(шрифт 3, буфер, 0x6865f8, x, 0x1c, 0xc4, 0)` |
| `0x489120`..`0x4891a2` | шесть подсказок (`0x485dd0`, шрифт 0, x `0x10`, `item -1`) |

`rows 1`/`step 0` совпадают с картой (`UI_SCREENS.md` §2). Все вызовы текста
передают `item = -1`, а `0x485dd0` при `item = -1` обнуляет смещение
(`cmp ecx,0xffffffff` в `0x485e04`), поэтому шаг `item*step` на этом экране не
используется: `step 0` ни на что не влияет. Других вызовов (стрелки
`MENUARRW`, `FILESLOT`, `MENULIT`, звук) в обработчике нет.

### 2.2. Заголовок и подсказки

| текст | VA | x | y | шрифт | источник |
|---|---|---:|---:|---:|---|
| `LOCAL PLAYER ONE NAME` | `0x4bd730` | центр | 14 | 5 | `0x489043`..`0x48905d` (`push 0x4bd730` в `0x489056`) |
| `LOCAL PLAYER TWO NAME` | `0x4bd748` | центр | 14 | 5 | `push 0x4bd748` в `0x48904f` |
| `TYPE THE NAME YOU` | `0x4bd71c` | 16 | 48 | 0 | `0x489120`..`0x48912f` |
| `WISH TO USE` | `0x4bd710` | 16 | 56 | 0 | `0x489137`..`0x489146` |
| `LEAVE BLANK TO USE A` | `0x4bd6f8` | 16 | 67 | 0 | `0x48914e`..`0x48915d` |
| `RANDOM NAME` | `0x4bd6ec` | 16 | 75 | 0 | `0x489165`..`0x489174` |
| `PRESS ENTER TO CONTINUE` | `0x4bd6d4` | 16 | 89 | 0 | `0x48917c`..`0x48918b` |
| `PRESS ESC TO ABORT` | `0x4bd6c0` | 16 | 102 | 0 | `0x489193`..`0x4891a2` |

Вызовы идут в порядке таблицы (заголовок, затем строка имени, затем шесть
подсказок) — это и есть порядок наложения. Центрирование заголовка — ветка
`centered` функции `0x485dd0`: `x = (196 - ширина)/2` (`0x485de2`..`0x485dfa`),
`x = 0x26` из вызова игнорируется. Шесть подсказок — те же данные, что уже
лежат в таблице `kPlayerOneNameItems` (`engine/src/ui/frontend_menu.cpp`).

### 2.3. Строка имени: буфер, центрирование, лимит

| факт | значение | источник |
|---|---|---|
| буфер игрока 0 | `0x682f60` | `0x48906e`: `0x682f60 + player*0x11` |
| буфер игрока 1 | `0x682f71` | то же (`player*0x10 + player`) |
| размер буфера | 17 байт на игрока | шаг `0x11` в `0x48906e` |
| позиция редактирования | `[0x683f90]` (общая для обоих экранов) | `0x48907f`, `0x48f4c6` |
| текст | **весь** буфер | `0x489115` пушит `edi` (база буфера), а не локальную копию |
| шрифт | **3** (`FONTS2`, 16×16) | `0x489116` (`push 3`) |
| y | **28** | `0x48910d` (`push 0x1c`) |
| x | **98 − ширина/2** | `0x4890d3` (`mov esi,0x62`) − `0x4890dd` |
| ширина | `0x47fa50(3, буфер)` по всему буферу | `0x4890bc`..`0x4890cd` |
| клип | 196×131 (буфер `0x6865f8`) | `0x486050`, stride `0xc4` |

Буфер — C-строка: `0x405b20` меряет его `repnz scas` (`0x405b3e`), NUL
завершает. Позиция редактирования при входе клампится к длине
(`0x405b2b`/`0x405b45`), поэтому «каретка в конце» — обычное состояние только
что набранного имени.

**Лимит — 10 символов.** Экран не пишет в буфер сам: ввод делает общий
редактор строки `0x405b20`, и его вызов для экранов 24/25 —
`0x405b20(буфер, 0xb, &0x683f90)` (`0x48f4c3`..`0x48f4da`, `push 0xb` в
`0x48f4cd`). Внутри `0x405b20` вставка символа отбрасывается, если
`strlen >= max-1` (`lea eax,[ebx-1]; cmp ecx,eax; jge` в `0x405c1d`..`0x405c22`),
т.е. 11 байт вместе с NUL — **10 символов**. Поэтому 17-байтовый буфер всегда
содержит короткую строку; модуль обрезает `options.name` до 10 символов и
считает отброшенные байты в `stats.truncated`.

Прочие факты ввода (в модуль не входят, но объясняют данные):

* редактор принимает `A-Z`, `0-9`, пробел и `-` (`0x405bef`..`0x405c0b`),
  строчные поднимает в верхний регистр (`0x405b85`..`0x405b8f`); Backspace
  (`0x8`) удаляет символ перед кареткой (`0x405bb6`..`0x405be0`), Delete
  (`0xb1`/`0xa3`) — под кареткой (`0x405c4e`);
* Enter (`0xd`/`0xa4`) возвращает 1 (`0x405cb7`), Esc (`0x1b`) — `-1`
  (`0x405caf`), отсутствие клавиши — 0 (`0x405cc1`);
* после Enter на экране 24 обработчик ставит состояние `0x1c` = 28 (`0x48f646`,
  `0x48f66a`) и рисует экран флага `0x4891c0(0)`; после экрана 25 —
  состояние `0x1d` = 29 (`0x48f68d`..`0x48f6ac`); Esc возвращает состояние 1
  (`0x48f6df`, `ebp = 1` из `0x48f06c`).

**Откуда берётся имя по умолчанию.** На входе в экран 24 буферы обоих игроков
**очищаются** (`0x48e3af`/`0x48e3b6` пишут 0 в `0x682f60`/`0x682f71`), так что
свежий кадр рисует пустую строку. Имя появляется только по Enter, если буфер
пуст: `0x48f513` вызывает `0x480120`, а та берёт `0x480e30() % 29` и
возвращает указатель из таблицы `0x4bbc98` (29 имён: `JIM BOB`, `AUTOBOT`,
`SLIME MOLD`, `LARRY`, `UNCLE SAM`, `ED 209`, `THX 1138`, `OBIWAN`, `INVADER`,
`EBENEEZER`, `THE DOCTOR`, `K-9`, `ZARBI`, `SOY BOY`, `TEX`, `DELTA NINE`,
`LORD GARTH`, `BIT BAIT`, `SPICE`, `BUD`, `BAD BOY`, `DAKINI`, `THE QUEEN`,
`THE KING`, `LEELOO`, `FONZ`, `DIGNOL`, `BUBBA`, `THE POPE` — все ≤ 10
символов); копирование `0x48f520`..`0x48f54c` идёт без проверки длины, но
длиннее 10 символов таблица не даёт. Затем три «easter egg» замены
(`0x48f551`..`0x48f643`): `WREN` (`0x4bde10`) → `THE KNIFE` (`0x4bde04`),
`SPHINXX` (`0x4bddfc`) → `SPHINX` (`0x4bddf4`), `SPHINX` → `WANNA BE`
(`0x4bdde8`). Всё это — состояние игры, а не рисование; модуль его не
воспроизводит.

### 2.4. Каретка

Каретка — не спрайт и не мигание, а **полая рамка** `0x485d40`:

| факт | значение | источник |
|---|---|---|
| позиция | x = `98 − ширина_буфера/2` + ширина префикса, y = **27** | `0x4890ed`: `0x687aa4 + x + ширина_префикса`; `0x687aa4 − 0x6865f8 = 27*196` |
| ширина | 16 для `M`/`W`, 6 для `I`, иначе **8** | `ebp = 8` в `0x489075`; `0x489095`..`0x4890ae` |
| высота | **17** | `push 0x11` в `0x4890f5` |
| форма | верхняя и нижняя строки целиком, в средних — только две боковые точки | `0x485d4c`..`0x485d98` (заливка `rep stos`, затем `[esi]`/`[ecx+esi-1]`) |
| заливка | `[0x5a4a74] & 0xFF` — младший байт счётчика тиков | `0x4890e4`; `mov dl,[esp+0x14]` в `0x485d44`; `inc ecx` в `0x44bdda` |
| порядок | рамка **до** текста | `call 0x485d40` (`0x4890fe`) раньше `call 0x47faf0` (`0x489118`) |

Ширина берётся у символа **под** кареткой: цикл `0x48907a`..`0x4890ba` копирует
в локальную строку только символы с индексом `< [0x683f90]` и запоминает
ширину символа с индексом `== [0x683f90]`. Если каретка стоит за последним
символом, под ней NUL — ширина остаётся 8. Рамка 16×17 для `M`/`W`
соответствует 16-пиксельной ячейке `FONTS2`; 17-я строка — нижняя граница
рамки, которая накрывает последнюю строку глифа (текст рисуется поверх).

Так как цвет рамки — младший байт тика, в оригинале рамка **перекрашивается
каждый кадр** (перебор индексов палитры). Время в модуле не моделируется:
`options.caret_colour` (по умолчанию 15) — фиксированный индекс одного кадра.

### 2.5. Ассеты (данные `FRONTEND/BMP.IDX`)

| ассет | размер | роль | проверка |
|---|---|---|---|
| `PLATE` | 196×131 | кадр/клип, копия `0x486050` | размер в тесте, независимый декод |
| `FONTS4` | 512×168 | грани 5 (заголовок) и 0 (подсказки) | `render/text_layout` |
| `FONTS2` | 1024×80 | грань 3 (имя, 16×16) | `cell_height == 16` в тесте |

Все три обязательны: без `PLATE` у кадра нет буфера, без `FONTS4`/`FONTS2` —
текста. Любой пропуск — текст `player_name_render: ...`, а не молча чёрный
кадр.

## 3. Модель (что добавлено и что нет)

| факт | статус |
|---|---|
| заголовок: `0x4bd730`/`0x4bd748`, шрифт 5, центр по 196, y 14 | proven: `0x489043`..`0x48905d`, `0x485de2`..`0x485dfa` |
| строка имени: шрифт 3, центр на x 98, y 28 | proven: `0x4890bc`..`0x489118` |
| лимит имени — 10 символов | proven: `push 0xb` (`0x48f4cd`) + `0x405c1d` |
| каретка — полая рамка 8×17 в (конец текста, 27) | proven: `0x4890f4`..`0x4890fe`, `0x485d40` |
| ширина рамки M/W 16, I 6, иначе 8 | proven: `0x489095`..`0x4890ae` |
| шесть подсказок x 16, y 48/56/67/75/89/102, шрифт 0 | proven: `0x489120`..`0x4891a2` |
| `rows 1`, `step 0`, `arrows 0` | proven: `0x489023`/`0x48902d`; вызовов `MENUARRW` нет |
| цвета текста — из палитр атласов (`FONTS4`/`FONTS2`) | proven палитрами BMP (как `MENU_RENDER.md` §3) |
| заливка рамки — индекс `tick & 0xFF`, цвет по палитре **PLATE** | **модель**: время не моделируется (`caret_colour`), палитра — источник «платы»; `PLATE` расходится с `GAMEPAL` только в индексе 0 |
| `player` вне 0/1 → заголовок второго игрока | proven: обработчик проверяет только ноль (`0x489049`) |
| `caret_pos` вне 0..len клампится, `-1` = конец | **модель**: редактор держит позицию в диапазоне сам (`0x405b2b`/`0x405b45`) |
| `background = "PLATE"` | **модель раскладки**: где движок кладёт 196×131 в 320×200, в коде не доказано (как в `MENU_RENDER.md` §2); по умолчанию чёрный холст |
| текст клипуется 196×131 | **модель**: буфер `0x6865f8` ровно 196×131, но блиттер `0x47faf0` сам не клипует; для штатных строк выхода за плату не бывает |
| штатная строка длины ≥ 10 не центрируется по фактическому bbox | proven: центр считается по сумме advance (`0x47fa50`), а не по ink |

Что это значит:

* `x = (196 − ширина)/2`: у 20-символьных заголовков ширина advance 120 и 122,
  отсюда x 38 и 37; bbox по ink — 118×7 и 120×7, ink 317 и 313. Кадры 24 и 25
  различаются **только** в полосе y 14..20 (424 px), ink отличается ровно на
  разницу заголовков.
* Строка имени центрируется на x 98: `"JIM BOB"` (advance 62) начинается с
  x 67, ink 523; смена имени меняет только строки 28..43 (540 px).
* 30-символьное имя даёт 10 нарисованных байт и 20 отброшенных; кадр
  **побайтово** равен кадру 10-символьного префикса (0 отличий).
* Каретка добавляет ровно 46 пикселей — рамку 8×17 (`2·8 + 2·15`), bbox
  (143,27)-(150,43) у конца 76-пиксельного имени `"PLAYER ONE"`. Ширины
  16/6/8 подтверждены сдвигом каретки внутрь `"MIKE"`: `M` → 16 px с x 80,
  `I` → 6 px с x 93, `K` → 8 px с x 98.
* `PLATE` совпадает с независимым декодом во всех 196×131 пикселях: 25 676
  отличий от чёрного кадра = 2 551 глиф + 23 125 «только плата»; ink не
  меняется, вне платы — чёрно.
* fade 11 — побайтовое тождество (0/64000); 12..15 — четыре разных кадра;
  уровень 0 — 64 000 чёрных пикселей (весь текст и плата выключены, как и в
  соседних рендерах).
* минимальный архив (`FONTS4`+`FONTS2`+`PLATE`) рисует кадр — модулю не нужны
  ни `GAMEPAL`, ни `MENUARRW`, ни `FILESLOT`.

## 5. Ограничения

* **Нет ввода.** Редактор `0x405b20` (фильтр `A-Z`/`0-9`/пробел/`-`, Backspace,
  Delete, стрелки), возврат `1`/`-1`/`0`, переходы в 28/29/1 и звуки
  (`UI_SOUNDS.md`) не реализованы. Модуль рисует переданный буфер.
* **Нет случайного имени и easter egg.** Таблица `0x4bbc98` (29 имён), выбор
  `0x480120` и замены `WREN`/`SPHINXX`/`SPHINX` — состояние игры (см. §2.3);
  рендер их не трогает. Имя никуда не пишется: ни в состояние игры, ни в файл.
* **Время каретки не моделируется.** Оригинал берёт цвет рамки из младшего
  байта тика `[0x5a4a74]`; кадр детерминирован через `caret_colour`.
* **Палитра — на источник.** Цвет берётся из палитры атласа/платы, а не из
  общей `FRONTEND/GAMEPAL` (та же оговорка, что в `MENU_RENDER.md` §5);
  `FONTS2`/`FONTS4` расходятся с `GAMEPAL` в 21 слоте-заглушке, `PLATE` — только
  в индексе 0. Для рамки выбран индекс 15, где палитры совпадают.
* **Плата — модель раскладки.** Экранный origin копии `0x6865f8` не
  документирован (`UI.md` §8), поэтому `"PLATE"` кладётся в (0,0), как в
  соседних рендерах.
* **Экраны 28/29 (флаг) и 31 (имя набора)** — другие срезы; их общий фрагмент
  (центр 98, рамка `0x485d40`) здесь не реализован.
* **CLI — есть (срез 24).** `--player-name [--player-name-player N]
  [--player-name-text NAME] [--player-name-caret-pos N]
  [--player-name-no-caret] [--no-plate] [--png OUT] [--fade-lut N]`: пустое
  имя — `player_name: player=0 rows=1 chars=0 truncated=0 caret=1 caret_px=46
  ink=1812 missing=0 arrows=0`; `JIM BOB` у второго игрока — `ink=2331`;
  30 символов — `chars=10 truncated=20 ink=2617`. CTest `cli_player_name*`;
  `cli_fade_lut` (11 = без fade).
