# Аудит установки по манифесту

Инструмент `tools/re/install_audit.py` отвечает на вопрос: **«лежит ли в
установке игры ровно то, что проект зафиксировал в манифесте?»** — побайтово,
по SHA-256 каждого файла.

```sh
python3 tools/re/install_audit.py --game "/mnt/d/games/Gunmetal 3dfx"
python3 tools/re/install_audit.py --game "$HOME/.cache/gunmetal-re/game" \
    --json /var/tmp/audit-mirror.json
python3 tools/re/install_audit.py --strict          # swaps — тоже провал
python3 tools/re/install_audit.py --selftest        # синтетическое дерево
```

Только чтение: ни установка, ни зеркало каталога не меняются. Только stdlib.

## Входные данные

| | |
|---|---|
| манифест | `docs/manifests/gunmetal-3dfx-136.sha256` (2161 игровой файл, формат `sha256sum`) |
| сводный SHA-256 манифеста | `b1d6e04321e011e8ea52a96df9c9cb738dcd8e950ae2465c339af880308601e4` (`docs/BASELINE.md`) |
| установка | `/mnt/d/games/Gunmetal 3dfx` (v1.36 3dfx), 4215 файлов на диске |
| зеркало | `~/.cache/gunmetal-re/game` (`tools/re/gmcache.py mirror --sync`) |

Манифест покрывает только **игровые** файлы. Неигровые (экспорт DXWnd,
`.txt`/`.docx`/`.png`, логи, `SAVEGAME/`) в него не входят — фильтр тот же,
что и у `gm.py manifest`: расширения, помеченные в `INVENTORY` как
«не игровой», плюс каталог `SAVEGAME/`. Инструмент берёт эту таблицу из
`gm.py` (парсит `INVENTORY` через `ast`, ничего не исполняя), а при
отсутствии `gm.py` — из встроенной копии. Поэтому «extra» — это
*игровой* файл, которого нет в манифесте, а не шум от DXWnd.

Обход каталогов: только обычные файлы; symlink'и и junction'ы не
разворачиваются (перечисляются в `skipped_symlinks`), каталог, посещённый
дважды, обходится один раз.

## Классификация

Сторона манифеста (2161 запись):

| статус | смысл |
|---|---|
| `ok` | файл на месте, SHA-256 совпал |
| `renamed` | содержимое манифеста найдено, но **под другим именем** (переименование или половина обмена) |
| `missing` | нет ни имени, ни содержимого |
| `modified` | имя на месте, байты другие, ожидаемого содержимого нет нигде |
| `volatile` | как `modified`, но файл переписывает сама игра (`GUNMETAL.CFG`); не считается провалом |
| `extra` | файл на диске, которого нет в манифесте и который не «принимает» переехавшее содержимое |

Ключевой приём: содержимое ищется **по хэшу**, а не по имени. Поэтому
переставленные местами файлы не превращаются в «изменённые».

`GUNMETAL.CFG` — конфиг игрока: игра переписывает его при выходе
(`tools/re/init_flow.py`: «сохранение: `GUNMETAL.CFG` в режиме "wb"»).
Манифест хранит снимок на момент снятия, поэтому расхождение здесь —
ожидаемый дрейф, а не повреждение. Список расширяется флагом
`--volatile NAME`; отключается целиком — `--no-volatile`.

## Как читать swaps

`swaps` — это группы, а не отдельные файлы: связные компоненты отношения
«содержимое A лежит в B». Группа называется `swap`, если она замкнутый
цикл (каждый файл группы содержит содержимое следующего), и `rename`
иначе (цепочка или одиночное переименование).

```json
{"kind": "swap",
 "names": ["level1.sbt", "level2.sbt"],
 "sha256": ["37592af2…", "3b758b4f…"],
 "members": [{"name": "level1.sbt",
              "expected_sha256": "37592af2…",
              "actual_path": "level2.sbt",
              "actual_sha256": "3b758b4f…"}, …],
 "absent": []}
```

`sha256` — ожидаемые дайджесты имён из группы, в том же порядке, что и
`names`; `members` — кто какой файл фактически подменил; `absent` — имена
группы, содержимое которых не найдено вовсе.

**Решение о разбиении:** группа — это *минимальный цикл* обмена, а не
«всё, что переехало». Для поставляемой установки это три группы по два
файла, а не одна группа из шести:

| группа | факт |
|---|---|
| `level1.sbc` <-> `level2.sbc` | содержимое переставлено |
| `level1.sbt` <-> `level2.sbt` | содержимое переставлено |
| `level1.sbw` <-> `level2.sbw` | содержимое переставлено |

Причина одна: обменены целиком тройки уровня 1 и уровня 2, поэтому набор
содержимого каждого уровня остаётся связным (`.sbc`/`.sbt`/`.sbw`
согласованы между собой). `tools/re/game_content.py` знает только про
`.sbt`/`.sbw` (там `EXTS = (".sbt", ".sbw")`) — пара `.sbc` в перечень
известных аномалий не попала, но на диске обменена тоже.

Происхождение обмена (гипотеза, не доказано): манифест снят 2026-10-20
(`git show 0a732bf`), а mtime файлов на диске — 1998 год, значит содержимое
поменяли после снятия манифеста, сохранив timestamps (типично для
копирования с сохранением времени). Кто и зачем — не установлено.

## Коды возврата

| код | когда |
|---|---|
| `0` | только `ok` + известные перестановки/переименования (`renamed`, `swaps`) |
| `2` | есть `missing`, `modified` или `extra`; либо при `--strict` — любая перестановка |
| `1` | ошибка ввода: нет каталога установки, нет/битый манифест, `--jobs < 1` |

`--strict` делает провалом именно перестановки (и переименования).
`volatile` не проваливает никогда.

## Ключи CLI

| ключ | смысл |
|---|---|
| `--game PATH` | установка (по умолчанию `$GUNMETAL_GAME`, иначе `/mnt/d/games/Gunmetal 3dfx`) |
| `--manifest PATH` | манифест (по умолчанию `docs/manifests/gunmetal-3dfx-136.sha256`) |
| `--json PATH` | отчёт в JSON (`-` — в stdout) |
| `--quiet` | без прогресса в stderr и без сводки в stdout |
| `--jobs N` | потоков хэширования (по умолчанию `min(16, cpu_count)`) |
| `--strict` | перестановки считаются провалом |
| `--all` | аудит всех файлов, включая неигровые (DXWnd, доки, логи) |
| `--include-saves` | включая `SAVEGAME/` (сейвы игрока) |
| `--volatile NAME` | дополнительный файл, который переписывает игра (можно повторять) |
| `--no-volatile` | не считать `GUNMETAL.CFG` изменяемым игрой |
| `--selftest` | самопроверка на синтетическом дереве (9 проверок) |

## Производительность

Хэш считается потоково (чанк 1 МиБ, файл целиком в память не читается),
параллельно через `ThreadPoolExecutor` (`hashlib` отпускает GIL).

| что | `--jobs 1` | `--jobs 16` |
|---|---:|---:|
| установка `/mnt/d` (drvfs, 2161 файл, 373.7 МиБ) | 9.0–9.2 с | 4.3 с |
| зеркало `~/.cache` (локальный диск, тёплый кэш) | 0.44 с | 0.74 с |

Выигрыш от потоков есть только на drvfs (там узкое место — ввод-вывод);
на тёплом локальном зеркале последовательный проход быстрее, поэтому для
зеркала разумно `--jobs 1`.

## Проверка (как повторить)

```sh
# 1. эталонная установка: 0 missing / 0 modified / 0 extra, код 0
python3 tools/re/install_audit.py --game "/mnt/d/games/Gunmetal 3dfx" \
    --json /var/tmp/audit-install.json; echo "exit=$?"

# 2. зеркало: тот же результат (зеркало полное), код 0
python3 tools/re/install_audit.py --game "$HOME/.cache/gunmetal-re/game" \
    --json /var/tmp/audit-mirror.json; echo "exit=$?"

# 3. --strict: перестановки — провал, код 2
python3 tools/re/install_audit.py --game "/mnt/d/games/Gunmetal 3dfx" \
    --strict --quiet; echo "exit=$?"

# 4. негативный тест: копия нескольких файлов, испорченный/удалённый/
#    переставленный/лишний — аудит видит modified/missing/extra, код 2
NEG=/var/tmp/gm-audit-neg; rm -rf "$NEG"; mkdir -p "$NEG"
for f in level0.sbt level1.sbt level2.sbt level3.sbt level4.sbt; do
    cp "/mnt/d/games/Gunmetal 3dfx/$f" "$NEG/$f"; done
(cd "$NEG" && sha256sum level*.sbt > /var/tmp/gm-audit-neg.sha256)
printf 'CORRUPT' | dd of="$NEG/level1.sbt" bs=1 seek=1000 conv=notrunc status=none
rm "$NEG/level2.sbt"
mv "$NEG/level3.sbt" "$NEG/tmp.sbt" && mv "$NEG/level4.sbt" "$NEG/level3.sbt" \
    && mv "$NEG/tmp.sbt" "$NEG/level4.sbt"
echo junk > "$NEG/extra.bin"
python3 tools/re/install_audit.py --game "$NEG" \
    --manifest /var/tmp/gm-audit-neg.sha256; echo "exit=$?"
# ожидается: ok=1, swap-группа level3/level4, missing=1, modified=1,
# extra=1, код 2
```

## Ограничения

* Сравнение идёт по SHA-256; коллизия манифеста и диска не различима от
  «файл на месте».
* Хэш файла, из которого игра читает данные, может отличаться от
  манифеста и без перестановки — тогда это `modified` (и `volatile` для
  конфига).
* `extra` не ловит файлы, отфильтрованные фильтром «игровых» файлов
  (DXWnd, сейвы): их видно только в `--all` / `--include-saves`.
* Инструмент ничего не чинит и не перезаписывает: он только говорит, где
  расхождение.
* Проверено на одной установке (v1.36 3dfx) и на её зеркале; на другой
  версии манифест нужно снять заново (`gm.py manifest --out`).
