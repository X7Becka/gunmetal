# `.soe` → `THING_TYPES`: семантика полей (M1.6)

Документ закрывает семантику `.soe`: какие токены текстового файла попадают
в какие смещения 936-байтовой записи `THING_TYPES` и **чем доказана** роль
каждого поля. Грамматика и байтовый round-trip уже описаны в
`docs/FORMATS.md` §13 и `gm/soe.py`; здесь — карта «поле → смещение → смысл →
xref/статус».

Единственный поставленный `.soe` — `SOBS/railrock.soe` (61 строка, 67 токенов).
Все 36 уровневых `.sbt` содержат **2896** записей `THING_TYPES` (408 различных
имён); на них проверены границы и инварианты.

Обозначения:

* `proven` — роль доказана форматом/строкой ошибки загрузчика или однозначным
  потребителем;
* `hypothesis` — смещение и ширина доказаны, роль выведена из 1–2
  потребителей и явно не названа в exe;
* `unknown` — известно только смещение/ширина (`fXX`);
* адреса — полные VA `gundx.exe` 1.36 (`ImageBase = 0x400000`).

## 2. Как выбирается тип

1. Загрузчик `0x47cb6c` получает имя типа (аргумент консольной команды
   `thingtype_add`), копирует его в `char name[16]` записи (`0x47cb7a`) и
   открывает `thing\<name>.soe`.
2. Токены файла заполняют эту же запись `0x776d60 + 0x3a8*idx`.
3. `0x47cb00` ищет тип по имени (`strcmp` по всем загруженным записям) и
   возвращает индекс; его используют `ADD_THING*` (операнд `G`) и children.
4. `THING_TYPES[idx] + 0x1a4` — индекс в `SOB_TABLE`, откуда берётся `.sob`.
5. В сохранённом `.sbt` запись типа — те же 936 байт: `name[16]` + 49 doubles
   (`+0x10..+0x197`) + 528 байт целых (`+0x198..+0x3a7`).

**Что общее, что переопределяется.** В поставке все 2896 записей имеют
`+0x198 = 10`, `+0x19c = 0` и нулевые `+0x138/+0x158/+0x178` (углы детей).
Остальные поля вариативны: например `+0x1a4` принимает 90 значений (модель),
`+0x1b4` — 12 значений (тип движения), `+0x1a0` — 3 значения (форма
коллизии), `+0x218` — 0..4 оружия, `+0x2fc` — 0..4 ребёнка, `+0x320` — 0..28
точек пути. Значения, которые загрузчик масштабирует (`+0x1e8`, `+0x214`,
`weapon.w2`), в `.sbt` уже лежат после умножения на `0.91`.

## 4. `railrock.soe` ↔ запись

`railrock.soe` — версия 13, 67 токенов, 67 полей, остаток 0. Симуляция
загрузчика (`--soe`) даёт:

```
+0x198 = 10        +0x1a0 = 2 (ellipsoid)   +0x1a8 = 37
+0x19c = 0         +0x1a4 = <railrock>      +0x1ac = 116982
+0x1b0 = 8         +0x1b4 = <pushable>      +0x1cc = 200
+0x218 = 1         weapon = [1, 128, 10, 0, 0, 0]
радиусы: rx=115, ry=115, rz=80 -> bounding radius 115
```

Числовые токены (`0`) записываются как есть; имена (`railrock`, `PUSHABLE`,
`NONE`, `push_crate`) требуют таблиц резолверов и в симуляции помечаются
`unresolved`. Для `pushable` это значение `18` таблицы `0x4ba8c8`, для
`railrock` — индекс `SOB_TABLE` (в уровнях его нет, поэтому `railrock.soe` —
источник, а не запись из `.sbt`).

## 5. Опровергнутые гипотезы

1. **Первый токен блока коллизии — не «тип коллизии».** Он резолвится
   `0x46c840` по таблице движений и пишется в `+0x1b4`. Настоящая форма
   коллизии — последний `%s` (`none/sphere/ellipsoid`), `+0x1a0`. Старое имя
   `collision_type` в `gm/soe.py` оставлено только для совместимости.
2. **`f1d4` — не event id.** Он копируется в два поля экземпляра
   (current/max), к нему прибавляется урон и сравнивается половина — это пул
   HP. Роль помечена `hypothesis`, потому что строка ошибки загрузчика
   называет только событие рядом.
3. **Leash location — не `+0xd0`.** Строка локации резолвится в `+0x204`;
   `+0xd0` — отдельный double (расстояние/радиус) из того же блока v≥13.
4. **Третья строка 10-блока — не текстура.** Это имя звука: `0x40b9c0`
   ищет его в таблице 300 сэмплов и пишет индекс в `+0x1fc`. Текстуры — это
   отдельный блок `%s %s` → `+0x208/+0x20c`.
5. **Индекс типа ребёнка — не `+0x310`.** Он пишется в `+0x300 + 4*i`;
   `+0x310 + 4*i` — отдельный `%ld` из строки ребёнка.
6. **Точки пути — не `+0x300`.** Счётчик `+0x320`, массив id `+0x324 + 4*i`.
7. **`str_c8`/`str_f0`/`str_1a4` — не смещения.** Это локальные имена
   буферов; реальные приёмники — `+0x1f8`, `+0x1c4`, `+0x1fc`.
8. **`+0x198/+0x19c` — не id типа.** Это границы проверки при спавне
   (`0x46d950/0x46d95c`) относительно глобала `0x83d62c`; в поставке
   постоянны (10 и 0).
