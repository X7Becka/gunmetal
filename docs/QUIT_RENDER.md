# Рендер экрана 33 `QUIT GAME?` / `QUIT OPTIONS` (`engine/src/ui/quit_render.h`)

Срез 4 пункта `M8.8`: модуль **рисует экран 33** в RGBA-буфер 320×200 в двух
вариантах одного обработчика `0x488780` — вне игры `QUIT GAME?` с `Yes`/`No`
(2 строки) и в игре `QUIT OPTIONS` с `Quit Game`/`Quit To Title`/
`Return To Game` (3 строки).  Вариант выбирает флаг `[0x83cb7c]`; в кадр
входят заголовок (шрифт 5, по центру, строка 14), пункты (`x 38`, строка 27,
шаг 16), подсветка курсора шрифтом 4 и опциональная плата `PLATE`.

Код: `engine/src/ui/quit_render.h/.cpp`; тест —
`engine/tests/test_quit_render.cpp` (CTest `quit_render`, label `quick`).
Канон поведения — `docs/UI_SCREENS.md` §2/§3.8/§12.4; образцы того же класса —
`docs/GAME_TYPE_RENDER.md` (19), `docs/DIFFICULTY_RENDER.md` (23),
`docs/START_GAME_RENDER.md` (13).  Кирпичи общие: атласы `FONTS4` из
`FRONTEND/BMP.IDX` (`render/text_layout`), плата 196×131 `0x486050`, точные
таблицы fade `0x682f90` (`docs/START_GAME_RENDER.md` §6, `docs/HUD_LUT.md` §2).

Проверка:

```sh
cmake --build build/sandbox --target gm_quit_render_tests -j 4
./build/sandbox/engine/tests/gm_quit_render_tests
ctest --test-dir build/sandbox -R '^quit_render$' --output-on-failure
python3 regress.py --mirror --json
```

## 1. Что доказано (`0x488780`, docs/UI_SCREENS.md §2/§3.8/§12.4)

Обработчик занимает `0x488780`..`0x48884e` (второй `ret`; дальше `nop` до
`0x488850`).  Листинг: `python3 tools/re/disrange.py 488780 488850`, общий
отрисовщик — `485dd0 485e70`.  Все числа в таблице — сайты этих двух функций,
а не догадка по картинке.

| факт | значение | источник |
|---|---|---|
| плата | `0x488780` вызывает `0x486050` — копию 196×131 `PLATE` в `0x6865f8`; текст пишется в неё, клип 196×131 | `0x488780`; §3, §9 |
| режим | `[0x83cb7c]`: `0` — вне игры, `!= 0` — в игре | `0x488785`, `test`/`jne` `0x488794`..`0x488796` |
| шаг строки | **16** (`[0x662d58] = 0x10`) | `0x48878a` |
| `rows` вне игры | **2** (`[0x67f10c] = 2`) | `0x4887a7` |
| заголовок вне игры | `QUIT GAME?` (`0x4bd3e0`), шрифт **5**, `centered=1`, `x 38`, `row 14`, `item -1` → **y 14**, x = (196−width)/2 | `0x488798`..`0x4887b1`; `0x485de2`..`0x485dfa` |
| item 0 вне игры | `Yes` (`0x4bd3dc`), шрифт 0, `x 38`, `row 27`, `item 0` → **y 27** | `0x4887b9`..`0x4887c8` |
| item 1 вне игры | `No` (`0x4bc7a4`), шрифт 0, `x 38`, `row 27`, `item 1` → **y 43** | `0x4887d0`..`0x4887df` |
| `rows` в игре | **3** (`[0x67f10c] = 3`) | `0x4887f7` |
| заголовок в игре | `QUIT OPTIONS` (`0x4bd3cc`), те же 5/центр/14 | `0x4887e8`..`0x488801` |
| item 0 в игре | `Quit Game` (`0x4bd3c0`) → **y 27** | `0x488809`..`0x488818` |
| item 1 в игре | `Quit To Title` (`0x4bd3b0`) → **y 43** | `0x488820`..`0x48882f` |
| item 2 в игре | `Return To Game` (`0x4bd3a0`) → **y 59** | `0x488837`..`0x488846` |
| модель строки | `centered` даёт `x = (196 − width)/2`, целочисленно; `item == -1` обнуляет `item·step`, `item >= 0` даёт `y = row + item·step` | `0x485de2`..`0x485dfa`, `0x485e04`..`0x485e09`, `0x485e4b`..`0x485e5c` |
| подсветка | `item == [0x68ccf4]` и текст не пуст → шрифт принудительно **4** | `0x485e0d`..`0x485e19` |
| стрелки/слайдеры/чекбоксы | **нет** ни одного вызова: только `0x486050` и 2/3 `0x485dd0` | весь листинг `0x488780`..`0x48884e` |
| порядок | плата → заголовок → item 0 … item N−1 | порядок вызовов |
| `ESC` | **ветки нет**: клавиатурный диспетчер `0x48b4d0` сравнивает `0x1b` только для состояний 9 (`0x48b536`), 5 (`0x48b571`), 2 (`0x48b5d9`), 0x0f (`0x48b6ff`), 0x23 (`0x48b880`), 0x22 (`0x48b973`); состояние 33 (`0x21`) с `0x1b` не сравнивается нигде | поиск `cmp bl,0x1b`/`cmp ebp,0x21` по листингу |
| вход в состояние | пункт 6 главного меню (`0x48d019`); второй писатель состояния 33 — `0x4951af` (путь в игре); в §4 строк для 33 нет | `0x48d019`, `0x4951af` |

### 1.1. Что делают пункты (модель, вне рендера)

Активация — ветка `cmp ebp,0x21` в диспетчере `0x48d92a`, затем выбор по
`[0x83cb7c]` и `[0x68ccf4]` (docs/UI_SCREENS.md §12.4):

| режим | курсор | что происходит | сайт |
|---|---:|---|---|
| вне игры | 0 `Yes` | `0x4913a0(0x4bdd34)`, `0x44b830` (teardown, обнуляет `[0x83cb7c]`), `0x404740` — выход процесса (`push 0; call [0x8413ec]`) | `0x48d978` |
| вне игры | 1 `No` | `[0x4bc440] = ecx`, где `ecx = 1` (задан в `0x48cf15` и не тронут цепочкой диспетчера) — возврат на титул | `0x48d942`..`0x48d94b` |
| в игре | 0 `Quit Game` | тот же путь выхода, что у `Yes` | `0x48d956` → `0x48d978` |
| в игре | 1 `Quit To Title` | `[0x4bc440] = 1` | `0x48da31` |
| в игре | 2 `Return To Game` | `0x498d40`, затем `0x485c50` (состояние 0, возврат в игру) | `0x48d969` |
| любой | вне 0..rows−1 | ничего (`jne 0x48e4ac`) | `0x48d963` и др. |

Модуль это **не** выполняет: он рисует один кадр и не пишет ни одного глобала.

## 2. Модель кадра (не доказано кодом)

* **Курсор.** `QuitRenderOptions::cursor` — это `[0x68ccf4]`, **id пункта**
  (0..1 вне игры, 0..2 в игре), а не номер видимой строки.  Значение вне
  диапазона варианта не подсвечивает ничего — ровно то, что делает `0x485dd0`,
  если id не совпал ни с одним вызовом (тот же контракт, что у
  `ui/game_type_render`).  В оригинале при входе в экран курсор обнуляется
  главным меню (`0x48cf5e`), поэтому первый кадр — item 0.
* **Цвета** — палитра атласа `FONTS4`: заголовок (шрифт 5) → `9b0f0f`
  (тёмно-красный), строки (0) → `130f0f` (тёмно-серый), подсветка (4) →
  `efefef` (белый), тени `6b473b`/`4b4b4b`/`afafaf`.  Привязка «номер шрифта →
  грань атласа» — из `text_layout::font_table_spec` (`UI_SCREENS.md` §11),
  проверена пикселями.
* **Плата.** `PLATE` рисуется в (0,0) в порядке `parse_bmp`, как в соседних
  рендерах; экранный origin копии `0x6865f8` не документирован (`UI.md` §8).
  Модуль **не** рисует плату неявно: её включает `options.background =
  "PLATE"`; пустая строка — чёрный холст.
* **Клип.** Глифы обрезаются полосой 196×131 (буфер `0x485dd0`).  Самый
  широкий текст — `Return To Game` (71 px), так что клип — страховка.
* **Ориентация глифов.** `FontGlyph::pixels` row 0 — верхняя строка
  визуального глифа (проверено на `L`/`T`/`V` шрифта 0: у `L` перекладина в
  последней строке, у `T` — в первой), поэтому строка `r` глифа пишется в
  `y + r`, как в соседних UI-рендерах.
* **`rows`/`arrows` в статистике.** `rows` = 2 или 3 — ровно то, что
  обработчик пишет в `0x67f10c`; `arrows` = 0 всегда — у экрана нет прокрутки
  и вызова `MENUARRW`; поле оставлено ради общей формы статистики.
* **Fade.** `fade_lut` — точный путь `0x682f90`: таблицы индекс → индекс,
  поэтому уровень применяется к индексу палитры каждого нарисованного пикселя
  **до** поиска цвета (`render/hud_lut.h::map`).  Уровни 0..15 берутся как
  есть (12..15 — реальные таблицы, они brighten).  Таблица — из памяти
  (`fade_lut_table`) или из дампа 4096 Б (`fade_lut_dump`, `docs/HUD_LUT.md`
  §2); без обоих — текстовый отказ, не «молча без fade».

## 3. API

```cpp
struct QuitRenderOptions {
    std::string background;          // "" = чёрный холст; "PLATE" — плата экрана 33
    bool in_game = false;            // [0x83cb7c] != 0: QUIT OPTIONS и три пункта
    int cursor = 0;                  // [0x68ccf4], id пункта; вне диапазона — без подсветки
    bool fade_lut = false;
    int fade_lut_level = kHudLutIdentityLevel;  // 11 — тождество, 0..15
    std::string fade_lut_dump;       // 4096-байтовый hud_lut.bin
    const gm::HudLut* fade_lut_table = nullptr; // приоритетнее дампа
};

struct QuitRenderStats {
    int rows = 0;            // 2 вне игры, 3 в игре
    int ink_pixels = 0;      // уникальные пиксели глифов
    int missing_glyphs = 0;  // символы без глифа (пропускаются)
    int arrows = 0;          // всегда 0: на экране нет MENUARRW
};

bool render_quit(const std::filesystem::path& game,
                 const QuitRenderOptions& options,
                 std::vector<std::uint32_t>& rgba,
                 int& width, int& height,
                 QuitRenderStats* stats = nullptr,
                 std::string* error = nullptr);
```

Константы: `kQuitTitleAsk = "QUIT GAME?"`, `kQuitTitleOptions =
"QUIT OPTIONS"`, `kQuitAskItems[2]`, `kQuitInGameItems[3]`,
`kQuitAskRows = 2`, `kQuitInGameRows = 3`, `kQuitItemStep = 16`,
`kQuitTitleY = 14`, `kQuitTitleX/kQuitItemX = 38`, `kQuitFirstRow = 27`,
`kQuitPanelName = "PLATE"`, `kQuitPanelWidth/Height = 196/131`,
`kQuitTitleFont/RowFont/SelectedFont = 5/0/4`; хелперы `quit_item_count`,
`quit_rows`, `quit_item_y`, `quit_item_label`, `quit_title`.

Контракт ошибок: любой отказ — текст с префиксом `quit_render:` (пустой
каталог игры, нет/битый `FRONTEND/BMP.IDX`, нет грани 5/0/4, нет/битый/не-8bpp
фон, fade без таблицы и дампа или с нечитаемым дампом).  При ошибке `rgba`
очищается, `width`/`height` = 0, `*stats` обнуляется.  Успех: `width == 320`,
`height == 200`, `rgba.size() == 64000`; вызов только читает установку,
детерминирован и не зависит от текущего каталога.

Что именно закреплено:

* оба варианта: `rows` 2/3, `arrows == 0`, `missing_glyphs == 0`,
  `ink == 228/576` = сумма независимых blit-полос (полосы не пересекаются);
* каждая полоса (заголовок + пункты) побайтово равна независимой отрисовке
  `compose_band`; bbox заголовка/первого/последнего пункта печатается и
  проверяется (`y0` = 14 / 27 / 43 (59), расстояние `16·(rows−1)`,
  `x0` заголовка = `(196 − width)/2` = 70 / 67);
* курсор 0..1 / 0..2: кадр равен независимому композиту с шрифтом 4 на этом
  пункте, отличия от кадра `cursor 0` лежат только в двух затронутых полосах
  (78 / 237 / 284 px), кадры попарно различаются (минимум 78 / 237 px),
  курсор вне диапазона (2/5/−1 и 3/6/−1) не подсвечивает ничего — 0 отличий от
  композита без подсветки;
* `PLATE`: все 25676 пикселей панели равны независимо декодированной `PLATE`
  (с учётом файлового порядка строк BMP), 228/576 пикселей под глифами
  совпадают с чёрным кадром, 38324 пикселя вне панели остаются чёрными;
  `menu_panel_asset(Screen::Quit) == "PLATE"`;
* fade: уровень 11 — 0 отличий из 64000 в обоих вариантах; уровень 0 —
  64000 чёрных (в чёрном кадре 38324) и 25676 отличий; 12..15 попарно
  различаются (17962/23830/20800) и все отличаются от 11
  (16960/25069/25308/25560); 99 → 15; негативы — тексты `quit_render:`;
* негативы без установки: пустой путь, каталог без `BMP.IDX`, синтетический
  `BMP.IDX` только с `FONTS1` (→ «FONTS4»), неизвестный фон `NOSUCH`;
* детерминизм: два одинаковых вызова дают 0 отличающихся пикселей.

Независимая сверка: числа кадра «вне игры» (`ink 228`, подсветка 78 px)
совпадают с давно закреплённым снимком `menu_render` (`docs/MENU_RENDER.md`
§4: `QUIT GAME? (id 33): items=2 drawn=2 ink=228 ... highlight_diff=78`), хотя
этот модуль считает кадр по другой модели (снимок `frontend_menu`).

## 5. Ограничения

* **Нет ввода и перехода.** Модуль только рисует кадр: не двигает курсор, не
  обрабатывает Enter/Esc, не пишет `[0x4bc440]`/`[0x68ccf4]`.  Ветка
  активации `0x48d92a` и переходы — в `ui/frontend_menu`
  (`docs/UI_SCREENS.md` §4, §12.4).
* **Нет звука.** `updown`/`select` и прочие UI-звуки — `ui/ui_sounds`,
  `docs/UI_SCREENS.md` §8.
* **CLI — есть (срез 5).** `--quit [--quit-in-game] [--quit-cursor N]
  [--no-plate] [--png OUT] [--fade-lut N]`: вне игры
  `quit: in_game=0 rows=2 cursor=0 ink=228 missing=0 arrows=0`, в игре
  `in_game=1 rows=3 cursor=2 ink=576`. CTest `cli_quit`, `_in_game`,
  `_png`; `cli_fade_lut` (11 = без fade, 13 ≠ без fade).
* **Нет самого действия выхода.** `Yes`/`Quit Game` в оригинале завершают
  процесс (`0x404740`), `Return To Game`/`No` меняют состояние — это поведение
  хоста, а не рендера.
* **Плата не рисуется неявно.** Без `background = "PLATE"` кадр — текст на
  чёрном; это осознанный контракт соседних рендеров, а не расхождение с
  оригиналом.
* **Шрифты.** Номера 5/0/4 — из таблицы `text_layout`; если в установке нет
  `FONTS4`, кадр не рисуется (отказ), а не подменяется другим атласом.
* **`ESC` не обрабатывается и в оригинале.** На экране нет строки
  `ESC TO CANCEL`, потому что её нет и в обработчике; ждать её от рендера
  нельзя.
