# RNG: `rand()` оригинала, сид и потребители

**Статус:** генератор **доказан инструкциями**; C++-порт `engine/src/game/rng.h`
проверен CTest `rng`. Сид оригинала — `time(nullptr)`, поэтому живой прогон
`gundx.exe` **не воспроизводим**; для тестов и парити нужен явный сид.

Проверки, которыми снят материал:

```sh
python3 tools/ghidra/mcp.py disasm 0x480e30 --count 14 --bytes   # rand
python3 tools/ghidra/mcp.py disasm 0x480e20 --count 5 --bytes    # srand
python3 tools/ghidra/mcp.py xrefs 0x480e30                       # 58 обращений
python3 tools/ghidra/mcp.py xrefs 0x480e20                       # 1 вызов
python3 tools/ghidra/mcp.py decompile 0x44a460 | head -45        # init + сид
```

## 1. `rand()` — `0x480e30`

```text
00480e30  e86b12f8ff        CALL 0x004020a0        ; _getptd()  (TLS)
00480e35  8b4814            MOV  ECX,[EAX+0x14]    ; _holdrand
00480e38  8d1449            LEA  EDX,[ECX+ECX*2]
00480e3b  8d1491            LEA  EDX,[ECX+EDX*4]
00480e3e  c1e204            SHL  EDX,4
00480e41  03d1              ADD  EDX,ECX
00480e43  c1e208            SHL  EDX,8
00480e46  2bd1              SUB  EDX,ECX           ; EDX = state*214013
00480e48  8d8c91c39e2600    LEA  ECX,[ECX+EDX*4+0x269ec3]  ; + 2531011
00480e4f  894814            MOV  [EAX+0x14],ECX    ; сохранить состояние
00480e52  8bc1              MOV  EAX,ECX
00480e54  c1e810            SHR  EAX,0x10
00480e57  25ff7f0000        AND  EAX,0x7fff
00480e5c  c3                RET
```

То есть классический MSVC CRT:

```text
state = state * 214013 + 2531011        (mod 2^32)
rand  = (state >> 16) & 0x7FFF          (0..32767)
```

Состояние лежит в **per-thread** структуре CRT (`_getptd()`, `TlsGetValue`,
`0x4020a0`), а не в глобале: два потока получали бы разные
последовательности. Движок однопоточный, поэтому в C++ достаточно одного
экземпляра.

## 2. `srand()` — `0x480e20`, единственный сид

```text
00480e20  e87b12f8ff        CALL 0x004020a0
00480e25  8b4c2404          MOV  ECX,[ESP+4]       ; аргумент seed
00480e29  894814            MOV  [EAX+0x14],ECX    ; _holdrand = seed
00480e2c  c3                RET
```

Вызов ровно один — в инициализации игры `FUN_0044a460`, сразу после старта:

```c
// 0x44a460
uVar5 = FUN_00480ef0(0);     // time(NULL) — CRT __time32/_time64
FUN_00480e20(uVar5);         // srand(time)
```

`0x480ef0` — обёртка CRT над `GetLocalTime`/`GetSystemTime` с проверкой
перехода на летнее время (`_isindst`), то есть действительно `time()`.

**Следствие:** последовательность оригинала зависит от секунды запуска.
Совпадение «случайных» величин с оригиналом возможно только при
воспроизведении сида; C++-тесты обязаны задавать сид явно.

Где ещё в билде стоит `rand()` (58 обращений):

| функция | шт. | что делает |
|---|---|---|
| `0x49dba0` | 10 | вариация питча/панорамы при проигрывании звука |
| `0x44a460` | 2 | инициализация (кроме сида — начальные значения) |
| `0x46ea40` | 2 | спавн снаряда (`FIRE_*`): точка/разброс |
| `0x478520`, `0x478be0` | 2+2 | hitscan BULLET / LASER: эффект попадания |
| `0x475f10`, `0x475930`, `0x476070` | 1+1+1 | визуальные эффекты снарядов |
| `0x473a00` | 1 | скан цели AI (`docs/AI_CPP.md`) |
| `0x4776d0` | 1 | двери/переключатели |
| `0x472790`, `0x4640c0`, `0x48*`, `0x49*` | по 1–2 | прочие эффекты/интерфейс |

Ни один из этих вызовов не влияет на **раскладку данных** или геометрию —
только на эффекты, звук и выбор цели. Поэтому детерминизм C++ не требует
побитового совпадения `rand`: достаточно фиксированного сида и явного
порядка вызовов (`M2.4`).

## 3. C++: `gm::MsvcRand`

`engine/src/game/rng.h` — header-only, без зависимостей:

```cpp
gm::MsvcRand rng(1u);      // srand(1)
int value = rng.next();    // rand(): 0..32767
rng.seed(seed);            // srand
std::uint32_t s = rng.advance(); // полное состояние после шага (для трасс)
```

CTest `rng` проверяет документированную последовательность MSVC
`srand(1)` — `41, 18467, 6334, 26500, 19169` — и сырое состояние после
первого шага (`2745024 = 1*214013 + 2531011`), границы `0..0x7FFF`,
ре-сид, нулевой сид и расхождение разных сидов.

**Не подменять** этим генератором разброс оружия (`Weapons::fire`): там
сейчас `mix64` с явным `Arsenal::seed` — это гипотеза, но она уже
зафиксирована golden-тестами; переход на `MsvcRand` должен идти вместе с
пересъёмкой голденов и доказательством порядка вызовов в оригинале.

## 4. Что **не** является `rand`: `0x480e6a`

В физике игрока (`0x444f28`) стоит вызов `0x480e6a`, который декомпилятор
показывает как `void FUN_00480e6a(void)` с `__cintrindisp2`. На самом деле
это FPU-обёртка CRT (`JMP 0x482040`, таблица `0x4bbe60`, `FPREM`-цикл
`0x480e74..0x480e8f`) — `fmod`. Аргументы передаются на x87-стеке:

```text
FLD  [player+0x68]        ; yaw
FSUB [0x4a23b0]           ; -(-2π) → yaw + 2π
FLD  [0x4a23b8]           ; 2π
CALL 0x480e6a             ; fmod(yaw + 2π, 2π)
FABS                      ; |...|
FSTP [player+0x68]
```

то есть нормализация угла рыскания в `[0, 2π)`, а не случайность. Константы
`0x4a23b0 = -2π`, `0x4a23b8 = +2π`, `0x4a23c0 = -π` (проверено `read_bytes`).

## 5. Что осталось

- Порядок вызовов `rand()` в покадровом цикле (для побитового парити
  эффектов) — нужен отладчик оригинала или длинная трасса.
- `rand() % n` vs `(rand() >> k) % n` в каждом потребителе: сейчас
  классифицированы только «эффекты/звук/цель», точные формулы не сняты.
- Многопоточность оригинала (звук) — отдельный `_holdrand`, в C++ не
  воспроизводится и не нужен (микшер детерминирован, `docs/AUDIO_MIXER.md`).
