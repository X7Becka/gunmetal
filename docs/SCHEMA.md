# Схема форматов: единый источник истины (M3.2.1)

Раскладки ключевых структур сейчас живут в трёх местах:

* C++-читатели `engine/src/res/{sbt,sbw,sbc}.h`;
* Python-оракул `gm/{sbt,sbw,sbc}.py`;
* проза `docs/FORMATS.md`.

Расхождение между ними до сих пор ловилось только глазами. Теперь схема
объявлена **один раз** — таблицами `CONST` и `SCHEMA` в
`tools/qa/schema_check.py` — и все три стороны проверяются против неё одной
командой.

## Что объявлено

`CONST` — фиксированные размеры и границы (84-байтовый заголовок `.sbt`,
`124 + 2*n` полигон, `300 * u32 + 300 * 9` таблица сэмплов, `2**w * 2**h`
лайтмап и т. д.). `SCHEMA` — по записи на структуру:

| Структура | Сторона | Что именно сверяется |
|---|---|---|
| `SbtRecord` | C++ `SbtRecord`, Python `Record` | `type/name/offset/size/payload`; запись на диске — `[u8 type][payload]`, `size = 1 + len(payload)` |
| `SbtHandle` | C++ `SbtHandle` | 4 × `u32` = 16 байт; Python хранит таблицы **по колонкам** (`HandleTable`), отдельного dataclass нет |
| `Script` | C++ `SbtScript`, Python `Script` | `count, things[count*40], n, 3*n u32, m, code[m], flag, tables` (0 или `9*0x400`) |
| `SoundSampleTable` | C++ `SoundSampleTable` + константы `kSlots/kNameWidth`, Python `SampleTable` | `300 * u32` + `300 * 9` байт (`0x4b0 + 0xa8c`) |
| `SbwPoly` | C++ `SbwPoly`, Python `Poly` | 30 полей; на диске `12 + 2*n_idx + 112` = `124 + 2*n_idx` байт |
| `SbwObject` | C++ `SbwObjectRef` + `SbwGeometry`, Python `Object` | заголовок 96 Б = `origin[3] + basis[3][3]` (12 × `f64`), `radius` 0x60, `bounds` 0x84; стадия 2 = `4 + 12*n_verts + 50` Б |
| `Sbc` | C++ `Sbc` + `SbcRecord`, Python `Sbc` + `Record` | `magic[4]`, `count`, записи `{u32 desc, 2**w * 2**h байт}` |

Поля структур объявлены с точными типами C++ (`u32`, `array[96]<u8>`, …) и
семействами Python (`int`, `bytes`, `tuple`, …): ширина C++-поля проверяется
до байта, Python не привязывается к 32 битам без нужды.

## Как проверяются три стороны

1. **C++ ↔ схема.** Заголовки `engine/src/res/{sbt,sbw,sbc}.h` режутся
   регулярным выражением на `struct NAME { … };`, из каждой строки берётся
   тип, имя и (для `T name[N]`) длина массива. Полученный словарь сравнивается
   с объявленным списком полей: пропавшее поле, переименование, смена ширины
   (`u32` → `u64`) и лишнее необъявленное поле — расхождение. Отдельно
   сверяются `static constexpr` константы (`kSlots = 300`, `kNameWidth = 9`).
2. **Python ↔ схема.** Из `gm/*.py` вытаскиваются `@dataclass`-классы и их
   аннотированные поля; алиасы (`Vec3 = tuple[…]`) разворачиваются. Сравнение
   то же, но по семействам типов; поля, которые Python намеренно держит
   дополнительно (`Record.raw`), перечислены в `allow_extra` и не считаются
   дрейфом.
3. **Данные ↔ схема.** Отдельный читатель на stdlib `struct` (без импорта
   `gm.*`) заново проходит каждый файл:
   * `.sbw` — три таблицы, 96-байтовые заголовки объектов, стадии 1/2,
     каждый полигон обязан иметь размер ровно `124 + 2*n_idx`, индексы
     `< n_verts`, поток заканчивается ровно на EOF;
   * `.sbt` — заголовок 84 Б, цепочка `[u8 type][payload]` по всем типам
     §12, границы счётчиков, `SCRIPT` (`count*40`, `3*n*4`, `m`, флаг),
     `SOUND_SAMPLE_TABLE` (`0x4b0 + 0xa8c`), конец ровно на `255`;
   * `.sbc` — магия `SBC0`/`SBC1`, `count`, каждая запись `u32 desc` +
     `2**(desc&0xffff) * 2**(desc>>16)` байт, сумма = размер файла.

Прогон идёт по установке `/mnt/d/games/Gunmetal 3dfx` **и** по зеркалу
`~/.cache/gunmetal-re/game` (отключается `--no-mirror`). Игра только читается.

## Команды и вывод

```sh
python3 tools/qa/schema_check.py --self-test

python3 tools/qa/schema_check.py --check
```

печатает те же строки одной структурой (`checks`, `summary`).

## Найденные расхождения

1. **`docs/FORMATS.md` §10.1, строка `n_idx`: «3..12» — устарело.**
   В поставке 4 полигона с большим числом индексов:
   `level22.sbw` @`0x3d18b` n=26 и @`0x61305` n=20,
   `level5.sbw` @`0x5f3fe` и @`0x6322c` n=14. Все они проходят по размеру
   `124+2*n` и по индексам `< n_verts`, то есть это настоящие полигоны, а не
   сдвиг разбора (оба файла доходят ровно до EOF). `gm/sbw.py` и C++-читатель
   предел не проверяют, поэтому данные парсятся; неверна только проза.
   В `CONST["sbw_poly_max_idx"]` зафиксирован доказанный максимум 26, а
   документированная граница 12 вынесена в `sbw_poly_doc_max` и даёт отдельную
   строку `sbw/n_idx` — после правки дока её нужно поднять.
2. **`gm/sbc.py`, docstring: «34 files in the game root and 17 object sets in
   `SOBS/`» — неверно.** Фактически 36 в корне + 15 в `SOBS/` = 51 (столько же
   в зеркале); общий счёт 51 совпадает, разбивка в комментарии — нет.
3. **Формулировка задания «`SbtRecord`: `u32 type, u32 size`» не
   подтверждается.** В бинарном `.sbt` запись — это `[u8 type][payload]`
   (`docs/FORMATS.md` §12, `gm/sbt.py::Record`, `engine/src/res/sbt.h`);
   `size` — производное поле разобранной записи, на диске его нет. Проверено
   цепочкой всех 36 файлов до `END_OF_FILE`. Схема фиксирует доказанную
   раскладку; попытка объявить `u32/u32` сразу дала бы ложное расхождение.
4. **Не «расхождение», а разная форма:** `SbtHandle` в Python не отдельный
   dataclass, а колонки `HandleTable`; `SbwObject` в C++ разрезан на
   `SbwObjectRef` (id + 96 Б заголовка) и `SbwGeometry` (стадия 2), в Python
   это один `Object`. Схема связывает обе формы с одной раскладкой, поэтому
   такие различия не считаются дрейфом.

## Ограничения

* Разбор C++ — **регулярка, а не компилятор**: понимаются только простые
  `struct NAME { … };` с полями `T name`, `T name[N]`, `std::array<T, N>`,
  `std::vector<T>`; не поддерживаются наследование, вложенные/анонимные
  структуры, макросы, `#if`, битовые поля и функции-члены. Незнакомые строки
  молча пропускаются — новое поле, записанное нестандартно, проверка не
  увидит.
* Python-разбор — тоже регулярка: только `@dataclass` с полями в теле класса;
  унаследованные поля и `ClassVar` не разворачиваются.
* Проверяются только структуры, перечисленные в `SCHEMA`. Поля, которых там
  нет, не проверяются; намеренно игнорируемые нужно вносить в `allow_extra`,
  иначе они дают «лишнее поле».
* Читатель данных независим от `gm.*`, но проверяет **раскладку и границы**,
  а не семантику: единичность нормалей, корректность UV, опкоды скриптов,
  значения лайтмапов не сверяются.
* Корпус — только поставочные `.sbw`/`.sbt`/`.sbc`. Сейвы (`SAVEGAME`),
  `.sob`, `.sou`, `.sbv` и прочие форматы в схему пока не входят.
* Скрипт ничего не пишет: и установка, и зеркало открываются только на
  чтение.
