# PERFORMANCE — измеренные времена (`M12.3`)

Снимок на машине разработки (WSL2, Ubuntu 26.04, Zig-сборка `build/sandbox`),
2026-10-23. Инструмент — `tools/qa/perf.py` (stdlib, только чтение);
`--self-test` не требует игры, `--json` — машинный формат, `--render-ms N` —
жёсткий бюджет для конкретной машины.

```sh
python3 tools/qa/perf.py --repeat 3
python3 tools/qa/perf.py --game ~/.cache/gunmetal-re/game --repeat 3
python3 tools/qa/perf.py --render-ms 400     # 1 при превышении бюджета
```

## 1. Что и как меряется

| фаза | что делает |
|---|---|
| `parse` | `gm.sbt` + `gm.sbw` для `level0`, `dm1`, `level24` (Python-эталон) |
| `vm` | `gm.sbtvm_exec` — главный блок `level0` (`max_time=0`) |
| `load` | C++ `gunmetal -l level0 --info` (разбор + сводка, без текстур и кадра) |
| `render` | C++ `--render OUT.png` — **холодный** прогон: загрузка уровня, один кадр, PNG |
| `decode` | `ALARMK` SOU1: контейнер → слоты 32 кГц (`gm.sou1`) |
| RSS | пик дочернего процесса (`ru_maxrss`, МБ) |

Важно: `render` — это не FPS. Это «полный процесс от старта до PNG»; бюджет
60 FPS относится к **прогретому** игровому циклу, которого пока нет
(следующий шаг — цикл с рендером, `M8`/`M9`).

## 2. Установка на `/mnt/c` (медленный 9p)

```
parse   level0 16.9 ms (best 15.9)   dm1 45.9 (41.2)   level24 61.2 (59.8)
vm      level0  1.6 ms
load    C++ -l level0 --info  84.6 ms
render  320x200 376.5 ms -> 2.66 холодных прогона/с
        640x400 438.0 ms -> 2.28
decode  ALARMK 13619 B -> 16000 Гц, 1 канал, 54408 кадров: 4.96 ms
RSS     52.4 MB
```

## 3. Зеркало в Linux-доме (`~/.cache/gunmetal-re/game`)

```
parse   level0  8.5 ms (best 7.2)   dm1 31.9 (27.4)   level24 47.8 (47.2)
vm      level0  1.6 ms
load    C++ -l level0 --info  61.7 ms
render  320x200 182.0 ms -> 5.50 холодных прогона/с
        640x400 243.4 ms -> 4.11
decode  ALARMK 4.88 ms
RSS     52.3 MB
```

**Вывод:** разница `/mnt/c` ↔ зеркало — почти двукратная на загрузке
(`level0`: 16.9 → 8.5 мс в Python, 84.6 → 61.7 мс в C++, 376 → 182 мс на
полный холодный рендер). Это стоимость 9p/drvfs, а не кода; тяжёлые прогоны
и сборки держать в Linux-доме (ср. `AGENTS.md`).

Холодный рендер раскладывается как `load` + кадр + PNG; прирост 640×400 против
320×200 — около 61 мс на зеркале, то есть растеризация и PNG заметны, но
основное время холодного прогона — загрузка уровня и подготовка текстур.

## 4. Что это значит для `M12.3`

* Разбор данных, ВМ и декод звука — миллисекунды, не узкое место.
* Узкое место холодного старта — файловый ввод и подготовка ресурсов; на
  `/mnt/c` это вдвое дороже.
* **60 FPS не измерен**: нужен прогретый цикл (кадр без загрузки и без PNG).
  Когда появится рантайм с рендером, `perf.py` дополнится фазой `--frames N`
  (несколько кадров в одном процессе) и бюджетом `--frame-ms 16.7`.
