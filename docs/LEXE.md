# LE/LX-формат: DOS-сборка Gunmetal (`gun.exe`)

Документ описывает формат, который **не** является PE: DOS-сборка 1998 года
лежит в `gun.exe` как MZ-образ с заголовком `LE` (Linear Executable). Ни
`objdump`, ни `tools/re/exelib.py` (PE-only) такой файл не читают, поэтому
формат разобран здесь самостоятельно.

Инструмент: **`tools/re/lexe.py`** (парсер + CLI, только stdlib).

## 1. Провенанс

| что | значение |
|---|---|
| файл | `/mnt/d/games/Gunmetal 3dfx/gun.exe` (только чтение) |
| размер | 3 041 664 байта (0x2E6980) |
| SHA-256 | `773cac90bf6b281142837003c3430155de599d26cbfdc79b78638a016879b83d` |
| MZ `e_lfanew` | `0x30A8` (u32 по 0x3C) |
| сигнатура по `e_lfanew` | `LE` (0x4C 0x45) |
| сборка | Watcom: строка `WATCOM C/C++32 Run-Time system. (c) Copyright by WATCOM International Corp. 1988-1995.` по **VA 0xAF615** (файл `0xD9E15`) |

Рантайм — 32-битный плоский DOS-модуль (Watcom C/C++32), хотя MZ-заглушка
собрана 16-битным рантаймом (`WATCOM C/C++16` по файлу `0x41F`).

## 2. Карта файла

| диапазон | что | чем доказано |
|---|---|---|
| `0x0000..0x30A7` | MZ-заголовок + DOS-заглушка | `e_lfanew = 0x30A8`; заглушка оканчивается строками WATCOM |
| `0x30A8..0x3167` | LE-заголовок (0xC0 байт) | подпись `LE` по `e_lfanew` |
| `0x316C..0x3213` | таблица объектов (7 × 24) | запись `+0x40` = `0xC4` → `0x30A8+0xC4 = 0x316C`; 7 записей по 24 байта покрывают `0x316C..0x3213` |
| `0x3214..0x3C8B` | таблица страниц объектов (670 × u32) | запись `+0x48` = `0x16C` → `0x3214`; длина 670 = числу страниц |
| `0x3C8C..0x3C8F` | имя модуля `03`+`gun` | запись `+0x50` = `0xBE4` → `0x3C8C` |
| `0x3C93..0x3C93` | таблица имён импортируемых модулей (пуста) | запись `+0x5C` = `0xBEB` → `0x3C93`; первый байт = 0 |
| `0x3C94..0x470F` | таблица страниц fixup (671 × u32) | запись `+0x68` = `0xBEC` → `0x3C94`; 671 × 4 = 0xA7C → ровно `0x4710` |
| `0x4710..0x4975E` | записи fixup (282 703 байта) | запись `+0x6C` = `0x1668` → `0x4710`; последняя запись таблицы страниц = 0x4504F, `0x4710+0x4504F = 0x4975F` |
| `0x4975F..0x497FF` | таблица импортируемых модулей (пуста) | запись `+0x70` = `0x466B7` → `0x4975F`; совпадает с концом fixup-записей |
| `0x49800..0x2E697F` | страницы данных (670 шт.) | запись `+0x80` = `0x49800` (абсолютный смещение в файле) |

## 3. Заголовок LE (`0x30A8`), проверенные смещения

Смещения — от начала LE-заголовка (= `e_lfanew`). Все значения вычитаны из
`gun.exe`; столбец «проверка» — чем подтверждено значение.

| смещение | размер | имя | значение | проверка |
|---|---|---|---|---|
| `+0x00` | 2 | сигнатура | `LE` | подпись по `e_lfanew` |
| `+0x02` | 1 | byte order | 0 (little) | заголовок однозначен только при little-endian |
| `+0x03` | 1 | word order | 0 (little) | то же |
| `+0x04` | 4 | format level | 0 | — |
| `+0x08` | 2 | cpu type | 2 (80386) | согласуется с 32-битным Watcom C/C++32 |
| `+0x0A` | 2 | os type | 1 (OS/2) | согласуется с форматом LE |
| `+0x0C` | 4 | module version | 0 | — |
| `+0x10` | 4 | module flags | 0x200 | — |
| `+0x14` | 4 | *не опознано* | 666 | ⚠ модуль на самом деле содержит **670** страниц (см. §4) — смысл поля не установлен |
| `+0x18` | 4 | EIP: номер объекта | 2 | EIP попадает в объект 2 (код) |
| `+0x1C` | 4 | EIP: смещение | 0x8F614 | EIP = `0x20000+0x8F614` = **VA 0xAF614** = файл `0xD9E14`; там `eb 76` (`jmp`), следом копирайт WATCOM ⇒ точка входа подтверждена на data |

## 4. Таблица объектов

24 байта на объект: `u32 size`, `u32 va`, `u32 flags`, `u32 first_page`,
`u32 page_count`, `u32 reserved`. `first_page` — **1-based** номер страницы
данных; `page_count` — число страниц объекта.

| объект | VA | размер | flags | R/W/X | страницы | файл | содержимое (по первым байтам) |
|---|---|---|---|---|---|---|---|
| 1 | 0x10000 | 0x10 | 0x2045 | R X | 1 | 0x49800 | `cc eb fd 90 90…` — заглушка DOS |
| 2 | 0x20000 | 0xA75E4 | 0x2045 | R X | 2..169 | 0x4A800 | код (`51 56 57 55 81 ec …`), внутри — строки `_GRA…@4` |
| 3 | 0xD0000 | 0x573 | 0x2045 | R X | 170 | 0xF2800 | код |
| 4 | 0xE0000 | 0x2B8 | 0x2045 | R X | 171 | 0xF3800 | код |
| 5 | 0xF0000 | 0x48 | 0x1045 | R X | 172 | 0xF4800 | код |
| 6 | 0x100000 | 0x1D5C40 | 0x2043 | R W | 173..642 | 0xF5800 | код (плюс строки) |
| 7 | 0x2E0000 | 0x3BC560 | 0x2043 | R W | 643..670 | 0x2CB800 | float-данные (`1.0f`, `9.7f`, …) |

Диапазоны страниц объектов **покрывают страницы 1..670 ровно по одному разу**
(1 + 168 + 1 + 1 + 1 + 470 + 28 = 670) — это и есть независимая проверка
модели страниц.

Объект 7 объявляет размер 0x3BC560 (3 915 552 байта), но имеет только 28
страниц (114 688 байт) ⇒ **механизм LE «iterated data» (повтор последней
страницы) в парсере не реализован**; отображение VA покрывает только
файлово-подтверждённые страницы, лишние адреса дают `None` (см. §7).

## 5. Отображение «(объект, смещение) → файл»

```
страница p (1-based)  ->  файл  data_pages_file_offset + (p-1) * page_size
страница объекта       ->  first_page .. first_page+page_count-1
(объект o, смещение x)  ->  страница  first_page(o) + x // page_size
                             внутри   x % page_size
```

Последняя страница (670) короче: 384 байта вместо 4096.

**Доказательство (end-to-end):** из 33 055 записей fixup 32 791 — «обычные»
(тип 0x07/0x05) — указывают на адрес в файле, где **до сих пор лежит
непропатченное значение цели** (смещение цели внутри объекта). Ещё 264
пропущено: 235 — self-relative (тип 0x08) и 16:16-указатели (тип 0x03, 8 шт.),
21 — записи с «сентинельными» смещениями `0xFFFD..0xFFFF`. Несовпадений — **0**.

## 6. Таблицы fixup

* **Таблица страниц fixup** (`0x3C94`): 671 запись `u32` — накопительные
  смещения (в байтах) начала записей каждой страницы; последняя запись = общий
  размер блока записей (0x4504F). Таблица монотонна.
* **Записи fixup** (`0x4710`): переменной длины. Формат (проверен на данных):

  | байты | смысл |
  |---|---|
  | `u8` | source type: младший ниб — вид fixup, бит 0x20 — «список смещений» |
  | `u8` | target flags: младшие 2 бита — вид цели, 0x04 — есть аддитив, 0x10 — 32-битное смещение цели, 0x40/0x80 — 16-битный номер объекта / 8-битный ординал |
  | `u16` | смещение в странице (или `u8` число элементов списка) |
  | … | номер объекта цели, смещение цели, аддитив, список смещений |

  Виды source (наблюдённые): `0x07` — 32-битное смещение (32 811 шт.),
  `0x08` — 32-битное self-relative (235), `0x03` — указатель 16:16 (8),
  `0x05` — 16-битное смещение (1). Вид цели у **всех** записей — внутренняя
  ссылка (`0x00`), т.е. внешних импортов в модуле нет.

## 7. Имена, импорты, таблица экспортов

* Имя модуля: `gun` (таблица длин в `0x3C8C`).
* **Импортов нет**: таблица имён импортируемых модулей (`0x3C93`) и таблица
  импортируемых модулей (`0x4975F`) пусты; все 33 055 fixup-ов — внутренние.
  Watcom C/C++32 линкуется статически.
* **Таблицы экспортов (entry table) в файле нет**: ни одно поле заголовка не
  удалось связать с таблицей бандлов; поиск по области таблиц бандлоподобных
  записей (VA, count ≤ 64, flags ≤ 3) даёт только случайные совпадения внутри
  данных fixup. В парсере есть метод `LEImage.parse_entry_table(offset, size)`
  с форматом LE-бандлов (u32 offset, u16 count, u16 flags + записи по 3 байта)
  — для других LE-файлов.

## 8. Что не поддержано / что осталось

* **Iterated pages** (объект 7: размер больше суммарного размера страниц) —
  не реализовано, зафиксировано в выводе как `over_declared_size`.
* **Смысл таблицы страниц объектов** (`0x3214`, 670 × u32) не установлен:
  значения — «перевёрнутый счётчик» (`(i+1) mod 256` в старших 16 битах,
  `(i+1) div 256` в младших), они не совпадают ни с номерами страниц, ни с
  VA страниц, ни с 64-КБ-сеткой. Модель страниц построена по таблице
  объектов и подтверждена 32 791 fixup-ами (§5). Таблица читается и
  отдаётся как `object_page_map` (сырые значения).
* Поля заголовка `+0x14`, `+0x30`, `+0x38`, `+0x94` и ряд других — смысл не
  установлен (значения приведены в §3).
* Биты флагов объектов 0x40/0x1000/0x2000 не опознаны; трактовка R/W/X
  (биты 0..2) — стандартная для LE, но объект 6 содержит код при флаге
  «R W», поэтому разграничение «код/данные» по флагам тут ненадёжно.

## 9. Команды проверки

```sh
python3 tools/re/lexe.py --game "/mnt/d/games/Gunmetal 3dfx" --info --json
python3 tools/re/lexe.py --game "/mnt/d/games/Gunmetal 3dfx" --segments
python3 tools/re/lexe.py --game "/mnt/d/games/Gunmetal 3dfx" --fixups --limit 20
python3 tools/re/lexe.py --game "/mnt/d/games/Gunmetal 3dfx" --strings --min-len 20
python3 tools/re/lexe.py --game "/mnt/d/games/Gunmetal 3dfx" --dump 2:0x8f614:32
python3 tools/re/lexe.py --game "/mnt/d/games/Gunmetal 3dfx" --selftest
python3 -m py_compile tools/re/lexe.py
```

`--selftest` (23 проверки): заголовок, покрытие страниц объектами, границы
файла, попадание EIP в объект, монотонность и границы таблиц fixup, сверка
32 791 мест fixup с целью, 10 испорченных вариантов заголовка — все должны
давать `ValueError` (не `IndexError`/`struct.error`).
