# SML: раскладка текста, шрифтовые атласы и пагинация

Документ описывает `engine/src/render/text_layout.h` / `text_layout.cpp` —
C++-порт текстового движка фронтенда: таблицу шрифтов, извлечение глифов из
`FRONTEND/BMP.IDX`, метрики, переносы, центрирование и страницы. Формат SML и
экраны — в [UI.md](UI.md), C++-читатель разметки — в [SML_CPP.md](SML_CPP.md).

Модуль только читает: `FRONTEND/BMP.IDX` открывается на чтение, игра и корпус
не изменяются.

Это следующий шаг после `docs/UI.md` §10 (пункты 3–4: «сопоставление номера
шрифта и атласа» и «разбиение на страницы»). Оба пункта закрыты; ниже
разделены доказанное и гипотезы.

## 1. API

```cpp
#include "render/text_layout.h"

std::string error;
auto font = gm::load_font("/path/to/game", 1, error);   // логический шрифт 1
if (!font) { /* error: нет атласа / архива / сетка не влезает */ }

gm::LayoutOptions opts;   // width=267, height=167, line_height=10
auto layout = gm::layout_text(doc, *font, opts, &error);
// layout.pages[i].lines[j].{x,y,width,height,font,first,last}
// layout.pages[i].{start,end,used_height,images}
// layout.runs[k].{x,y,width,font,first,last,text}

auto bounds = gm::text_bounds(layout);   // width/height/lines/pages

gm::RenderResult frame;
frame.width = 320; frame.height = 200;
frame.rgb.assign(320u * 200u * 3u, 0);
gm::draw_text(frame, layout, *font, 26, 16, error);
```

| Тип / функция | Назначение |
|---|---|
| `FontSpec`, `font_spec(n)`, `font_table_spec(n)` | запись таблицы `0x65ddd0`; `font_spec` учитывает отображение 1→0, 2→5 |
| `FontAtlas` | `width/height` атласа, `cell_width/cell_height`, `first_char/last_char`, `advance[]`, `glyphs[]`, палитра |
| `FontGlyph` | `advance`, `width` (ширина чернил), `pixels` — `width*cell_height` индексов палитры, строка 0 = **низ** глифа |
| `load_font(game, n, error)` | загрузка из `FRONTEND/BMP.IDX` |
| `load_font_bmp(n, bytes, error)` | то же из сырых байт BMP (тесты, синтетика) |
| `logical_font_number(n)`, `font_line_height(n)` | отображение шрифтов и высота строки |
| `layout_text(doc, font, opts, error)` | раскладка одним атласом (метрики всех прогонов — из него) |
| `layout_text(doc, lookup, default_font, opts, error)` | раскладка с провайдером атласов: `<f s=N>` берёт метрики своего шрифта |
| `LayoutOptions` | `width`, `height`, `line_height`, `big_line_height`, `max_pages`, `image_width/height`, `wrap` |
| `LayoutRun` / `LayoutLine` / `LayoutImage` / `LayoutPage` | прогоны, визуальные строки, картинки, страницы |
| `text_bounds(layout)` | bbox и счётчики |
| `draw_text(...)` | блит глифов в `RenderResult` (RGB), палитра атласа, индекс 0 прозрачный |

Ограничения честно помечены:

* `FontAtlas::has_glyphs() == false` — «только метрики»; `draw_text` вернёт
  ошибку `... is metrics-only`, а не нарисует мусор.
* ошибки раскладки: пустой документ, `width/height <= 0`, `line_height <= 0`,
  шрифт без глифов, превышение `max_pages` (плюс `LayoutResult::truncated`).
* `draw_text` проверяет размер `RenderResult::rgb` и наличие атласа для
  каждого прогона.

## 2. Где лежат глифы

### 2.1. Таблица шрифтов

Загрузчик `0x47fe30` заполняет таблицу `0x65ddd0` — 31 запись по `0x1c`
байт (`shl 3; sub; shl 2`). Поля записи:

| Смещение | Поле | Смысл |
|---|---|---|
| `+0x00` | width | ширина клетки глифа |
| `+0x04` | height | высота клетки |
| `+0x08` | first | первый код (`atoi`-диапазон) |
| `+0x0c` | last | последний код (`first + count - 1`) |
| `+0x10` | extra_before | добавка к ширине в `0x47fa50` |
| `+0x14` | extra_after | вторая добавка |
| `+0x18` | glyphs | массив блоков `1 + w*h` байт |

Внутри блока: **первый байт — ширина (advance)**, далее `w*h` индексов
палитры. Блоки лежат подряд, индекс блока — `code - first`.

### 2.2. Аргументы вызовов

`0x47fe30` вызывается 12 раз (`0x490165` … `0x49054f`) сразу после загрузки
BMP. Аргументы (последний push — номер шрифта):

```
(number, cell_w, cell_h, first, count, extra_before, extra_after, space,
 mode, bitmap, x0, y0, col_pitch, row_pitch, stride, columns)
```

* `mode=1` — обрезка по чернилам (обычные шрифты);
* `mode=0` — копия всей клетки (цифровые `NUMFONTS`);
* `space` — advance для пробела в режиме обрезки (`0x47ff5b`);
* `bitmap` — указатель на пиксели (BMP загружается **без** переворота строк,
  поэтому буфер bottom-up);
* источник глифа: `bitmap + y0*stride + x0 + (i/columns)*stride*row_pitch +
  (i % columns)*col_pitch`.

В режиме обрезки (`0x47ff9c`) загрузчик ищет крайние непустые столбцы клетки,
пишет `advance = high - low + 1` и копирует только эти столбцы. Поэтому
`extra_before/after` (0 и 1 у всех шрифтов поставки) добавляются уже при
измерении. Пробел — исключение: `advance = space`, пиксели нулевые.

### 2.3. Какие шрифты инициализируются

| № | атлас | клетка | коды | сетка (x0,y0 / pitch / cols) | пробел | режим |
|---:|---|---|---|---|---:|---|
| 0 | `FONTS4` 512×168 | 8×8 | 32..127 | 8,0 / 16×14 / 32 | 3 | обрезка |
| 1 | `FONTS1` 512×168 | 8×8 | 32..127 | 8,0 / 16×16 / 32 | 4 | обрезка |
| 2 | `FONTS1` 512×168 | 8×8 | 32..127 | 8,96 / 16×16 / 32 | 4 | обрезка |
| 3 | `FONTS2` 1024×80 | 16×16 | 32..95 | 8,32 / 24×32 / 32 | 7 | обрезка |
| 4 | `FONTS4` 512×168 | 8×8 | 32..127 | 8,42 / 16×14 / 32 | 3 | обрезка |
| 5 | `FONTS4` 512×168 | 8×8 | 32..127 | 8,84 / 16×14 / 32 | 3 | обрезка |
| 7 | `FONTS3` 520×56 | 8×8 | 32..95 | 8,32 / 16×16 / 32 | 4 | обрезка |
| 8 | `FONTS4` 512×168 | 8×8 | 32..95 | 8,126 / 16×14 / 32 | 3 | обрезка |
| 9 | `NUMFONTS` 180×48 | 8×10 | 48..57 | 8,6 / 16×16 / 10 | 8 | копия |
| 10 | `NUMFONTS` 180×48 | 8×10 | 48..57 | 0,22 / 16×16 / 10 | 8 | копия |
| 11 | `NUMFONTS` 180×48 | 8×8 | 48..57 | 8,32 / 16×8 / 10 | 8 | копия |
| 12 | `NUMFONTS` 180×48 | 8×8 | 48..57 | 0,40 / 16×8 / 10 | 8 | копия |

`y0` — в координатах буфера (снизу вверх): `image_row = H - 1 - y`.

**Шрифты 6 и 13..30 не инициализируются**. `0x47fa50` для них возвращает 0
(нет базы), `0x47faf0` — `-2`; `load_font` в этом случае даёт чистую ошибку.

### 2.4. Логическое отображение шрифтов

`0x497b10` (измерение) и `0x497b60` (отрисовка) перед обращением к таблице
делают:

```
font 1 -> 0, font 2 -> 5, иначе без изменений
```

То есть SML-шрифт `2` рисуется **не** вторым слотом FONTS1, а слотом 5
(FONTS4, `y0=84`). Поэтому `load_font(game, 2)` возвращает `source = 5` и
атлас `FONTS4`, а `font_table_spec(2)` показывает сырой слот `FONTS1`.

Метрики шрифтов 0, 1, 5 и 2 совпадают (advance FNV одинаков), но пиксели
слота 2/5 отличаются от слота 0/1 (другая область FONTS1/FONTS4).

### 2.5. Ширина и высота строки

`0x47fa50(text, font)`:

```
width = 0
for byte c in text:
    if c < first or c > last: continue          # включая байты >= 0x80
    width += block(c).advance + extra_before + extra_after
```

Высота строки — `0x4983c3` (после выбора шрифта):

```
line_height = (font == 3) ? 18 : 10
```

Это уточнение к `docs/UI.md` §5.3: 18 px получает **только** шрифт 3, а не
«все шрифты >= 3». Для поставки (2/3) разницы нет.

## 3. Раскладка

### 3.1. Состояние (глобалы движка → поля `PageState`)

| Адрес | Поле | Смысл |
|---|---|---|
| `0x68e648` | `y` | текущая строка (верх строки) |
| `0x68e658` | `right_edge` | правый край; правый `<I>` сдвигает его влево |
| `0x68e64c` | — | остаток ширины (`right - x`), не хранится |
| `0x68e65c` | `line_height` | 10/18 |
| `0x68e654` | `left_float_bottom` | низ левой картинки |
| `0x68e644` | `right_float_bottom` | низ правой картинки |
| `0x68f008` | `x` | перо в строке |
| `0x68ee74` | `column_start` | левый край колонки (для левого `<I>`) |
| `0x4be8b8/0x4be8bc` | `width/height` | страница, задаётся `0x4972f0(w,h)` |
| `0x68ee70` | — | номер страницы |

Вызов пагера: `0x4972f0(0x10b, 0xa7)` = **267×167** (брифинги), рендер в
буфер `0x6c597c` шириной 320 (`0x487c4a`).

### 3.2. Цикл страницы (`0x497880`)

```
y = 0; x = column_start = 0; right = width
font = 1; line_height = 10
next = start_offset

повторять:
    если y > height - line_height: конец страницы
    если до следующего тега есть текст:
        пропустить ведущие пробелы, если x == column_start      # 0x497930
        (consumed, w, wrap) = wrap_run(текст, font, right - x)
        нарисовать прогон [pos, pos+consumed) в (x, y)
        x += w
        если wrap: line_feed(pos + consumed)
    иначе: обработать тег
```

`line_feed` (`0x497ba0`): `y += line_height`; если `y > left_float_bottom`,
`column_start = 0`; если `y > right_float_bottom`, `right_edge = width`;
`x = column_start`; `right = right_edge`.

### 3.3. Перенос (`0x497c20`)

Жадный поиск по словам: берётся самый длинный префикс до пробела, который
влезает в остаток; если не влезает ни одного слова, слово режется по символам
(в бинарнике при нулевой ширине возможен цикл — здесь принудительно
потребляется один символ). Прогон, занявший строку ровно (`w >= available`),
тоже завершает строку (`0x497cf1`).

Начальная оценка в бинарнике — `width / 7` (таблица `0x4be8c0`, четыре
записи по 7); на результат не влияет, это только старт поиска.

### 3.4. Теги

| Тег | Обработчик | Поведение в раскладке |
|---|---|---|
| `<r>` | `0x497d7c` | перевод строки; в самом начале страницы игнорируется |
| `<p>` | `0x497da0` | `+line_height/2`, затем перевод строки; если строка уже полная (`x == right`), добавка пропускается |
| `<c>` | `0x497ec2` | измерить следующий текстовый сегмент (до следующего тега) и сдвинуть `x` на `(right - x - measured)/2` |
| `</c>` | `0x49838e` → `0x4983e6` | перевод строки (таблица закрывающих тегов `0x498540`/`0x49855c`) |
| `<f s=N>` | `0x497e9f` | сохранить шрифт, выбрать `N`, пересчитать `line_height` |
| `</f>` | `0x4983be` | восстановить сохранённый шрифт |
| `<x>` | `0x497f38` | `x = value * width / 100`, только если `column_start <= x < right` |
| `<s>` | `0x497de8` | `x += min(width(" "), right - x)` (без переноса) |
| `<k>` | `0x497e2c` | «Soldier»; если не влезает — перевод строки, затем вывод |
| `<m B/S>` | `0x497f92` | только запись в `0x68cc8c`/`0x68cc88`, раскладку не меняет |
| `<i ...>` | `0x498012` | картинка-float (см. §3.6) |
| `</d>` | `0x4983aa` | конец документа: маркер продолжения = 0 |
| прочее | `0x4983eb` | no-op |

Значения атрибутов в поставке в кавычках (`<f s="2">`), парсер `0x498580`
читает первую строку в кавычках после двух символов тега. Если у `<f>` нет
`s`, бинарник всё равно «парсит» следующий кавычечный литерал в документе —
в C++ такой тег оставляет шрифт без изменений (осознанное отличие).

### 3.5. Страницы (`0x498600` / `0x4986b0` / `0x498750`)

* `0x68ee78[N]` — начало страницы, `0x68ee7c[N]` — её конец (это одна
  сдвинутая пара массивов: начало N+1 = конец N).
* `0x498600(page)` раскладывает страницу и возвращает биты
  `bit0 = page > 0`, `bit1 = конец != 0` (есть следующая).
* `0x4986b0` — следующая (до 99 страниц, иначе `"..."` и сброс на первую),
  `0x498750` — предыдущая.
* `0x68ee78[0] = 0` при загрузке (`0x497509`).

C++: страницы идут подряд, `LayoutPage::start/end` — байтовые смещения в
`SmlDocument::text`, `end == 0` — последняя.

**Отличие (зафиксировано):** бинарник записывает маркер продолжения только
тогда, когда следующая строка ещё влезает (`0x497c08`), и маркер указывает на
тег, вызвавший удачный перевод строки. Буквальный повтор этого тега на новой
странице для `<r>` безвреден (тег в начале страницы игнорируется), а для
`</c>`/`</p>` повторил бы перевод строки. C++ пишет маркер **после** тега,
поэтому страницы не повторяют строку и не начинаются с пустой строки. Это
единственное расхождение с буквальным кодом; проверка на кадре игры — в
остатке.

### 3.6. Картинки `<I>` (гипотеза)

`0x498012` разбирает `x`, `y`, `f`, `a` и грузит `SML/<f>.bmp` (все 15 имён
поставки — 64×64, `x=y=64`, `a=l|r`). Раскладка трактует картинку как float:

* `a=l`: `column_start += width(" ") + image_width`, картинка у старого
  `column_start`; строки до `left_float_bottom` начинаются с отступа;
* `a=r`: `right_edge -= image_width`, картинка у правого края;
* низ float — `y + image_height`; после него `line_feed` восстанавливает
  `column_start`/`right_edge`;
* высота обрезается по странице (как `0x498332`).

Точный прямоугольник блита (и вклад `x`/`y`) в бинарнике не восстановлен:
поставка всегда `x=y=64`, поэтому C++ ставит картинку в текущую строку и
игнорирует эти атрибуты для позиции. Метрики текста вокруг картинки
закреплены golden'ом `brief/level10.sme`, сам прямоугольник — гипотеза.

## 6. Доказано и гипотезы

Доказано (xref + совпадение с независимым Python-извлечением):

* таблица `0x65ddd0` (31×`0x1c`), поля, размер блока `1+w*h`, байт advance;
* 12 инициализируемых шрифтов, их атласы, сетки, диапазоны и режимы
  (`0x490145`…`0x49054f`, строки `fonts1..4`, `numfonts`);
* отображение 1→0, 2→5 (`0x497b10`/`0x497b60`);
* формула ширины (`0x47fa50`) и высоты строки (`0x4983c3`: только шрифт 3 → 18);
* перенос `0x497c20`, `<r>`/`<p>`/`<c>`/`</c>`/`<f>`/`</f>`/`<x>`/`<s>`/`<k>`
  (`0x497d7c`…`0x4983e6`, таблицы `0x4983f8`/`0x498448`/`0x498540`/`0x49855c`);
* страницы `0x498600`/`0x4986b0`/`0x498750`, экстенты `0x4972f0(267,167)`,
  рендер в буфер шириной 320 (`0x487c4a`);
* 12 шрифтовых и 6 файловых golden'ов (advance/пиксели/страницы/строки/bbox).

Гипотезы / не добито:

1. **Маркер страницы** — см. §3.5: C++ начинает страницу со следующей строки;
   буквальный код может повторять перевод строки. Нужен кадр игры.
2. **`<I>`** — прямоугольник блита, вклад `x`/`y` и точный момент сброса
   float; закреплены только метрики текста вокруг картинки.
3. **Цвет текста** — `draw_text` берёт палитру BMP атласа; движок передаёт в
   `0x47faf0` отдельную 32-битную таблицу цветов, её источник не проверен.
4. **`<x>`** в поставке не встречается; реализовано по `0x497f38`, на
   реальных файлах не проверено.
5. **`<m S>`** — по-прежнему только запись в `0x68cc88` (UI.md §10).
6. **Меню** (`0x485dd0`, шрифт 4 для выбранного пункта) не переносилось:
   это отдельный от SML путь.
7. **Корпусные числа `<f>`**: в `.sme` 59 тегов (34 `s=2`, 25 `s=3`), в
   `.sml` — 124 (86/38). Цифра 268 из `docs/UI.md` §2.2 не воспроизводится
   ни C++-читателем, ни `gm/sml.py` (там, видимо, считались вхождения буквы
   `f`, а не теги).
