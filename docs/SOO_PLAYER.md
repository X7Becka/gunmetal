# SOO_PLAYER — runtime-плеер `Sobanim/*.soo`

**Статус:** M1.1 runtime (2026-10-20). C++-плеер поверх уже проверенных
`res/anim.*` (`parse_soo`, `soo_pose_at`) и `res/sob.*` (`parse_sob`,
`morph_sob`). Новый парсинг `.soo`/`.sob` не добавлен.

**Файлы:**

| файл | роль |
|---|---|
| `engine/src/anim/soo_player.h` | API `SooPlayer`, `SooPlayerPose`, `SooPlayerStats` |
| `engine/src/anim/soo_player.cpp` | загрузка, кэш, выбор кадра, морф, нормали |
| `engine/tests/test_soo_player.cpp` | синтетика + golden трёх файлов поставки |
| `engine/tests/CMakeLists.txt` | тест `soo_player`, метка `quick` |
| `engine/CMakeLists.txt` | `src/anim/soo_player.cpp` в `gm_engine` |

Игра только читается: плеер открывает `Sobanim/*.soo` и `SOBS/*.sob` на
чтение, ничего не пишет.

---

## 1. API

```cpp
gm::SooPlayer player(game_dir);

std::string error;
if (!player.load("Cultist.soo", error)) { /* error — clean message */ }

auto pose = player.pose_at(2197, error);   // ms
if (pose) {
    pose->mesh.vertices;   // std::vector<Vec3f>, интерполированы
    pose->normals;         // по одной единичной нормали на грань
    pose->alpha;           // 0..1
    pose->frame_a, pose->frame_b;
    pose->name_a, pose->name_b;
    pose->tick, pose->elapsed, pose->total_ticks;
    pose->mesh.faces;      // текстуры/индексы из frame_a, плоскости смешаны
}

player.set_loop(true);       // переопределить mode текущей анимации
player.loop();
player.duration_ticks();     // 91 Гц
player.duration_ms();        // ticks * 1000 / 91
player.stats();              // счётчики кэша и загрузок
```

`load` принимает:

* абсолютный путь (`/mnt/d/.../Sobanim/Cultist.soo`);
* путь относительно `game_dir` (`Sobanim/Cultist.soo`);
* короткое имя (`Cultist.soo`, `Cultist`, `cultist`) — ищется в
  `<game_dir>/Sobanim`, расширение `.soo` можно опустить.

ASCII-регистр компонентов пути игнорируется (`resolve_ci`), как в Windows.
Регистр имён кадров внутри `.soo` тоже не важен для поиска `.sob`.

`set_loop` действует на уже загруженную анимацию; следующий `load` снова
берёт `mode` из файла. До первого `load` вызов — no-op.

`pose_at(ms)` при `ms < 0` возвращает позу для `ms = 0` (движок
`0x433e84`), а не ошибку. `INT_MAX` безопасен: перевод в тики идёт через
`long long`, затем `%`/clamp.

## 2. Время, кадры, интерполяция

Всё повторяет `gm/soo.py::Soo.frame_at` и плеер `0x433e00`; см.
`docs/SOO.md` §3.

```
tick   = ms * 91 / 1000                 (floor; ms <= 0 -> 0)
total  = sum(duration[0 .. count-1])    (тики)
phase  = tick
mode 0: phase = min(phase, total - 1)   (последний кадр удерживается)
mode 1: phase %= total                  (закольцовано)

acc = 0
i = первый индекс, где phase < acc + duration[i]
elapsed = phase - acc
alpha   = duration[i] > 0 ? elapsed / duration[i] : 1
next    = i + 1, если i не последний
          иначе mode 1 -> 0, mode 0 -> i
```

Затем для каждой вершины и каждой компоненты плоскости грани:

```
out = a * (1 - alpha) + b * alpha
```

Вершины и плоскости (`origin`, `u`, `v`, `normal`, `spare`) считаются в
`double`, результат округляется в `float` — ровно как `morph_sob`, который
используется повторно. Текстуры, флаги и индексы берутся из `frame_a`.

**Нормали.** `morph_sob`/Python оставляют интерполированный `normal` как
есть (длина может быть не 1). Плеер дополнительно нормирует нормаль каждой
грани:

```
n = normalize(lerp(n_a, n_b, alpha))
```

Нулевая нормаль остаётся нулевой (без NaN). Это единственное намеренное
отличие от «сырого» `morph_sob`; вершины и плоскости побитово совпадают с
эталоном. `pose->normals[i] == pose->mesh.faces[i].normal` после нормировки.

Загрузка (`load`) повторяет ограничения загрузчика `0x42b4e1`:

* `mode` только 0 или 1;
* `count` 1..32;
* файл должен содержать минимум `count` кадров (лишние, как и в движке,
  игнорируются; `nblast`/`nbloom`/`ruinbeam` играют только `count`);
* суммарная длительность > 0;
* все `SOBS/<name>.sob` находятся и парсятся;
* у всех поз одинаковые число вершин и число граней (иначе морф невозможен).

При любой ошибке `load` возвращает `false`, пишет понятный `error`, а
предыдущая успешно загруженная анимация остаётся рабочей.

## 3. Кэш

* Ключ — имя кадра в ASCII-нижнем регистре. `cult1a` и `CULT1A` — одна
  запись.
* `load` резолвит **все** `count` кадров сразу (как загрузчик движка) и
  кладёт `shared_ptr<const Sob>` в `std::map`; список кадров хранит те же
  указатели. Повторное имя в одном `.soo` (`Cultist.soo`: `cult1a` дважды,
  `cult1b` дважды) парсится один раз.
* Кэш живёт в объекте `SooPlayer` и очищается его деструктором. Циклов нет
  (`Sob` — значения, `shared_ptr` без обратных ссылок), утечек нет.
* Вытеснения нет: корпус мал (40 `.soo`, 672 `.sob`), а кэш ограничен
  кадрами одной анимации и предыдущими загрузками этого плеера.
* `stats()`: `soo_loads`, `frame_loads`, `cache_hits`, `cache_misses`,
  `cached_models`. `frame_loads == hits + misses` для успешных кадров;
  `cached_models` — число различных имён в кэше.

## 4. Golden

Тест `gm_soo_player_tests` (CTest `soo_player`, метка `quick`) содержит
синтетику (2 кадра, hold/loop, t=0/середина/конец, `set_loop`, missing,
mismatch, empty, bad frame name, `ms<0`, `INT_MAX`) и реальные файлы.

Golden сгенерирован независимо через `gm/soo.py` + `gm/sob.py`:
`frame_at(ms)`, затем те же `float32`-входы, `double`-смешивание и

## 5. Доказано / гипотеза / trust

**Доказано (дизассемблер + Python-эталон):**

* Тики 91 Гц, `ms*91/1000`, clamp отрицательного времени.
* `mode 0` — удержание последнего кадра, `mode 1` — `% total`, последний
  кадр интерполируется в кадр 0.
* `count` — авторитетное число кадров; лишние строки не читаются.
* Вершины и плоскости: `a*(1-alpha)+b*alpha`; `alpha = elapsed/duration`.
* Отсутствующий `.sob`, разная топология и `count` вне 1..32 — ошибка
  загрузки.

**Гипотеза / решение API:**

* Нормировка нормалей после интерполяции. Движок и Python этого не делают
  (они хранят/рисуют линейно смешанную плоскость); для runtime-потребителя
  единичная нормаль удобнее и требование задачи. Направление совпадает,
  длина — нет; golden нормалей фиксирует именно нашу политику.
* `set_loop` переопределяет `mode` только текущей анимации; следующий
  `load` возвращается к файлу.
* Нет вытеснения кэша и общего межобъектного кэша — сознательное упрощение
  под малый корпус.

**Trust:** высокая для таймлайна и вершин (golden совпадает с Python
побитово на трёх файлах, 12 моментах); средняя для нормалей (намеренное
отличие, зафиксировано тестом); высокая для диагностики ошибок.

## 6. Остаток

* Нет общего `AssetCache`-подобного разделяемого кэша между объектами; при
  сотнях одновременных `SooPlayer` модели будут дублироваться.
* Нет API абсолютного старта (`start_tick`) и внутренних часов: вызывающий
  сам передаёт `ms`. `soo_pose_at_tick` можно обернуть позже.
* Нет интерполяции UV как отдельных величин: `morph_sob` смешивает
  плоскости `origin/u/v`, чего достаточно текущему рендеру.
* Нет записи `.soo`/`.sob` (и не требуется): плеер только читает игру.
