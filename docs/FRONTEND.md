# Безголовый автомат меню (`M8`, срез 1)

`engine/src/ui/frontend_menu.*` — перенос **экранного автомата оболочки**
`gundx.exe` в C++ без окна, без рендера и без чтения установки: только
состояние, пункты текущего экрана и таблица переходов. Экранная карта, пункты и
переходы взяты из `docs/UI_SCREENS.md` (§1 автомат, §2 карта, §3 пункты, §4
переходы) — этот документ источником истины не является и при расхождении
уступает `UI_SCREENS.md`.

Что это **не** делает: не рисует (атласы `FRONTEND/BMP.IDX`, шрифты, `plate`),
не читает `KEYCFG`/сейвы/`.sml`, не играет UI-звуки и не принимает клавиатуру —
вызывающий подаёт `gm::KeyEvent`. См. «Ограничения».

Проверка: `ctest --test-dir build/sandbox -R '^frontend_menu$' -V`
(CTest `frontend_menu`, label `quick`, игра не нужна).

### 2.1. Правила вне §4

Их нет в байтовой таблице §4; они нужны, чтобы «QUIT» работал как экран
(требование среза).

| из | в | правило | основание |
|---|---|---|---|
| 1 `MAIN` | 33 `QUIT` | Esc на титуле | инвариант задания; в §4 строки нет (Esc обрабатывается только в подэкранах) |
| 33 `QUIT` | `Exit` | Enter, пункт 0 `Yes` | §3.8 (`Yes`/`No`), выход — дело вызывающего цикла |
| 33 `QUIT` | 1 `MAIN` | Enter, пункт 1 `No` | §3.8; адреса в §4 нет — вывод |

### 2.2. Почему `ui_screens.py --json` печатает 34 перехода

`transitions` инструмента — не таблица §4: он **включает** недоказанную строку
титров (`9 → 1`), **опускает** условную строку 20 (`10 → 30/34`) и алиас
`34 → 35` (это не сайты `mov imm`), а `10 → 36` печатает дважды. Наша таблица
сохраняет все 35 строк §4 и их номера — поэтому сверять надо с §4, а не с
`--json.transitions`.

## 3. Рёбра достижимости (только для отчёта)

§4 не содержит входов в мастер «новой игры», в список видеорежимов и в
SML-пагер, поэтому обход только по §4 из `MAIN` накрывает **18 из 34**
экранов. Чтобы граф был полным, заведена отдельная таблица
`FrontendMenu::entry_edges()`; `feed()` её **не применяет**, она существует
только для BFS-отчёта. Каждое ребро помечено классом доказательства.

| из → в | основание |
|---|---|

| 2 → 3 | §1: состояние 2 гонит переходы брифинга 3/4 (вывод) |
| 3 → 4 | §1: 3 и 4 — два перехода брифинга (вывод) |

Проверки:

* **Экраны** — 34 шт., id 0..37 без 7/8/28/29, id и имена уникальны,
  `screen_name(None) == "(none)"`, `screen_id(Exit) == -1`.
* **Переходы** — 36 записей, номера строк 1..35 по одному разу, ровно одна
  выключенная (строка 13 = `9 → 1` на `0x48347e`), 35 включённых; каждая
  включённая запись **исполняется** из своего экрана и попадает в `to`;
  у каждой есть site VA.
* **Строка 20** — все три ветки: set 0 → `KeySetView`, именованный set 1 →
  `KeySetEditorEntry`, непустой `NEW SET` (слот 15) → `NewKeySetName`; алиас
  34 → 35 срабатывает на следующем `feed`.
* **Достижимость** — BFS по §4 из `MAIN` = 18/34 (16 перечислены выше),
  BFS по полному графу = 34/34, недостижимых 0; печатаются пути BFS до
  `CONTROL OPTIONS`, `START GAME`, `PLAY OPTIONS`, `KEY SET EDITOR`.
* **Esc/`back()`** — 10 строк §4 (11 записей: строка 34 покрывает 34 и 35):
  `back()` предсказывает тот же экран, куда уводит `feed(Esc)`; Esc на `MAIN` →
  `QUIT`; экраны без строки Esc остаются на месте.
* **QUIT** — Enter по `Yes` → `Exit` (терминальное состояние игнорирует
  клавиши), `No` → `MAIN`, `reset()` выводит из терминального состояния.
* **Пункты** — `MAIN` 7 артов и порядок 0..6, `CONTROL OPTIONS` 10, просмотр
  набора 31 имя + подсказка, редактор — подсказка `Enter changes, Delete clears`
  (`0x4bd7a8`), двухстрочные пункты (`NUMBER OF LOCAL PLAYERS`) — один id и один
  шаг выбора.
* **Детерминизм** — одна и та же строка клавиш даёт одинаковую цепочку экранов
  и одинаковое выделение (два независимых экземпляра).
* **Негативы** — до `reset()`: `None`, пустые пункты, `feed` возвращает false;
  неизвестный код (`Other` 0x98/999), `Text`, `Backspace`, пустое событие —
  false и состояние не меняется; `enter(None)` отклонён; экран без выделяемых
  пунктов игнорирует Enter; 500 циклов Down/Enter/Esc не выводят автомат в
  `None`.

## 5. Ограничения

* **Нет рендера и атласов** — ни `plate`, ни шрифтов, ни `slide`/`knob`/`check`;
  `items()` отдаёт только текст, `x`, `row`, id и VA.
* **Нет ввода с клавиатуры** — SDL/скан-коды не разбираются, вызывающий сам
  превращает клавиши в `KeyEvent`.
* **Нет SML-пагера и загрузки сейвов** — экраны 2/3/4 пустые (нет пунктов и
  переходов), 13/14/15 знают только переходы §4: слоты не читаются, имя не
  пишется, запись сейва не выполняется.
* **`KEYCFG` не читается** — 16 слотов засеяны по §7/`CONFIG.md`: `PERFECT`
  (0), `SPLIT1` (1), `SPLIT2` (2), остальные — `NEW SET`; игрок 1 стартует с
  набора 0, игрок 2 — с 1.
* **UI-звуки не играются** — `updown`, `select`, `selectm`, `vleft`, `menuon`
  (`UI_SOUNDS.md` §2) не моделируются; событие «клик/перемещение» не выводится.
* **Пункты — статический снимок**: слоты 13 показаны одной строкой вместо
  шести (§3.6), список уровней 17 — одной строкой (имена из `LVLNAMES.SLU` не
  читаются), 19 — по маске `0x4c1290` не фильтруется, 27 — без выбранного типа
  матча, 33 — только вариант «вне игры» (`QUIT GAME?`, §12.4), 36 — заголовок
  игрока 1 (§2), 25 — без строк (§2 их не приводит).
* **`Done` не выходит** — §4 не даёт строк для `Done`/`Esc` экранов 11, 12, 32,
  22, 10 (пункт 9), 31, 37; `feed` там возвращает false. В оригинале `Done`,
  вероятно, возвращает на титул, но байтовой строки в §4 нет — не выдумываем.
  Экран 31 (`NAME OF NEW KEY SET`) вообще без выхода в §4/§7.
* **Выбор ходит по кругу** — направление и поведение на концах списка в §3/§4
  не описаны; выбрано зацикливание. Подсветка — по id пункта (§3), поэтому
  двухстрочные пункты выделяются вместе.
* **Алиас 34 → 35** — `enter(34)` даёт наблюдаемый экран 34 ровно до следующего
  `feed`, затем состояние переписывается в 35 до диспетчеризации клавиши
  (`0x48e212`), как в оригинале.
* **`--json` расходится с §3.8 по id 37** — инструмент находит только `Yes`,
  в снимке `Yes`/`No` по §3.8 (VA `No` — `0x4bc7a4`, общая строка).

## 6. Что осталось для CLI (`--menu`)

`main.cpp`/`config.*` в этом срезе **не менялись** — проводку делает основной
агент. Предлагаемый контракт (всё уже поддержано API):

* `--menu` — напечатать текущий экран, его пункты (`id`, `x`, `row`, текст) и
  `back()`, затем выйти (диагностика снимка);
* `--menu-keys up,down,enter,esc,backspace,text:0x1b` — прогнать
  последовательность через `feed()` и напечатать цепочку экранов + конечное
  состояние; `Enter` на `QUIT`/`Yes` даёт `Screen::Exit` (код возврата 0,
  отдельный признак — `screen() == Screen::Exit`);
* `--menu-keys ... --json` — та же цепочка одной строкой для тестов;
* `--menu-screen <id>` — стартовый экран (`enter()`), по умолчанию `MAIN`.

Осталось на следующие срезы: рендер `plate`/шрифтов из `FRONTEND/BMP.IDX`,
чтение `KEYCFG/*.KEY` и `GUNMETAL.CFG` (имена наборов, реальные биндинги),
списки сейвов/уровней, SML-пагер (2/3/4), звуки `UI_SOUNDS.md`, строки `Done`
и выход из 31 (нужны новые байтовые доказательства в `UI_SCREENS.md`).
