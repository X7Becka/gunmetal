# Рендер экрана 20 `LAY DOWN THE BUCKS` (`engine/src/ui/lay_bucks_render.h`)

Срез 14 пункта `M8.8`: один кадр экрана **20** фронтенда (`gundx.exe`, ImageBase
`0x400000`) в RGBA-буфер 320×200. Модуль без состояния — рисует то, что ему
передали в `LayBucksRenderOptions`, и отдаёт числа (`rows`, `ink_pixels`,
`missing_glyphs`, `arrows`). Шрифты и метрики — из `render/text_layout`
(`FONTS4` в `FRONTEND/BMP.IDX`), точный fade — из `render/hud_lut`. Ничего не
измеряется заново.

Код: `engine/src/ui/lay_bucks_render.h/.cpp`; тест —
`engine/tests/test_lay_bucks_render.cpp` (CTest `lay_bucks_render`, label
`quick`). Соседние срезы — `KEY_JAMMING_RENDER.md` (16, тоже `rows 1 / step 0`),
`MATCH_SETUP_RENDER.md` (27, единственный экран с суммой), `MENU_RENDER.md`
(общая механика `0x485dd0`).

Главный вывод среза: **это статичная заглушка shareware**, а не ставка.
Заголовок обещает заклад, но обработчик не читает ни суммы, ни ставки, ни
таблицы кредитов `0x4bc6f8` — на экране четыре фиксированные строки, и всё.

## 1. API

```cpp
#include "ui/lay_bucks_render.h"

gm::LayBucksRenderOptions options;    // black canvas, cash = 4 (игнорируется)
options.background = "PLATE";         // "" = чёрный холст

std::vector<std::uint32_t> rgba;      // 0xRRGGBBAA
int width = 0, height = 0;
gm::LayBucksRenderStats stats;
std::string error;
if (!gm::render_lay_bucks(game, options, rgba, width, height, &stats, &error)) {
    // error: текст с префиксом "lay_bucks_render: "
}
// width=320 height=200, rgba.size()==64000
// stats: rows=1 ink_pixels=1036 missing_glyphs=0 arrows=0
```

| Поле `LayBucksRenderOptions` | По умолчанию | Смысл |
|---|---|---|
| `std::string background` | `""` | запись `FRONTEND/BMP.IDX` в (0,0); `"PLATE"` — панель экрана; пусто — чёрный холст |
| `int cash` | `4` | **принимается и игнорируется**: `0x48a830` не читает `0x4bc6f8` и не печатает цифр. Значение 4 — `.data`-умолчание индекса экрана 27, чтобы вызывающий мог отдать одно и то же число обоим рендерерам |
| `bool fade_lut` | `false` | точный fade `0x682f90` по палитровым индексам |
| `int fade_lut_level` | `11` | 0..15; 11 — тождество, 12..15 светлеют |
| `std::string fade_lut_dump` | `""` | дамп 4096 Б (`load_hud_lut`) |
| `const HudLut* fade_lut_table` | `nullptr` | готовая таблица, приоритетнее дампа |

Публичные помощники (нужны тесту и будущему CLI): `lay_bucks_line_y(line)`,
`lay_bucks_line_text(line)`, `lay_bucks_line_font(line)`; строка 0 — заголовок,
1..3 — три строки-уведомления, вне диапазона возвращается заголовок.

`LayBucksRenderStats`: `rows` (всегда 1 — запись `0x67f10c`, **не** длина
списка), `ink_pixels` (уникальные пиксели глифов; фоновая плата не считается —
как в `menu_render`/`key_jamming_render`), `missing_glyphs` (байты без глифа,
пропускаются, не фатальны), `arrows` (спрайтов `MENUARRW` на экране нет —
всегда 0, тест пинует 0).

Константы: `kLayBucksCanvasWidth/Height` (320/200), `kLayBucksBackground`
(`0x000000FF`), `kLayBucksTitle`, `kLayBucksNotice1..3`, `kLayBucksPanelName`
(`"PLATE"`), `kLayBucksPanelWidth/Height` (196/131), `kLayBucksTitleFont` (5),
`kLayBucksRowFont` (0), `kLayBucksRows` (1), `kLayBucksItemStep` (0),
`kLayBucksTitleX/Y` (38/14), `kLayBucksNoticeX` (42),
`kLayBucksNotice1Y/2Y/3Y` (27/36/45), `kLayBucksLineCount` (4),
`kLayBucksCashDefault` (4).

## 2. Доказано (листинг + данные)

### 2.1. Пролог и константы обработчика

`0x48a830`..`0x48a8a5` — 44 байта кода, `ret` в `0x48a8a5`, дальше 10 `nop`
(`0x48a8a6`..`0x48a8af`). Диспетчер `0x487e71` берёт адрес из таблицы `0x4883d8`
(id 5..37); вход для id 20 — stub `0x487f16: call 0x48a830; jmp 0x487f64`
(общий эпилог).

```
48a830: mov DWORD PTR ds:0x67f10c,0x1     ; rows = 1
48a83a: mov DWORD PTR ds:0x662d58,0x0     ; step = 0
48a844: call 0x486050                     ; PLATE -> 0x6865f8
48a849: push 0xffffffff                   ; item = -1
...
48a8a5: ret
```

Больше обработчик не пишет **ничего**: во всей функции только две записи в
память (обе выше) и пять вызовов — `0x486050` и четыре `0x485dd0`. Нет
`0x4833e0` (чекбоксы), `0x486070`/`0x4860b0` (слайдеры), `0x485cc0`/`0x485d00`
(стрелки), нет `sprintf`, нет чтения `0x4bc6f8`/`0x4bc728`/`0x68cd84`/
`0x68cd88`.

`0x486050` копирует `0x1913` dword (0x1913 = 6419 = 196×131) из `0x6d2b60` в
`0x6865f8` — это предзагруженный фронтенд-фон `PLATE` (`docs/UI_SCREENS.md` §9:
`plate` 196×131 → буфер `0x6d2b60`): его грузит `0x48fccc`
(`call 0x47efe0` с аргументами `"frontend"`, `"plate"`, буфер `0x6d2b60`,
196 (`0xc4`), 131 (`0x83`)). Поэтому 196×131 — и холст текста, и геометрия
панели.

### 2.2. Все четыре вызова `0x485dd0`

Порядок аргументов (стек): `font, text, centered, x, row, item`; `y` считается
внутри: для `row >= 0` — `y = row + step*item` (`0x485e4b`..`0x485e5c`), для
`row < 0` — `y = -row` (`0x485e2b`..`0x485e38`). `centered != 0` заменяет `x`
на `(196 − width)/2` (`0x485de2`..`0x485dfa`, `width` — `0x47fa50`).

| # | текст | VA | font | centered | x | row | item | y | сайт `push`/`call` |
|---|---|---|---:|---:|---:|---:|---:|---:|---|
| 0 | `LAY DOWN THE BUCKS` | `0x4bdb80` | 5 | да | 38 (игнор.) | 14 | −1 | 14 | `0x48a849`..`0x48a858` |
| 1 | `THIS FEATURE IS NOT` | `0x4bdb6c` | 0 | нет | 42 | 27 | −1 | 27 | `0x48a860`..`0x48a86f` |
| 2 | `AVAILABLE IN THE` | `0x4bdb58` | 0 | нет | 42 | 36 | −1 | 36 | `0x48a877`..`0x48a886` |
| 3 | `SHAREWARE VERSION` | `0x4bdb44` | 0 | нет | 42 | 45 | −1 | 45 | `0x48a88e`..`0x48a89d` |

Независимое подтверждение — оракул `tools/re/ui_screens.py --json`: для id 20
он отдаёт `rows 1`, `step 0`, `title 0x4bdb80` и те же три пункта с
`item = -1`, `x = 42`, `row` 27/36/45.

`step = 0` делает `item*step` нулевым в любом случае, а `item = -1` дополнительно
срезает проверку подсветки: `0x485e04`

```
485e04: cmp ecx,0xffffffff     ; item == -1 ?
485e07: jne 0x485e0d           ; иначе — сравнить с [0x68ccf4]
485e09: xor ecx,ecx            ; и пропустить подсветку
```

Поэтому **шрифт 4 недостижим**: замена лица на 4 в `0x485e19` требует
`item != -1` и `font == 0`. Строк с `item >= 0` обработчик не делает, курсора у
экрана нет, стрелки/Enter/клик ничего не выбирают.

### 2.3. Ни суммы, ни ставки

Заголовок `LAY DOWN THE BUCKS` — обещание заклада, но:

* в `0x48a830` нет чтения таблицы кредитов `0x4bc6f8` (экран 27) и индекса
  `0x4bc728`; поиск по функции не даёт ни одного обращения к ним;
* нет `sprintf`/`%s`/`%ld` и нет ни одной подстановки: все четыре строки —
  литералы по фиксированным VA, проверены чтением образа;
* нет `NUMFONTS` (шрифт 9..12) — цифр на кадре не будет вообще.

Поэтому `options.cash` — поле ради симметрии API с `ui/match_setup_render`
(там строка 1 печатает `Starting Cash: %ld` из `0x4bc6f8`). Тест пинует, что
`cash` 0/4/11/99/−7 дают побайтово одинаковый кадр: **0/64000** отличий.

Текст сам объясняет, почему суммы нет: «THIS FEATURE IS NOT AVAILABLE IN THE
SHAREWARE VERSION».

### 2.4. Состояние 20, ввод и достижимость

* Состояние фронтенда — dword `0x4bc440` (`docs/UI_SCREENS.md` §1). Ни одной
  **непосредственной** записи 20 в него в exe нет: все 51 `mov DWORD PTR
  ds:0x4bc440,imm` проверены (значения 0..0x24, 0x14 среди них отсутствует);
  вычисляемые записи (`mov ds:0x4bc440,eax/ebp/ecx/esi`) стоят в уже
  документированных переходах.
* Единственное упоминание состояния 20 в обработчике ввода — `0x48e06c`:

```
48e06c: cmp ebp,0x14
48e06f: jne 0x48e07e        ; не 20 — дальше по цепочке (14, ...)
48e071: mov ebp,ecx
48e073: mov DWORD PTR ds:0x4bc440,ebp
48e079: jmp 0x48e4ac
```

  Это ветка цепочки отмены (`cmp ebp,0xd` у 13, затем 27, 21, 19, 28, 29, 20,
  14, ...): экран заменяет состояние на `ecx` и **больше ничего не делает** —
  ни переменных, ни звука, ни кадра. Тот же приём (`mov ebp,ecx`) стоит у
  экрана 6 (`0x48d949`), т.е. `ecx` — состояние-приёмник отмены, не константа
  экрана 20. Своего ввода (пунктов, стрелок, подтверждения) у экрана нет.

**Гипотеза, не доказательство:** состояние 20 в поставке v1.36 недостижимо —
ни один из документированных переходов в него не ведёт, а `0x48a830` — это
заглушка «фичи нет в shareware». Доказано обратное только частично (нет
immediate-записи 20); полный анализ всех вычисляемых записей не делался.

### 2.5. Ассеты, цвета, палитра

* `FRONTEND/BMP.IDX`: `PLATE` (196×131) + `FONTS4` (грани 5 и 0); `CHECK`/
  `NOCHECK`, `SLIDE`/`KNOB`, `MENUARRW`, `NUMFONTS` не читаются.
* `UI_SCREENS.md` §2 в сводной строке ассетов пропускает экран 20 (там
  «5–6, 10–14, 16, 21–26, 31–37 — plate + шрифты»), но оракул
  `ui_screens.py --map/--json` для id 20 печатает `plate, fonts`, и это
  согласуется с `0x48a844` (`0x486050`) — расхождение самой сводки, не кода.
* Палитра атласа `FONTS4`: шрифт 5 → `(155,15,15)` = `0x9b0f0f`, шрифт 0 →
  `(19,15,15)` = `0x130f0f` (`docs/MENU_RENDER.md` §3). Белого (шрифт 4) на
  кадре нет — тест это проверяет.
* `PLATE` использует собственную палитру BMP; индекс 0 у шрифтов прозрачен.

## 3. Модель

1. **Холст** 320×200, непрозрачный `#000`; опционально `background`
   (`FRONTEND/BMP.IDX`) в (0,0), клип по холсту.
2. **Плата.** `PLATE` (196×131) загружается и проверяется **всегда**: обработчик
   копирует её в `0x6865f8` (`0x486050`), без ассета кадр пуст. Куда движок
   блитит этот буфер на 320×200, не задокументировано (`docs/MENU_RENDER.md` §2),
   поэтому панель не рисуется неявно: `background = "PLATE"` кладёт её в (0,0),
   пусто — чёрный холст.
3. **Клип текста** — 196×131 (окно записи `0x485dd0`).
4. **Строки**: заголовок (шрифт 5) центрируется в полосе 196 px
   (`x = (196 − width)/2`), три уведомления (шрифт 0) — слева от `x = 42`.
   `y` = 14/27/36/45, `step = 0`, `item = -1` (абсолютный `y`).
5. **Курсора, подсветки, чекбоксов, слайдеров, стрелок нет** — все четыре
   вызова статические; `stats.arrows = 0`.
6. **Суммы нет**: `cash` игнорируется (§2.3).
7. **Точный fade** `0x682f90`: индекс палитры каждого нарисованного пикселя
   проходит через `render/hud_lut.h::map(level, index)` **до** выборки цвета;
   уровень 11 — тождество, 12..15 — реальные таблицы. Нужна таблица
   (`fade_lut_table`) или дамп 4096 Б (`fade_lut_dump`,
   `docs/HUD_LUT.md` §2). Без обоих — отказ, а не «тихо без fade».
8. **Отказы** (префикс `lay_bucks_render: `, буфер очищен, `width`/`height` = 0,
   `*stats` обнулён): пустой каталог игры; нет/битый `FRONTEND/BMP.IDX`; нет
   грани 5 или 0 (`FONTS4`); нет/битая/не 196×131 `PLATE`; неизвестная/битая/
   не-8-bpp запись `background`; `fade_lut` без таблицы и дампа; нечитаемый
   дамп. `cash` отказать не может — он не используется.

## 4. Числа (поставочная установка, тест `lay_bucks_render`)

Тест: 186 проверок, `lay_bucks_render: ok (186 checks)`; CTest
`lay_bucks_render` — 1.2 с. Печатаемые строки:

```
  frame: 320x200, rows=1 arrows=0 ink=1036 missing=0; title 102 px wide at x=47 y=14;
    lines: (47,14)-(147,20) 101x7, 268 px | (42,27)-(139,33) 98x7, 249 px |
           (42,36)-(123,42) 82x7, 220 px | (42,45)-(139,51) 98x7, 299 px
  cash 0/4/11/99/-7: 0/64000 px differ (0x48a830 reads no 0x4bc6f8)
  PLATE: 196x131 decoded, black vs PLATE diff=24640 px, text ink 1036 unchanged
  minimal archive (FONTS4+PLATE): ink=1036 missing=0 rows=1
  negatives: rows=1 ink=1036 arrows=0 missing=0
```

| величина | значение |
|---|---|
| холст / пикселей | 320×200 / 64000, все непрозрачные |
| `rows` / `arrows` / `missing_glyphs` | 1 / 0 / 0 |
| ширина заголовка (шрифт 5, `0x47fa50`) | 102 px → `x = (196−102)/2 = 47` |
| чернила (уникальные пиксели глифов) | **1036** = 268 + 249 + 220 + 299 |
| bbox заголовка | (47,14)-(147,20), 101×7, 268 px |
| bbox `THIS FEATURE IS NOT` | (42,27)-(139,33), 98×7, 249 px |
| bbox `AVAILABLE IN THE` | (42,36)-(123,42), 82×7, 220 px |
| bbox `SHAREWARE VERSION` | (42,45)-(139,51), 98×7, 299 px |
| чёрный холст vs `PLATE` | 24640 отличающихся пикселей |
| `cash` 0/4/11/99/−7 vs 4 | 0 / 0 / 0 / 0 / 0 из 64000 |
| fade 11 vs без fade | 0 / 64000 |
| fade 12/13/14/15 vs 11 | 16493 / 24647 / 24886 / 25560 |
| fade 12↔13 / 13↔14 / 14↔15 | 17758 / 23348 / 20912 |

Строки не пересекаются (клетка шрифтов 5 и 0 — 8 px: 14..21, 27..34, 36..43,
45..52), поэтому сумма четырёх полос в точности равна `ink_pixels`; тест
сверяет это с независимой отрисовкой через атлас.

## 5. Ограничения

* **Нет ввода**: пунктов нет; ветка `0x48e06c` только переставляет состояние.
* **Нет звуков** интерфейса и нет перехода «назад» как отдельного действия —
  экран не знает, куда возвращаться (`ecx` приходит снаружи).
* **Нет самой транзакции**: заклада/списания денег в бинаре нет, экран —
  сообщение об отсутствии фичи в shareware; `cash` — мёртвое поле.
* **CLI — есть (срез 15).** `--lay-bucks [--no-plate] [--png OUT]
  [--fade-lut N]`: `lay_bucks: rows=1 ink=1036 missing=0 arrows=0`. CTest
  `cli_lay_bucks`, `_png`; `cli_fade_lut` (11 = без fade).
* **Нет доказанной достижимости** состояния 20 в v1.36 (см. §2.4): кадр
  определён листингом, но «увидеть в игре» нечем.
* Куда движок блитит буфер 196×131 на 320×200 — по-прежнему не
  задокументировано; модуль рисует панель и текст от (0,0), как соседние
  рендереры (`KEY_JAMMING_RENDER.md` §3, `MATCH_SETUP_RENDER.md` §3).
* `UI_SCREENS.md` §2 не упоминает экран 20 в сводной строке ассетов (см. §2.5);
  файл в этом срезе не правился (вне списка разрешённых).
