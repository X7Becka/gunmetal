# Baseline: установка, инвентарь и регрессия

* **Дата:** 2026-10-19/20.
* **Тулкит:** commit `be4f75f` (+ этот файл).
* **Установка:** `D:\games\Gunmetal 3dfx` → `/mnt/d/games/Gunmetal 3dfx`
  (v1.36, 3dfx-сборка).
* **Воспроизведение:** `python3 regress.py --full` (пишет только в
  `/tmp/opencode/regress`, установку не меняет).

## Регрессия

CTest после integration-коммитов: **52/52** (~699 с), label `quick` — **41/41**
(~110 с); `events`, `weapons`, `soe` входят в оба набора.

`regress.py --full`: **124/124 проверок** за **~220 с** (быстрый прогон без
извлечения: **114/114 за ~85 с**; до оптимизации было 355 с / ~15 мин), exit code 0.
Шесть проверок — границы доверия: смещение за EOF, обрезанный `.sbw`,
невозможная высота `.sbv`, отказ от перезаписи без `--force`, фазз-матрица;
седьмая (только в `--full`) — аудит установки по манифесту (swaps
`level1`↔`level2` принимаются, missing/modified/extra — нет).
Что ускорено: `entities.py` больше не декодирует скрипт на каждую сущность
(индекс блоков вместо 45k декодирований: 132 с → 0.4 с), `sbc`/`sob` в быстром
режиме только парсят (`--check`), проходы по 36 уровням идут через пул процессов,
а четыре тяжёлые проверки извлечения запускаются параллельно, и
`extract` больше не перечитывает весь `.DAT` на каждую запись.
Покрыты архивы BIGFILE
(чтение/запись/`set`), `.sbw`/`.sbt`/`.sbc`/`.sob`/`.soo`/`.sof`/`.sbm`,
скриптовая ВМ и сцена, сохранения (игрок, оружие/патроны, цепочка блоков,
`--set`), `.sml/.sme`, кампания, шасси, вещи, мелкие форматы, инвентарь.

## Инфраструктура реверса (2026-10-22)

Быстрый прогон после перевода инструментов на постоянный кэш:

* `python3 regress.py` — **114/114** за **78,8 с** (установка на `/mnt/d`);
* `python3 regress.py --mirror` — **114/114** за **45,9 с** (зеркало на `/dev/sdd`);
* `python3 regress.py --full --mirror` — **124/124** за **89,0 с** холодным
  кэшем и **60–77 с** тёплым (зависит от фоновой нагрузки; было 175,7 с);
* `python3 regress.py --full --mirror` повторно — **124/124 за 76,8 с**
  (6 попаданий в кэш, в т.ч. аудит установки; холодный прогон 89,0 с);
* `python3 tools/re/gmcache.py selftest` — 98 сэмплов строк, 0 расхождений с
  сырым листингом (283 626 строк);
* `ctest --test-dir build/sandbox -L quick -j 8` — **50/50** за **34,0 с**;
  полный набор — **61/61** за **235 с** (`-j 8`). `core`/`camera_rig`/
  `sbtvm`/`vm`/`things_full` починены адресацией уровней по содержимому
  (`engine/tests/game_content.h`, `tools/re/game_content.py --check`:
  переставлены три пары `level1`↔`level2` — `.sbc`/`.sbt`/`.sbw`; аудит
  установки `tools/re/install_audit.py`: 2154 ok, 6 renamed, 0 missing/
  modified/extra, `GUNMETAL.CFG` — volatile; 4,3 с на 8 потоках).

Что изменилось и почему:

* листинг objdump и его бинарный индекс (`gundx.asm.idx`) переехали из `/tmp`
  (tmpfs, стирается при `wsl --shutdown`) в `~/.cache/gunmetal-re`;
  `exelib` собирает их сам, `disasm()` читает диапазон по индексу
  (~100 мс → ~0,02 мс на запрос);
* зеркало установки (`tools/re/gmcache.py mirror`): `gm.py inventory`
  7,1 с → 0,14 с, `gm.py sob --check` 1,5 с → 0,07 с; `--mirror` сверяет
  зеркало с установкой и сам синхронизирует при расхождении;
* `regress.py` ищет файлы игры регистронезависимо (`gp()`): на drvfs
  `LEVEL0.SBW` и пары `.SME/.SML` находились, на ext4-зеркале — нет;
* `tools/re/savegame.py` больше не требует копию exe в `/tmp/opencode`
  (берёт кэш, иначе установку) — это и был единственный «внешний» провал
  прежнего baseline;
* контекст: `tools/ctx.py` + `docs/INDEX.md` (срезы вместо чтения 200-КБ
  документов целиком), методика — `docs/RE_METHOD.md`.

### Внешние расхождения установки (2026-10-22)

`tools/re/install_audit.py` находит в установке ещё одно отличие от манифеста:
**изменены `KEYCFG/PERFECT.key`, `KEYCFG/SPLIT1.KEY`, `KEYCFG/SPLIT2.KEY`**
(плюс известные swaps `level1`↔`level2` и volatile `GUNMETAL.CFG`). Из-за
этого же файла падает CTest `controls`: тест сверяет пары клавиш с
зафиксированными значениями, а в установке лежат другие.

Это внешнее расхождение, а не регрессия кода — правится только переустановкой
игры, поэтому:

| прогон | результат | причина |
|---|---|---|
| `regress.py --full --mirror` | **122/123** (66,5 с) | `install / manifest audit` — KEYCFG |
| `ctest --test-dir build/sandbox -j 6` | **60/61** (258,6 с) | `controls` — KEYCFG |
| `regress.py --mirror` | 113/113 | быстрый набор аудит не запускает |
| `ctest -L quick` без `controls` | 49/49 | — |

Остальные 60 тестов CTest зелёные, включая `core`, `sprite`, `sbv_parity`,
`sou2_full`, `core_full` после правки палитры и 1-based индексов текстур
(`docs/PALETTE.md`).
