# Спрайтовые golden'ы: постоянный Python-эталон

`tools/re/sprite_goldens.py` считает FNV-1a64 тех же 7 кадров, что проверяет
`real_cases` в `engine/tests/test_sprite.cpp`. Golden'ы в тесте остались
константами (Python в runtime не нужен), но теперь они — паритет с
независимым оракулом, а не снимок вывода C++.

## Что за эталон

Скрипт не вызывает C++ и не читает его результаты: он берёт те же входные
данные теми же модулями `gm/` и повторяет правила `docs/SPRITE.md`:

* спрайт — уровень 0 `.sbm` из `sprites/SBM.IDX` / `PICS/SBM.IDX`
  (`gm/bigfile.py` + `gm/sbm.py`);
* палитра — таблица движка `FRONTEND/GAMEPAL` из `FRONTEND/BMP.IDX`
  (`gm/palette.py::from_archive`, локальный фолбэк на `gm/bigfile.py` +
  `gm/bmp.py`), а не `FLAG/naUSA.BMP`, у которого 21 слот занят magenta
  плейсхолдерами;
* кадр — детерминированный градиент
  `r=(7x+3y+11)&255`, `g=(2x+11y+29)&255`, `b=(13x+5y+47)&255`,
  padding строк нулевой; хеш — по всему буферу, включая padding;
* nearest: clip по четырём краям, `sx=(px-x)//scale`, затем flip;
* bilinear: `u=(dx+0.5)/scale-0.5`, flip по `width-1-u`, wrap по маске
  степени двойки, веса `(1-ax)(1-ay)`…, порог покрытия `0.5`;
* цвет: `mix`/`add` с весом `alpha/255` и `_clamp` (усечение к нулю, затем
  0..255), `alpha == 0` не трогает кадр, additive насыщается на 255.

## Команды

```sh
python3 tools/re/sprite_goldens.py            # таблица + сверка с тестом
python3 tools/re/sprite_goldens.py --json     # машинный вывод (cases[], all_match)
python3 tools/re/sprite_goldens.py --check    # код 1 при расхождении
python3 tools/re/sprite_goldens.py --palette carrier   # старый FLAG/naUSA.BMP
```

Прогон ~0.24 с; три подряд `--json` дают побайтно одинаковый вывод
(проверено `md5sum`), вычисление детерминировано, установка только читается.
Коды возврата: 0 — успех, 1 — расхождение с тестом (только с `--check`),
2 — нет установки / палитры / спрайта.

## Доказательство паритета

* `--palette carrier` (старый источник) даёт **7/7** старых констант
  `test_sprite.cpp` — оракул воспроизводит C++ на тех же входах, включая
  bilinear, clip и additive;
* `--palette engine` даёт ровно 5 новых чисел, которые печатает C++ с
  палитрой движка (`ctest -R sprite` зелёный), и два прежних значения для
  `EXPL0001`: этот спрайт из 21 отличающегося слота использует только
  индекс 0, а 0 — прозрачный индекс всех реальных кейсов, т.е. в кадр не
  попадает;
* таблица выше — вывод `--check` после обновления констант (7/7 `OK`).

## Ограничения

* Нужна установка игры (`sprites/`, `PICS/`, `FRONTEND/`); без неё скрипт
  завершается с кодом 2, а тест печатает skip и оставляет синтетику.
* **Палитра.** Константы рассчитаны на `FRONTEND/GAMEPAL`. Пока в ветке нет
  правки `engine/src/res/bmp.cpp` (чтение `FRONTEND/BMP.IDX` вместо
  `FLAG/naUSA.BMP`), `installed_palette` отдаёт старую таблицу, и ровно эти
  5 кейсов печатают прежние хеши — это ожидаемый сигнал «палитра не та»,
  а не регрессия спрайтов. С правкой — 7/7 и `ctest -R sprite` зелёный.
* Только уровень 0: mip/LOD/трилинейность/dither Glide не воспроизводятся;
  alpha палитры игнорируется, additive не использует material intensity.
* Фаза bilinear `+0.5` — принятая модель ресемплинга, а не трассировка Glide;
  для произвольного quad'а двигателя возможен сдвиг на полтекселя.
* Кейсы заданы в скрипте таблицей `CASES` и должны совпадать с `real_cases`
  теста (имена, суб-архив, спрайт, размер кадра, `stride_extra`, параметры
  блита). Добавили кейс в тест — добавьте его и сюда.
