# `SOU2`: музыкальный кодек и правила рендера

Статус: **кодек и синтез разобраны**. Независимый декодер — `gm/sou2.py`,
прослушиваемый PCM — `tools/re/render_sou2.py` (настоящий фильтр `0x8534c0`
из `gundx.exe` через `tools/re/x86mini.py`). Контейнер и битстрим описаны в
`docs/FORMATS.md` §5.2.1.

Этот файл фиксирует не геометрию формата, а **эксплуатационные грабли**: из-за
них уже были испорчены `out/L01BONUS_switch_music.mp3` и
`out/level1_switch_sequence.mp3`.

## 1. Выход декодера — не PCM

`0x852d80` пишет **13 мультиплексированных поддиапазонов** в блок 1024 кадра.
Играть этот буфер как PCM нельзя: получится треск/шум. Настоящий звук даёт
только связка микшера `0x409330`:

1. история фильтра `0x19d` (413) сэмплов из предыдущего блока;
2. lookahead `0x184` (388) сэмплов из следующего блока;
3. polyphase-синтез `0x8534c0`.

`render_sou2.py` воспроизводит именно эту схему, а не `clamp(raw >> 1)` из
`gm.py music`.

## 2. Частота: всегда 32000 Гц

DirectSound-буфер музыки создаётся с `nSamplesPerSec = 32000`
(`FUN_00405cd0`, `0x405d8c`/`0x405e4b`). `FUN_00409330` за callback отдаёт
1024 кадра без шага/ресемплинга.

Поле `sample_rate` в заголовке SOU2 (`16000` у `L01BONUS` и `LOADSCRN`) для
формата 4 **не является playback rate**: `FUN_0040af30` считает step
`rate / 32000` в `0x83d96c`, но музыкальный путь это поле не читает.

Следствие: 66304 кадра `L01BONUS` — это **2.072 с при 32000 Гц**, а не 4.144 с
при 16000. Рендер без `--out-rate 32000` звучит на октаву ниже и тянется
вдвое дольше.

## 3. Однотрековый `.sog` зацикливается

`MUSIC/L01H.sog` содержит один сэмпл — `L01BONUS`. Плейлист микшера после
конца снова выбирает индекс 0 (`DAT_0084a688 = 1`, `DAT_0084a684`
сбрасывается в 0). Поэтому игровая 3-секундная вставка — это **1.45 цикла**:

```
2.072 с (первый цикл) + 0.928 с (начало второго)
```

Шов слышен как повтор ровно на **2.072 с = 69%** трёхсекундного файла. Это не
артефакт MP3 и не ошибка энкодера; onset/self-similarity дают пик 2.072 с.

`render_sou2.py --loop --seconds 3` воспроизводит игровое поведение, включая
историю/lookahead через шов. **Но** в `out/` по просьбе пользователя лежит
**один цикл без повтора**: 2.072 с музыки + тишина до 3.0 с. Не добавляй
`--loop` в дефолтную сборку MP3 без явного запроса.

## 4. Правый канал `L01BONUS` тихий по данным, а не потерян

| | peak | RMS |
|---|---|---|
| raw L / R | 98850 / 17181 | 10127 / 1199 |
| render L / R | 0.900 / 0.110 | 0.269 / 0.0188 |

Правый канал тише примерно на **18.5 дБ** в поддиапазонах и на **23 дБ** после
синтеза. Проверка симметрии `0x8534c0`: при одинаковом входе в оба канала
выходы совпадают бит-в-бит, то есть фильтр не виноват.

В `FUN_00409330` после фильтра есть пост-фильтровая M/S-матрица
(`0x409d01`, ветка `DAT_004c22cc == 0`). Прямое применение к `L01BONUS` даёт
почти равные каналы, но **противофазу** (корреляция L/R ≈ −0.95) и задержку
левого на блок 1024 кадра. В обычном стерео-прослушивании это звучит как
фазовый эффект, поэтому в `render_sou2.py` M/S-ветка **не включается**.
Не «исправляй» тихий правый канал усилением или M/S без отдельного решения:
сначала проверь фазу и моно-совместимость.

Для `out/L01BONUS_switch_music.mp3` выбран **моно-даунмикс** `(L+R)/2` с
дублированием в оба канала: правый в источнике — тихий ambient, поэтому
потеря стерео минимальна, зато вставка слышна в обоих каналах.

## 5. Что лежит в `out/` и как это пересобрать

| файл | содержимое |
|---|---|
| `SWELEC1_switch_level1.mp3` | только щелчок `SWELEC1`, **не менять** |
| `L01BONUS_switch_music.mp3` | один цикл 2.072 с + тишина до 3.0 с, моно в обоих каналах |
| `level1_switch_sequence.mp3` | щелчок + эта вставка |

Музыка:

```sh
python3 tools/re/render_sou2.py L01BONUS /tmp/L01BONUS.wav --out-rate 32000
# далее: (L+R)/2, fade 5 мс, pad до 3.0 с, peak 0.9, ffmpeg 44.1 кГц stereo
```

Игровой цикл (с ожидаемым повтором на 2.072 с):

```sh
python3 tools/re/render_sou2.py L01BONUS /tmp/L01BONUS_3s.wav \
    --out-rate 32000 --loop --seconds 3
```

Подробный отчёт по вставке, корреляции и SHA — `out/switch_level1_README.md`.
