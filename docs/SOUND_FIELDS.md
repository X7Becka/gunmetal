# Звук: записи сэмплов и голоса (M2.3.7)

Статус: **карта снята**, обе структуры разобраны по читателям/писателям,
шапки всех 4091 `.sou` сверены с формулами загрузчика.
Инструмент: `tools/re/sound_fields.py` (`--map`, `--verify`, `--self-test`).
Разбор: Ghidra 12.1.4, бинарь `gundx.exe` v1.36, проект `re/ghidra/`.

## 0. Что исправлено в ROADMAP

Строка `M2.3.7` читалась как «записи сэмплов (`0x83d960`, 28), голоса
(`0x84e068`, `0x50`)». На самом деле:

| | база | шаг | записей | конец | доказательство |
|---|---|---:|---:|---|---|
| записи сэмплов | `0x83d960` | `0x1c` (28) | **300** | `0x83fa30` | цикл очистки `0x40b460` (`puVar1 += 7` dword до `< 0x83fa30` = 300×28), проверка `299 < i` в загрузчике `0x40af30`, `param_1 < 300` в `0x40a4b0`/`0x40a690`, `300` слотов `SOUND_SAMPLE_TABLE` (тип 12 `.sbt`) |
| голоса | `0x84e068` | `0x50` (80) | **9** | `0x84e338` | цикл микшера `0x40a388` (`CMP EDX,0x8` — 8 эффект-голосов), проверка `< 9` в `0x40a7d0`, обход 9 слотов `0x40a840` (`< 0x84e33c`); слот 8 (`0x84e2e8`) — музыкальный поток |

То есть «28» и «0x50» — шаги, а не количества. Голосов не 32 (32 — это
требование API `Mixer`, не оригинала): **8 эффектов + 1 музыкальный стрим**.
Слот 8 использует те же смещения (`+0x00` остаток, `+0x10` указатель,
`+0x18`/`+0x1c` петля, `+0x20` формат 4), но его заводит отдельная функция
`0x40a3a0`, а микшер обрабатывает отдельной ветвью `DAT_0084e300 != 0`.

## 1. Метод

1. `tools/ghidra/mcp.py decompile/disasm/xrefs/read_bytes` по адресам из
   `NOTES.md` §2, `docs/INIT.md` §7, `docs/SOU1.md` §4.
2. Владельцы найдены по xref на базы: `0x40b460` (init/clear), `0x40af30`
   (загрузка), `0x40b400` (выгрузка), `0x40a4b0`/`0x40a690` (play),
   `0x40a5e0` (старт голоса), `0x40a7d0` (стоп), `0x40a8a0` (обновление
   громкости/панорамы), `0x409330` (микшер), `0x40a3a0` (музыкальный слот).
3. Смещения читались из инструкций `[reg+disp]`, а не из псевдо-C: у структур
   много байтовых обращений (`(char)voice[0xb]` = `+0x2c`), декомпилятор
   путает типы. Ключевые: `0x409dde`, `0x409e59..0x409e9b`, `0x409ead..0x409ee8`,
   `0x40a099..0x40a0fa`, `0x40a2a0..0x40a37f`, `0x40a5e0..0x40a682`.
4. Формулы загрузчика сверены с шапками всех `.sou` (`--verify`): 999
   `sounds/SOU.IDX` + 3092 `MUSIC/SOU.IDX`, только чтение, кодек не
   декодируется.
5. 3D-параметры взяты из реальных уровней (`gm/scene.py`, опкод
   `ADD_SOUND_SOURCE`) и из очереди `0x62ce18`.

## 2. Запись сэмпла: `0x83d960 + id*0x1c`, id 0…299

Индекс 0 не используется: загрузчик ищет свободный слот с 1 (`0x40af30`,
`piVar5 = &0x83d97c`, т. е. `+0x1c` следующей записи). Поля:

| off | тип | поле | кто пишет | кто читает | статус |
|---|---|---|---|---|---|
| `+0x00` | u32 | `size_bytes` — SOU0/1: `length & ~1`, SOU2: `frames` | `0x40af30` | `0x40a4d9`, `0x40a6b9`, `0x40a745`, `0x40a853`, `0x40b41c`; очистка `0x40b460` | доказано |
| `+0x04` | u32 | `slots_32k` — длина в слотах 32 кГц | `0x40af30` (`0x40b0e8`, `0x40b258..0x40b2b0`) | `0x40a578`/`0x40a766` (play), `0x40a9b0` (длительность), `0x40a489` (музыка) | доказано |
| `+0x08` | u32 | `step_hi` = `rate / 32000` (целая часть) | `0x40b10d` | `0x40a09d` (SOU0-ветка микшера) | доказано |
| `+0x0c` | u32 | `step_lo` = `((rate<<16)/32000)<<16` (младшие 32 бита шага 32.32) | `0x40b11b` | `0x40a099` (SOU0-ветка) | доказано |
| `+0x10` | ptr | указатель на данные (`FUN_00402770`) | `0x40b168` | `0x40a591`, `0x40a0a5`/`0x40a0d6`, `0x40a422` (музыка); освобождение `0x40b400`/`0x40a840` | доказано |
| `+0x14` | u32 | `right_offset` — смещение правого канала в буфере: `payload/2` для stereo, 0 для mono | `0x40b0e8` (stereo) / `0x40b0f0` (mono 0) | только загрузчик при деинтерливе (`0x40b2d8`); **в голос не копируется** | доказано |
| `+0x18` | u32 | `format`: 0 = SOU0, 1/2/3 = SOU1 (1/2/4 копии), 4 = SOU2 | `0x40af30` | `0x40a556`, `0x40a43a` → `voice+0x20` | доказано |

Шаг — единое 32.32-число `rate * 2^32 / 32000`: `+0x08` хранит старшие 32
бита, `+0x0c` — младшие. Проверено на всех записях: для 8000 Гц это
`0x00000000:40000000`, для 16000 — `0x00000000:80000000`, для 32000 —
`0x00000001:00000000`.

Кэш вокруг таблицы (для полноты): 300 имён по 9 байт `0x4c9c90`, 300
хэндлов `0x4ca720`, счётчики ссылок `0x4cebd8`/`0x4cf1a8`, бюджет памяти
`0x4c8770` (`0x40af30`: `+= 0x100 + FUN_0040dc00(ptr)`, `0x40b400`:
`-= 0x100 + FUN_0040dc00(ptr)`).

## 3. Голос: `0x84e068 + i*0x50`, i 0…8

| off | тип | поле | кто пишет | кто читает | статус |
|---|---|---|---|---|---|
| `+0x00` | u32 | `remaining` — остаток слотов 32 кГц | `0x40a67c` (старт), `0x40a0fa` (−0x400), `0x40a37f` (петля) | `0x409dde` (`count = min(remaining, 0x400)`) | доказано |
| `+0x04` | u32 | `sample_id` — владелец-запись `0x83d960` | `0x40a600` | `0x40a867` (стоп по сэмплу), `0x40a8b3` (обновление) | доказано |
| `+0x08` | u32 | `step_hi` | `0x40a60a` = `rate/32000` | `0x40a09d` только format 0 | доказано |
| `+0x0c` | u32 | `step_lo` — младшие 32 бита шага 32.32 | `0x40a614` | `0x40a099` только format 0 | доказано |
| `+0x10` | ptr | курсор левого канала | `0x40a61e`; после декода `0x40a0e9`/`0x40a36c` | `0x409ead`, `0x40a0a5`, `0x40a0d6` | доказано |
| `+0x14` | u32 | `right_offset` — правый канал = `cursor + right_offset` | **писатель не найден** | `0x409ee5`, `0x40a0a1`, `0x40a2c8` | гипотеза: 0 для моно (верно), для stereo — другой путь |
| `+0x18` | ptr | `loop_start` (0 = без петли) | `0x40a635` (arg6); музыка `0x40a42e` | `0x40a101`, `0x40a2cc`, `0x40a322` | доказано |
| `+0x1c` | u32 | `loop_len` в слотах | `0x40a62f` (arg5); музыка `0x40a42e` (record+`0x04`) | `0x40a374` (`remaining = loop_len − remainder`) | доказано |
| `+0x20` | u32 | `format` 0…4 | `0x40a63f` | `0x409e64` | доказано |
| `+0x24` | u32 | предыдущая громкость L | `0x40a2f6` | `0x409e70` | доказано |
| `+0x28` | u32 | предыдущая громкость R | `0x40a301` | `0x409e8a` | доказано |
| `+0x2c` | u32 | громкость L 1…32 | `0x40a665` (arg9); update `0x40a8a0` | `0x409e16`, `0x409e59`, `0x40a0bc` → `[0x84a6a8] = vol−1` | доказано |
| `+0x30` | u32 | громкость R 1…32 | `0x40a66f` (arg10); update `0x40a8a0` | `0x409e1d`, `0x409ec6`, `0x40a2ad` | доказано |
| `+0x34` | u32 | состояние музыки A | слот 8 (`0x84e31c`) | музыкальная ветвь | гипотеза |
| `+0x38` | u32 | состояние музыки B | слот 8 (`0x84e320`) | музыкальная ветвь | гипотеза |
| `+0x3c` | u32 | состояние музыки C | слот 8 (`0x84e324`) | музыкальная ветвь | гипотеза |
| `+0x40` | i32 | `acc_l` — аккумулятор ADPCM | `0x40a653` (0), `0x409e81` (пересчёт) | `0x409e77`, декодер `0x852b40` | доказано |
| `+0x44` | i32 | `level_l` — индекс уровня | `0x40a64d` (0) | декодер `0x852b40` | доказано |
| `+0x48` | i32 | `acc_r` | `0x40a65f` (0), `0x409e9b` | `0x409e94`, декодер | доказано |
| `+0x4c` | i32 | `level_r` | `0x40a659` (0) | декодер | доказано |

Старт `0x40a5e0` получает 11 аргументов (общий стек с вызовом `0x40d110`):
`length_slots, step_hi, step_lo, data, 0, loop_ptr, format, sample_id,
vol_l, vol_r, voice_index`. Он же обнуляет `acc/level` обоих каналов
(`0x40a64d..0x40a65f`), поэтому новый сэмпл всегда начинается с `0/0`.

Слот 8 — музыка: `0x40a3a0` кладёт в него `record+0x04` (длина),
`record+0x10` (указатель), `record+0x18` (формат), `0x84e300`/`0x84e304`
(петля от начала до конца), `0x84e2e8` (остаток). Микшер обрабатывает его
как «последний голос» только когда `DAT_0084e300 != 0`.

## 4. Вспомогательные таблицы

**Запросы звука** — `0x4cabd8`, шаг `0x20`, до 8 одновременных (список
`0x4cf088`), счётчик `0x4ca71c` (≤ 0x200, `0x40be20`):

| off | поле | смысл |
|---|---|---|
| `+0x00` | `queued` | 0/1, ставит планировщик `0x40c080` |
| `+0x04` | `class` | id группы; по нему `0x40c080` не перезапускает уже играющий звук |
| `+0x08` | `sample_id` | индекс записи `0x83d960` |
| `+0x0c` | `volume` | 0…0xff |
| `+0x10` | `pan` | 0…0xff |
| `+0x14` | `rate` | аргумент `param_2` в `0x40a4b0` (шаг/длительность SOU0) |
| `+0x18` | `priority` | `0x40c080` берёт максимум и вытесняет голос |
| `+0x1c` | `flags` | `0x80` = петля (`0x40ad20`/`0x40bec0`), иначе one-shot |

**Очередь 3D-звуков** — `0x62ce18`, шаг `0x2c`, до 256 (`0x62fa18`):

| off | поле | смысл |
|---|---|---|
| `+0x00` | f64 `atten_per_unit` | затухание на единицу расстояния (0.03 у `0x46b840`, 0.015…0.1 у источников уровня) |
| `+0x08` | i32 `x` | позиция |
| `+0x0c` | i32 `y` | |
| `+0x10` | i32 `z` | |
| `+0x14` | u32 `class` | уникальный id источника (`4000000+i`, `0x989680+i`, …) |
| `+0x18` | u32 `sample_id` | индекс `0x4ca720` → запись `0x83d960` |
| `+0x1c` | u32 `volume` | базовая громкость |
| `+0x20` | u32 `rate` | 16000 для `ADD_SOUND_SOURCE`, 0x2b11 для событий |
| `+0x24` | u32 `priority` | 1000 |
| `+0x28` | u32 `loop` | 1 у источников/петель |

Замечание к `docs/EVENTS.md`: там аргументы `FUN_0046b840` названы
`(index, sound_id, 0x2b11, 1000, x, y, z)`. По коду `param_1` (`+0x18`)
служит индексом `0x4ca720` (id сэмпла), а `param_2` (`+0x1c`) — **базовой
громкостью** в формуле `volume − atten*dist` (`0x46c246..0x46c258`);
`1000` — приоритет (`+0x24`), `0x2b11` — rate (`+0x20`).

## 5. Как оригинал микширует (только видимое в коде)

* **Выход 32 кГц, stereo, 16 бит** (`0x4a6810 = 0x7d00`), блок микшера —
  `count = min(voice.remaining, 0x400)` слотов (1024). Микшер вызывается из
  тик-потока (`0x405f30` → `0x4092e0` → `0x409330`).
* **SOU1 (format 1/2/3)** — не ресемплинг, а **дублирование слотов**:
  `0x852b40` (1 копия), `0x852c00` (2), `0x852cc0` (4). Частота 8/16/32 кГц
  уже закодирована форматом, шаг `voice+0x08/+0x0c` в этой ветке
  **не читается**. Интерполяции нет.
* **SOU0 (format 0)** — `0x861000`: байтовый указатель с шагом 32.32
  (`EAX` — целая часть, `ESI` — дробная, `ADD ESI, step_lo; ADC EAX,
  step_hi`), чтение **без интерполяции** (берётся байт по целому адресу),
  8-битное значение масштабируется таблицей `0x858000` (32 строки × 256,
  индекс = `volume*256 + byte`).
* **SOU2 (format 4)** — отдельный тракт `0x852d80` (бит-поток) +
  `0x8534c0` (polyphase), всегда 1:1 на 32 кГц, шаг не используется.
* **Громкость/панорама** — две 5-битные громкости на голос:
  `L = clamp(((255−pan)*vol + 0x3d)/0x7a, 1, 32)`,
  `R = clamp((pan*vol + 0x3d)/0x7a, 1, 32)` (`0x40a4b0`). Громкость
  выбирает строку дельта-кривой ADPCM (`volume−1` в `[0x84a6a8]`) или
  строку таблицы `0x858000`; отдельного умножения после декодера нет.
* **Смена громкости на ходу** не даёт щелчка: перед блоком аккумулятор
  масштабируется `acc = acc*new_vol/old_vol` (`0x409e77..0x409e9b`), затем
  `prev_volume = volume` (`0x40a2f6`/`0x40a301`).
* **Петля** — не флаг, а указатель `loop_start` (`+0x18`) и длина
  `loop_len` (`+0x1c`): после блока `remaining = loop_len − remainder`
  (`0x40a374..0x40a37f`), указатель возвращается на `loop_start`.
* **Финальный вывод** — `0x8610d0`: `sample = (acc + 0x10) >> 5`, затем
  насыщение в `[-0x8000, 0x7fff]` и interleaved `int16`. То есть усиление
  `>>5` с **округлением +0x10**; полная шкала аккумулятора ≈ `2^20`.
* **3D**: позиция источника → расстояние `0x4344df`; громкость
  `base − atten*dist` (не ниже 0), при split-screen сдвиг на число
  слушателей; затем запрос в `0x4cabd8` и планировщик `0x40c080`, который
  выбирает максимальный приоритет и вытесняет голос. Формула
  `FUN_00437909` (скалярное произведение направления) **вычисляется, но её
  результат не сохраняется** — панорама в очередь передаётся константой
  `0x00` или `0xff` (гипотеза: канал на слушателя в split-screen).

## 6. Поле → C++ → покрытие тестом

| оригинал | C++ | тест |
|---|---|---|
| sample `+0x10`/`+0x18`, заголовок rate/channels | `audio::SoundRef` (`data`, `format`, `channels`, `sample_rate`) | `mixer` (адаптеры U8/S16/S32), `sou1`/`sou2` |
| sample `+0x04` (slots) | `SoundRef::frames` + `Sound::frames()` | `mixer` (импульс/DC/длины), `sou1` |
| sample `+0x08`/`+0x0c` (32.32 шаг) | `Mixer::Voice::step` (32.32) | `mixer`: 11025→22050, 44100→22050 — но это **другая** семантика: оригинал ресемплит только SOU0 |
| sample `+0x14` (right_offset) | нет: C++ хранит interleaved | `mixer` (стерео-клипы) |
| voice `+0x00` (remaining) | `Voice::active` + `Voice::pos` | `mixer` (естественное завершение) |
| voice `+0x04` (owner) | нет | — |
| voice `+0x10` (курсор) | `Voice::pos` | `mixer` (loop/конец) |
| voice `+0x18`/`+0x1c` (петля) | `Voice::loop` + `SoundRef::frames` | `mixer` (loop 100/200/300/400) |
| voice `+0x20` (format) | `SoundRef::format` | `mixer`/`sou1`/`sou2` |
| voice `+0x24`/`+0x28` (prev vol) | нет (гейны Q15 без ramp) | — (различие) |
| voice `+0x2c`/`+0x30` (vol 1..32) | `Voice::gain_l/gain_r` (Q15) | `mixer` (pan L/C/R, расстояние) — закон панорамы другой (линейный float) |
| voice `+0x40..+0x4c` (acc/level) | нет per-voice состояния; `Sou1Stream` держит декодер внутри | `sou1` (паритет 983/983) |
| финал `(acc+0x10)>>5`, clamp | `Mixer::mix` Q15 `>>15`, clamp | `mixer` (клиппинг 32×2000); **округление +0x10 не воспроизведено** |
| слот 8 (музыка) | нет | `sou2` + `mixer` golden (не музыкальный стрим) |
| запросы `0x4cabd8` | нет; `game::SoundCommand` только переносит type-2 | `events` (`direct.sounds[0].rate == 0x2b11`, `volume == 1000`) |
| 3D-очередь `0x62ce18` | `Mixer::PlayParams::position` + `Listener` | `mixer` (distance/direction) — модель `1/(1+d)`, не `vol−k·d` |
| 32 голоса API | `Mixer::kMaxVoices = 32` | `mixer` (33-й отклоняется) — у оригинала 8+1 |

загрузчик отклоняет — они считаются отдельно, не как ошибка формул.
Стерео: 6 SOU1 (`CUT-EMP`, `CUT-PAM`, `CUT-PREZ`, `INTRO`, `VRCHAMBR`,
`VRCHAMHQ`, все 32 кГц) + 3 SOU2 (`FINALE`, `OVERTURE`, `WINNER`).

**3D-источники уровней** (`gm/scene.py`, опкод `ADD_SOUND_SOURCE` 187;
все `sample` < 300, таблица имён — ровно 300 слотов):

| уровень | источников | sample | volume | atten/ед. | пример позиции |
|---|---:|---|---:|---:|---|
| `level0` | 6 | 114, 128, 129 | 12, 19 | 0.05, 0.1 | `(-616,-168,71)`, `(1552,608,23)` |
| `dm1` | 21 | 65, 112, 119…121 | 6…64 | 0.015…0.09 | `(4468,2591,192)`, `(-3520,528,-20836)` |

Отсюда затухание: `volume − atten*dist`; при `level0` `vol=19, atten=0.05`
источник слышен до ~380 единиц.

**Уточнения 2026-10-23** (`docs/AUDIO_3D.md`, доказано по коду):

* расстояние — не евклидово: `max(|dx|,|dy|,|dz|) + 0.25·(mid+min)`
  (`0x4344df`, константа `[0x4a2248]`), снизу клампится `1.0`;
* гейн `trunc(volume − atten·2^n·dist) >> 2n`, `n` — биты `0x2/0x4` флагов
  сектора слушателя (`0x46bce5/0x46bcec`), затем `min(gain, volume)`;
  `gain < 2` — запрос не создаётся;
* панорама — `clamp(trunc((dot(направление, right)/dist + 1)·128), 0, 255)`
  по базису объекта тела игрока (`0x437909`, `0x46be1a`);
* у голоса `+0x18 = priority + volume_index` (не просто priority).

## 8. Доказано / гипотеза / осталось

**Доказано (код + данные):**

* базы, шаги и количества: 300×`0x1c` (`0x83fa30`), 9×`0x50` (`0x84e338`),
  8 эффект-голосов + музыкальный слот 8 (`0x40a388`, `0x40a3a0`);
* все поля таблиц §2/§3 с адресами читателей/писателей;
* формат шага 32.32 (`0x40b10d`, `0x40b11b`) и его использование только в
  SOU0-ветке (`0x40a099/0x40a09d`, `0x861000`);
* SOU1 дублирует слоты 1/2/4 раза, без интерполяции
  (`0x852b40`/`0x852c00`/`0x852cc0`);
* финальное усиление `(acc+0x10)>>5` и clamp (`0x8610d0`);
* громкости 1..32 на канал и формула панорамы (`0x40a4b0`, `0x40a690`);
* пересчёт `acc` при смене громкости (`0x409e77..0x409e9b`);
* таблица запросов `0x4cabd8` и планировщик с приоритетами (`0x40c080`);
* 3D-очередь `0x62ce18`, затухание `volume − atten*dist` (`0x46bed0`);
* все 4091 шапки `.sou` согласованы с формулами загрузчика.

**Гипотеза:**

* `voice+0x14` (правый канал): писатель не найден; для моно 0 корректен,
  для стерео-эффектов путь не подтверждён (стерео SOU1 в поставке —
  длинные cutscene-треки, вероятно, играются другим трактом).
* `+0x34..+0x3c` слота 8 — состояние SOU2-синтеза (band 12), точная роль
  не разобрана.
* панорама в 3D-пути: результат `FUN_00437909` не сохраняется, в запрос
  уходит константа `0x00`/`0xff`; назначение (канал на игрока в
  split-screen) не доказано.
* `+0x14` записи сэмпла (`right_offset`) в голос не копируется —
  предположительно стерео-эффекты не проходят через `0x40a5e0`.

**Осталось:**

* stereo-эффекты SOU1 (6 записей): найти тракт, который копирует
  `record+0x14` в `voice+0x14`, или доказать, что его нет;
* точная семантика `FUN_00437909` и панорамы 3D (сейчас — константы);
* интеграция карты в C++: кэш 300 записей, таблица запросов, планировщик
  приоритетов и 3D-очередь не имеют аналогов в `engine/` (есть только
  транспорт `game::SoundCommand`);
* округление `+0x10` в финальном сдвиге не воспроизведено в `Mixer::mix`
  (`>>15` без `+0x10`) — регрессионный golden этого не проверяет.
