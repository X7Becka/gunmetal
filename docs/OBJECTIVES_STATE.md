# Маска целей и секреты в движке (`M6.4.5`, срез 2)

**Статус:** модуль `engine/src/game/objectives.{h,cpp}` + тест `objectives`
(`engine/tests/test_objectives.cpp`, CTest label `quick`, **537 проверок**).
Чистое состояние: объявление целей (опкод 103), маска выполнения (104),
условие «все цели выполнены» (7), значение маски для сейва (блок 11, сущность
`-3`, опкод `0x68`), объявленное число секретов (94) и счётчик найденных (95).
Без `GameRuntime`, VM, сейв-писателя, HUD, часов, RNG и рендера; файлов игра
не открывает вообще.

Канон поведения — `docs/OBJECTIVES.md` (снят с `gundx.exe` v1.36 только на
чтение, без Ghidra) и `tools/re/objectives.py`; поток кампании —
`docs/CAMPAIGN_FLOW.md` §4–5. Здесь — реализация, API, числа теста и
ограничения.

Проверка:

```sh
cmake --build build --target gm_objectives_tests -j 4
./build/engine/tests/gm_objectives_tests        # objectives: ok (537 checks) ...
ctest --test-dir build -R '^objectives$' --output-on-failure
python3 regress.py --mirror --json
```

## 2. API (`game/objectives.h`)

`class Objectives` — состояние уровня, не кампании:

| метод | семантика | статус |
|---|---|---|
| `bool declare(int count)` | опкод 103: `0..30`; `31`/`-1` — `false` + текст, состояние не меняется | доказано (кроме отказа на отрицательном: u32-парсер) |
| `int count()` | `0x80d7ec` | доказано |
| `bool set(int index, bool done = true)` | 104: `mask |= 1<<index`, повтор — no-op; индекс вне `[0, count)` — `false` + текст | доказано для `true`; `false` — MODEL |
| `bool done(int index) const noexcept` | тихий запрос бита; вне диапазона — `false` | модель API (читатели оригинала не выходят за `count`) |
| `std::uint32_t mask()` | поле `0x80f9d0` как есть, бит в бит | доказано |
| `std::uint32_t declared_mask()` | `mask & ((1<<count)-1)`: то, что видит HUD и проверяет условие 7 | производное |
| `void load_mask(uint32_t)` | загрузка значения из сейва (`0x456f50` сначала обнуляет) | доказано |
| `std::uint32_t save_mask() const` | значение для блока 11 / `-3` / опкод `0x68` | доказано |
| `bool all_done() const noexcept` | условие 7 | доказано |
| `void reset() noexcept` | сброс уровня: count 0, маска 0 | доказано (`0x45709d`/`0x4570a3`) |

`class Secrets`:

| метод | семантика | статус |
|---|---|---|
| `bool add()` | 95 -> `0x4536b0`: `tally += 1`, без предела и дедупликации | доказано; `INT_MAX` — MODEL-отказ |
| `int tally()` | `player+0x33cc` | доказано |
| `void reset()` | `0x45280f`: tally 0, объявленное число сохраняется | доказано |
| `int declared()` / `bool set_declared(int)` | опкод 94; вход вызывающего, отрицательное — `false` + текст | доказано (94), вход — модель |
| `void clear_declared()` | `0x45708a`: объявленное -> 0 | доказано |

Оба класса держат одну строку `last_error()`; удачный вызов её очищает,
отказ — оставляет текст и не меняет состояние.

## 3. Что модель (не доказано кодом)

1. **`set(index, false)`.** Оригинальный опкод 104 только делает `or`
   (`0x45be49`); снятие бита — API модуля, не поведение скриптов. В тесте
   помечено `MODEL clear`.
2. **Тихий `done()`.** Вне `[0, count)` возвращает `false` и не пишет
   `last_error()`: HUD и условие 7 всегда ходят по `i < count`, поэтому
   поведение оригинала для такого индекса не определено; выбран тихий отказ.
3. **`declare()` не трогает маску.** Это доказано (103 пишет только count и
   указатели), но следствие — модельное решение: после меньшего объявления
   старые биты остаются в поле `mask()`/`save_mask()` и **скрыты** от
   `declared_mask()`/`all_done()`. Так же ведёт себя условие 7, игнорируя
   старшие биты. Тест: `declare(8)`+`0xff`, затем `declare(3)` -> `mask()
   0xff`, `declared_mask() 0x7`, `all_done() 1`.
4. **Чужие биты при загрузке сохраняются, а не отсекаются.** Док (§2.5) не
   описывает очистку поля при загрузке, поэтому выбран точный round-trip:
   `load_mask(0xffffffff)` при `count=5` даёт `mask() == save_mask() ==
   0xffffffff`, `declared_mask() == 0x1f`; тест печатает оба числа.
5. **`Secrets::add()` при `INT_MAX`.** Оригинальный `inc` переполнил бы i32
   (UB); модуль отказывает с текстом. Байт-код до этого не доходит.
6. **`set_declared()` — вход вызывающего.** Модуль не читает ни опкод 94 из
   `.sbt`, ни сейв: 101 — это **сумма по 25 уровням**, а не предел на уровень.
   Поэтому принимается любое `>= 0`; отрицательное — отказ с текстом.
7. **`Secrets::reset()` и `clear_declared()` раздельны**, хотя в оригинале оба
   сброса стоят рядом в `0x456f50` (`0x45280f` — счётчик, `0x45708a` —
   объявленное). Раздельность нужна, чтобы «респавн» не терял объявление
   уровня; это решение модели, не факт кода.

## 5. Ограничения

- **Не подключено** к `GameRuntime`, VM (`vm_exec`), сейв-писателю
  (`save_load`/`save_write`), HUD и фронтенду. Модуль — библиотека состояния;
  вызовов из движка нет.
- **Нет текстов целей.** `0x80d800[i]` — указатели в код уровня; строки,
  разбиение по `'*'` (`0x487394`) и HUD-маркеры `check`/`nocheck`
  (`0x4833e0`, буферы `0x67fc10`/`0x683fb8`) не реализованы.
- **`entity -3` и опкод `0x68` не эмулируются.** `save_mask()` отдаёт только
  значение; под-скрипт `INTERNAL_LEVEL_RESUME`, его создание (`0x462e0c`) и
  дописывание команд в блок 11 — вне модуля. End-to-end проверки «сейв с
  ненулевой маской» нет и в поставке (оба сейва — `level0`).
- **Условие 7 не вызывает VM-команду**; `all_done()` — его арифметика, не
  интеграция с интерпретатором.
- **Секреты — один игрок.** Восемь слотов `0x819040 + i*0x3510` (индекс
  `0x83d308`) не моделируются: класс соответствует текущему игроку.
- **Экран конца уровня** (`0x483c07`, `%ld / %ld`) и панель F6
  (`0x499534`) не рисуются — формат и подписи вне scope.
- **`SET_LEVEL_SECRETS` из скрипта не разбирается**: `set_declared()` —
  вызывающий код; 101/105 — константы корпуса, а не чтение `.sbt`.
- Тест не читает установку игры: это состояние, а не формат, поэтому запуск
  всегда полный (без `SKIP`).
