# Рендер экрана START GAME (`engine/src/ui/start_game_render.h`)

Срез 8 пункта `M8.7`: [`SaveMenu`](SAVE_MENU.md) знает 20 слотов и выделение,
этот модуль **рисует экран 13 — `START GAME`** — в RGBA-буфер 320×200: заголовок,
два пункта меню, шесть видимых слотов с полосами `FILESLOT` (срез 9),
подсветку курсора шрифтом 4, стрелки прокрутки `MENUARRW` и `ESC TO CANCEL`.
Атласы и метрики — из `render/text_layout` (`FONTS4` в `FRONTEND/BMP.IDX`),
координаты — из обработчика `0x48aa60` и таблицы `docs/UI_SCREENS.md`
§2/§3.6/§5.1, плата — та же `PLATE`, что у меню, экрана 14 и экрана 17.
Срез 8 добавил **точный fade** по таблицам `0x682f90` (`fade_lut*` в опциях,
§6) — тем же индексным слоем, что у пейджера (`docs/PAGER_RENDER.md` §2.6).
Срез 9 добавил **полосу слота** `FILESLOT` 124×10 под каждой видимой строкой:
`0x48ab90`, копия `rep movs`, `(35, 43 + 11·i)` — геометрия доказана адресами
и закреплена пикселями (§1, §4).

Код: `engine/src/ui/start_game_render.h/.cpp`; тест —
`engine/tests/test_start_game_render.cpp` (CTest `start_game_render`, label
`quick`). Канон поведения — `docs/UI_SCREENS.md` §3.6/§5.1, `docs/SAVE_MENU.md`,
`docs/SAVE_SLOTS.md`, `docs/SAVE_MENU_RENDER.md` и `docs/LEVEL_SELECT_RENDER.md`
(тот же класс задачи: шрифты `FRONTEND/BMP.IDX`, цвета `FONTS4`, контракт
ошибок, `MENUARRW`).

### 1.1. Модель отрицательных строк (доказано кодом)

Числа `-33`, `-44 … -99`, `-110` из §3.6 — **не смещение списка**, а абсолютная
строка экрана: `0x485dd0` при `row < 0` считает
`dest = 0x6865f8 + x - 196·row` (умножение `((3·row)<<4 + row)<<2` в
`0x485e2b`..`0x485e37`), т.е. `y = -row`. Для `row >= 0` — `y = row + item·step`
(`0x485e4b`..`0x485e5c`). Поэтому:

```
пункт 0: item 0, row  23        -> y = 23 + 0·10 = 23
пункт 1: item 1, row -33        -> y = 33
слот i : item i+2, row -(44+11i) -> y = 44 + 11·i   (i = 0..5)
ESC    : item -1, row -110      -> y = 110
```

Прокручивается только **окно** слотов: имя берётся из
`0x6c2fe0 + (scroll + i)·0x13`, а строки у `i` фиксированы — база `44` и шаг
`11` не зависят от `scroll`. Заголовок при `centered` игнорирует `x` и
центрируется в полосе: `x = (196 - width) / 2` (`0x485de2`..`0x485dfa`), а
`item == -1` делает строку абсолютной, поэтому заголовок стоит на y 12.

## 2. Модель (не доказано кодом)

* **Текст слота** — запись таблицы `0x6c2fe0 + slot·0x13`: имя сейва для
  занятого слота, `::: empty slot :::` (`0x4bc3b0`) для пустого. Это ровно
  `SaveMenu::label`/`SaveSlotView`; поля модели `level`/`seconds` не печатаются
  — оригинальная строка их не содержит.
* **Источник окна** — `StartGameRenderOptions::first_slot` (по умолчанию 0),
  зажимается в `0..13` (следствие `scroll + 6 < 20`, `SAVE_SLOTS.md` §4);
  вызывающий обычно передаёт `SaveMenu::visible_first()`. Рендер не читает
  `visible_first()` сам: это позволяет нарисовать произвольное окно тем же
  кадром (тест 0/5/12).
* **Подсветка** — шрифт 4 у строки, чей абсолютный номер слота равен
  `SaveMenu::selected()`. В оригинале сравнивается `item` (для слотов
  `row + 2`) с курсором `0x68ccf4`; отображение «курсор = номер слота» — наша
  модель, потому что у `SaveMenu` выделение абсолютное. Если выделение вне
  окна (`first_slot` задан вручную), подсветки нет. Пункты 0/1 в нашей модели
  невыделяемы: `StartGameRenderOptions` не несёт их курсора (в оригинале
  `0x68ccf4` может указывать и на них — это следующий срез).
* **Цвета** — палитра атласа `FONTS4`: заголовок (шрифт 5) → `9b0f0f`
  (тёмно-красный), строки (0) → `130f0f` (тёмно-серый), подсветка (4) →
  `efefef` (белый), тени `6b473b`/`4b4b4b`/`afafaf`. Привязка «номер шрифта →
  грань атласа» — из `text_layout::font_table_spec` (`UI_SCREENS.md` §11),
  проверена пикселями теста.
* **`rows`** в статистике = `2 + slot_rows` (при полной таблице 8, как
  immediate `0x67f10c`); `slot_rows` = сколько полос слотов нарисовано
  (`min(6, slots − first_slot)`). У `ui/save_menu_render` одноимённое поле
  значит другое (занятые слоты) — здесь оно по заданию считает полосы.
* **Плата** — `PLATE` рисуется в (0,0) в порядке `parse_bmp`, как в соседних
  рендерах; экранный origin копии платы не документирован (`UI.md` §8).
* **Клип** — глифы обрезаются полосой 196×131 (буфер `0x485dd0`). Самый
  широкий текст — `New Single Player Game` (107 px при x 35 → до 141), так что
  клип — страховка.
* **Полоса `FILESLOT`** — из своего ассета, без прозрачности. Ориентация — как у
  загрузчика, а не у `parse_bmp`: `0x47efe0` читает `width*height` байт пикселей
  файла как есть (`fread` на `0x47f0f8`), `0x484cc0` копирует строки вперёд,
  поэтому строка экрана `r` — это файловая строка `r`, т.е. `parse_bmp`-строка
  `height−1−r`. Это то же `flipV(parse_bmp)`, что доказан у пейджера по читаемым
  заголовкам (`PAGER_RENDER.md` §2.4), и та же конвенция, что у `MENUARRW` в
  этом рендере. На плату это **не** переносится: `PLATE` по-прежнему рисуется в
  порядке `parse_bmp` (§5) — расхождение унаследовано от недоказанной ориентации
  платы.
* **Палитра полосы** — из самой `FILESLOT`: на всех 14 использованных индексах
  она побайтово равна палитрам `PLATE`/`MENUARRW`/`FONTS4` (тест), различаются
  только неиспользуемые записи 0/64/144, так что выбор палитры на кадр не влияет.
* **Порядок и прозрачность** — полоса `i` кладётся перед текстом строки `i`
  (как `call 0x48ab90` перед `call 0x485dd0`), все 1240 байт копируются, включая
  индекс 0; поэтому под текстом всегда полоса, а не плата.
* **Пиксели полосы не входят в `ink_pixels`** — счётчик остаётся «чернилами
  глифов»; число полос — `fileslot_bands`, прямоугольники считает тест.
* **Фон** — непрозрачный чёрный; `background="PLATE"` рисуется только по
  явному запросу (конвенция `ui/menu_render`).

## 3. API

```cpp
#include "ui/save_menu.h"
#include "ui/start_game_render.h"

gm::SaveMenu menu;
menu.open(gm::SaveMenuMode::save, "/mnt/d/games/Gunmetal 3dfx");

gm::StartGameRenderOptions options;
options.background = "PLATE";           // пусто = чёрный холст
options.first_slot = menu.visible_first();
options.fileslot = true;                // полосы FILESLOT под строками (по умолчанию)
options.fade_lut = true;                // точный fade 0x682f90 (§6)
options.fade_lut_level = 11;            // 0..15, 11 = тождество
options.fade_lut_table = &lut;          // или options.fade_lut_dump = ".../hud_lut.bin"

std::vector<std::uint32_t> rgba;        // 0xRRGGBBAA
int width = 0, height = 0;
gm::StartGameRenderStats stats;
std::string error;
if (!gm::render_start_game("/mnt/d/games/Gunmetal 3dfx", menu, options, rgba,
                           width, height, &stats, &error)) {
    // текст с префиксом start_game_render: ...
}
// width=320 height=200 rgba.size()==64000
```

Точный fade (§6): `fade_lut` (включить), `fade_lut_level` (`0..15`, по
умолчанию `kHudLutIdentityLevel = 11`), `fade_lut_table` (`const HudLut*` из
`build_hud_lut`, приоритет) и `fade_lut_dump` (путь к 4096-байтному дампу).
Без таблицы и дампа — отказ; уровень клампится `map` в `0..15`.

`fileslot` (по умолчанию **true**) рисует полосу `FILESLOT` 124×10 под каждой
видимой строкой слота, как оригинал (он делает это безусловно, холст —
копия платы). Ассет обязателен: если записи `FILESLOT` нет или она не 124×10,
вызов отказывает текстом `start_game_render: fileslot FILESLOT: ...`. `false` —
осознанный текстовый кадр (частичная установка, стенды), а не способ скрыть
битый ассет.

Константы: `kStartGameTitle` (`"START GAME"`), `kStartGameSinglePlayer`,
`kStartGameMultiplayer`, `kStartGameCancel` (`"ESC TO CANCEL"`),
`kStartGameRows` (8), `kStartGameVisible` (6), `kStartGameItemStep` (10),
`kStartGameItemX` (35), `kStartGameItemFirstY` (23), `kStartGameSlotX` (39),
`kStartGameSlotFirstY` (44), `kStartGameSlotStep` (11), `kStartGameCancelX` (35),
`kStartGameCancelY` (110), `kStartGameTitleY` (12), `kStartGameTitleFont` (5),
`kStartGameRowFont` (0), `kStartGameSelectedFont` (4), `kStartGamePanelName` (`"PLATE"`),
`kStartGamePanelWidth/Height` (196/131), `kStartGameMaxFirst` (13),
`kStartGameArrow*` (16/8, x 159, y 2/121),
`kStartGameFileslotName` (`"FILESLOT"`), `kStartGameFileslotWidth/Height` (124/10),
`kStartGameFileslotX` (35), `kStartGameFileslotFirstY` (43).

`StartGameRenderStats`: `rows` (8 = 2 + полосы), `first_slot` (эффективное
окно, 0..13), `slot_rows` (нарисованные полосы слотов, 6), `fileslot_bands`
(скопированные полосы `FILESLOT`: 6 при `fileslot`, 0 без него; при полной
таблице равно `slot_rows`), `ink_pixels`
(пиксели холста, закрытые хотя бы одним пикселем глифа; стрелки и полосы не входят),
`arrows` (0..2: вверх при `first_slot > 0`, вниз при `first_slot + 6 < 20`),
`missing_glyphs` (символы без глифа, пропускаются).

Контракт ошибок: на отказе `rgba` очищается, `width`/`height` = 0, `stats`
обнуляется. Отказы: пустая таблица слотов (контракт, через модель недостижим),
пустой каталог игры, нет `FRONTEND/BMP.IDX` или нужного атласа (`FONTS4` для
шрифтов 0/4/5), фон отсутствует/битый/не 8 bpp, нет полосы `FILESLOT` или она
не 124×10 (при `fileslot = true`), точный fade без таблицы и без
дампа (или с нечитаемым/неверного размера дампом). Все тексты начинаются с
`start_game_render: `.

  прямоугольников 124×10; по строкам (число = 1240 − глифы, лежащие поверх

## 5. Ограничения

1. **Полосы `FILESLOT` нарисованы (срез 9).** `0x48ab90` вызывает `0x484cc0`
   (обычный `rep movs`, 10 строк по 31 dword = 124 байта, без прозрачности) из
   буфера `0x661298` в `0x688707 + i·0x86c`, т.е. спрайт 124×10 в
   **(35, 43 + 11·i)** копии платы (`0x688707 − 0x6865f8 = 43·196 + 35`,
   `0x86c = 11·196`). Каждая полоса и текстовый слой поверх неё сверены
   пикселями (196×10 на строку, §4). Живой кадр оригинала в этой среде не
   снимался — доказательство кодовое (адреса выше) + ассет + пиксельный тест.
   **Ориентация полосы** — файловая (`flipV(parse_bmp)`, §2), доказана
   загрузчиком `0x47efe0` (`fread` строк как есть) и копией вперёд; это не
   проверено на живом экране, но совпадает с доказанной ориентацией пейджера
   (`PAGER_RENDER.md` §2.4). Плата по-прежнему рисуется в порядке `parse_bmp`
   (§2) — расхождение унаследовано от недоказанной ориентации платы.
2. **Пункты 0/1 невыделяемы**: API не несёт их курсора (в оригинале `0x68ccf4`
   может указывать на них, `0x485e0d`). Модель рисует их всегда шрифтом 0.
3. **Нет звука** `updown`/`select` (`ui/ui_sounds.*`) и курсора мыши.
4. **Нет диалога имени (экран 15)**, миниатюр/превью и записи сейва
   (`game/save_action.*`).
5. **CLI — есть (срез 6), но без fade**: `--start-game [--save-menu-slot N]
   [--no-plate] [--png OUT] [--png-scale N]`. Печатает `start_game: slots=20
   occupied=2 selected=0 first=0`, затем `render: rows=8 first_slot=0
   slot_rows=6 320x200 ink=1608 arrows=1 missing=0` (полосы `FILESLOT` в
   строку статистики не входят и `ink` не меняют; PNG теперь с полосами) и PNG;
   CTest `cli_start_game`, `_png`, `_scale`. Флага «выключить полосы» в CLI нет:
   опция API `fileslot = false` в `main.cpp` не выведена (файл вне этого среза).
   Флаг `--fade-lut K` для экрана 13 подключён: уровень 11 = кадр без fade
   (0 отличий), 12..15 различаются (`cli_fade_lut`).
   Связки с `frontend_menu.*`/`GameRuntime` нет.
6. **Модель не пишет и не читает игру**: `render_start_game` только читает
   `FRONTEND/BMP.IDX` и состояние `SaveMenu`; `SAVEGAME` открывается самим
   `SaveMenu::open`.
7. **Ориентация и origin платы** — модель, как у соседних рендеров (§2).
8. **Клип 196×131** — доказан (буфер `0x485dd0`), но ни одна строка этого
   экрана в него не упирается.

## 6. Точный fade `0x682f90` (срез 8)

Таблицы затемнения движка — **индекс → индекс** (`0x682f90`, 16×256,
docs/HUD_LUT.md §2): движок блитит уже собранный 8-bpp буфер через `LUT[k]`,
поэтому цвет пикселя берётся из палитры **после** подстановки. На готовом
RGBA-кадре это не повторить, поэтому `render_start_game` применяет `map` к
палитровому индексу в момент записи пикселя (`PaletteFade` в `.cpp`), до
`palette_colour`. Слой тот же, что у пейджера (`docs/PAGER_RENDER.md` §2.6);
`FadeSource` там приватный, поэтому здесь минимальная локальная копия.

```cpp
gm::HudLut lut;
std::string error;
gm::build_hud_lut(*gm::installed_palette(game, error), lut, &error); // GAMEPAL
gm::StartGameRenderOptions options;
options.background = "PLATE";
options.first_slot = 0;
options.fade_lut = true;
options.fade_lut_level = 11;          // 0..15; 11 = тождество (k/11 = 1)
options.fade_lut_table = &lut;        // или options.fade_lut_dump = ".../hud_lut.bin"
```

Фон `PLATE`, стрелки `MENUARRW`, полосы `FILESLOT` и все глифы проходят через
`map(lut, level, index)`; уровень берётся как есть (`0..15`, `map` клампит),
поэтому 12..15 **осветляют**, а не повторяют 11. Пиксель без палитрового
индекса (чёрный холст вне платы) не трогается. Если `map` вернул индекс вне
палитры источника — отказ с текстом (на поставочных 256-слотовых палитрах
недостижимо, защита от коротких). Без `fade_lut_table` и без `fade_lut_dump` —
`start_game_render: fade LUT needs a table (fade_lut_table) or a dump
(fade_lut_dump)`; нет файла/не тот размер — `start_game_render: hud_lut: ...`.
Таблица в памяти приоритетнее дампа; при отказе буфер очищается, `width`/
`height` = 0, `*stats` обнуляется.

Числа (тест, кадр `saved0`/`saved1` + `PLATE`, 64 000 пикселей, таблица
построена из `FRONTEND/GAMEPAL` в памяти — дамп не читается):

| Проверка | Число |
|---|---|
| уровень 11 против кадра без fade | **0** отличий |
| уровень 0: чёрных пикселей (RGB 0) | **63 981** (без fade 38 324) |
| уровень 0: отличий от кадра без fade | 25 657 |
| 12/13, 13/14, 14/15: отличий между соседними | 14 841 / 21 637 / 19 089 |
| 12/13/14/15 против уровня 11 | 15 325 / 24 325 / 24 559 / 25 565 |
| вне платы 196×131 на всех уровнях | 0 не-чёрных (нет индекса) |
| уровень 99 | равен уровню 15 (кламп `map`) |

**Ограничения.** Нужна палитра (`build_hud_lut`) или дамп; таблица работает
только на палитровом пути этого модуля (RGBA-модели `fade`/`fade_level` у
экрана 13 нет). Цвет берётся из палитры источника каждого пикселя (плата,
спрайт стрелки, полоса `FILESLOT`, атлас шрифта), а `map` идёт по индексу. CLI `--start-game --fade-lut K` подключён: уровень 11 = кадр без fade,
12..15 различаются (`cli_fade_lut`).
