# LAYOUT — каталоги, конфигурация, канон

Статус: **рабочий документ** (инвентаризация 2026-10-23). Отвечает на три
вопроса: где что лежит, что является источником истины и какой инструмент
самый дешёвый для типа задачи. Расхождения с реальностью — ошибка этого
файла; проверять `ls`/`grep`, а не верить на слово.

## 1. Каталоги

| путь | что | в git | канон |
|---|---|---|---|
| `gm/`, `gm.py` | Python-оракул (эталон раскладки и поведения) | да | да |
| `engine/` | C++-переиздание | да | нет (сходится с оракулом) |
| `regress.py`, `tools/qa/` | ворота: проверки, снимок, покрытие | да | да |
| `tools/re/` | реверс-инструменты (`exelib`, `gmcache`, `fncache`, …) | да | да |
| `tools/editor/` | ассемблер/дизассемблер скриптов `.sbt` (`sbtasm.py`) | да | да |
| `tools/ghidra/` | MCP-обвязка и кэш декомпиляций | да | да |
| `tools/win/` | Windows-сторона (снятие кадров) | да | да |
| `docs/` | знания и выводы, по одному факту в одном месте | да | да |
| `build/` | артефакты CMake | нет | — |
| `out/` | эталонные кадры (`out/oracle/win*.png|json`) и отчёты | нет | да (кадры) |

Правила: игра в `/mnt/d/games/Gunmetal 3dfx` — **только чтение**; тяжёлые
сборки — `build/`, `/var/tmp`, `~/build`, а не `/tmp` (tmpfs).

## 2. Канон по типу данных

| тип | единственный источник | зеркала/ссылки |
|---|---|---|
| факт о формате или поведении | `docs/FORMATS.md`, `NOTES.md` (карта exe) | профильный `docs/*.md` ссылается на них |
| имена функций | `tools/re/names.csv` | проект Ghidra получает их `apply_names.py` |
| очередь задач | `NEXT.md` (сверху — следующий шаг) | `docs/RE_AUDIT.md` §7 — снимок аудита, не очередь |
| измеренный срез (HEAD, счётчики, тесты, кэш) | `python3 tools/qa/state.py` | `CURRENT_STATE.md` — прозаическая версия того же |
| история ходов | `docs/JOURNAL.md` | коммиты; в `NEXT.md` истории нет |
| прогресс | `ROADMAP.md` (id `M4.2.3`) | `state.py` считает статусы, `grep -c` — нет |
| baseline внешних расхождений | `docs/BASELINE.md` | — |

Канон один: новый факт пишется в свой профильный док, а `ROADMAP`/`NEXT`
ссылаются на него. Дублировать абзац в двух доках — ошибка.

## 3. Переменные окружения

Все пути переопределяемы; по умолчанию — реальная установка и `~/.cache`.
Читатели перечислены по факту (`grep environ`).

| переменная | по умолчанию | кто читает |
|---|---|---|
| `GUNMETAL_GAME` | `/mnt/d/games/Gunmetal 3dfx` | большинство `tools/re/*.py`, `regress.py` |
| `GUNMETAL_EXE` | `$GUNMETAL_GAME/gundx.exe` | `tools/re/exelib.py`, `regress.py`, `init_flow.py` |
| `GUNDX_ASM` | `$GUNMETAL_CACHE/gundx.asm` | `tools/re/exelib.py`, `player_fields.py` |
| `GUNMETAL_CACHE` | `~/.cache/gunmetal-re` | `exelib` (кэш, зеркало, регрессия) |
| `GUNMETAL_LEVELS` | — | `texuv.py` (доп. корпус уровней) |
| `GUNMETAL_ORACLE` | `out/oracle` | `hud_audit.py`, `frame_metric.py` |
| `GUNMETAL_MIRROR_TTL` | 900 с | `gmcache.py` (проверка свежести зеркала) |
| `GM_REGRESS_CACHE` | `1` | `regress.py` (`0` — отключить кэш проверок) |
| `GM_PROGRESS`, `GM_PROGRESS_ASCII` | вкл / off | `tools/loadbar.py` |

Новый скрипт обязан брать путь отсюда (или из `exelib`), а не хардкодить
`/mnt/d/...`; свой дефолт допустим только как `os.environ.get(X, DEFAULT)`
рядом с таким же в других инструментах.

## 4. Кэш и его инвалидация

| путь | что | когда устаревает |
|---|---|---|
| `gundx.asm`, `gundx.asm.idx` | листинг + индекс | смена SHA exe (`gmcache.py status`) |
| `gundx.exe` | копия exe для оффлайн-прогонов | то же |
| `game/`, `game.manifest.json` | зеркало установки | расхождение stat/sha (`mirror --check/--verify`) |
| `ghidra/<sha12>/` | декомпиляции (`fncache.py`) | смена SHA exe |
| `regress-cache/` | результаты тяжёлых проверок | хэш исходников/зеркала |

Кэш — не доказательство: в отчёт идёт SHA/манифест, при котором он снят.
Единственную копию доказательств (кадры `out/oracle`, `docs/`) очистка кэша
не трогает.

## 5. Маршрутизация: тип задачи → самый дешёвый инструмент

| вопрос | инструмент | не делать |
|---|---|---|
| где это уже описано | `tools/ctx.py addr VA`, `ctx.py find`, `docs/INDEX.md` | читать 200-КБ доки целиком |
| что делает функция по адресу | `fncache.py get VA --head 40` (кэш), иначе `disrange.py` | тянуть функцию на 3000 строк |
| точный байт/константа | `exelib.disasm(lo,hi)` по индексу листинга | парсить 283k строк |
| формат/раскладка | `gm.py parse/dump`, `regress.py --category` | писать новый парсер |
| паритет Python↔C++ | `ctest --preset quick`, `regress.py --mirror --json` | полный `--full` без нужды |
| кадр vs оригинал | `oracle_render.py` + `frame_metric.py` | `corr` как решающая метрика |
| снимок проекта | `state.py`, `gmcache.py status` | ручной пересчёт |

## 6. Расширение

- Новый скрипт: `--self-test` (или замер), `--json`, понятные коды возврата,
  запись только в `out/`, `build/`, `~/.cache`; разрушительные операции — с
  `--force`/бэкапом.
- Новый док: строка в `docs/INDEX.md` (генерируется `ctx.py index`), канон —
  ровно один, остальные ссылаются.
- Новый агент/процесс/сервис/БД — только при измеренной потребности; Ghidra
  одна на всех, второй MCP-сервер не поднимать.
- **Один писатель на общий файл.** Замечено 2026-10-23: в одном дереве
  работали две сессии, обе правили `NEXT.md`/`ROADMAP.md`/`engine/`; git
  слил без конфликта, но очередь и счётчики на минуту расходились. Правило:
  общие файлы (`NEXT.md`, `ROADMAP.md`, `docs/JOURNAL.md`, `docs/INDEX.md`,
  `regress.py`, `gm/*`, `engine/CMakeLists.txt`) правит одна сессия; вторая
  работает в worktree (`~/build/gm-sub-*`) и отдаёт ветку на merge. Перед
  правкой общего файла — `git status`, после — быстрый `state.py --check`.
