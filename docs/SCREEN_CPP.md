# SML-экран в C++: один рантайм от `.sme` до RGB

Документ описывает `engine/src/ui/screen.h` / `screen.cpp` — слой, который
соединяет готовые модули в один экран: разметку читает `res/sml`, раскладку и
страницы считает `render/text_layout`, картинки `<I>` блитит `render/sprite`,
BMP — `res/bmp`/`res/bigfile`. Своего парсера, таблицы шрифтов и второго
блиттера здесь нет.

Формат и семантика тегов — [UI.md](UI.md), читатель разметки — [SML_CPP.md](SML_CPP.md),
раскладка/шрифты — [TEXT_LAYOUT.md](TEXT_LAYOUT.md), блиттер — [SPRITE.md](SPRITE.md).
Модуль только читает игру: `.sml`/`.sme`, `SML/*.bmp` и `FRONTEND/BMP.IDX`
открываются на чтение, ничего не переписывается.

## 1. API

```cpp
#include "ui/screen.h"

std::string error;
auto screen = gm::Screen::load("help.sme", game, error);  // путь/имя
// или: gm::Screen::load(bytes, "BRIEF/LEVEL10", game, error);
if (!screen) { /* error: файла нет / разметка битая */ }

if (!screen->layout()) {          // по умолчанию 267x167
    // screen->state().error: шрифт, картинка, размер страницы
}
screen->pages();                  // число страниц
screen->lines();                  // все визуальные строки всех страниц

screen->select(5);                // строка 5, страница переключается сама
screen->scroll(+1);               // вниз на строку, с зажимом на краях
screen->show_page(2);             // страница пагера

gm::RenderResult frame;
frame.width = 320; frame.height = 200;
frame.rgb.assign(320u * 200u * 3u, 0);
screen->render(frame, {}, 2, error);   // пустая палитра = палитры BMP
screen->state();                  // страницы/строки/выбор/хеш/ошибка
```

| Метод / тип | Назначение |
|---|---|
| `Screen::load(path, game, error)` | файл; путь абсолютный, от CWD, от `game` или от `game/SML`, после точного промаха — ASCII-case-insensitive (`HELP.SME` → `help.sme`) |
| `Screen::load(bytes, game, error)` | уже прочитанные байты (`.sml` и `.sme`, `parse_sml` сам пробует шифр) |
| `Screen::load(bytes, name, game, error)` | то же с логическим именем для `state().source` и ошибок |
| `layout(width=267, height=167)` | шрифты из `FRONTEND/BMP.IDX`, `layout_text`, загрузка `<I>`; сбрасывает страницу и выбор |
| `pages()`, `lines()` | страницы раскладки и плоский список `ScreenLine` (`page`, `index`, `x/y/width/height`, `font`, `first/last`, `text`) |
| `select(index)` | выбор строки по индексу в `lines()`; `false` + ошибка вне диапазона, состояние не меняется |
| `scroll(delta)` | сдвиг выбора на `delta` строк с зажимом; без выбора `+1` встаёт на первую строку, `-1` остаётся на первой; пустой экран: `0` — no-op, иначе ошибка |
| `show_page(page)` | текущая страница пагера (0-based), выбор не трогает |
| `render(target, palette, page, error)` | страница в RGB с origin `(0,0)`; `palette` — либо пустой span, либо 1024 байта RGBA на все картинки |
| `render(target, palette, error)` | то же для `state().page` |
| `state()` | `ScreenState`: счётчики, текущая/отрисованная страница, выбор, `rgb_hash` (FNV-1a64 последнего кадра), ошибка, флаги гипотез |
| `document()`, `layout_result()`, `image_slots()`, `image_assets()` | доступ для тестов и диагностики без копирования данных |

Ошибки валидации `render` (раскладка не выполнена, target меньше страницы,
неверный размер `rgb`, короткая палитра, страница вне диапазона) не пишут ни
одного пикселя. `state().rgb_hash` считается по всему target после успешной
отрисовки — удобно для golden'ов и логов.

## 2. Теги, страницы и строки

Раскладку целиком делает `render/text_layout`; Screen только вызывает её и
переводит результат в плоские строки. Поэтому действуют все правила
[TEXT_LAYOUT.md](TEXT_LAYOUT.md) §3:

| Тег | Что видно в Screen |
|---|---|
| текст, `<r>`, `<p>` | строки/абзацы `LayoutLine`; текст строки склеен из прогонов с общей базовой линией |
| `<c>` | сдвиг прогона в остатке ширины (`<c>AB</c>` при 30 px → x = 9) |
| `<f s=N>` / `</f>` | шрифт прогона; высота строки 10 px, у шрифта 3 — 18 px |
| `<x v=...>` | `x = value * width / 100` (в поставке не встречается) |
| `<k>` | прогон `Soldier`; `<s>` — прогон `" "`; `<M B/S>` — no-op раскладки |
| `<I ...>` | слот `ScreenImageSlot` + декодированный `ScreenImageAsset` |
| `</d>` | конец документа, последняя страница |

Страницы — `LayoutPage::start/end` (байтовые смещения в декодированном
тексте); `lines()` содержит строки всех страниц подряд, `ScreenLine::page` и
`index` дают локальные координаты. Пустой `<d></d>` — одна страница, ноль
строк; `render` рисует пустоту, `select(0)` и `scroll(+1)` возвращают `false`.

Выбор строки — удобство рантайма, а не поведение брифинг-пагера: в движке
пункты меню подсвечиваются через `0x68ccf4` и шрифт 4 ([UI.md](UI.md) §6.2), у
SML-пагера курсора нет. Рамка — 1 px цветом `kScreenSelectionColor`
(255,255,0) вокруг `x/y/width/height` выбранной строки; рисуется после текста,
поэтому остаётся видимой.

## 3. `<I>`: позиция, масштаб, палитра

Ассет ищется так (первое совпадение):

1. loose-BMP `SML/<f>.bmp` (в поставке все 15 имён — 64×64, 8 бит);
2. запись `FRONTEND/BMP.IDX` (`BIGFILE`) с именем `<f>` или `<f>.bmp`.

Имена с `..`, `\`, `:`, ведущим `/` и длиннее 128 байт отвергаются
(`screen: unsafe <I> image name`), чтобы разметка не читала файлы вне игры.
Отсутствующая картинка — ошибка `layout()`, а не молчаливый пропуск.

**Зафиксированный прямоугольник (гипотеза).** Позиция берётся из
`LayoutImage` — float-модели `text_layout`: `a=l` — левый край колонки,
`a=r` — `right_edge - 64`, `y` — текущая строка; высота обрезается страницей.
Атрибуты `x`/`y` на позицию не влияют (они одинаковы во всём корпусе,
`x=y=64`). Это осознанная фиксация: `docs/TEXT_LAYOUT.md` §3.6 и
`docs/HUD_BIND.md` §2.3 расходятся в трактовке `y` (строка против абсолютной
координаты 64 у HUD-фильма), точный прямоугольник в бинарнике не восстановлен.

Масштаб — целое увеличение `s`/`scale` (1..64), по умолчанию 1: слот и все
поставленные BMP — 64×64, поэтому корпус рисуется 1:1. Увеличенный слот
растёт вправо/вниз от верхнего левого угла слота и обрезается страницей;
`layout_text` резервирует только 64×64 (зафиксированное ограничение).

Палитра: по умолчанию каждый BMP рисуется своей палитрой (у 15 файлов они
разные). Если в `render` передан непустой span, он должен быть 256 RGBA-квадов
и заменяет палитру всем картинкам. Индекс 0 не прозрачный: иллюстрации
непрозрачные, как и в `hud_compose`.

## 4. Golden

`engine/tests/test_screen.cpp` (`ctest -R screen`, метка `quick`, < 1 с).
Страницы/строки сверены с таблицей [TEXT_LAYOUT.md](TEXT_LAYOUT.md), FNV-1a64 —
по RGB страницы 267×167:

| файл | страниц | строк (по страницам) | FNV страницы 0 | FNV всех страниц |
|---|---:|---|---|---|
| `help.sme` | 3 | 42 (15,15,12) | `e19f3ef44f57c6af` | `f8cdde79f171e28c` |
| `prelevel/level21.sme` | 1 | 13 (13) | `44b4c00f86496903` | `44b4c00f86496903` |
| `design/weapon20.sme` | 1 | 2 (2) | `674f46c7bd980c4d` | `674f46c7bd980c4d` |
| `brief/level10.sme` | 3 | 35 (16,16,3) | `daa9fcc5f7fd2c2a` | `a77b19b6abb9c2e1` |

«Все страницы» — FNV по конкатенации кадров 267×167. `brief/level10` —
единственный golden с `<I>`: два слота, оба проверяются на попадание в
страницу; сами тексели закреплены синтетикой.

Как проверялись хеши:

* синтетический текст `AB<r>CD` (100×100, шрифт 1) независимо пересобран
  Python-скриптом из `gm/bigfile.py` + `gm/bmp.py` по правилам `draw_text`;
  буферы совпали побайтово, FNV `b6301b1416cbbd2a`;
* синтетическая страница только с `<I f="drilhed">` (267×167) независимо
  пересобрана из `gm/bmp.py`; совпало побайтово, FNV `e409d7bcd891a88f`;
* в тесте все 64×64 тексела каждой картинки на синтетической странице
  сравниваются с `res/bmp` (не с блиттером);
* хеши четырёх реальных файлов — регрессионные пины самого Screen: компоненты
  доказаны отдельно (раскладка, `draw_text`, `blit`), но полный кадр игры для
  сверки недоступен (см. §6).

Синтетика покрывает: одну и две страницы, перенос (30 px → 22+18), центр
(`<c>AB</c>` → x = 9), `<f s=3>`/`</f>`, `<x v=50>` → 133, `<s>`/`<k>`, `<M>`,
`<I>` слева/справа, масштаб `s=2` с подменой палитры, выбор и `scroll`,
пустой экран, повторный `layout`,
target больше страницы (пиксели вне 267×167 не трогаются).

Негативы: битая разметка (`<d>AB`), пустой ввод, отсутствующий файл, пустой
`<d></d>`, `render` до `layout`, страница вне диапазона, target меньше
страницы, неверный размер `rgb`, короткая палитра, небезопасное имя `<I>`,
отсутствующая картинка, `<f s=6>` (шрифт без атласа). Для ошибок валидации
проверяется, что target остался нетронутым.

## 5. Проверки

```sh
cd /path/to/gunmetal-re
export PATH=$HOME/tools/cmake-4.4.4-linux-x86_64/bin:$HOME/tools/bin:$PATH
cmake -S . -B build/sandbox -G Ninja
cmake --build build/sandbox --target gm_screen_tests -j 32
ctest --test-dir build/sandbox -R screen --output-on-failure
python3 regress.py          # игра и Python-инструменты не менялись
```

Ожидаемый вывод:

```
screen: synthetic (pages/wrap/centre/fonts/<I>/selection), negatives and 4 shipped goldens; OK
```

Без установленной игры тест печатает `screen: game not installed, skipped` и
завершается успешно, как остальные корпусные тесты (`GUNMETAL_DIR` задаёт
другой путь).

## 6. Доказано, гипотезы, доверие, остаток

Доказано (переиспользованные модули + проверки этого слоя):

* разметка `.sml`/`.sme` и ремонты — `res/sml` (`docs/SML_CPP.md`);
* шрифты, метрики, переносы, `<r>/<p>/<c>/<f>/<x>/<s>/<k>`, страницы
  267×167 — `render/text_layout` (`docs/TEXT_LAYOUT.md`);
* блит индексированных картинок и палитра BMP — `render/sprite`,
  `res/bmp` (`docs/SPRITE.md`);
* ровно 15 loose-BMP 64×64, 72 `<I>` на 24 экранах — `tools/re/ui_semantics.py`;
* счётчики страниц/строк четырёх golden'ов совпадают с независимой
  раскладкой (`TEXT_LAYOUT.md`);
* синтетические RGB-хеши воспроизведены Python-читателем побайтово.

Гипотезы / зафиксированные решения:

1. **Прямоугольник `<I>`** — float-слот `LayoutImage`, `x`/`y`-атрибуты
   игнорируются, масштаб по умолчанию 1 (в корпусе атрибута `s` нет);
   расхождение с HUD-трактовкой `y=64` (`HUD_BIND.md`) не разрешено.
2. **Selection** — рамка 1 px жёлтым; в движке SML-пагер курсора не имеет,
   подсветка меню идёт другим путём (шрифт 4, `0x68ccf4`).
3. **Цвет текста** — палитра атласа шрифта (как `draw_text`); отдельная
   32-битная таблица цветов движка (`0x47faf0`) не проверена.
4. **Палитра картинок** — собственная палитра BMP; общая палитра игры не
   подставляется, пока вызывающий не передаст её явно.
5. **Маркер страницы** — страницы начинаются со следующей строки
   (`TEXT_LAYOUT.md` §3.5), а не с повторного перевода строки.

Остаток (сознательно вне этого шага):

* сверка полного кадра с игрой (эталонного скриншота брифинга нет);
* точная семантика `x`/`y` у `<I>` и момента сброса float; после `<I>` в одной
  строке `text_layout` не двигает перо, поэтому текст на той же строке может
  лечь на картинку — это ограничение используемой раскладки, а не Screen;
* `<M B/S>` только фиксируется в документе, музыку Screen не запускает;
* подсветка выбранного пункта меню (шрифт 4, `PLATE` 196×131), экранный
  автомат `0x4bc440`/`0x4883d8`, фон `DISBAND`/`DEMOTION`;
* SDL-окно, ввод и тайминги пагера — слой выше; Screen остаётся чистой
  логикой без SDL.
