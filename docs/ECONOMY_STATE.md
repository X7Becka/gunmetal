# ECONOMY_STATE — деньги и магазин в движке (`M6.2.6`, срез 2)

**Статус:** чистый модуль состояния + тест на синтетике и реальных
`level0.sbt`/`dm1.sbt`. Файлы: `engine/src/game/economy_state.h/.cpp`,
`engine/tests/test_economy_state.cpp` (CTest `economy_state`, label `quick`,
**353 проверки**). RE-канон — `docs/ECONOMY.md` (далее §); здесь только
перенос в C++ и явное разделение «доказано / модель».

## 0. Итог

* Деньги — одно поле игрока `+0x332c` (`0x81c36c`), не «стоимость
  комплекта» (§0, §2). Модуль хранит его как `int cash`.
* Покупка по доку: запись должна быть «покупаемой» (`flags & 1`) и
  `cash >= цена`; **при нехватке денег не меняется ничего** (§4.2 шаг 4,
  §4.3). Это и есть поведение `buy()`: отказ, `cash`/`owned`/масса на месте,
  `rejected_funds += 1`, текст в `last_error()`.
* Продажа начисляет **ту же** цену E9, которую списывает покупка
  (`0x47b879`/`0x47b881`, §4.2 шаг 3) — поэтому в каталоге `sell == buy`.
* Масса — сумма `mass * count` по каталогу (§6, `0x4524d0`). Лимит массы
  **не блокирует покупку в оригинале** (единственный читатель `+0x3338` —
  штраф скорости `0x4525e7`, §6). В модуле лимит — опциональная модель,
  по умолчанию **выключен**.
* `SELL_ALL` (op 140, `0x45bc1a`, §7) обобщён до «продать все строки
  инвентаря по `sell`»; поля и масса обнуляются, возврат идёт в `cash`.
* Каталог — **вход** модуля (`set_catalog`), а не чтение `.sbt`. Тест
  доказывает, что зашитые в него числа совпадают с `level0`/`dm1`:
  экипировка **7/7**, стволы **4/4**, патроны **3/3**, шасси **4/4**;
  суммы §12 (`Σ «купить» = 1 100 000`, вес `2185`/`1335`) сходятся.

## 1. Что доказано (и откуда)

| факт | источник |
|---|---|
| деньги — `i32` `player+0x332c` (`0x81c36c`), HUD печатает `CASH: %ld` | §0, §2.1 |
| `ADD_SOURCEPLAYER_CASH`: `cash += arg`, отрицательное зажимается в 0 | §2.1, `0x459dc2/0x459dce/0x459ddb` |
| покупка: `flags & 1` **и** `cash >= цена`; иначе no-op | §4.2 шаг 4, `0x47b8ba..0x47b8d5`, §4.3 |
| продажа: `cash += E9`, `owned &= ~бит`; при активном — ещё E4 | §4.2 шаг 3, `0x47b879/0x47b881` |
| одна и та же цена E9 в обе стороны (нет наценки/скидки) | §4.2, оба чтения `0x814c84 + i*0x40` |
| `SOURCEPLAYER_SELL_ALL` возвращает щиты/патроны/стволы/экипировку и обнуляет маски/индексы | §7, `0x45bc1a..0x45bde3` |
| масса = `Σ щиты/100*вес + Σ стволы + Σ экипировка + Σ патроны` | §6, `0x4524d0` |
| лимит массы покупку **не** ограничивает (только скорость) | §6, единственное чтение `+0x3338` — `0x4525e7` |
| щит: цена 50 за 100 единиц, вес 0 (все 36 уровней) | §3, §12, `DEFINE_SHIELDS (50, 0)` |
| цена комплекта шасси = `база + 4*щиты*цена_щита` (`0x479dd0`) | §3 |
| сохранение хранит `cash` как есть; в `saved0`/`saved1` — 2000 | §9, `0x4671c0` |

Данные в тесте не пересказываются, а **читаются**:
`gm::load_level` → `gm::decode_sbt_script` → верхнеуровневые таблицы
`DEFINE_EQUIPMENT`/`DEFINE_WEAPONS`/`DEFINE_AMMO`/`DEFINE_PLAYER_TYPES` +
`DEFINE_SHIELDS`. Сверка идёт по именам записей и полям цены/веса/партии,
поэтому дрейф любого числа в поставе немедленно валит тест.

## 2. Модель

`namespace gm` (имён `EconomyState`/`EconomyStats`/`PriceEntry` в движке
раньше не было — проверено `grep`).

```cpp
struct PriceEntry { int id, buy, sell, mass; };
struct EconomyStats { int purchases, sales, rejected_funds, rejected_mass; };

class EconomyState {
  bool set_catalog(std::vector<PriceEntry>, std::string* error = nullptr);
  const std::vector<PriceEntry>& catalog() const;
  const PriceEntry* find(int id) const;

  int  cash() const;
  bool set_cash(int);          // < 0 — отказ с текстом (все доказанные
                               // писатели оставляют поле >= 0, §2.1)
  int  add_cash(int);          // op 114: +=, зажим снизу в 0 (§2.1)

  bool buy(int id, int count = 1);
  bool sell(int id, int count = 1);
  int  sell_all();
  bool sell_all(int* total);

  int  mass() const;                       // Σ mass * owned (§6)
  int  mass_limit() const;                 // kNoMassLimit = -1 по умолчанию
  bool set_mass_limit(int);                // модель, §6 оригинала не знает
  int  owned(int id) const;
  const EconomyStats& stats() const;
  const std::string& last_error() const;
};
```

Порядок проверок `buy()` (как в коде оригинала: средства — на `0x47b8d3`):

```
id в каталоге -> count > 0 -> cash >= buy*count -> (модель) масса <= лимита
```

Каждый отказ атомарен: `cash`, `owned`, масса и остальные счётчики не
меняются, `last_error()` содержит текст. Отдельные счётчики:
`rejected_funds` (не хватило денег) и `rejected_mass` (сработал
модельный лимит). `purchases`/`sales` считают успешные операции;
`sell_all()` добавляет по единице за каждую очищенную строку инвентаря.

Денежная арифметика — в `std::int64_t` с проверкой результата: транзакция,
которая вывела бы `cash` за `int`, отклоняется до изменения состояния.
Это модель (в оригинале поле `i32`, а сценарии с переполнением не
встречаются).

### 2.1. `sell_all` и что именно обобщено

Оригинал (§7) идёт в фиксированном порядке: 4 щита → патроны → стволы по
маске → купленная экипировка, причём экипировку возвращает **по таблице
стволов** (`0x45bce9`, ошибка оригинала). Наш каталог не знает категорий,
поэтому `sell_all()` возвращает `Σ sell*owned` по всем строкам, обнуляет
инвентарь (значит и массу) и пишет сумму в `cash`. Для одной и той же
строки это ровно то же число, что `sell(row, owned)`. Ошибка с таблицей
стволов **не воспроизводится**: цена `sell` — авторитетный вход.

### 2.2. Чего модуль не делает

* Не проверяет `flags`: `buyable`/`sellable`/`hidden` (`0x01/0x02/0x08`,
  §4.2/§10) должны быть отфильтрованы до `set_catalog`. Поэтому `sell()`
  проверяет только владение.
* Не трогает `owned`-биты экипировки, маску оружия, `active`, `index`,
  `salvage`, `action_state`, события E1/E4 — это поля `GameRuntime`/VM,
  см. `docs/EQUIPMENT_STATE.md` и `docs/WEAPONS_CPP.md`.
* Не считает цену комплекта шасси: `0x479dd0` проверяется в тесте как
  формула на константах §3; отдельного класса шасси нет.
* Не подключён к рантайму, UI, сейву (`SAVE_FIELDS.md` §9), сети и
  респавну (§8). Нет скидок, репутации, гандикапа и «стартовых денег».

Цены/масса каталога (buy = sell; §3/§12):

```text

MINE DETECTOR   40000  / 45           TARGETING       60000 / 10
WARP DEVICE     100000 / 300          RADAR           25000 / 30
MINE LAYER      75000  / 300
MACHINE GUN     0      / 15           CANNON          50000 / 600
AUTOCANNON      350000 / 1300         RAILGUN        500000 / 900
BULLETS         500    / 0 (партия 100)   CANNON SHELLS 4000 / 0 (30)
POWER CELLS     3000   / 0 (3000)     100 щитов        50 / 0
```

Синтетика (печатается тестом):

```text
set_cash(-1) -> false (текст); saved0 cash = 2000
buy FORCE SHIELD 800000 при cash 2000 -> false, cash 2000, rejected_funds 1
buy FORCE SHIELD:             cash 1000000 -> 200000, mass 650,  purchases 1
buy MINE LAYER x2:            cash  200000 ->  50000, mass 1250, purchases 2
buy TARGETING x3 (180000) при 50000 -> false, cash 50000, rejected_funds 2
add_cash -1000000 от 50000 -> 0 (зажим §2.1), затем +2000 -> 2000
масса без лимита: CANNON 600 -> true, mass 600 (правило оригинала, §6)
модель-лимит 500: MG 15 + CANNON 600 -> false, mass 15, rejected_mass 1
лимит 615 (saved0): 15 + 600 = 615 -> true (граница), ещё CANNON -> false
sell FORCE SHIELD: cash 200000 -> 1000000, mass 0, sales 1
sell MINE LAYER 1 из 2: cash 50000 -> 125000, mass 300, owned 1
sell_all: RADAR + 2x MINE LAYER, mass 630 -> 0, total 175000, cash -> 175000
sell при cash INT_MAX -> false (cash overflow), owned остаётся 1
```

Данные (`level0` / `dm1`, вывод теста):

```text

dm1:    equipment 12, buy_sum 1100000, all_mass 1335, matched 7/7 4/4 3/3, chassis 4/4
щиты 50/0; шасси LIGHT 10000/80/500, MEDIUM 30000/130/1000,
       STEALTH 350000/90/500, HEAVY 80000/200/1600

итог: 353 проверки, ok
```

`dm1` без `BALLAST` даёт ровно `Σвес = 1335` (§12), `level0` — 2185;
обе суммы проверяются по реальным записям, а не по доку.

## 4. Воспроизведение

```sh
export PATH=$HOME/tools/cmake-4.4.4-linux-x86_64/bin:$HOME/tools/bin:$PATH
cmake --build build/sandbox --target gm_economy_state_tests -j 4
ctest --test-dir build/sandbox -R '^economy_state$' --output-on-failure
```

Без установки игры синтетическая половина всё равно выполняется, файловая
печатает `not installed, file checks skipped` и не падает. Вне игры ничего
не требуется (stdlib C++), новых зависимостей нет.

## 5. Ограничения и следующий шаг

* Модуль не подключён ни к `GameRuntime`, ни к VM-опкодам 114/140/189–193,
  ни к HUD/витринам, ни к сейву — это следующий срез `M6.2.6`.
* Каталог — вход: сборка из `DEFINE_*` (включая `flags`) остаётся за
  вызывающим; тест показывает, что числа совпадают с поставкой, но сам
  `.sbt`-ридер не добавляется.
* Нет скидок/репутации/гандикапа (§8), нет цены комплекта шасси и обмена
  старого шасси (`0x479dd0`/`0x47aa28`), нет разделения по категориям в
  `sell_all` и нет ошибки оригинала с таблицей стволов (§7).
* Лимит массы — модель: включённый лимит **расходится** с оригиналом,
  поэтому по умолчанию `kNoMassLimit`.
