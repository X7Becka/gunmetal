# C++ HUD-фильмы: проигрывание `.sof` + `.fdx` во времени

* **Статус:** проигрывание HUD-фильма по тикам 91 Гц — привязка имени к строке
  индекса, `count`/`fps`, `start_frame`/`loop`/`hold`, композиция текущего кадра
  в RGB через `blit_indexed`. Привязки к `.sml`-экранам и семействам
  (`AMMO`/`WEAPON`/…) по-прежнему нет (§7).
* **Ветка:** `feat/hud-playback`, база `master` `0420c1a`, дата 2026-10-20.
* **Игра:** только чтение (`Film/*.SOF`, `Film/*.fdx`, `Film/Kflm0000.bmp`).
* **Файлы:** `engine/src/render/hud_player.h`, `engine/src/render/hud_player.cpp`,
  `engine/tests/test_hud_player.cpp`; строка `src/render/hud_player.cpp` в
  `engine/CMakeLists.txt`, регистрация `gm_hud_player_tests`/`hud_player` в
  `engine/tests/CMakeLists.txt`.
* **Эталон:** `engine/src/res/sof.*` (тайл-кодек и `.fdx`), `docs/FILM.md`
  (тайминг, привязка, `0x4958d0`), `docs/HUD_CPP.md` (`blit_indexed`),
  `gm/sof.py` (`binding`, `find_fdx`, `film_id`).

`render_scene` и `hud.*` не менялись: плеер вызывает существующий
`blit_indexed` и работает только с готовым `RenderResult::rgb`.

## 1. API

```cpp
struct HudFilm {
    Sof sof;                        // тайлы фильма
    Fdx fdx;                        // индекс целиком (для инспекции/писателя)
    int line = 0;                   // строка индекса = числовой суффикс имени

    std::uint32_t count = 0;        // кадров играется, из строки .fdx
    std::uint32_t fps = 0;          // частота, из строки .fdx
    std::uint32_t start_frame = 1;  // кадр на тике 0 (HUD-загрузчик: 1)
    bool loop = true;               // зацикливание (HUD-загрузчик: 1)
};

struct HudFrame {
    std::size_t frame = 0;          // индекс тайла для блита
    bool ended = false;             // non-loop фильм доигран (кадр удержан)
};

std::optional<HudFilm> load_hud_film(const std::filesystem::path& game,
                                     const std::string& name, std::string& error);

std::optional<HudFrame> frame_at(const HudFilm& film, std::uint64_t tick,
                                 std::string& error);

bool draw(const HudFilm& film, RenderResult& target,
          const std::vector<std::uint8_t>& palette, int x, int y,
          bool transparent, int scale, double opacity, std::uint64_t tick,
          std::string& error);
```

`HudFilm` — агрегат: три обязательных поля (`sof`, `fdx`, `line`) плюс
параметры проигрывания с безопасными значениями по умолчанию
(`start_frame = 1`, `loop = true` — политика HUD-загрузчика `0x4958d0`).

### 1.1. `load_hud_film`

1. Имя: берётся basename, расширение отбрасывается; буквы → префикс в нижнем
   регистре, цифры → `id` (как `gm/sof.py:film_id`). `Default.sof` без цифр
   получает `id = 0` (`0x49597c`). Имя без цифр и не `Default` — ошибка.
2. Фильм: `<game>/Film/<name>.sof` (расширение добавляется, если его нет);
   поиск регистронезависимый (`resolve_ci`), потому что поставка смешивает
   `AMMO4.SOF`, `ammo4.sof`, `Weapon18.sof`. Можно передать и путь с `/`.
3. Индекс: соседний `<буквы>.fdx`, при отсутствии — устаревший `<буквы>.idx`
   (как `find_fdx`). Нет ни одного — ошибка `no .fdx index`.
4. Строка: запись с **физическим** номером строки `id` (пустые строки в
   поставке отсутствуют, но движок пропускает строки, поэтому сравнивается
   `entry.line`, а не позиция в `entries`). Выход за файл — ошибка
   `line N outside weapon.fdx (M records)`.
5. `count` и `fps` берутся из этой строки; `count > tiles` — ошибка,
   `count == 0`/`fps == 0` — ошибка. `count < tiles` разрешён: у 47 из 48
   HUD-фильмов последний тайл не играется (`docs/FILM.md` §2.1).

Возвращается готовый `HudFilm` с `start_frame = 1`, `loop = true`.

### 1.2. `frame_at` и `draw`

`frame_at` не трогает буфер и не аллоцирует; `draw` вызывает его, собирает
`HudLayer` и делегирует `blit_indexed`. `transparent` включает ключ по индексу
**0** (фон фильмов VGA); `scale`/`opacity` валидирует блиттер (1..4, конечное
число, клампинг 0..1). `x`/`y` обязаны быть неотрицательными — HUD-позиции
задаются дескрипторами экрана, отрицательное начало координат считается
ошибкой вызывающего; частично заэкранный слой по-прежнему доступен напрямую
через `blit_indexed`. Ошибка всегда очищается при успехе.

## 2. Тайминг

Движок считает фильмы в тиках (счётчик `0x5a4a74`, +1 за итерацию главного
цикла, `0x44bdda`), а HUD-вызов превращает `fps` в шаг `ms = 91 // fps`
(`0x49594a`). Плеер использует рациональную форму той же шкалы:

```
frame = (tick * fps / 91 + start_frame)        # целочисленное деление
loop:  frame %= count
hold:  frame = min(frame, count - 1), ended = frame >= count
```

* `tick` — неотрицательный счётчик 91 Гц; `tick = 0` — первый кадр
  (`start_frame`). За 91 тик проходит ровно `fps` кадров (при `fps = 91` —
  один кадр на тик).
* `start_frame = 1` у HUD-загрузчика (первый кадр фильма — тайл 1), `0` у
  скриптового; параметр вынесен в поле, а не захардкожен.
* `count` — эксклюзивная верхняя граница: играются кадры `0 … count-1`.
* `loop = false` — фильм удерживает последний кадр и сообщает `ended = true`
  (ветка «фильм кончился» в `0x49fd40`); при `loop = true` `ended` всегда
  `false`.

**Отличие от движка.** `0x49fd40` делит на `ms = 91 // fps`, то есть при
`fps = 24` шаг равен 3 тикам (30.3 кадра/с). Здесь по заданию используется
`tick * fps / 91` (24 кадра/с), что не теряет остаток от целочисленного
деления. Для `fps = 91` и `fps = 15` (91 кратно) формулы совпадают; для
`fps = 24` кадры на тиках 91/182 — 25/49 (движковый вариант дал бы 31/61).
Если потребуется побитовый паритет с оригиналом, добавляется режим
`ms = 91 // fps` (см. §7).

## 3. Лимиты и trust

* Нет индекса, `fps = 0`, `fps > kFdxMaxFps` (1000), `count = 0`,
  `count > tiles`, строка вне файла, суффикс без цифр, имя пустое/длиннее
  `kHudMaxNameLength` (64), переполнение `tick * fps` (64 бита) — всё даёт
  `nullopt`/`false` и текст в `error`, без записи в буфер.
* Параметры `Sof`/`Fdx` уже ограничены `parse_sof`/`parse_fdx`
  (`kSofMaxTiles`, `kFdxMaxLines`, `kFdxMaxCount`, `kFdxMaxFps`).
* Кадр всегда `< count <= tiles`, поэтому частичный хвостовой тайл `.sof`
  кадром не считается.
* Отрицательные координаты и нефинитная `opacity` отвергаются до записи;
  буфер назначения проверяется `blit_indexed` (`width > 0`, `rgb.size() ==
  width*height*3`), палитра — 256 квадов RGBA.
* Пути только читаются (`std::ifstream`); файлы игры не создаются и не
  изменяются, временный каталог в тесте — вне игры.

## 4. Golden FNV

Сцена: чёрный RGB-кадр 320×200, `AMMO4.SOF` (`ammo.fdx` строка 4, `count =
131`, `fps = 24`, `start_frame = 1`, `loop`), палитра `Film/Kflm0000.bmp`,
слой `x = 14, y = 125` (место HUD-оверлея, `docs/FILM.md` §1.3), `opacity = 1`,
`scale = 1`, без прозрачности. FNV-1a64 (offset `0xcbf29ce484222325`,
prime `0x100000001b3`) по всему буферу `320*200*3`:

| tick | кадр `(tick*24/91+1) % 131` | FNV-1a64 |
|---|---|---|
| 0 | 1 | `aaf521e923f31099` |
| 91 | 25 | `eeb1a6677e96f650` |
| 182 | 49 | `505b37daeecc1c76` |

Значения получены независимо на Python-эталоне (`gm/sof.py` + `gm/bmp.py`,
`decode_tile` + палитра BMP + блит в `(14,125)`), а не сняты с C++-вывода.
Тест также проверяет, что строка 124 остаётся нетронутой, и что `draw` в
тиках 0/91/182 выдаёт кадры 1/25/49.

Синтетический фильм (2 тайла, индексы 1 и 2, `2,15`) фиксирует переходы:

| tick | `start_frame = 0` | `start_frame = 1` | `loop = false` |
|---|---|---|---|
| 0 | 0 | 1 | 1 |
| 6 | 0 | 1 | 1 |
| 7 | 1 | 0 | 1 (`ended`) |
| 13 | 0 | 1 | 1 (`ended`) |
| 91 | 1 | 0 | 1 (`ended`) |

Для `fps = 91` кадр равен `tick` (по модулю `count`). Привязка суффикса
проверяется на поставке: `WEAPON8` → `weapon.fdx:8` → `count = 137`,
`fps = 24`, 137 тайлов (единственная строка, отличная от 131), `AMMO4` →
`ammo.fdx:4` → `count = 131` при 132 тайлах. Синтетический каталог проверяет
`line 9 outside a 9-line index`, отсутствие индекса, `.idx`-фолбэк,
`Default` → строку 0 и регистронезависимый поиск.

## 5. Сборка и проверка

```sh
export PATH=$HOME/tools/cmake-4.4.4-linux-x86_64/bin:$HOME/tools/bin:$PATH
cmake --build build/sandbox --target gm_hud_player_tests -j 32
ctest --test-dir build/sandbox -R hud_player --output-on-failure
python3 regress.py          # 113/113, игра только читается
```

CTest `hud_player` (`quick`, ~0.2 с) пропускает поставку, если игра не
установлена (`GUNMETAL_DIR` переопределяет путь). Golden-числа зашиты, так что
на машине без игры проверяются синтетика и негативы.

## 6. Что доказано и что нет

**Доказано кодом/данными:** формат тайла и транспонирование (`docs/FILM.md`
§1.1), `count` = число кадров, суффикс имени = строка индекса
(`0x49590f`/`0x49592d`, `weapon.fdx:8 = 137`), `fps <= 0` — ошибка движка,
политика HUD-загрузчика `start_frame = 1`, `loop = 1`, место оверлея
`(14,125)` при 320×200, палитра из `Film/Kflm0000.bmp`.

**Не доказано:** точная wall-clock частота главного цикла (число тиков в
секунду — константа `91` в коде, но реальный FPS машины 1997 года неизвестен);
почему у 47 фильмов остаётся неиспользуемый последний тайл; что именно хранит
`0x81c4a0` (слот оружия или тип боеприпаса).

## 7. Что осталось

1. **Привязка к `.sml`-экранам и семействам.** Нужен слой «описание экрана →
   список `HudFilm` + позиции»: префиксы `AMMO`/`WEAPON`/`TANK`/`SHIELD`/
   `EQUIP`/`DEFAULT`, номер из `0x81c4a0`, элементы `.sml` задают координаты.
   Сейчас имя и позиция передаются вызывающим вручную.
2. **Движковый шаг `ms = 91 // fps`.** Рациональная формула выбрана по
   постановке задачи; для побитового паритета с `0x49fd40` нужен режим
   целочисленного шага (и его golden-кадры).
3. **Скриптовые фильмы.** `FILM_DEFINE` задаёт `count/ms/flag` без `.fdx`;
   загрузчик такого фильма — отдельная функция (сейчас `load_hud_film` честно
   отказывает: `Kelfilm` → `no .fdx index`).
4. **Палитра и fade.** Палитра передаётся снаружи; интеграция с
   `installed_palette`/`TexturePool` и затемнениями экрана не сделана.
5. **Прозрачный индекс.** `draw` использует ключ 0; если понадобится другой
   (например, неоновые слоты), параметр нужно вынести в API.
6. **Полный обход 48 фильмов в RGB.** Сейчас golden только для `AMMO4`
   (3 кадра) и `WEAPON8` (индексы); побайтовый обход 11 637 кадров есть в
   `gm_sof_tests`, но не в композиции.

## CLI

`gunmetal --level NAME --render OUT --hud AMMO4 --hud-tick 0 --hud-x 14 --hud-y 125`
накладывает кадр фильма на готовый RGB-кадр; `--hud-scale`/`--hud-opacity`
пробрасываются в `blit_indexed`. В интерактивном viewer тик равен счётчику
кадров (91 Гц), `--hud` загружается один раз до цикла.
