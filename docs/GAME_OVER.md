# Game over, титры, рестарт и экран конца уровня (`M9.5`)

**Статус:** исследование закончено, отрицательные результаты проверены
перебором. Только новые файлы (`tools/re/gameover.py`, этот документ);
существующие доки и код не правились. Ghidra не использовалась — все факты
получены из байтов `gundx.exe` (`tools/re/exelib.py`) и файлов установки.

* База: `master` `35b528c`, ветка `feat/gameover`.
* Игра: `/mnt/d/games/Gunmetal 3dfx` (v1.36, sha256 exe
  `929ffa724c67…`), только чтение.
* Инструмент: `tools/re/gameover.py` (stdlib + `exelib`), `--self-test`,
  `--fields`, `--flows`, `--assets`, `--json`.
* Проверка: `python3 tools/re/gameover.py --self-test` → **120/120**.

## 0. Итог

1. **Отдельного состояния «game over» в кампании нет.** Смерть переводит
   игрока в `action_state = 7` (`0x453763`), и через **136 тиков** (≈1.49 с
   при 91 Гц) вызывается штатный респавн `0x452670` (`0x443b0a`..`0x443b1e`).
   Жизней, счётчика смертей, экрана `GAME OVER` и автосейва нет — проверено
   перебором: 0 строк `GAME OVER`/`LIVES` в exe, 0 упоминаний в установке,
   3 сайта записи сейва (меню + Quick Save) и 2 загрузки.
2. **Единственный «game over»-экран — это меню `RESTART GAME` (state 6).**
   Оно открывается, если нажать Activate (бит `0x8000`) **пока мёртв**
   (`0x443af9`), либо по Esc в игре (`0x48b54c`). Пункты: Reload last saved
   game / Restart level with same R.P.V. / Restart level from HQ / Quit to
   title.
3. **Титры (`SML\CREDITS.SML`) показываются один раз — на титульном экране
   после интро.** Причина: `pager_state` (`0x4bc3a8`) инициализирован в exe
   значением **1**, а загрузчик титров (`0x487d94`) срабатывает ровно при
   `state==1 && pager_state==1`. Записать 1 в этот глобал больше не может
   ни одна инструкция (перебор всех 18 сайтов).
4. **Автоматических титров после `level24` нет.** В `-8` (`SYSTEM_LEVEL_FINISHED`)
   у `level24` только `IF DEATHMATCH_GAME { NEW_LEVEL "DM1" }` и пустой
   `ELSE` → кампания остаётся на экране результатов (это и есть «конец игры»).
   Ветка «winner.sbv + поздравление + чит-коды» (`0x483470`) достижима только
   через VM-опкод 54 `CUSTOM_COMMAND_2`; в 36 поставочных `.sbt` — **0 сайтов**
   этого опкода.
5. **Рестарт из штаба** (`0x4428f0(1)`) уменьшает счётчик миссий на 1 (если
   игра идёт не в штабе), клампит его к 1, восстанавливает структуру игрока
   из снимка штаба `0x815440` (деньги `+0x332c`, оружие/экипаж/шасси) и грузит
   уровень штаба `0x5a4868`. «Тот же R.P.V.» (`0x4428f0(0)`) — то же самое, но
   из снимка старта миссии `0x8338c0`/`0x5a48b8`, без изменения счётчика.
6. **Экран конца уровня** — это опкод **91** `SHOW_LEVEL_END_SCREEN`
   (обработчик `0x45c057`), а не 96 (96 — `SET_LEVEL_GRAVITY`). Показывает
   время, лучшее время, найденные секреты, убийства, salvage. По Activate
   постится `-8`; что произойдёт дальше — решает подскрипт `-8` уровня.

## 1. Состояния и переходы

Фронтенд-состояние — `[0x4bc440]`, подрежим кадра — `[0x83cb7c]`
(`docs/MAINLOOP.md` §4). Для этой задачи важны:

| значение | смысл | доказательство |
|---:|---|---|
| state 0 | интро/загрузка уровня | `0x487709` (0→1), `0x485c53` (→0) |
| state 1 | титульный экран + титры (pager) | `0x487d51` |
| state 2 | SML-пагер (`HELP.SML`, брифинги) | `0x487b69` |
| state 6 | меню `RESTART GAME` | `0x488850` (строитель), `0x48d994` (ввод) |
| state 9 | уровень | `0x4971f4` (start game), `0x48b531` (Esc) |
| submode 5 | экран конца уровня | `0x45c066`, `0x445445` |

Полная диаграмма печатается `python3 tools/re/gameover.py --flows`.
Ключевые переходы:

| из | в | сайт | что |
|---|---|---|---|
| state 9 | state 6 | `0x48b54c` | Esc открывает меню |
| state 6 | state 0 | `0x48da0b` → `0x4428f0` → `0x485c50` | перезапуск уровня |
| state 6 | state 1 | `0x48da31` | Quit to title |
| state 9 (жив) | `action_state 7` | `0x453763` | смерть |
| `action_state 7` | state 6 | `0x443af9` | Activate во время смерти |
| `action_state 7` | state 9 | `0x443b0a` → `0x452670` | респавн через 136 тиков |
| state 9 | submode 5 | `0x45c057`/`0x45c066` | опкод 91 |
| submode 5 | штаб | подскрипт `-8` уровня | `NEW_LEVEL "<штаб>"` |
| штаб | следующая миссия | entity 305 | `NEXT_LEVEL [SOURCE_IS_PLAYER]`, `0x457b11` |

## 2. Смерть и «game over»

### 2.1. Что происходит при смерти

1. `player_killed` `0x4536e0` ставит `action_state (+0x3210 → 0x81c250) = 7`
   (`0x453763`) и обнуляет `death_timer (+0x33d4 → 0x81c414)` (`0x45372f`).
2. Пока состояние 7, обработчик кадра прибавляет к таймеру дельту кадра
   (`0x443849`..`0x443853`).
3. По Activate (`flags2 & 0x8000`, `0x443ace`) **и** если
   `[0x83d620]==0` (не пропуск кадра), `[0x83d940]==0` (не финальный режим) и
   `[0x5a46d8]==0` (чит `regen` выключен) — ставится `state = 6`
   (`0x443af9`), то есть открывается меню `RESTART GAME`.
4. Иначе при `death_timer >= 0x88` (136) вызывается `0x452670(player)`
   (`0x443b0a`..`0x443b1e`) — респавн: в кампании `SET_PLAYER_START`,
   в DM — самый далёкий от живых слот (`docs/DM_RULES.md` §4.2).

**Число 136 тиков.** Единица таймера — тик потока `0x4074e0`
(`Sleep(11)` → ~91 тик/с, `docs/PLAYER_GHIDRA.md`), значит 136/91 ≈ **1.49 с**.
В `docs/DM_RULES.md` §4.3 стояло «≈2.3 с при 60 Гц» — это оценка без
измеренной частоты; уточнение внесено здесь (§8).

### 2.2. Чего в оригинале нет (проверено перебором)

| гипотеза | результат | как проверено |
|---|---|---|
| экран/строка `GAME OVER` | **нет** | `--self-test`: поиск `game over`/`gameover` по строкам `.text/.rdata/.data` → 0; `grep -ril "game over"` по установке → только чужой `DXWnd/*.dxw` |
| счётчик жизней | **нет** | 0 строк `LIVES`/`LIVES:`/`PLAYER LIVES` |
| счётчик смертей | **нет** | `player_killed` не трогает `0x80f9cc`; декремент счётчика миссий только в `0x44295e` |
| автосейв при смерти/конце уровня | **нет** | писатель сейва `0x4422d0` вызывается из 3 мест: `0x48b7e2` (меню SAVE), `0x495087`, `0x495131` (Quick Save); загрузчик `0x442340` — `0x48db6c` (меню), `0x495194` (Quick Load) |

Смерть не отгружает уровень и не трогает `mission_counter` (`0x80f9cc`):
респавн идёт внутри того же уровня.

### 2.3. Что видит игрок

* Панель статуса игрока (опциональная, `0x448218` при `[0x5a4908]!=0`;
  в help.sml это «F3 - Toggle PLayer ID» — связь с клавишей **гипотеза**)
  при `action_state==7` рисует **`PRESS ACTIVATE TO RESTART`**
  (строка `0x4bc2c8`; условие — `0x493279`..`0x493283`, вывод `0x493283`).
* `player_killed` формирует чат-строку `%s HAS DIED` (`0x4be618`,
  `0x493640`) и постит её текстовым событием `0x4798b0` (`0x4538a6`), затем
  очищает очередь звуковых запросов `0x40c030` (`0x4538c4`).
  Отдельного «похоронного» джингла в коде нет.

## 3. Титры и финал

### 3.1. `SML\CREDITS.SML` — титры на титуле

| шаг | адрес | что |
|---|---|---|
| условие | `0x487d51`, `0x487d63`, `0x487d7e` | `state==1 && pager_state > 0 && frame_submode==0 && pager_state==1` |
| загрузка | `0x487d94` → `0x497310` | `SML\CREDITS.SML` (строка `0x4bd228`); одна dword-ссылка на строку — только здесь |
| буфер | `0x487dba` | `malloc(0x22600)`, ошибки `0x4bcaac`/`0x4bd20c` |
| инициализация | `0x487e0b`..`0x487e1b` | `0x4972f0(0xb0, 800)`, первая страница `0x498600`, `pager_state = 2` |
| отрисовка | `0x485e80` → `0x498820` | окно со скроллом; вызовы из пагерной ветки `0x487e27` и `0x487e42` |
| закрытие | `0x48b4e5`..`0x48b50c` | при `0x498ac0()==1`, `pager==2` и Enter (`0xd`/`0xa4`) → `0x498d40` (освобождение SML-ресурсов) |
| закрытие (меню) | `0x48cf2b`..`0x48cf4a` | выбор пункта: `free(0x67fc0c)`, `0x497600`, `pager_state = 0` |

**Почему «один раз».** В файле `gundx.exe` dword по VA `0x4bc3a8` равен
`01 00 00 00`. Полный перебор ссылок на этот адрес (18 сайтов, все — в
`.text`) даёт:

```
immediate-записи: 0x4834ab=0, 0x48352b=2, 0x487e1b=2, 0x48cf4a=0
через регистр:    0x4834e7, 0x487d73, 0x487db2, 0x487de0
```

Ни одна не пишет 1 (`--self-test` проверяет и список, и значения). Значит
`pager_state==1` бывает только из начального значения файла — то есть титры
грузятся один раз, на первом кадре состояния 1 после интро.

На этом кадре `frame_submode == 0`: это начальное значение BSS, а ни один
писатель `0x83cb7c` в ветке интро не вызывается (единственный вызов
`0x44b85a` идёт из `0x44b830`, а её вызывают только `0x45758f` `END_GAME`,
`0x483488` финал, `0x48d985`/`0x48da3b` меню).

`SML\CREDITS.SML` в поставке есть: 1470 байт, plain-текст (`<d><c>Created by
…`), `SML/credits.sme` — его закодированная копия.

### 3.2. Ветка «winner.sbv + поздравление + чит-коды» (пункт меню 3)

| шаг | адрес | что |
|---|---|---|
| диспетчер | `0x4971e0` | `jmp [eax*4+0x4972cc]`, индекс 3 → `0x4972c1` |
| обработчик | `0x4972c1` → `0x483470` | вызов |
| ролик | `0x483471`/`0x483476` → `0x4913a0("winner")` | `Vid/winner.sbv` (15 343 896 байт, 1820 кадров), музыка `MUSIC/winner.sog` |
| возврат в титул | `0x48347e` | `state = 1`; `0x44b830` — стоп уровня |
| экран | `0x48348d`/`0x483492` → `0x497310("SML\BRIEF\LEVEL0A.SML")` | грузится `LEVEL0A.SME` (загрузчик сам пробует `.SME`, `0x49736e` дописывает `E`) |
| буфер | `0x4834c1` | `malloc(0x22600)`, ошибки `0x4bcad4` («cheats.sml») и `0x4bcaac` |
| готово | `0x48352b` | `pager_state = 2` |

`LEVEL0A.SME` после декодирования (Caesar `-(i%10)`, `docs/UI.md` §3) — это
**не титры**, а экран финала с чит-кодами:

```
CONGRATULATIONS!  You have been named  THE NATAKA  CORPORATE EMPIRE
EMPLOYEE OF THE MONTH!   C H E A T   C O D E S
```

Это единственная «финальная» картинка в игре.

### 3.3. Автоматического показа после `level24` нет

* `level24` — `-8` (`0xf799`) состоит из `IF DEATHMATCH_GAME { NEW_LEVEL "DM1" }`
  и пустого `ELSE`; кампанийных выходов — **0** (`--assets`, `script_scan`).
* Ветка `0x483470` достижима только через VM-опкод **54 `CUSTOM_COMMAND_2`**
  (`docs/VM_EXEC.md`: обработчик `0x45f083`, вызов `0x4971e0` в `0x45f0cb`).
  Перебор всех 36 поставочных `.sbt` (все записи 11, вложенные `IF`):
  `CUSTOM_COMMAND_*` — **0 сайтов**.
* Строка `winner` (`0x4bcb08`) имеет **одну** dword-ссылку (`0x483472`), а
  функция `0x483470` вызывается ровно из **одного** места (`0x4972c1`).
* `SML\CREDITS.SML` (`0x4bd228`) — **одна** ссылка (`0x487d95`, титул).

Отсюда: ни сценарий, ни состояние счётчика не включают финальную ветку.
Проверено и по счётчику: все 15 ссылок на `0x80f9cc` — `inc`/`dec`/`mov`/
`sprintf("LEVEL%ld")`, ближайшие `cmp` рядом с ними сравнивают с 1 или с
регистром, но не с 24/25. Финала «после уровня» в коде нет.

### 3.4. Звук

`FINALE`, `OVERTURE`, `WINNER` — не команды и не скрипты, а три SOU2-сэмпла
в `sounds/SOU.IDX` (1000 записей `name[8]+u32`; проверено `--assets`).
`Vid/winner.sbv` играет `MUSIC/winner.sog`, но в поставке это 8-байтовый
текстовый файл со словом `winner` (`77 69 6e 6e 65 72 0d 0a`), а не банк
данных; сам сэмпл `WINNER` лежит в `sounds/SOU.IDX`.

## 4. Рестарт и возврат в штаб

### 4.1. Меню `RESTART GAME` (state 6)

Строитель `0x488850`; пункты и гейты:

| слот | id-переменная | строка | гейт | обработчик |
|---|---|---|---|---|
| 0 | `0x4bc278` | `Reload last saved game` (`0x4bd44c`) | `[0x4bc274] >= 0` (последний слот) | `0x48d9e9` → `0x442340(slot)` |
| 1 | `0x4bc27c` | `Restart level with same R.P.V.` (`0x4bd42c`) | `[0x836ad0] != 0` | `0x48d9fd` push 0 → `0x4428f0(0)` |
| 2 | `0x4bc280` | `Restart level from HQ` (`0x4bd3fc`) | имя `0x5a48b8` не `LEVEL20`/`SECRT1`/`SECRT2` (`0x4888f6`..`0x488924`) и `[0x818650] != 0` | `0x48da09` push 1 → `0x4428f0(1)` |
| 3 | `0x4bc284` | `Quit to title` (`0x4bd3ec`) | — | `0x48da31` → `state=1` |

### 4.2. `0x4428f0(param)` — что именно сбрасывается

1. `0x44290f`: если `[0x5a4728]==0` (нет уровня) — `submode=0`, ранний выход
   с `-1`.
2. `0x44293c` → `0x451b20`: очистка массивов DM-стартов
   (`0x5a9500`…`0x5a96e8`, блоки по 8 и 16 dword) — разбор уровня.
3. **Счётчик миссий** (только при `param&1`, т.е. «из штаба»):
   `0x442946` `strnicmp(0x5a48b8, "LEVEL0", 6)` — имя последнего *не-штабного*
   уровня; если оно **не** начинается с `LEVEL0` (то есть снимок миссии есть)
   → `dec dword [0x80f9cc]` (`0x44295e`); затем кламп `>= 1`
   (`0x442964`..`0x442973`). Следствие: рестарт из штаба откатывает счётчик
   на одну миссию — и из миссии, и из самого штаба (тогда следующая миссия
   будет той же).
4. **Снимок игрока**:
   * `param&1` → имя уровня `0x5a4868`, структура `0x815440` (снимок штаба,
     `0x442978`..`0x4429a7`);
   * иначе → имя `0x5a48b8`, структура `0x8338c0` (снимок старта миссии,
     `0x4429a9`..`0x4429d8`).
   Копируется **0x3510 байт** — вся структура игрока, включая `cash +0x332c`,
   оружие/патроны/экипировку и шасси.
5. `0x4429f7`/`0x442a35`: если `[0x81c250]==0` (в снимке нет активного игрока) или
   первый байт имени `0x5a47c8` пуст — имя берётся из `0x4ab6d4` (`"LEVEL0"`),
   счётчик = 1 (`0x442a0e`, `0x442a4c`).
6. `0x442a18`..`0x442a2e`: `[0x81c1b8]=0` и обнуление 16 dword с `0x81c1bc`
   — таблица привязок спрайтов (`+0x3178`/`+0x317c`, ср. `docs/SAVE.md` §3).
7. `0x442a56`..`0x442a63`: `[0x83d300] = 4` — подрежим кадра после загрузки
   (обычный уровень). Для `param` 0/1 бит 1 не выставлен, поэтому всегда 4.
8. `0x442a69` → `0x442ef0` — загрузка уровня: `0x5a47c8 → 0x5a4728`,
   `level.sbw/.sbt/.sbc`; при ошибке `submode=0` и возврат `-4`
   (`0x442a72`), иначе `0`.

**Снимки** делаются при загрузке уровня, в хвосте `0x442ef0`
(`0x4435e3`): если имя уровня начинается с `SAVEGAME` — снимок не делается;
если с `LEVEL0` (все штабы) — пишется в `0x815440`/`0x5a4868`
(`0x443621`); иначе — в `0x8338c0`/`0x5a48b8` (`0x443655`). Поэтому
«из штаба» всегда возвращает состояние последнего визита в штаб (с деньгами
и покупками), а «тот же R.P.V.» — состояние на входе в текущую миссию.

### 4.3. Что видит игрок

Экран загрузки и уровень с начала: игрок в стартовой точке, деньги/инвентарь
из соответствующего снимка, счётчик миссий на 1 меньше (при рестарте из
штаба). При рестарте из штаба грузится именно штаб (`0x5a4868`), то есть
игрок оказывается в магазине/армори, а не в миссии.

### 4.4. Возврат в штаб после миссии

* Конец миссии → `-8` → подскрипт грузит **свой** штаб: `level1` →
  `NEW_LEVEL "level00"`, акт 2 → `level000`, акт 3 → `level0a`,
  акт 4 → `level0b` (`docs/CAMPAIGN_FLOW.md` §3, 24/24).
* В штабе предмет `entity 305` вызывает `NEXT_LEVEL [SOURCE_IS_PLAYER]`
  (обработчик `0x457b11`): имя следующего уровня берётся из счётчика, счётчик
  инкрементируется. Это и есть «возврат в штаб → следующая миссия».

## 5. Экран конца уровня

* **Опкод 91** `SHOW_LEVEL_END_SCREEN`, обработчик `0x45c057`
  (`docs/VM_EXEC.md` §опкоды). Опкод 96 — `SET_LEVEL_GRAVITY`
  (`0x45b7db`), к экрану отношения не имеет.
* `0x45c057`:
  * `[0x5a46e4]` (счётчик тиков уровня, 91 Гц) делится на 91 магической
    константой `0xb40b40b5` + `sar 6`; результат — секунды уровня →
    `[0x83d638]` (`0x45c05d`..`0x45c080`). Проверка деления: x=91 → 1,
    x=600 → 6, x=6000 → 65 (это x // 91);
  * `frame_submode = 5` (`0x45c066`);
  * `0x45c880(level_name, seconds)` открывает `GUNMETAL.HI`
    (`0x493630` → строка `0x4be60c`, `fopen` `0x40dae0`), ищет строку с
    именем уровня (буфер имени `0x80f860`, его пишет `SET_LEVEL_NAME`,
    `0x45b753`), при улучшении перезаписывает рекорд; возвращает лучшее
    время → `[0x83d2c0]` (`0x45c08e`).
* Отрисовка (подрежим 5, `0x447748`):
  * один активный игрок (`0x454110` == 0) → `0x483a70`;
  * несколько → `0x483550` (табличный вариант, `TEAM`/`TOTAL`).
* Содержимое одиночного экрана (`0x483a70`..`0x483e30`): фон `levelend`
  (`0x4bcbc8`) / `levelen2` (`0x4bcb54`), подписи и значения:

```
KILLS:            0x4bcbc0   значение 0x442270 (+0x3270 shield_misc)
SECRETS FOUND:    0x4bcbb0   значение 0x442290 (secret_tally +0x33cc),
                            формат "%ld / %ld" 0x4bcb78 (всего 0x80d8c0)
SALVAGE:          0x4bcba4   значение 0x4422b0 (+0x3330; в DM_RULES — salvage)
TIME:             0x4bcb9c   [0x83d638]
BEST TIME:        0x4bcb90   [0x80d88c] — par из SET_LEVEL_BEST_TIME
YOUR BEST:        0x4bcb84   [0x83d2c0] — рекорд из GUNMETAL.HI
PRESS <ключ> TO CONTINUE   0x4bcb6c + 0x4bcb60
```

  Время форматируется `0x483f00`: `%ld : %ld%ld` (`0x4bcbdc`), при нуле —
  `UNKNOWN` (`0x4bcbd4`).

  Списка целей на этом экране нет: цели/секреты в HUD — отдельная панель
  по F6 (`0x499030`, `SECRETS FOUND` `0x4beb10`, счётчик `+0x33cc` и общий
  `0x80d8c0`; `docs/CAMPAIGN_FLOW.md` §5).
* По Activate (`0x445456`) постится `event_post(-8, …)` (`0x4454a2`/`0x4454a4`)
  = `SYSTEM_LEVEL_FINISHED` (`docs/EVENTS.md` §4.1). Дальше — подскрипт `-8`:
  штаб/следующий уровень (§4.4). Меню на этом экране не открывается.
* `level24`: `-8` не имеет кампанийного выхода, поэтому нажатие Activate
  ничего не меняет — игрок остаётся на экране результатов. Выйти можно
  Esc → меню (state 9 → 6) → Quit to title. Это и есть конец кампании.

## 6. Инструмент

```sh
python3 tools/re/gameover.py --self-test   # 120/120
python3 tools/re/gameover.py --fields      # 22 поля: адрес, писатели, читатели, статус
python3 tools/re/gameover.py --flows       # ASCII-диаграмма + таблица переходов

```

`--self-test` без Ghidra и без файлов игры: структурные проверки таблиц и
(если exe найден) сверка 48 байтовых сигнатур, 27 строк, перебор ссылок,
негативные сканы. Без exe байтовые проверки печатаются как `SKIP`, а не
падают. `--assets` дополнительно парсит 36 `.sbt` и печатает число сайтов
`CUSTOM_COMMAND_*` и выходы `-8` у `level24`.

## 7. Гипотезы и остатки

1. **Закрытие титров.** Доказаны два сайта: Enter при `0x498ac0()==1` и
   `pager==2` освобождает SML-ресурсы (`0x498d40`), но сам ключ **не**
   гасится (`0x48b516`..`0x48b525`), то есть, вероятно, проходит и в меню;
   активация пункта меню освобождает буфер и ставит `pager_state=0`
   (`0x48cf2b`..`0x48cf4a`). Как это выглядит на живой игре — не проверено;
   не исключено, что титры висят до первого выбора пункта.
2. **Пропуск `winner.sbv`.** Цикл плеера `0x49e1e8` завершается по
   декодированию/файлу; явной проверки Esc в диапазоне `0x49e1e8..0x49ed60`
   не найдено. Возможен пропуск через WndProc — не проверялось.
3. **Смысл `0x83d620`.** Используется как гейт в `0x443ae0` (`==0`), а
   `==4` пропускает кадр (`0x44c2a2`). Точная семантика (пауза/демо/конец
   уровня) не установлена; для смерти важно только, что при `!=0` меню не
   открывается.
4. **Возможен ли второй показ титров.** Единственные записи значения 1 —
   `mov [0x4bc3a8], ebx` (`0x487d73`/`0x487db4`), и только если `ebx==1`; в
   обычном пути `ebx=0` (`0x48769f`), а в ветке 320×200 (`0x487692`) при
   `pager==0` блок вообще пропускается (`cmp eax,ebx; jle`). Даже если 1
   запишется, загрузка требует `pager==1` и `submode==0`, а при `submode!=0`
   пагер сбрасывается в 0 (`0x487d73`). Второго показа не ожидается; на
   живой игре не проверялось.
5. **Видимость `PRESS ACTIVATE TO RESTART` в одиночной игре.** Надпись
   рисует панель статуса (`0x4926a0`), вызываемая из HUD при
   `[0x5a4908]!=0`. Что это ровно переключатель F3 из `help.sml` —
   **гипотеза**.
6. **`0x4bc3a8` как «запрос титров».** Значение 1 больше нигде не
   выставляется; не исключено, что это остаток вырезанного меню «credits».
7. **`END_GAME`** по-прежнему 0 сайтов (`docs/VM_SCENE.md` §4): кампания
   заканчивается отсутствием перехода, а не командой.
