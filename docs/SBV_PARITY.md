# Паритет C++ ↔ Python для `.sbv` на всём корпусе

Статус: **6 843 / 6 843 кадра декодируются C++-портом в тот же RGB, что и
Python-эталон**. Проверка автоматизирована: `engine/tests/test_sbv_parity.cpp`,
CTest-тест `sbv_parity` с меткой `full`.

Документ дополняет `docs/SBV.md` (§7.2 — выборочная сверка) и не меняет
описание формата. Кодек: `gm/sbv.py` (`decode_frame_rgb`) ↔
`engine/src/res/sbv_video.cpp` (`gm::decode_sbv_frame`).

## 1. Метод

Эталон — Python-декодер, транслитерация `gundx.exe` `0x49ee8c`/`0x49e33b`.
Для каждого кадра клипа:

1. блок вырезается из контейнера по таблице `end_offset`
   (`[data_start + end[i-1], data_start + end[i])`);
2. `gm.sbv.Sbv.decode_frame` → `decode_frame_rgb` даёт упакованный RGB
   (320×160×3 = 153 600 байт, сверху вниз);
3. по буферу считается **FNV-1a 64** (basis `0xcbf29ce484222325`,
   prime `0x100000001b3`);
4. per-frame хеши складываются в **цепочку**: 8 байт хеша (little-endian)
   вливаются в одно продолжающееся состояние FNV. Цепочка фиксирует все
   кадры в порядке воспроизведения одним 64-битным числом, поэтому в тест
   не нужно коммитить манифест на 6 843 строки;
5. дополнительно запоминаются 6 опорных кадров на клип (первый, второй,
   четверть, середина, три четверти, последний): индекс, размер блока, хеш.

Генератор манифеста — временный, в репозиторий не входит:

```
cd /tmp/opencode/wt-sbv-parity
JOBS=28 python3 /tmp/opencode/sbv_fnv_gen.py
# -> /tmp/opencode/sbv_fnv_manifest.json (все 6 843 per-frame хешей, локально)
# -> /tmp/opencode/sbv_fnv_aggregates.json (агрегаты, из него взяты константы)
```

Python-прогон всех трёх клипов на 28 процессах — **91.9 s**.

Общая цепочка — продолжение той же FNV через клипы в порядке

каждого клипа (смещения покрывают данные без дыр и хвостов).

## 4. Что проверяет C++-тест

`engine/tests/test_sbv_parity.cpp` (собирается как `gm_sbv_parity_tests`,
CTest `sbv_parity`, метка `full`):

* контейнер: `SBV0`, 320×160, `frame_count`, размер файла, `data_start =
  16 + 8*frames`, `sbv_offsets_valid`, монотонность `end_offset`;
* каждый блок: `begin ≤ end ≤ filesize`, ненулевой размер в границах
  клипа, сумма блоков + `data_start` = размер файла;
* декодирование **всех** 6 843 кадров: успех, размеры 320×160,
  `rgb.size() == 153 600`, per-frame FNV, per-clip цепочка, 6 опорных
  кадров, общая цепочка;
* повторный прогон в **обратном порядке**: per-frame хеш обязан совпасть
  (кадры внутрикадровые — ни порядок, ни повтор не влияют);
* негативный случай: блок, обрезанный до 0/4/12/100/1000/1500 байт,
  отвергается. Внутренний `PlaneMemory` отмечает любое обращение за
  границу плоскости, и `decode_sbv_frame` возвращает `nullopt`, поэтому
  успешный проход по всему корпусу — это и есть доказательство отсутствия
  OOB;
* Python в runtime не требуется: все эталоны — константы в тесте.

## 5. Прогон

```
export PATH=$HOME/tools/cmake-4.4.4-linux-x86_64/bin:$HOME/tools/bin:$PATH
cmake --build build/sandbox --target gm_sbv_parity_tests -j 32
ctest --test-dir build/sandbox -R sbv_parity --output-on-failure
```

`build/sandbox` — Debug (`zigcxx`, без оптимизации). Два прохода по корпусу
(вперёд + назад): Intro ≈ 16.1 s, orient ≈ 149.8 s, winner ≈ 59.9 s, итого
**≈ 3m46s** на 32-ядерной машине; декодирование доминирует, второй проход
удваивает время. Поэтому тест помечен `full` и не попадает в `-L quick`.

## 6. Расхождения

Для декодера их **нет**: 0 расхождений по 6 843 кадрам, 0 ошибок разбора,
0 обращений за границы плоскостей, повторный проход побитово совпал.
Единственное содержательное отличие от игры — гамма (см. ниже): и Python,
и C++ возвращают «естественный» RGB, а не экранный.

## 7. Остаток

* **Энкодер** (`gm/sbv.py:encode_frame`) остаётся только в Python; C++-порта
  нет. Байтового паритета с оригинальным компрессором не будет в принципе:
  выбор классов/экспонент не восстанавливается из кадра (см. `docs/SBV.md`
  §5, §8).
* **Гамма**: таблицы `0x4a6a40`/… не применяются ни в Python, ни в C++.
  Если понадобится цвет «как в игре», это отдельный слой после
  `planes_to_rgb`, и его придётся сверять с эмуляцией, а не с текущими
  хешами.
* **Геометрия**: тест пинует только поставочные 320×160. Кадры с высотой
  не кратной 32 остаются неопределёнными в декодере (см. `docs/SBV.md`
  §8) — в поставке таких нет.
* C++ не портирован для `build`/`rebuild` контейнера; пересборка — Python.
