# Gunmetal — двери и лифты в коллизии рантайма

Пункт roadmap: **M6.4.1, срез 2** (интеграция). Срез 1 — кинематические панели
(`docs/MOVING_COLLIDERS.md`, `world/moving_collider.*`); этот срез подключает их к
`CollisionWorld` и к тику `GameRuntime`, чтобы закрытая дверь **держала** игрока,
ИИ, лучи и снаряды, а открытая — пропускала.

Тест: `engine/tests/test_door_collision.cpp`, CTest `door_collision`, label
`quick`. Сборка: `build/sandbox`, `zig`-тулчейн, Debug.

---

## 0. Коротко

| что | значение |
|---|---|
| статический набор | `CollisionWorld::triangles()` — как был: `.sbw` в закрытой позе, `triangle_count()`/`stats()` не меняются |
| динамический набор | `CollisionWorld::set_dynamic(triangles, suppressed)` |
| исключение статики | список `(sector, object)`; запросы пропускают статические треугольники этих пар, сами треугольники остаются в `triangles()` |
| источник динамики | `MovingCollider` на каждую движущуюся скользящую дверь: rest-треугольники её `(sector, object)` + `Door::open - Door::closed` |
| пересборка | только когда `motion_fraction()` какой-то двери изменился; в тике — фаза 4a (`sync_door_colliders`) |
| распашные двери | остаются статикой (`DoorAxis::Rotating`), §6 |
| лифт | `lift_offset = 0`: привязки «лифт → объект `.sbw`» в модели нет, §6 |
| фильтры/нормали | те же, что у статики: `CollideFilter`, `surface_of(data_normal)`, двусторонне, нормаль против запроса |
| broad-phase динамики | общий AABB набора + блоки по 32 треугольника (`kDynamicChunk`), подавление — байтовая маска по статическим треугольникам |
| пустая динамика | побитовый паритет со старым `CollisionWorld` (все прежние тесты зелёные без правки пиннингов) |
| числа | §5, стоимость — §6.3 |

## 1. Что подключено

### 1.1. `CollisionWorld` (`render/collide.h/.cpp`)

```cpp
bool set_dynamic(std::vector<Triangle> triangles,
                 std::vector<std::pair<std::uint32_t, std::uint32_t>> suppressed = {},
                 std::string* error = nullptr);
void clear_dynamic();

const std::vector<Triangle>& dynamic_triangles() const;
std::size_t dynamic_triangle_count() const;
const Aabb& dynamic_bounds() const;
const std::vector<std::pair<std::uint32_t, std::uint32_t>>& suppressed() const;
std::size_t suppressed_count() const;
bool is_suppressed(std::uint32_t sector, std::uint32_t object) const;
```

* `set_dynamic` **заменяет** динамический набор и список исключений целиком;
  замены атомарны: отказ (см. §4) оставляет прежний набор и прежний список.
* `raycast`/`sphere_cast`/`floor_at` перебирают сначала статику (пропуская
  подавленные пары), затем динамику. Порядок «статика, потом динамика» и
  правило «при точном равенстве `t` побеждает первый треугольник» сохранены:
  статика выигрывает ничью у динамики.
* `RayHit`/`SphereHit` получили `bool dynamic`; `triangle_index` — индекс в
  `triangles()` для статического попадания и в `dynamic_triangles()` для
  динамического. `triangle` — указатель внутрь соответствующего массива
  (живёт, пока жив мир и не вызван следующий `set_dynamic`).
* `triangle_count()` по-прежнему считает **только статику**; динамика —
  `dynamic_triangle_count()`. `stats()`/`bounds()` описывают сборку уровня и
  не меняются. `overlap_aabb` остаётся статическим (его индексы однозначны
  только для статики), но подавленные пары тоже пропускает.
* `clear()` (и `build()`) сбрасывают динамику: мир после пересборки уровня
  снова чисто статический.

### 1.2. `GameRuntime` (`game/runtime.h/.cpp`)

```cpp
bool sync_door_colliders();                       // переложить текущие позы
bool rebuild_door_colliders(std::string* error);  // пересобрать панели с нуля
const DoorCollisionStats& door_collision() const;
```

* `build_world()` собирает панели **до** подмены `world_`/`collision_`
  (временные объекты), поэтому отклонённый уровень не оставляет
  полупостроенный динамический набор. Одна панель = одна движущаяся
  скользящая дверь (один `MovingCollider` на панель; панели объединяются в
  один `set_dynamic`).
* Порядок треугольника в динамике — порядок панелей (порядок `doors()`), внутри
  панели — порядок `CollisionWorld::triangles()`; количество совпадает с числом
  статических треугольников этой пары.
* `tick_once()`: фаза 4 (`WorldState::tick`) → фаза 4a `sync_door_colliders()` →
  фаза 5 (события). Т.е. в пределах тика двери двигаются раньше, чем
  публикуется новая поза; игрок/ИИ/снаряды, шагающие в следующем тике или
  после него, видят уже новую позу.
* `DoorCollisionStats`: `doors`, `panels`, `triangles`, `suppressed`,
  `static_triangles`, `skipped_rotating`, `skipped_static`,
  `skipped_duplicate`, `skipped_unbound`, `skipped_refused`, `rebuilds`
  (`set_dynamic` за всё время, включая сборку — их ровно 1), `failed_rebuilds`,
  `sync_ticks`.

### 1.3. Какие двери становятся динамикой

Панель строится, если `Door::active()` (`kind` 1..3), `sector`/`object` >= 0,
`door_axis(door) != Rotating`, `open != closed`, и у пары есть треугольники в
`CollisionWorld`. Остальные считаются в `skipped_*`:

| случай | счётчик |
|---|---|
| распашная (`A1..A3` != 0) | `skipped_rotating` (остаётся статикой) |
| `open == closed` | `skipped_static` (rest-поза и есть конечная) |
| вторая дверь на ту же пару | `skipped_duplicate` (панелью владеет первая) |
| пара без треугольников / `object < 0` | `skipped_unbound` |
| `MovingCollider` отказал (NaN и т.п.) | `skipped_refused` |

## 2. Как исключаются статические треугольники

`CollisionWorld` не удаляет и не двигает статические треугольники: он лишь
пропускает их в запросах, если пара `(sector, object)` есть в списке
подавления. Причины:

1. **Паритет и обратимость.** `triangles()`/`triangle_count()`/`stats()` —
   контракт для рендера, тестов и инструментов; «вырезание» меняло бы индексы
   и ломало пиннинги. Пустой список подавления + пустая динамика возвращают
   ровно прежнее поведение (это проверяется побайтово: `t`, `triangle_index` и
   `point` совпадают).
2. **Атомарность.** `set_dynamic` может быть отклонён (§4) — при хранении
   «вырезанных» треугольников откат был бы дороже.
3. **Дешёвая проверка.** Список — единицы–десятки пар; проверка идёт только
   когда список непуст (`if (!suppressed_.empty() && ...)`), поэтому на мира
   без динамики она не выполняется вовсе.

Подавление — по паре, а не по индексу: `CollisionWorld` не хранит «индекс
объекта», а `(sector, object)` уже есть в каждом треугольнике и в `Door`.

Замечание: подавление **без** динамической панели оставляет дыру (створки нет
ни там, ни там). Это осознанное поведение `CollisionWorld` (он не знает, кто и
зачем подавляет), и рантайм его не создаёт: пара попадает в список только
вместе с непустой панелью.

## 3. Когда пересобирается динамика

`sync_door_colliders()`:

1. `++stats.sync_ticks`;
2. для каждой панели сравнивает `doors()[i].motion_fraction()` с последней
   **применённой** долей (`MovingCollider::open_fraction()`, не запрошенной —
   отклонённый `update` не повторяется вечно);
3. если ни одна доля не изменилась — выходит, **не трогая** ни коллайдеры, ни
   `set_dynamic` (покой = ноль пересборок за тик);
4. иначе перекладывает изменившиеся панели и один раз вызывает
   `set_dynamic` (все панели вместе), `++stats.rebuilds`.

`motion_fraction()` — `min(phase, 0xffff) / 65535` (docs/DOORS_CPP.md), т.е. ровно
то, чем движок интерполирует створку (`0x44dfc0`). Сравнение точное (`double`
из целого слова фазы), поэтому «дребезга» нет: пока фаза стоит, пересборок нет.

Ручные вызовы:

* `sync_door_colliders()` — опубликовать позу после того, как вызывающий сам
  подвинул дверь (`world().doors_mutable()`, восстановление сейва) без тика;
* `rebuild_door_colliders()` — пересобрать список панелей (сменилась привязка
  `(sector, object)`, добавились/убрались двери). Тоже атомарно.

## 4. Отказы и негативы

| вход | поведение |
|---|---|
| NaN/inf вершина/нормаль/центроид динамического треугольника | `set_dynamic` → `false`, `error` с номером треугольника; прежний набор и список живут |
| вершина за `kCollideMaxCoordinate` (1e9) | то же |
| пустой `bounds`/нулевая нормаль у переданного треугольника | поля достраиваются из вершин (`bounds`, `normal`, `plane_offset`, `centroid`) — можно передать «голый» `Triangle{a,b,c}` |
| `set_dynamic({}, {})` | статический мир, побитово прежние попадания |
| `set_dynamic({}, {pair})` | дыра на месте пары (см. §2); рантайм так не делает |
| дверь без геометрии | `skipped_unbound`, панели нет, тик не ломается |
| распашная дверь | `skipped_rotating`, остаётся статикой, тик не ломается |
| `sync_door_colliders()` без мира/панелей | `false`, счётчики не растут (кроме `sync_ticks`) |

Тест проверяет: NaN-вершину, вершину `1e12`, «голый» треугольник, пустой набор,
подавление без панели, дверь, перепривязанную на несуществующий объект
(`sector = 9999` → `skipped_unbound`, `dynamic` 422 → 416, тик `ok`).

## 6. Ограничения (и почему)

1. **Распашные двери статичны.** `DoorAxis::Rotating` (357 поставочных дверей,
   из них 113 движутся) не описывается переносом: створка поворачивается
   вокруг `center` (`0x434887`). `MovingCollider` такие панели не принимает,
   рантайм считает их в `skipped_rotating` и оставляет статику как есть — т.е.
   распашная дверь всегда стоит в закрытой позе, но **не исчезает** и не
   «телепортируется». Это записано и в `docs/MOVING_COLLIDERS.md` §6.
2. **Лифт без привязки.** `lift_offset` панели всегда `0`. В модели нет
   отображения «лифт → объект `.sbw`»: `Lift::sob` — индекс SOB-модели, а не
   объект уровня (docs/MOVING_COLLIDERS.md §2.2). `MovingCollider::update`
   принимает знаковый `lift_offset`, и когда привязка появится, кабина
   подключится одной строкой (`update(fraction, lift_offset)`), без изменения
   `CollisionWorld`.
3. **Broad-phase динамики — коарс, не секторный.** Динамический набор не имеет
   секторной сетки (панель выезжает из своего сектора), поэтому у него свой
   дешёвый индекс:
   * общий AABB набора — одна отсечка на запрос;
   * блоки по `kDynamicChunk = 32` треугольника со своим AABB; луч/сфера
     тестирует блоки, треугольники берутся только из пересечённых блоков;
   * обратные компоненты направления считаются один раз на запрос
     (`RaySlab`), а не на каждый блок;
   * подавление статики — байтовая маска на статический треугольник
     (`suppressed_triangles_`), а не поиск по списку пар: без неё запрос в
     секторе с дверью платил бинарный поиск за каждый треугольник (замер:
     `--sim level23 --ticks 100` в Debug 8.50 с с поиском по парам против
     5.22 с маской; базовый `master` — 4.67 с).
   Статический цикл намеренно дублирует тело кандидата вместо лямбды: Debug
   собирается в `-O0`, и вызов на каждый треугольник был бы заметен на
   десятках тысяч кастов в тик. Дублирование помечено в коде; порядок клауз и
   эпсилоны обязаны совпадать.

   Замеры (Debug+UBSan, `level23`, 100 тиков, 80 дверей / 1762 динамических
   треугольника): `master` 4.67 с, с интеграцией 5.22 с (+12 %). Стоимость
   самого `sync_door_colliders` в покое — 80 сравнений `double` на тик, без
   единой пересборки (`rebuilds` остаётся 1); при движении двери — одна
   пересборка на тик (копия ≤ 1762 треугольников + маска не пересобирается,
   список пар не менялся).
4. **`overlap_aabb` — только статика.** Его результат — индексы в
   `triangles()`; смешивать с динамикой значило бы ввести неоднозначный
   индекс. Подавленные пары он пропускает. Если понадобится overlap по
   дверям, нужен отдельный API с флагом `dynamic`.
5. **ИИ, снаряды и прицел используют тот же `CollisionWorld`.** `Ai::tick`,
   `Projectiles::tick_results`, `hitscan`, `aim_switch` и `SimPlayer` получают
   `const CollisionWorld&`, поэтому динамика видна им без отдельного кода — это
   следствие §1.1, а не отдельная интеграция.
6. **Двусторонняя коллизия C++ и настоящие проёмы.** `CollisionWorld` по
   построению двусторонний (docs/COLLIDE.md §3): стена держит с обеих сторон.
   В поставочных уровнях стены секторов односторонние (лицом внутрь комнаты), и
   проём двери часто закрыт **обратной** стороной стены соседнего сектора;
   оригинал такие грани не тестирует, C++ — тестирует. Поэтому:
   * `level0`, створка `sec=4 obj=1` заперта в замкнутой раме `sec=4 obj=0`
     (грани рамы в 4 единицах от створки): сквозь неё нельзя пройти ни
     закрытой, ни открытой, и «открытая пропускает» показана на **тех же
     настоящих треугольниках створки** в мире из одного объекта (та же
     `CollisionWorld::build`, тот же `set_dynamic`, тот же `gm::step`);
   * `dm1`, створка `sec=17 obj=37`: закрытая держит игрока (8010), открытая
     пропускает его сквозь всю толщину створки, и останавливает статическая
     стена `sec=17 obj=35` (8002). Это стена уровня, не дверь.
   
   Односторонний режим уже есть в фильтре (`CollideFilter::backfaces = false`),
   но контроллер игрока фильтр не принимает; это отдельная задача (проверка
   секторной видимости/порталов), а не интеграция двери.
7. **Порядок «игрок → тик».** `SimPlayer::tick` делает `gm::step` **до**
   `runtime.tick(1)` (срез 1: контроллер не тикает рантайм). Значит, при
   движущейся двери поза, которую видит шаг игрока, отстаёт на один тик
   (≤ 1.7 единицы при типовой скорости створки). В покое и после явного
   `sync_door_colliders()` поза точная. Порядок не менялся, чтобы не трогать
   детерминизм и пиннинги `sim_player`.
8. **Две двери на один объект.** Панелью владеет первая; вторая учитывается в
   `skipped_duplicate`. Поставка таких пар не содержит (`regress.py`: у 1779
   дверей 1779 различных `(sector, object)`), но модель обязана быть
   определённой.

## 7. Как проверить

```sh
export PATH=$HOME/tools/cmake-4.4.4-linux-x86_64/bin:$HOME/tools/bin:$PATH
cmake --build build/sandbox -j
ctest --test-dir build/sandbox -R door_collision --output-on-failure
./build/sandbox/engine/tests/gm_door_collision_tests        # числа §5
ctest --test-dir build/sandbox -j 4                         # всё дерево
python3 regress.py --mirror --json                          # оракул
```

Паритет «пустая динамика = старый мир» проверяется не только тестом §5.1, но и
тем, что `collide`, `player_controller`, `moving_collider`, `sim_player` и
`thing_motion` проходят без изменения своих пиннингов.
