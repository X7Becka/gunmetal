# Рендер экрана 15, ввод имени сейва (`engine/src/ui/save_name_render.h`)

Срез 13 пункта `M8.8`: один кадр экрана **15** фронтенда (`gundx.exe`,
ImageBase `0x400000`) в RGBA-буфер 320×200. Модуль без состояния — рисует то,
что ему передали в `SaveNameRenderOptions` (буфер имени `0x661280` и окно-строку
`[0x68ccf4]`), и отдаёт числа (`rows`, `chars`, `truncated`, `ink_pixels`,
`missing_glyphs`, `arrows`, `fileslot_bands`). Шрифты и метрики — из
`render/text_layout` (`FONTS4` в `FRONTEND/BMP.IDX`), точный fade — из
`render/hud_lut`, плата и полоса слота — те же `PLATE`/`FILESLOT`, что у
экрана 14. Ничего не измеряется заново.

Код: `engine/src/ui/save_name_render.h/.cpp`; тест —
`engine/tests/test_save_name_render.cpp` (CTest `save_name_render`, label
`quick`). Соседние срезы и опоры: `SAVE_MENU_RENDER.md` (экран 14, откуда
приходят; те же `PLATE`, `FILESLOT`, `MENUARRW` и `0x485dd0`), `SAVE_MENU.md`
(список слотов), `UI_SCREENS.md` §2/§3/§5.2 (карта и ввод), `SAVE.md` §1.1
(имя в заголовке сейва), `SAVE_WRITE_CPP.md` (писатель `0x4422d0` вне среза).

## 1. API

```cpp
#include "ui/save_name_render.h"

gm::SaveNameRenderOptions options;    // name = "A SAVED GAME", caret = true, row = 0
options.name = "MY SAVE";             // текст буфера БЕЗ каретки (17 символов max)
options.caret = true;                 // дорисовать хвостовой '-' (0x48b6d1)
options.row = 2;                      // [0x68ccf4]: строка окна 0..5 (клампится)
options.background = "PLATE";         // "" = чёрный холст
options.fileslot = true;              // полоса FILESLOT под строкой (умолчание)

std::vector<std::uint32_t> rgba;      // 0xRRGGBBAA, 320*200
int width = 0, height = 0;
gm::SaveNameRenderStats stats;
std::string error;
if (!gm::render_save_name(game, options, rgba, width, height, &stats, &error))
    // error начинается с "save_name_render: "

gm::save_name_buffer(options);        // "MY SAVE-" — ровно то, что рисуется
gm::save_name_text_y(2);              // 52  (28 + 12*row)
gm::save_name_band_y(2);              // 51  (27 + 12*row)
```

`render_save_name` при отказе очищает `rgba`, ставит `width = height = 0` и
обнуляет `*stats`; `stats`/`error` могут быть `nullptr`. Запись в установку не
происходит: каталог игры только читается.

## 2. Доказано (листинг `gundx.exe`, данные `FRONTEND/BMP.IDX`)

### 2.1. У экрана нет своего обработчика отрисовки, но кадр он рисует сам

`UI_SCREENS.md` §2 ставит экрану 15 «handler —», `rows 1`, `step 0`. Это верно
для таблицы диспетчера, но кадр всё равно рисуется: ввод и отрисовка лежат в
одной функции `0x48b4d0` (`sub esp,8` в `0x48b4d0`, `ret` в `0x48b876`), и её
ветка состояния 15 — `cmp ebp,0xf` в `0x48b691` / `jne 0x48b877` — в конце
каждого прохода делает три вызова:

| сайт | вызов | что видно |
|---|---|---|
| `0x48b816` | `0x48abd0` | кадр экрана 14: копия `PLATE` (`0x486050`), стрелки `MENUARRW`, заголовок `SAVE GAME` (шрифт 5, центр, y 14), шесть строк слотов, `ESC TO CANCEL` (шрифт 0, x 38, y 101) |
| `0x48b840` | `0x48ab90` | полоса `FILESLOT` 124×10 в `0x687aca + c*0x930` |
| `0x48b867` | `0x485dd0` | буфер `0x661280`: x 42, `row = -0x1c - 12*c`, шрифт 0 → **4** |

`0x48abd0` пишет `0x67f10c = 6` (`0x48abd3`) и `0x662d58 = 0xc` (`0x48abdd`),
но все его вызовы (и вызов строки ввода) передают **отрицательный** `row`,
поэтому шаг `item*step` на этом экране не используется, а карта записывает
1/0: своих immediate-записей у ветки 15 нет.

### 2.2. Заголовок и подсказки

* `SAVE GAME` — строка `0x4bdc2c`, пушится в `0x48ac2e`; шрифт `5`
  (`0x48ac33`), `centered = 1` (`0x48ac2c`), `x = 0x26` (`0x48ac2a`,
  игнорируется центрированием), `row = 0xe` → `y = 14` (`0x48ac28`),
  `item = -1` (`0x48ac26`).
* `ESC TO CANCEL` — `0x4bd9d8`, `push 0x26` (x 38) `0x48acab`, `push 0x65`
  (y 101) `0x48acaa`, `centered = 0`, шрифт `0` (`0x48acb4`), `item = -1`.
* Отдельной подсказки `Enter` в кадре **нет**: Enter (`0xd`/`0xa4`) обрабатывает
  только код (`0x48b74c`..`0x48b801`).

### 2.3. Строка ввода

| факт | значение | источник |
|---|---|---|
| x | **42** | `push 0x2a` в `0x48b85c` |
| y | **28 + 12·c** | `mov ecx,0xffffffe4` / `sub ecx,eax`, `eax = 12*c` (`0x48b84d`..`0x48b859`) |
| `c` | `[0x68ccf4]`, строка окна 0..5 | `mov eax,ds:0x68ccf4` (`0x48b845`), `0x48abd0` рисует шесть строк при `c = 0..5` |
| шрифт | **4** (принудительно) | `0x485dd0`: `cmp ecx,[0x68ccf4]` + `test esi,esi` → `mov esi,4` (`0x485e0d`..`0x485e19`); вызов передаёт `font = 0`, `item = c` |
| текст | байты `0x661280` как есть | `push 0x661280` (`0x48b860`) |
| полоса | `FILESLOT` 124×10 в **(38, 27 + 12·c)** | `0x687aca + c*0x930`, `0x687aca − 0x6865f8 = 0x14d2 = 27*196 + 38`, `0x930 = 12*196` (`0x48b839`); `0x48ab90` = 10 строк по 124 Б из `0x661298` шагом `0x7c` в плату шагом `0xc4` |
| порядок | полоса, затем текст | `call 0x48ab90` (`0x48b840`) до `call 0x485dd0` (`0x48b867`) — имя лежит на полосе |
| клип | 196×131 | текст пишется в копию `PLATE` `0x6865f8` (`0x486050`) |

Ориентация полосы: `0x47efe0` читает пиксели BMP «как есть» (`fread`
`width*height`), `0x484cc0` копирует строки вперёд, поэтому строка экрана `r` —
это *файловая* строка `r`; `parse_bmp` отдаёт строки сверху вниз, значит в
рендере `source_row = height - 1 - r` (та же логика, что в
`SAVE_MENU_RENDER.md` §1).

### 2.4. Буфер и каретка

* Буфер — `0x661280`, NUL-терминированный, не длиннее **18** байт:
  `cmp ecx,0x12` / `jge` в `0x48b6c2` отбрасывает 19-й байт. Значит имя — до
  **17** символов **плюс** каретка (`stats.chars` = длина буфера, максимум 18).
* Вход в 15 (`0x48e0e7`/`0x48e0fb`, `0x48e15a` пишет `0x4bc440 = 0xf`):
  пустой слот → `-` (`0x4bdd28`), занятый → `"%s-"` (`0x4bdd24`) от имени
  слота.
* Ввод принимает только `A-Z`, `0-9`, пробел (`0x48b6a9`..`0x48b6c0`), пишет
  символ **поверх** каретки и снова дописывает `-` (`0x48b6cb`/`0x48b6d1`);
  Backspace/стрелки (`0x8`/`0xab`/`0x9b`) сдвигают каретку влево (`0x48b803`);
  Esc (`0x1b`) возвращает в 14 и восстанавливает имя слота (`0x48b710`);
  Enter/`0xa4` срезает каретку (`0x48b75f`) или, если в буфере только она,
  подставляет `A SAVED GAME` (`0x4bdd44`, `0x48b768`), после чего пишет слот и
  файл (`0x4422d0`) и ставит кулдаун `0x4bc3dc = tick + 0x12c`.
* **Каретка — это литеральный `'-'` (0x2d) в конце буфера**, а не спрайт и не
  мигание: в `0x48b691`..`0x48b876` нет ни таймера, ни флага; `-` рисуется тем
  же шрифтом 4, что и остальной буфер. Поэтому в API нет позиции каретки —
  только `bool caret`, и тест доказывает, что кадр меняется ровно на пиксели
  глифа `-` (5 px).

### 2.5. Ассеты (данные `FRONTEND/BMP.IDX`)

| ассет | размер | роль | проверка |
|---|---|---|---|
| `PLATE` | 196×131 | кадр/клип, копия `0x486050` | размер в тесте, палитра в `SAVE_MENU_RENDER.md` §1 |
| `FILESLOT` | 124×10 | полоса строки ввода | размер и файловый порядок строк в тесте |
| `FONTS4` | атлас | лица 5/0/4 | `render/text_layout`, `missing_glyphs == 0` на умолчании |

Все три обязательны: без `PLATE` у кадра нет буфера, без `FILESLOT` — полосы
строки (ветка вызывает `0x48ab90` безусловно), без `FONTS4` — текста. Любой
пропуск — текст `save_name_render: ...`, а не молча чёрный кадр.

## 3. Модель (что добавлено и что нет)

| факт | статус |
|---|---|
| заголовок кадра — `SAVE GAME` (`0x4bdc2c`), шрифт 5, центр, y 14 | proven: `0x48ac26`..`0x48ac35` |
| `ESC TO CANCEL` в (38, 101), шрифт 0 | proven: `0x48ac9e`..`0x48acc4` |
| строка ввода (42, 28 + 12·c), шрифт 4 | proven: `0x48b845`..`0x48b867` + `0x485e19` |
| полоса `FILESLOT` (38, 27 + 12·c) под текстом | proven: `0x48b840`, `0x48ab90` |
| буфер ≤ 18 байт, имя ≤ 17 символов | proven: `cmp ecx,0x12` |
| каретка = хвостовой `-`, без мигания | proven: `0x48b6d1`, отсутствие таймера в ветке |
| умолчание имени `A SAVED GAME` | proven: `0x4bdd44` (`0x48b768`) |
| цвета: 5 → (155,15,15), 0 → (19,15,15), 4 → (239,239,239) | proven палитрой атласа (как `MENU_RENDER.md` §3) |
| заголовок центрируется по 196 px, `x` из вызова игнорируется | proven: `0x485de2`..`0x485dfa` |
| **шесть строк слотов и стрелки** `MENUARRW` | **не рисуются**: это кадр `ui/save_menu_render`; ветка 15 их только вызывает через `0x48abd0`, а таблица слотов `0x6c2fe0` — вне API этого модуля |
| `row` вне 0..5 клампится; имя длиннее 17 символов обрезается | **модель**: оригинал таких значений не получает |
| `background = "PLATE"` | **модель раскладки**: где движок кладёт 196×131 в 320×200, в коде не доказано (как в `MENU_RENDER.md` §2); по умолчанию чёрный холст |
| текст поверх полосы | proven порядком вызовов; но в оригинале под строкой ещё лежит имя слота из `0x48abd0`, и его хвост правее x = 161 может выглядеть из-под полосы. Модуль это не воспроизводит (нет таблицы слотов) |

## 4. Числа (поставочная установка, тест `save_name_render`)

`gm_save_name_render_tests`: **302 проверки**, зелёный. Кадр по умолчанию
(`name = "A SAVED GAME"`, `caret = true`, `row = 0`, `fileslot = true`):

```
save_name frame: rows=1 chars=13 ink=544 (title 157 + ESC 185 + input 202) missing=0 arrows=0 bars=1
save_name bands: title y=14 x=70 bbox (70,14)-(123,20) 54x7, 157 px;
                 input y=28 x=42 bbox (42,28)-(117,34) 76x7, 202 px;
                 ESC y=101 x=38 bbox (38,101)-(109,107) 72x7, 185 px
save_name names: "A SAVED GAME" (13 chars, ink 544) vs "GUNMETAL" (9 chars, ink 488): diff=244 px
save_name cut:   30 chars -> chars=18 truncated=13 ink=642, diff vs 17-char prefix=0 px
save_name caret: '-' at x=54 y=28 ink=5, caret on/off diff=5 px, bbox (54,31)-(58,31)
save_name rows:  row 0 y=28 vs row 3 y=64 diff=2480 px
save_name fileslot: 124x10 at (38,27), 1094 bar px under the glyphs,
                    with/without diff=1094 px, ink 488 unchanged
save_name plate: 196x131 decoded, black vs PLATE diff=24094 px, text ink 414 unchanged
save_name minimal archive (FONTS4+PLATE+FILESLOT): rows=1 chars=4 ink=399 missing=0 bars=1
fade: level 11 vs no fade: 0/64000 px differ; adjacent 12..15 diffs 17571/23767/20575;
      vs 11: 16840/25152/25391/25560
```

Что это значит:

* `title x = 70` = `(196 − 54)/2` по метрикам лица 5; bbox заголовка 54×7.
* строка ввода `"A SAVED GAME-"`: 13 байт, ink 202, bbox 76×7 на (42, 28).
* смена имени меняет только строку ввода (вне 28..35 — 0 отличий), 244 px.
* 30-символьное имя даёт 18 байт буфера и 13 отброшенных; кадр **побайтово**
  равен кадру 17-символьного префикса (0 отличий).
* каретка добавляет ровно 5 пикселей глифа `-` (bbox (54,31)-(58,31)) — это и
  есть доказательство «каретка = хвостовой дефис».
* `row = 3` двигает полосу и строку (2480 px различий), всё остальное — 0.
* полоса: 124×10 в (38, 27), 1094 пикселя под глифами совпадают с независимым
  декодом в файловом порядке строк; `fileslot = false` убирает ровно 1094 px.
* `PLATE` совпадает с независимым декодом под текстом, вне 196×131 — чёрно;
  ink не меняется.
* fade 11 — побайтовое тождество (0/64000); 12..15 — четыре разных кадра.

## 5. Ограничения

* **Нет ввода**: клавиатурный опрос `0x498ac0`, фильтр `A-Z`/`0-9`/пробел,
  Backspace/стрелки, Esc → 14 (`0x48b710`), Enter → писатель `0x4422d0`
  (`0x48b7e2`) и кулдаун `0x4bc3dc` не реализованы. Модуль только рисует
  переданный буфер.
* **Нет файлов сейвов**: таблица слотов `0x6c2fe0`, чтение имени `0x455d90`,
  запись `saved<N>.sbt`/`.sbw` — это `ui/save_menu`, `ui/save_slots`,
  `res/save` и `game/save_action`; здесь ничего не пишется и не читается,
  кроме `FRONTEND/BMP.IDX`.
* **Нет шести строк слотов, стрелок и списка**: кадр экрана 14 — отдельный
  модуль `ui/save_menu_render`; этот рисует одну строку ввода, заголовок и
  `ESC TO CANCEL`. `stats.arrows` поэтому всегда 0 (у самой ветки 15 вызова
  `MENUARRW` нет).
* **CLI — есть (срез 15), звука нет.** `--save-name [--save-name-text NAME]
  [--save-name-row N] [--save-name-no-caret] [--no-fileslot] [--no-plate]
  [--png OUT] [--fade-lut N]`: по умолчанию
  `save_name: rows=1 chars=13 truncated=0 row=0 ink=544 missing=0 arrows=0
  bars=1`; 30-символьное имя в строке 3 — `chars=18 truncated=7 ink=570`;
  без каретки — `chars=12 ink=539`. CTest `cli_save_name`, `_long`,
  `_no_caret`; `cli_fade_lut` (11 = без fade). Звуки интерфейса
  (`docs/UI_SOUNDS.md`) не моделируются.
* **Нет мигания каретки** — его нет и в оригинале (см. §2.4).
* Известный квирк оригинала не воспроизведён: под строкой ввода остаётся имя
  слота, нарисованное `0x48abd0`; его хвост правее полосы (x > 161) может быть
  виден, если имя слота длиннее ~16 символов. Для этого нужна таблица слотов,
  которой у модуля нет.

## 6. Проверка

```sh
cmake --build build/sandbox --target gm_save_name_render_tests -j 4
./build/sandbox/engine/tests/gm_save_name_render_tests
ctest --test-dir build/sandbox -R '^save_name_render$' --output-on-failure
python3 regress.py --mirror --json
```

Тест печатает все числа §4; пиксельная часть пропускается с чистым сообщением
`save_name_render: game not installed, pixel runs skipped`, если установки нет
(модельные проверки и негативы без игры всё равно идут).
