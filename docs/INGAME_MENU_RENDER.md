# Рендер экрана 9, in-game (кадр `DEMOTION`/`DISBAND`)

(`engine/src/ui/ingame_menu_render.h`)

Срез 12 пункта `M8.8`: один кадр **экрана 9** фронтенда (`gundx.exe`, ImageBase
`0x400000`) в RGBA-буфер 320×200. Модуль без состояния — рисует то, что ему
передали в `IngameMenuRenderOptions`, и отдаёт числа.

Главный результат среза — **отрицательный и доказанный**: у экрана 9 нет меню.
Нет пунктов, нет подписей, нет `rows`/`step`, нет заголовка, нет `PLATE`, нет
подсветки и нет `MENUARRW`. Кадр экрана — это ровно одна полноэкранная картинка
`FRONTEND/BMP.IDX` (`DEMOTION` или `DISBAND`) в (0,0), 320×200, без ключа
прозрачности и без смены палитры. Поэтому `rows`/`ink_pixels`/`missing_glyphs`/
`arrows` равны 0 не «потому что не измерено», а потому что рисовать нечего.

Код: `engine/src/ui/ingame_menu_render.h/.cpp`; тест —
`engine/tests/test_ingame_menu_render.cpp` (CTest `ingame_menu_render`, label
`quick`, 169 проверок). Соседние срезы — `RESTART_RENDER.md` (6, меню по `Esc` в
уровне), `MENU_RENDER.md` (общая механика `0x485dd0`/`PLATE`),
`MATCH_SETUP_RENDER.md` (27, там меню есть), `PAGER_RENDER.md` §2.4 (порядок
строк полноэкранных BMP), `HUD_AUDIT.md` §2.5 (слой HUD).

## 1. API

```cpp
#include "ui/ingame_menu_render.h"

gm::IngameMenuRenderOptions options;   // background = "DEMOTION" (.data 0x4bc1b8)
options.background = "DISBAND";        // "DEMOTION"/"DISBAND"; "" = чёрный холст
options.cursor = 0;                    // принимается и игнорируется (пунктов нет)

std::vector<std::uint32_t> rgba;       // 0xRRGGBBAA
int width = 0, height = 0;
gm::IngameMenuRenderStats stats;
std::string error;
if (!gm::render_ingame_menu(game, options, rgba, width, height, &stats, &error)) {
    // error: текст с префиксом "ingame_menu_render: "
}
// width=320 height=200, rgba.size()==64000
// stats: rows=0 ink_pixels=0 missing_glyphs=0 arrows=0
```

| Поле `IngameMenuRenderOptions` | По умолчанию | Смысл |
|---|---|---|
| `std::string background` | `"DEMOTION"` | запись `FRONTEND/BMP.IDX`, рисуется в (0,0) на весь холст; `"DISBAND"` — вторая картинка; `""` — ничего не рисуется (чёрный холст) |
| `int cursor` | `0` | `[0x68ccf4]`; на этом экране **не используется** (`-1`/`0`/`3` дают побайтово одинаковый кадр) |
| `bool fade_lut` | `false` | точный fade `0x682f90` по палитровым индексам |
| `int fade_lut_level` | `11` | 0..15; 11 — тождество, 12..15 светлеют |
| `std::string fade_lut_dump` | `""` | дамп 4096 Б (`load_hud_lut`) |
| `const HudLut* fade_lut_table` | `nullptr` | готовая таблица, приоритетнее дампа |

Публичные помощники:

* `ingame_menu_background_for_start_arg(int)` — выбор имени из `0x497210`:
  аргумент 0 → `"DEMOTION"` (`0x4be8a8`), любое иное значение → `"DISBAND"`
  (`0x4be8a0`). Оригинал не клампит (`test eax,eax` в `0x49720c`), поэтому
  отрицательные значения тоже дают `DISBAND`.
* `ingame_menu_highlighted_item(options)` — всегда `-1`
  (`kIngameMenuNoHighlight`): пункта, который мог бы совпасть с курсором, нет.

`IngameMenuRenderStats`: `rows` (всегда 0), `ink_pixels` (всегда 0 — глифов и
спрайтов нет), `missing_glyphs` (всегда 0 — текст не раскладывается), `arrows`
(всегда 0 — вызова `MENUARRW` нет). Форма полей оставлена как у соседних
рендереров, чтобы вызывающий печатал все экраны одинаково; значения закреплены
тестом.

Контракт буфера: при отказе `rgba` очищается, `width`/`height` = 0, статистика
обнуляется; `stats`/`error` могут быть `nullptr`. Функция только читает
установку, детерминирована, не зависит от текущего каталога.

Отказы (`ingame_menu_render: `): пустой каталог игры, нет/битый
`FRONTEND/BMP.IDX`, запрошенной записи нет в архиве, запись не 8 bpp / без
палитры, запись не 320×200, `fade_lut` без таблицы и дампа, дамп не читается.
**Отказа «нет шрифта» нет** — на этом экране нечего рисовать шрифтом (тест
рендерит архив, в котором есть только `DEMOTION`).

## 2. Доказано (листинг + данные)

Инструмент: `python3 tools/re/disrange.py`. Скриншот-артефакты не нужны:
проверка идёт по байтам `.data`/BMP и по коду.

### 2.1. Обработчика экрана 9 нет, и это не «потеря»

| Факт | Где |
|---|---|
| диспетчер экранов: `eax = [0x4bc440] - 5`, `cmp eax,0x20`, `jmp [eax*4+0x4883d8]` | `0x487e4f`..`0x487e7d` |
| слот id 9 в таблице (индекс 4) = `0x487f64` | `0x4883d8 + 4*4` (данные) |
| `0x487f64` — общий **хвост** диспетчера, а не отдельный экран: ids 7/8/9/28/29/31 идут туда же; хвост блитит собранную копию `PLATE` `0x6865f8` (`0x484cc0`, `0x487f81`..`0x487fdd`) и рисует арт карусели главного меню (`0x660790`/`0x662268`/`0x662f60`, `0x48801d`..) | `0x487f64`..`0x4880xx` |
| **но** у state 9 свой ранний выход: ветка `0x4876af` заканчивается `pop`/`ret` в `0x487739`, до вызова диспетчера | `0x4876af`..`0x487740` |
| все 182 `call 0x485dd0` (блиттер пункта с подсветкой) лежат в `0x485f0d..0x48ed01` — в обработчиках фронтенда; код уровня (`0x44xxxx..0x47xxxx`) его не вызывает | листинг |
| `rows`/`step`/`title` для id 9 в `docs/UI_SCREENS.md` §2 — «—» (совпадает с кодом) | §2 |

Отсюда: пунктов, их текстов (VA), `x`/`y`, `rows`/шага, заголовка, `PLATE` и
подсветки у экрана 9 **нет**. Игровое меню по `Esc` — это state 6
(`RESTART GAME`, `0x48b531`..`0x48b54c`, отдельный срез `RESTART_RENDER.md`),
а QUIT OPTIONS — state 33 (`QUIT_RENDER.md`).

### 2.2. Кадр state 9 — одна полноэкранная картинка

Ветка `0x4876af` (ветка «состояние == 9» фронтового кадра `0x487580`):

| шаг | адрес | что |
|---|---|---|
| условие | `0x4876af` | `cmp DWORD PTR ds:0x4bc440, 0x9` |
| указатель холста | `0x4876bc`..`0x4876ca` | `[0x68cca0]`; если 0 — подставляется `0x6c3160`; `Esc` обнуляет его (`0x48b556`), т.е. дефолт возвращается |
| «уже загружено» | `0x4876cf` | `[0x68cca4] != 0` → пропустить загрузку; сбрасывается в 0 при обработке state 6 (`0x48d9aa`) |
| загрузка | `0x4876d9`..`0x4876f0` | `push 200`, `push 320`, `push 0`, `push canvas`, `push 0x4bc1b8`, `push 0x4abbec "frontend"` → `call 0x47efe0` |
| ошибка | `0x4876fc`..`0x487709` | `push 0x4bd2dc "error loading DEMOTION.BMP\n"` → `0x40c530`, затем `[0x4bc440] = 1` (откат в титул) |
| предъявление | `0x48772a`..`0x487731` | `call 0x4848b0(canvas, width, height)` |
| выход | `0x487739` | `pop`/`ret` — больше ничего не рисуется |

`0x47efe0` — загрузчик полноэкранного BMP:

| факт | где |
|---|---|
| открывает `frontend\NAME.BMP`: `0x40d1a0(0x4abbec "frontend", name, 0x4bbc90 "BMP")` | `0x47eff0`..`0x47eff7` |
| заголовок 0x36 Б, палитра 0x400 Б | `0x47f013`..`0x47f07e` |
| палитра копируется только при ненулевом 4-м аргументе (здесь 0) | `0x47f09a`..`0x47f0cd`, `0x4876e3` |
| размер сверяется с аргументами 320/200; несовпадение → код возврата 5 | `0x47f0e5`..`0x47f12d` |
| **один сырой `fread` на `width*height` байт** — без переворота строк, без ключа, без перекраски | `0x47f0f8`..`0x47f100` |

Порядок строк: холст адресуется сверху вниз — `0x487500` считает
`canvas + y*320 + x` (`0x48751a`..`0x487524`, шаг строки `0x140`), — а
загрузчик кладёт в буфер строки файла как есть. Значит видимая картинка =
`flipV(parse_bmp)`, ровно как у фона SML-пагера (`ui/pager_render.cpp`,
`PAGER_RENDER.md` §2.4: `flipV(LOADPAGE)` читается как `LOADING`). Для этих
двух ассетов переворот виден глазом: `YOU'RE FIRED.` и `GAME OVER` читаются
только в «движковом» порядке.

### 2.3. Какой фон и когда

| факт | где |
|---|---|
| `[0x4bc1b8]` — 10-байтовый буфер имени (8 символов + NUL), в `.data` = `"DEMOTION"` | `0x4bc1b8`; строки `0x4be8a0 "DISBAND"`, `0x4be8a8 "DEMOTION"` |
| диспетчер VM-действий `0x4971e0`, case 0 = «старт уровня»: `push 1`, `[0x4bc440] = 9`, `call 0x44bed0` | `0x4971f4`..`0x497205` |
| 9-й аргумент действия: `test eax,eax; jne 0x497238` | `0x49720c`..`0x49720e` |
| 0 → копия `0x4be8a8` (`DEMOTION`) в `[0x4bc1b8]` | `0x497210`..`0x497237` |
| иначе → копия `0x4be8a0` (`DISBAND`) | `0x497238`..`0x497253` |
| имя передаётся в кадр через `[0x4bc1b8]` | `0x4876e6` |

Единственный писатель имени — этот case; второго пути выбора фона в exe нет.

### 2.4. Данные ассетов (`FRONTEND/BMP.IDX`, 143 записи)

| запись | размер | смещение в `BMP.DAT` | байт | bpp | палитра | пикселей с индексом 0 |
|---|---|---:|---:|---:|---:|---:|
| `DEMOTION` | 320×200 | 625226 | 65078 | 8 | 256 | 0 |
| `DISBAND` | 320×200 | 691638 | 65078 | 8 | 256 | 0 |

* 65078 = 14 (file header) + 40 (info header) + 1024 (palette) + 64000 (пиксели);
  `biHeight` положительный (bottom-up заголовок), `biClrUsed = 0`.
* Пикселей с индексом 0 нет ни в одной картинке → спорить о ключе
  прозрачности не нужно: кадр полностью непрозрачен (alpha = 255 на всех 64000
  пикселях, проверено тестом).
* Палитры обеих записей совпадают с `GAMEPAL` на индексах 1..255 (255 из 256) и
  различаются только неиспользуемым индексом 0; тест сверяет цвет каждого
  пикселя кадра с цветом `FRONTEND/GAMEPAL` по индексу (0 расхождений).
* `DEMOTION` и `DISBAND` различаются на **49323** из 64000 пикселей (sha256
  записей: `1e70950509d908e5…` и `e0a9cfbe7f8756b3…`).

Содержимое — газетная вырезка о провале миссии: `YOU'RE FIRED.` + письмо +
красное `GAME OVER`; у `DISBAND` текст письма другой (расформирование
подразделения), `GAME OVER` тот же. Это экран «игра окончена», который
фронтенд держит в холсте state 9.

### 2.5. `Esc` и плата

| факт | где |
|---|---|
| `state 9 + Esc (0x1b)` → `0x487500(0,0,320,200,0)` (заливка холста чёрным), затем `[0x4bc440] = 6`, `[0x68cca0] = 0` | `0x48b531`..`0x48b56b` |
| `[0x68cca4] = 0` в обработчике state 6 — при следующем входе в state 9 фон грузится заново | `0x48d9aa` |
| `PLATE` на экране 9 не используется: в списке ассетов §2 его нет, вызовов `0x486050`/`0x485dd0` в ветке нет | §2, `0x4876af`..`0x487740` |

```
$ ./build/sandbox/engine/tests/gm_ingame_menu_render_tests

  ingame_menu diffs: DEMOTION vs DISBAND 49323/64000, DEMOTION vs black 64000, DISBAND vs black 64000
```

Что закреплено:

* кадр = независимый `flipV`-блит записи (0 расхождений из 64000) для обеих
  картинок; bbox непрозрачных пикселей — весь холст `(0,0)-(319,199)`;
* три разницы: `DEMOTION`↔`DISBAND` 49323, `DEMOTION`↔чёрный 64000,
  `DISBAND`↔чёрный 64000 (в обеих картинках нет ни одного чёрного пикселя);
* `rows=0`, `ink=0`, `missing=0`, `arrows=0`; курсор `-1/0/3` — 0 отличий,
  `ingame_menu_highlighted_item` = `-1`;
* fade: уровень 11 — побайтово равен кадру без fade (0/64000), 12..15 — четыре
  разных кадра, и число отличий каждого совпадает с независимым предсказанием
  по таблице (55571/58666/59652/60176); кадр из дампа 4096 Б равен кадру из
  готовой таблицы;
* негативы: пустой путь, каталог без `BMP.IDX`, архив без `DEMOTION`, `DEMOTION`
  196×131 (несовпадение размера), запрос `DISBAND` без него, fade без
  таблицы/дампа, отсутствующий дамп — все с префиксом `ingame_menu_render: ` и
  очищенным буфером; архив **только** с `DEMOTION` рендерится (шрифт/плата/
  слайдер не нужны), имя ищется без учёта регистра; два прогона совпадают.

## 4. Модель (не доказано)

1. **Смысл 9-го аргумента** старта уровня (0 → `DEMOTION`, ≠0 → `DISBAND`)
   не установлен. Гипотеза: одиночная игра / мультиплеер(команда) — текст
   писем разный («вас увольняют» / «подразделение расформировано»). API
   принимает имя напрямую, поэтому модель вызывающего не навязывается.
2. **Момент показа.** Доказано, что фронтовый кадр state 9 грузит картинку в
   холст и предъявляет её; не прослежено, в какой именно момент боя холст
   выходит на экран (старт уровня / провал миссии). Это слой кадра игры
   (`0x44xxxx`), не экранный автомат.
3. **Fade.** Оригинальный путь `0x47efe0` копирует индексы и таблицы
   `0x682f90` не применяет. Опция `fade_lut` — та же модель «экранного»
   затемнения, что у соседних рендереров (`MOUSE_SETUP_RENDER.md`,
   `MATCH_SETUP_RENDER.md` §2), и нужна для общего CLI/регрессии; на реальной
   палитре уровень 11 — тождество для индексов этих картинок (0 и 65, две
   нетождественные записи таблицы, в них не встречаются).
4. **Палитра.** Цвет берётся из палитры самой записи (как в
   `ui/pager_render`). Оригинал палитру не переключает (4-й аргумент 0), т.е.
   показывает индексы в текущей экранной палитре; для поставочных файлов это
   одно и то же (см. §2.4).

## 5. Ограничения

* Нет ввода: `Esc` → state 6 и триггеры провала миссии не моделируются.
* Нет звука (`selectm`/`updown`/`vback` этого экрана не касаются).
* **CLI — есть (срез 13).** `--ingame-menu [--ingame-menu-bg DEMOTION|DISBAND]
  [--png OUT] [--fade-lut N]`: `ingame_menu: bg=DEMOTION rows=0 ink=0
  missing=0 arrows=0`; `DISBAND` отличается в 49 323 из 64 000 пикселей.
  CTest `cli_ingame_menu`, `_disband`; `cli_fade_lut` (11 = без fade).
* Меню не влияет на игру: модуль ничего не пишет ни в установку, ни в
  `GUNMETAL.CFG`, ни в состояние.
* Не рисуются: HUD-панель (`HUMPAN`/`PANEL`/`PANELMID` — выбор VM-действием 2
  `0x497264`, композиция слоем `0x491a70`, `COCKPIT.md`/`HUD_AUDIT.md` §2.5),
  транзиентный баннер `GAME SAVED` (`0x4875ad`..`0x487622`, строка `0x4bd304`,
  счётчик `0x4bc3dc`) и баннер `PAUSED`, который игровой кадр пишет в экранный
  буфер (`0x449d82`), а не в этот холст.
* Экран 9 остаётся без «настоящего» меню: если в будущем найдётся пункт,
  которого нет в листинге, это будет новый факт, а не регресс этого модуля —
  тест закрепляет именно `rows = 0`.
