# C++ HUD-слой: блит кадров `.sof`

* **Статус:** компонование одного декодированного кадра `.sof` (128×64
  индексов) в готовый RGB-кадр — палитра, прозрачный индекс, целочисленный
  масштаб и прозрачность. Привязки к `.sml`-экранам и логики HUD-семейств
  (`AMMO`/`WEAPON`/…, `0x4958d0`) пока нет.
* **Ветка:** `feat/hud-cpp`, база `master` `0d5c183`, дата 2026-10-20.
* **Игра:** только чтение (`Film/*.SOF`, `Film/Kflm0000.bmp`).
* **Файлы:** `engine/src/render/hud.h`, `engine/src/render/hud.cpp`,
  `engine/tests/test_hud.cpp`; строка `src/render/hud.cpp` в
  `engine/CMakeLists.txt`, регистрация `gm_hud_tests`/`hud` в
  `engine/tests/CMakeLists.txt`.
* **Эталон:** `gm/sof.py` (тайл-кодек и кадр), `gm/bmp.py` (палитра),
  `docs/FILM.md` (раскладка, место оверлея).

`render_scene` не меняется: `blit_indexed` работает только с уже
существующим `RenderResult::rgb` (плотный RGB, шаг `width * 3`).

## 1. API

```cpp
struct HudLayer {
    int x = 0;                          // левый верхний угол в пикселях кадра
    int y = 0;
    bool transparent = false;           // включить прозрачный индекс
    std::uint8_t transparent_index = 0; // какие индексы не рисовать
    double opacity = 1.0;               // 0..1, по каналам
    int scale = 1;                      // целочисленный nearest, 1..4
};

bool blit_indexed(RenderResult& target, const Sof& film, std::size_t frame,
                  const std::vector<std::uint8_t>& rgba_palette,
                  const HudLayer& layer, std::string& error);
```

* `film` — результат `parse_sof`; кадр декодируется через `Sof::frame`
  (транспонирование 64×128 → 128×64 уже выполнено там).
* `rgba_palette` — 256 квадов RGBA, ровно как `BmpImage::palette` (1024 байта).
  Альфа-байт не используется: кадры `.sof` — непрозрачные индексы VGA.
* Возврат `false` + текст в `error` при битом кадре/палитре/масштабе/opacity;
  при успехе `error` очищается. Слой, целиком лежащий вне кадра, — успешный
  no-op (`true`), а не ошибка.
* `scale` — поле `HudLayer`, добавленное к перечисленным в задаче полям, потому
  что иначе масштаб некуда передать; значение по умолчанию 1 сохраняет
  поведение «как в движке».

## 2. Палитра, прозрачность, масштаб, opacity

**Палитра.** Кадр — байты индексов; цвет берётся как
`palette[index*4 + 0..2]`, четвёртый байт игнорируется. Для `.sof`-фильмов
используется общая 256-цветная таблица установки; `installed_palette()` ищет
её в `FLAG/naUSA.BMP`, `FLAG/aanataka.bmp`, `PICS/oaktabl1.bmp`,
`PICS/mine-1c.bmp`, а тест берёт `Film/Kflm0000.bmp` — дамп кадра фильма с той
же байт-идентичной таблицей.

**Прозрачность.** При `transparent == true` пиксели с индексом
`transparent_index` не пишутся вообще (независимо от `opacity`); остальные
пиксели кадра копируются/смешиваются. Ключ не хардкодится: движок рисует
фильмы в режиме 0 без ключа, так что вызывающая сторона выбирает индекс сама.

**Масштаб.** `scale` — целое 1..4, nearest neighbour: исходный пиксель
превращается в блок `scale × scale`. Блоки клиппируются по краям кадра
по-пиксельно, координаты считаются в `int64`, поэтому отрицательные `x`/`y` и
значения у границ `int` не переполняются и не заворачиваются.

**Opacity.** `alpha = clamp(opacity, 0, 1)`; нефинитные значения (NaN/inf) —
ошибка. Смешение по каналам:

```
dst = floor(dst + (src - dst) * alpha + 0.5)
```

то есть округление половины вверх, без накопления ошибки (результат всегда
0..255). При `alpha == 0` кадр не трогается, при `alpha == 1` — побайтовая
копия. Операции — IEEE-754 double в фиксированном порядке, поэтому результат
детерминирован и совпадает с Python-эталоном.

## 3. Golden FNV

Сцена: чёрный (или залитый `7,9,11`) RGB-кадр 320×200, `AMMO4.SOF` кадр 0,
`Film/Kflm0000.bmp`, слой `x=14, y=125` (место HUD-оверлея из `docs/FILM.md`
§1.3: строка 125, сдвиг +14), `opacity=1`, `scale=1`, без прозрачности.
FNV-1a64 (offset `0xcbf29ce484222325`, prime `0x100000001b3`) по всему
буферу `320*200*3`:

| фон | FNV-1a64 |
|---|---|
| чёрный `0,0,0` | `e86048ae84209fca` |
| `7,9,11` | `5a5caa743a6b4f0a` |

Значения получены временным скриптом на `gm/sof.py` + `gm/bmp.py`
(`decode_tile` кадра 0, палитра BMP, блит в `(14,125)`); скрипт в репозиторий
не входит, в `engine/tests/test_hud.cpp` зашиты числа. Тест также проверяет,
что строка 124 остаётся нетронутой, а синтетические 2×2-кадры фиксируют
точный RGB, клиппинг, прозрачный индекс, масштабы 1/2/4 и opacity 0/1/0.5.

## 4. Границы и trust

* Буфер назначения проверяется на `width > 0`, `height > 0` и
  `rgb.size() == width*height*3`; иначе — ошибка, без записи.
* `frame >= film.tiles()` (и `frame == SIZE_MAX`) отвергается до вычислений;
  частичный хвостовой тайл `.sof` кадром не считается (`Sof::frame`).
* Палитра короче 1024 байт отвергается — индексы кадра не маскируются и не
  заворачиваются.
* `scale` вне 1..4 — ошибка, а не молчаливое приведение: движковый блиттер
  масштаба не имеет, это расширение для оконного режима.
* Координаты и размеры блоков — `int64`; `INT_MIN`/`INT_MAX` не переполняют
  арифметику и дают пустое пересечение.
* Функция ничего не аллоцирует, кроме декодированного кадра (`Sof::frame`
  возвращает 8192 байта), и не пишет за пределами `rgb`.
* `.sof` не содержит палитры, поэтому доверять ей можно только из
  установки/проверенного BMP; тест падает, если таблица не 256 цветов.

## 5. Что осталось

1. **Привязка к `.sml`-экранам.** HUD-семейства (`AMMO`, `WEAPON`, `TANK`,
   `SHIELD`, `EQUIP`, `DEFAULT`) выбираются загрузчиком `0x4958d0` по
   префиксу и номеру; элементы `.sml`-экрана задают позиции/номера. Нужен
   слой «описание экрана → список `HudLayer`» с учётом `start_frame = 1`
   (HUD-фильмы стартуют с кадра 1) и счётчика `count = tiles - 1`.
2. **Тайминг.** `ms = 91 // fps` из `.fdx`/`FILM_DEFINE` и выбор кадра по
   тикам — вне этого слоя.
3. **Палитра экрана.** Сейчас палитра передаётся снаружи; интеграция с
   `TexturePool`/`installed_palette` и затемнениями (fade) не сделана.
4. **Тест на всех 48 фильмах.** Сейчас golden только для `AMMO4.SOF` кадра 0;
   полный обход 11 637 кадров уже есть в `test_sof` на уровне индексов, но не
   RGB-композиции.
