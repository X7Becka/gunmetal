# Gunmetal — примитивы коллизий `.sbw`

Что здесь: модуль `engine/src/render/collide.{h,cpp}` — треугольники уровня в
мировом кадре, broad-phase по AABB секторов, `raycast`, `sphere_cast`,
`floor_at`, `overlap_aabb`. Это **новый слой примитивов** для будущего
игрока/камеры, а не порт оригинального кода столкновений: движковые функции
(`0x4344df` — приближённое расстояние, `0x434887` — объёмный запрос,
`0x4795b0` — `event_post`, в том числе событие −22 для двери) разобраны лишь
частично, и их константы в этот модуль не переносились (см. §9).

Статус: API, геометрия, broad-phase, тесты и golden'ы готовы. Синтетика и
`level0.sbw` сходятся с Python-эталоном; CTest `collide` проходит. Ничего в
`engine/src/main.cpp`, `render.*`, `sbw.*`, `gm.py`, `gm/**`, `regress.py` и
документации других подсистем не менялось.

## 0. Коротко

| что | значение |
|---|---|
| единицы | мировые единицы `.sbw` (`world = origin + basis · local`, базис `diag(1.875)`) |
| точность | `double` на всех этапах, `float` только в файле |
| стороны | по умолчанию **двусторонние**; нормаль всегда против луча |
| near-plane | `t >= 1e-9` (`kCollideRayEps`) |
| порог пол/стена/потолок | `n.z >= 0.8` / `|n.z| < 0.8` / `n.z <= -0.8`, допуск `1e-12` |
| broad-phase | AABB сектора, затем AABB треугольника |
| аллокации на запрос | нет (кроме caller-owned `std::vector` в `overlap_aabb`) |
| `level0.sbw` | 192 объекта, 1449 полигонов, 3162 треугольника (2 вырожденных), 58 секторов |

## 1. Кадр и построение мира

`CollisionWorld::build(const SbwLevel&, std::string* error)` обходит секторы и
объекты в том же порядке, что `parse_sbw` и Python `gm/sbw.py`:

```
для каждого sector s (по порядку файла):
  для каждого object o внутри s:
    geometry = level.geometry[k++]            // стадия 2, sector-major
    transform = decode(object.header[96])     // 4 точки × 3 компоненты (u32 pad, f32)
    world_v  = origin + bx*x + by*y + bz*z   // ровно Object.world_vertices()
    для каждого poly:
      fan: (i0, i1, i2), (i0, i2, i3), ...   // i0 — первый индекс полигона
```

Заголовок объекта — `origin + 3 базисных вектора`; во всех 28 192 поставочных
объектах базис `diag(1.875)` (docs/FORMATS.md §10), но модуль читает его
честно, без предположения о масштабе. Origin лежит в ±8, поэтому «файловый»
кадр (`local`) и мир различаются в 1.875 раза — все результаты модуля **в
мировом кадре**.

Треугольник (`Triangle`) хранит:

| поле | смысл |
|---|---|
| `a,b,c` | мировые вершины |
| `normal` | единичная нормаль из обхода: `cross(b−a, c−a) / |…|` |
| `centroid`, `bounds` | центроид и AABB треугольника |
| `plane_offset` | `dot(normal, a)` |
| `sector`, `object` | индексы сектора и объекта **внутри сектора** |
| `texture`, `material`, `lightmap` | поля полигона (docs/FORMATS.md §10.1) |
| `source_poly` | индекс полигона в объекте |

Индексы: полигон с `< 3` индексами и треугольники нулевой площади
**пропускаются** (`stats().degenerate`). Индекс вне `0..n_verts-1` —
**ошибка сборки** (`stats().bad_index`, `build` возвращает `false`). Это
отличается от «тихого» пропуска: битые индексы означают повреждённый файл.

### 1.1. Ошибки сборки

`build` очищает мир и возвращает `false` с одной строкой в `error`, если:

* число `geometry` не совпадает с числом объектов заголовка;
* в трансформе или вершине `NaN`/`inf` (`stats().non_finite`);
* координата `|x|,|y|,|z| > 1e9` (`kCollideMaxCoordinate`, `stats().out_of_range`);
* индекс вершины вне диапазона (`stats().bad_index`).

Счётчики `stats()` остаются заполненными и после ошибки — для диагностики;
сам мир пуст (`empty() == true`), запросы безопасно возвращают «промах».
Вырожденные полигоны ошибкой **не** считаются.

## 2. API

```cpp
#include "render/collide.h"

gm::CollisionWorld world;
std::string error;
const bool ok = world.build(level, &error);   // SbwLevel из parse_sbw()

// Луч: direction не обязан быть единичным, t — расстояние в мировых единицах.
std::optional<gm::RayHit> hit =
    world.raycast({24, -208, 58}, {0, 0, -1}, gm::kCollideInfinity, filter);

// Сфера радиуса r, заметающая отрезок.
std::optional<gm::SphereHit> sh =
    world.sphere_cast({24, -208, 300}, {0, 0, -1}, 10.0);

// Пол под точкой (только «пол», без стен/потолков).
std::optional<double> z = world.floor_at(24, -208, 58);

// Все треугольники, чей AABB пересекает бокс (вектор переиспользуется).
std::vector<std::uint32_t> out;
const std::size_t n = world.overlap_aabb(box, out, filter);
```

| тип | поля |
|---|---|
| `RayHit` | `t`, `point`, `normal`, `triangle` (`const Triangle*`), `triangle_index`, `sector`, `front_face` |
| `SphereHit` | `t`, `point` (точка контакта на треугольнике), `centre` (центр сферы), `normal`, `triangle`, `triangle_index`, `sector` |
| `CollideFilter` | `floors`, `ceilings`, `walls`, `backfaces`, `min_normal_z`, `sectors` (`std::span<const uint32_t>`, пустой = все) |
| `Aabb` | `lo`, `hi`, `valid()`, `expand(Vec3d)`, `expand(Aabb)`, `grow(r)`, `contains`, `centre`, `size` |

`Hit::triangle` — указатель в массив мира; он валиден, пока жив
`CollisionWorld`. Копии треугольника нет, поэтому запрос не аллоцирует.
Промах — `std::nullopt`; `max_t`/`radius`/`direction`, равные `NaN`, `inf`
или неположительные, дают «промах» без исключений.

Свободные функции: `surface_of(triangle, min_normal_z)`,
`surface_name(surface)`, `closest_point_on_triangle`, `point_in_triangle`,
`ray_triangle` (все — с теми же эпсилонами, что и `raycast`).

Векторные хелперы (`operator+/-/*`, `dot`, `cross`, `length`, `normalized`,
`finite`) для `Vec3d` объявлены рядом — по образцу `core/math.h`, но в
`double`.

## 3. Backface: выбор и обоснование

**Решение: запросы двусторонние по умолчанию.** `.sbw` — набор независимых
секторов/объектов, а не замкнутая оболочка с гарантированным обходом:
полигоны приходят из редактора, стены/полы могут быть односторонними, а
игрок/камера должны упираться в поверхность с любой стороны. Поэтому
`CollideFilter::backfaces = true` — физика не зависит от того, какой стороной
повёрнут полигон.

При этом отчёт всегда согласован с запросом:

* `RayHit::normal` — единичная нормаль, направленная **против луча**
  (к его началу); если луч попал в обратную сторону, нормаль перевёрнута.
  Так вызывающий код может скользить по стене, не проверяя `front_face`.
* `RayHit::front_face` — `true`, если луч пришёл со стороны обхода
  (`dot(n, d) < 0`).
* `SphereHit::normal` — вектор выталкивания: из ближайшей точки треугольника
  к центру сферы в момент контакта (для грани — нормаль грани, ориентированная
  к центру).
* `CollideFilter::backfaces = false` отбрасывает треугольники, к которым
  запрос пришёл с обратной стороны: для луча — `dot(n, d) >= 0`, для сферы —
  центр в момент контакта по отрицательную сторону плоскости.

Классификация пол/стена/потолок делается по **геометрической** нормали
(`n.z`), а не по стороне запроса: пол, увиденный снизу, остаётся полом. Это
сознательно: фильтр описывает геометрию, а не направление взгляда.

## 4. Формулы и эпсилоны

### 4.1. Луч–треугольник (Möller–Trumbore, double)

```
e1 = b − a, e2 = c − a, p = d × e2
det = e1 · p                      // |det| <= 1e-12 -> параллельно/вырождено
u = (s · p) / det,  s = o − a
v = (d · (s × e1)) / det
t = (e2 · (s × e1)) / det
```

Принимается `u >= -1e-9`, `v >= -1e-9`, `u + v <= 1 + 1e-9` (допуск на
границу), `t >= 1e-9` и `t <= max_t`. `direction` нормируется внутри, поэтому
`t` — расстояние, а `max_t` — длина в мировых единицах.

### 4.2. AABB

* `raycast`/`sphere_cast`: slab-тест `[0, max_t]` по сектору (сфера —
  расширенный на `radius`), затем по треугольнику; текущий лучший `t`
  поджимает интервал.
* `overlap_aabb`: `a.lo <= b.hi && b.lo <= a.hi` по каждой оси.

### 4.3. Пол

`floor_at(x,y,z,max_drop)` = `raycast((x,y,z), (0,0,−1), max_drop)` с фильтром
«только пол». Это **верхняя** поверхность под точкой (луч вниз даёт
наибольший `z` из ближайших), что совпадает с
`tools/re/spawn.py::TriGrid.floor` (там перебор проекций и максимум `z`).
Проверено: `level0` в точке спавна `(24,−208,58)` оба метода дают
`z = 48.546875`.

### 4.4. Сфера

Заметание сферы — это луч против суммы Минковского «треугольник ⊕ шар»:
грани, три ребра и три вершины. Для каждой особенности берётся **наименьший**
корень, что и есть время входа (сумма выпукла).

* **Грань.** `d0 = n·(o−a)`, `den = n·d`. Если `|d0| > r` и шар движется к
  плоскости, `t = (r − d0)/den` (или `(−r − d0)/den` с другой стороны).
  Точка на плоскости проверяется барицентрически; нормаль — `±n` к центру.
* **Ребро** `p0..p1`, `e = p1−p0`, `c = e·e`, `b = d·e`, `m = o−p0`:
  `A = 1 − b²/c`, `B = 2(m·d − (e·m)b/c)`, `C = |m|² − (e·m)²/c − r²`,
  корни `A t² + B t + C = 0`; параметр `s = ((e·m) + t b)/c` должен лежать в
  `[0,1]`. При `A <= 1e-12` (луч параллелен ребру) цилиндрическая часть не
  даёт изолированного контакта — её закрывают вершины.
* **Вершина** `v`: `|o + t d − v|² = r²`.
* **Старт внутри радиуса**: `|o − closest_point| <= r` → `t = 0`, нормаль
  выталкивания из ближайшей точки (если центр ровно на поверхности —
  против движения).

Контакты рёбер и вершин проверяются без дополнительной проверки «не закрыт ли
гранью»: любая точка ребра/вершины — граница суммы Минковского, поэтому
контакт настоящий, а минимум по всем особенностям даёт корректное время
входа.

### 4.5. Таблица констант

| константа | значение | где |
|---|---:|---|
| `kCollideRayEps` | `1e-9` | минимальный `t`; «луч из поверхности» не бьёт её же |
| `det` MT | `1e-12` | параллельность/нулевая площадь |
| барицентрика | `1e-9` | граница треугольника |
| порог `n.z` | `0.8` | классификация; допуск `1e-12` на округление нормали |
| вырожденность | `|cross| <= 1e-12 · max(1, e_max²)` | относительный порог |
| `kCollideInfinity` | `1e30` | «далеко», чтобы не смешивать `inf · 0` в slab |
| `kCollideMaxCoordinate` | `1e9` | защита от мусорных координат |

Допуск `1e-12` у порога 0.8 появился не «на всякий случай»: восемь
треугольников пола `level0` имеют ровно `n.z = 0.8`, и нормализация в C++
даёт `0.79999999999999993`, тогда как `tools/re/spawn.py` — `0.8`. Без
допуска счётчики пол/стена расходились (514/2090 вместо 522/2082).

## 5. Broad-phase

* При сборке каждый треугольник получает AABB, каждый сектор — AABB
  объединения своих треугольников. Треугольники лежат в массиве
  **sector-major** (все треугольники сектора подряд), сектор хранит
  `begin/count`, поэтому обход сектора — это непрерывный диапазон.
* `raycast`/`sphere_cast`: slab-тест AABB сектора (для сферы — расширенного на
  `r`), затем slab-тест AABB треугольника, затем точная проверка.
* `CollideFilter::sectors` (непустой span) ограничивает перебор списком
  секторов; проверка линейная, без аллокаций. Пустой span — все секторы.
* `overlap_aabb` возвращает индексы треугольников в порядке сборки; вектор
  очищается (`clear`, без освобождения памяти) — его можно переиспользовать.

## 8. Доверие: что доказано, что нет

Доказано (сверено с Python/данными):

* сборка 1:1 с `gm/sbw.py` по числу объектов/полигонов/треугольников и по AABB;
* мировые координаты через `origin + basis·local` (тот же порядок операций);
* первый луч вниз/по сторонам на `level0` и `floor_at` в точке спавна;
* счётчики поверхностей и секторные AABB;
* синтетические `t/point/normal` с точными дробями (куб, пол, рёбра, вершины);
* ошибки на NaN/inf/огромных координатах/битых индексах — без падений.

Не доказано / приближения:

* **Сфера**: математика точна для грани/ребра/вершины (сумма Минковского),
  но старт «внутри» отдаёт `t = 0` и нормаль по ближайшей точке — это
  push-out, а не физическое разрешение проникновения.
* **Две стороны**: выбор двусторонности — инженерное решение, оригинальный
  движок мог отсекать иначе; на поставочных данных это не проверено.
* **Классификация 0.8** — эвристика из `tools/re/spawn.py`, не константа
  движка.
* **Порядок при равных `t`** — «первый по порядку сборки» (совпадает с Python
  перебором), но геометрически это произвол: в `level0` есть дубликаты
  (например `t = 17.65625`, секторы 2 и 20).

## 9. Что осталось

1. **Капсула/цилиндр игрока.** Сейчас есть только сфера; для шасси нужен
   вертикальный капсульный sweep (радиус + высота), slide по нормали,
   step-up/step-down и гравитация. Константы (радиус, высота, шаг, трение,
   скорость падения) в оригинале не найдены.
2. **Оригинальные константы и алгоритм.** `0x4344df` (расстояние
   `max + (mid+min)/2`), `0x434887` (объёмный запрос), `0x4795b0`
   (`event_post`, событие двери −22) разобраны только по смыслу; пороги и
   порядок разрешения коллизий не восстановлены.
3. **Двери как движущиеся объёмы.** docs/FORMATS.md §12 фиксирует, что дверь —
   это бокс (`corner … corner+size`), а не полигоны; в `CollisionWorld` его
   нет. Нужен слой динамических AABB/OBB поверх статического мира.
4. **`.sob`-модели и объекты сцены.** 68/143 кампанийных спавнов лежат вне
   AABB `.sbw` (интерьеры из `.sob`, docs/PLAYER.md §7); для них нужна
   коллизия по размещённым моделям.
5. **Секторные порталы/видимость.** Broad-phase по AABB — не BSP/PVS;
   для больших уровней стоит проверить производительность на всех 36 `.sbw`
   (сейчас измерен только `level0`).
6. **`SphereHit` vs капсула**: контакт ребра считается для бесконечной прямой
   с ограничением `s ∈ [0,1]`; для капсулы понадобится та же схема с
   параллельным переносом сегмента.
7. **Числа `floor_at` на всех спавнах.** Сверен один `level0`; имеет смысл
   прогнать 143 кампанийные точки и сравнить с `spawn.py` (сейчас это делает
   Python-инструмент, C++-паритета нет).
