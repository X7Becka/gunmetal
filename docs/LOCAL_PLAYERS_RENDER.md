# Рендер экрана 21 `NUMBER OF LOCAL PLAYERS` (`engine/src/ui/local_players_render.h`)

Срез 3 пункта `M8.8`: модуль **рисует экран 21** в RGBA-буфер 320×200 из
реальной установки: заголовок `NUMBER OF LOCAL PLAYERS`, три пункта по **две**
текстовые строки (кроме `Cancel`), подсветку курсора шрифтом 4 на обеих строках
пункта и плату `PLATE`. Геометрия — из обработчика `0x48a780`
(`docs/UI_SCREENS.md` §2/§3.8), атласы — из `render/text_layout` (`FONTS4` в
`FRONTEND/BMP.IDX`), курсор по умолчанию — из входа в состояние `0x15`
(`0x48b0c5`/`0x48b126`, `docs/MAINLOOP.md` §4.1).

Код: `engine/src/ui/local_players_render.h/.cpp`; тест —
`engine/tests/test_local_players_render.cpp` (CTest `local_players_render`,
label `quick`). Канон поведения — `docs/UI_SCREENS.md` §3.8 и этот документ;
образцы того же класса задач — `docs/GAME_TYPE_RENDER.md` (19) и
`docs/DIFFICULTY_RENDER.md` (23).

Проверка:

```sh
export PATH=$HOME/tools/cmake-4.4.4-linux-x86_64/bin:$HOME/tools/bin:$PATH
cmake --build build/sandbox --target gm_local_players_render_tests -j 4
./build/sandbox/engine/tests/gm_local_players_render_tests
ctest --test-dir build/sandbox -R '^local_players_render$' --output-on-failure
python3 regress.py --mirror --json
```

## 1. Что доказано (`0x48a780`, docs/UI_SCREENS.md §2/§3.8)

Обработчик занимает `0x48a780`..`0x48a823` (последний `ret`; дальше `nop` до
`0x48a830`). Всё в таблице — его сайты и сайты общего отрисовщика `0x485dd0`
(листинг: `python3 tools/re/disrange.py 48a780 48a830` и `485dd0 485e80`).

| факт | значение | источник |
|---|---|---|
| длина списка | **3** (`0x67f10c = 3`) = `One Player` (item 0), `Two Players` (1), `Cancel` (2) | `0x48a780` |
| шаг пункта | **27** (`0x662d58 = 0x1b`) | `0x48a78a` |
| плата | `0x486050` копирует `PLATE` 196×131 в `0x6865f8`; весь текст пишется в эту копию (клип 196×131) | `0x48a794`; §3, §9 |
| заголовок | `NUMBER OF LOCAL PLAYERS` (`0x4bdb2c`), шрифт **5**, `centered=1`, `x 38`, `row 14`, `item -1` → **y 14**, x = (196 − advance)/2 | `0x48a799`..`0x48a7a8`; `0x485de2`..`0x485dfa` |
| `centered` | `x = (196 − measure(text)) / 2`, целочисленно | `0x485de2`..`0x485dfa` |
| `item == -1` | обнуляет `item·step`, поэтому y = row | `0x485e04`..`0x485e09` |
| пункт 0, строка 1 | `One Player` (`0x4bdb20`), item **0**, `x 38`, `row 27`, шрифт 0 → **y 27** | `0x48a7b0`..`0x48a7bf` |
| пункт 0, строка 2 | `Full Screen` (`0x4bdb14`), item **0**, `x 38`, `row 36`, шрифт 0 → **y 36** | `0x48a7c7`..`0x48a7d6` |
| пункт 1, строка 1 | `Two Players` (`0x4bdb08`), item **1**, `x 38`, `row 27` → **y 54** (= 27 + 27) | `0x48a7de`..`0x48a7ed` |
| пункт 1, строка 2 | `Split Screen` (`0x4bdaf8`), item **1**, `x 38`, `row 36` → **y 63** (= 36 + 27) | `0x48a7f5`..`0x48a804` |
| `Cancel` | `0x4bda0c`, item **2**, `x 38`, `row 27` → **y 81** (= 27 + 2·27); одна строка | `0x48a80c`..`0x48a81b` |
| `y` при `row >= 0` | `y = row + item·[0x662d58]` — поэтому шаг 27 разносит **пункты**, а две строки одного пункта стоят через 9 px (27 → 36) | `0x485e4b`..`0x485e5c` |
| подсветка | `item == [0x68ccf4]` **и** вызывающий передал шрифт 0 (`test esi,esi`) → шрифт принудительно **4**; подсвечиваются **обе** строки пункта; `Cancel` — тоже item, поэтому тоже может подсвечиваться | `0x485e0d`..`0x485e19` |
| стрелки | обработчик не вызывает `0x485cc0`/`0x485d00`; список кончается на y 81 (ячейка 8 px) в полосе 131 px, прокрутки нет | листинг `0x48a780..0x48a823` |
| порядок | заголовок → item 0 (2 строки) → item 1 (2 строки) → `Cancel` | порядок вызовов `0x48a7a8`..`0x48a81b` |
| курсор при входе | **0** (`One Player`): `0x48b11c` пишет состояние `0x15`, `0x48b126` копирует `edx` в `0x68ccf4`, а `edx` обнулён `xor edx,edx` на `0x48b0c5` | `0x48b0c5`, `0x48b11c`, `0x48b126`; `docs/MAINLOOP.md` §4.1 |

### 1.1. Порядок пунктов, id и геометрия

| item | строки | VA | y |
|---:|---|---|---|
| 0 | `One Player` / `Full Screen` | `0x4bdb20` / `0x4bdb14` | 27 / 36 |
| 1 | `Two Players` / `Split Screen` | `0x4bdb08` / `0x4bdaf8` | 54 / 63 |
| 2 | `Cancel` | `0x4bda0c` | 81 |

`x` у всех строк — 38 (`push 0x26`), шрифт 0. Второй `push 0x26` заголовка —
это аргумент `x` вызова с `centered=1`, он не используется: `0x485de2`
заменяет его на `(196 − measure)/2`. При поставочном `FONTS4` ширина заголовка
130 px, поэтому **x = 33** (проверено bbox’ом в тесте).

«Две строки на пункт» — это буквально два вызова `0x485dd0` с одним и тем же
`item`; поэтому курсор и подсветка работают на уровне пункта (обе строки), а не
строки. Шаг 27 в `0x662d58` задан один раз и прибавляется к обеим базовым
строкам (27 и 36) — отсюда §3.8: «по две строки на пункт (27 и 36), `Cancel` —
27». Ячейка шрифта 8×8: строка `y` занимает `y..y+7`, соседние строки одного
пункта не пересекаются (27..34 и 36..43).

### 1.2. Курсор и выбор

`[0x68ccf4]` — общий курсор фронтенда (`docs/UI.md` §6.2), для этого экрана
это **item id** `0..2`, а не номер видимой строки. Единственный вход, который
рисует экран 21, — ветка старта игры `0x48b11c`: она берётся, когда тип
мультиплеера `[0x664598]` не равен 0 и не равен 3 (`0x48b115`/`0x48b117`), и
кладёт в курсор **0**. Ветка `0x48b131` (тип 0 или 3) пишет тот же 0, но уходит
на выбор уровня (17), не рисуя 21.

Что означает выбор, этот модуль не решает: `Enter` на пункте 0/1 в оригинале
ведёт к именам игроков (24/25) и списку уровней (17), `Cancel` — назад. Рендер
только красит кадр; навигация — у `frontend_menu`/CLI.

## 2. Модель кадра

* Холст — 320×200 (`0x6d8fc0`, mode 13h), по умолчанию непрозрачный чёрный
  `#000000FF`. `options.background` — имя записи `FRONTEND/BMP.IDX`,
  нарисованной в (0,0) **до** текста; пустая строка = чёрный холст.
  Доказанная плата экрана — `PLATE` 196×131 (`0x486050`,
  `menu_panel_asset(Screen::LocalPlayers)`), но она не рисуется неявно.
* Текст клипается к полосе 196×131: `0x485dd0` пишет в копию `PLATE`
  `0x6865f8`, за её пределы пиксель не попадает. Холст вне платы остаётся
  чёрным.
* Шрифты — три грани `FONTS4`: заголовок 5, строки 0, подсветка 4 (§3).
  Цвета из палитры атласа: заголовок (155,15,15), строки (19,15,15),
  подсветка (239,239,239). Ячейка 8×8.
* Заголовок центрируется по ширине **advance**-сумм (`0x47fa50`), а не по
  чернилам: при поставочном `FONTS4` `x = (196 − 130)/2 = 33`.
* Подсветка — только смена грани на 4 (`0x485e0d`..`0x485e19`) и только когда
  вызывающий передал шрифт 0; ни полосы, ни рамки, ни `MENULIT` здесь нет.
  Курсор на пункте 0/1/2 подсвечивает **обе** строки этого пункта; значения вне
  `0..2` (например `-1` или `99`) не подсвечивают ничего — это точное сравнение
  `0x485e0d`, а не кламп.
* Точный fade (`fade_lut*`) — тот же индексный слой `0x682f90`, что у
  `ui/start_game_render`/`ui/game_type_render`/`ui/difficulty_render`: таблица
  применяется к индексу палитры **до** поиска цвета. Без таблицы и дампа —
  отказ, не «молча без fade». Уровень 11 — тождество (0 отличий), 0..10
  затемняют, 12..15 осветляют.

## 3. API

```cpp
struct LocalPlayersRenderOptions {
    std::string background;              // "" = чёрный; "PLATE" = плата экрана
    int cursor = 0;                      // [0x68ccf4], item id 0..2
    bool fade_lut = false;
    int fade_lut_level = 11;             // 0..15
    std::string fade_lut_dump;           // 4096 байт, docs/HUD_LUT.md §2
    const HudLut* fade_lut_table = nullptr;
};

struct LocalPlayersRenderStats {
    int rows;             // пункты, 3 (не строки: строк 5)
    int ink_pixels;       // уникальные пиксели чернил глифов
    int missing_glyphs;
    int arrows;           // всегда 0 (на экране нет прокрутки)
};

bool render_local_players(const std::filesystem::path& game,
                          const LocalPlayersRenderOptions&,
                          std::vector<std::uint32_t>& rgba,
                          int& width, int& height,
                          LocalPlayersRenderStats* = nullptr,
                          std::string* error = nullptr);
```

Данные экрана доступны как константы: `kLocalPlayersEntries[3]` (`first`,
`second`, `item`), `kLocalPlayersTitle`, `kLocalPlayersCancel`,
`kLocalPlayersRows = 3`, `kLocalPlayersItemStep = 27`,
`kLocalPlayersItemFirstY = 27`, `kLocalPlayersSecondLineOffset = 9`,
`kLocalPlayersItemX = 38`, `kLocalPlayersTitleY = 14`,
`kLocalPlayersDefaultCursor = 0`, `kLocalPlayersPanelName = "PLATE"`,
`kLocalPlayersPanelWidth/Height = 196/131`.

Отказы (префикс `local_players_render:`): пустой путь игры; нет/битый
`FRONTEND/BMP.IDX`; нет атласа `FONTS4` (шрифты 5/0/4); неизвестная/битая/
не-8-bpp запись фона; `fade_lut` без таблицы и дампа или с нечитаемым дампом.
При отказе `rgba` очищен, `width = height = 0`, статистика обнулена.

## 5. Ограничения

* **Нет ввода/навигации**: модуль не читает клавиатуру и не двигает
  `[0x68ccf4]`; правило «оба строки одного item» — модель выделения, а сам
  переход по пунктам делает `frontend_menu`/CLI.
* **Нет звука**: `updown`/`select` (`docs/UI_SOUNDS.md`) не моделируются.
* **CLI — есть (срез 4):** `--local-players [--local-players-cursor N]
  [--no-plate] [--png OUT] [--fade-lut N]`. Печатает
  `local_players: rows=3 cursor=0 ink=936 missing=0 arrows=0`; курсор 1 —
  `cursor=1` (подсветка обеих строк пункта). CTest `cli_local_players`,
  `_png`; `cli_fade_lut` (11 = без fade, 13 ≠ без fade).
* **Выбор ничего не значит для состояния игры**: пункт 0/1 в оригинале задаёт
  число локальных игроков и уводит на имена игроков/выбор уровня; здесь
  рисуется только кадр, глобалы `0x664598`/`0x68ccf4` не читаются и не пишутся
  (кроме значения по умолчанию в документации).
* **Курсор вне `0..2` не клампится**: это точное сравнение `0x485e0d`;
  поставочная навигация держит значение в диапазоне, поэтому «пустая»
  подсветка — валидное состояние API, а не ошибка.
* **Соответствие «номер шрифта → атлас»** для 0/4/5 взято из `docs/UI.md`
  §10.3/`docs/MENU_RENDER.md` §3; независимой привязки номеров в коде нет — это
  общее открытое место фронтенда, не специфика экрана 21.
