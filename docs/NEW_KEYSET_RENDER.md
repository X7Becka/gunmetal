# Рендер экрана 31 `NAME OF NEW KEY SET` (`engine/src/ui/new_keyset_render.h`)

Срез 23 пункта `M8.8`: один кадр экрана **31** фронтенда (`gundx.exe`,
ImageBase `0x400000`) в RGBA-буфер 320×200. Модуль без состояния — рисует то,
что ему передали в `NewKeysetRenderOptions` (текст поля имени и флаг каретки), и
отдаёт числа (`rows`, `chars`, `truncated`, `ink_pixels`, `missing_glyphs`,
`arrows`). Шрифты и метрики — из `render/text_layout` (`FONTS4`/`FONTS2` в
`FRONTEND/BMP.IDX`), точный fade — из `render/hud_lut`, плата — тот же `PLATE`,
что у соседних экранов. Ничего не измеряется заново.

Код: `engine/src/ui/new_keyset_render.h/.cpp`; тест —
`engine/tests/test_new_keyset_render.cpp` (CTest `new_keyset_render`, label
`quick`). Опора: `UI_SCREENS.md` §2/§3.7 (карта и описание), `SAVE_NAME_RENDER.md`
(экран 15 — такое же текстовое поле, но с кареткой-символом), `KEYCFG_RENDER.md`
(экраны 30/34/35 — куда ведёт Enter), `TEXT_LAYOUT.md` §2.1 (шрифт 3 = `FONTS2`,
ячейка 16×16), `MENU_RENDER.md` §3 (цвета), `INIT.md` §3 (тик `0x5a4a74`).

## 1. API

```cpp
#include "ui/new_keyset_render.h"

gm::NewKeysetRenderOptions options;   // name = "NEW SET", caret = true
options.name = "MY KEYS";             // текст поля БЕЗ каретки (15 символов max)
options.caret = true;                 // рамка 8×17 в конце имени
options.background = "PLATE";         // "" = чёрный холст
options.fade_lut = true;              // точные таблицы 0x682f90
options.fade_lut_level = 11;          // 11 = тождество
options.fade_lut_dump = "hud_lut.bin";// или fade_lut_table

std::vector<std::uint32_t> rgba;      // 0xRRGGBBAA, 320*200
int width = 0, height = 0;
gm::NewKeysetRenderStats stats;
std::string error;
if (!gm::render_new_keyset(game, options, rgba, width, height, &stats, &error))
    // error начинается с "new_keyset_render: "

gm::new_keyset_name(options);         // текст, который рисуется (NUL и лимит 15)
gm::new_keyset_text_x(66);            // 65  (98 - 66/2)
gm::new_keyset_caret_width('M');      // 16  (8 по умолчанию, 6 у 'I')
```

`render_new_keyset` при отказе очищает `rgba`, ставит `width = height = 0` и
обнуляет `*stats`; `stats`/`error` могут быть `nullptr`. Запись в установку не
происходит: каталог игры только читается (открывается `FRONTEND/BMP.IDX`).

Числа кадра (`NewKeysetRenderStats`): `rows` — доказанная длина списка
(`0x67f10c = 1`); `chars` — сколько символов имени реально нарисовано (после NUL
и лимита 15); `truncated` — сколько символов лимит отбросил; `ink_pixels` —
уникальные пиксели, закрытые **глифами** (рамка каретки — не чернила, как
`MENUARRW` у `keycfg_render`); `missing_glyphs` — символы без глифа в атласе
(пропускаются, не фатальны); `arrows` — всегда 0 (`MENUARRW` в `0x48ebb0` не
вызывается).

## 2. Доказано (листинг `gundx.exe`, данные `FRONTEND/BMP.IDX`)

### 2.1. Обработчик есть, но в таблице диспетчера его нет

`UI_SCREENS.md` §2 ставит экрану 31 «handler —», `rows 1`, `step 0`. Как и у
экрана 15, «—» означает только отсутствие записи в таблице диспетчера
`0x4883d8`; кадр целиком рисует одна функция **`0x48ebb0`** (`sub esp,0x20` в
`0x48ebb0`, `ret` в `0x48ed0f`) с единственным аргументом — **индексом набора
клавиш**:

| сайт | вызов | что видно |
|---|---|---|
| `0x48ebb3` | `mov [0x67f10c],1` | `rows 1` |
| `0x48ebbd` | `mov [0x662d58],0` | `step 0` |
| `0x48ebca` | `call 0x486050` | копия `PLATE` 196×131 в буфер композиции `0x6865f8` (6419 dword) |
| `0x48ebcf` | `call 0x485dd0` | заголовок (ниже) |
| `0x48ec8b` | `call 0x485d40` | рамка каретки (ниже) |
| `0x48eca5` | `call 0x47faf0` | имя, шрифт 3 (ниже) |
| `0x48ecbc`..`0x48ed01` | `call 0x485dd0` ×4 | четыре подсказки (ниже) |

Кадр рисуется из двух мест: `0x48d1a5` (переход в состояние 31 из списка
наборов; там же обнуляется поле имени, §2.6) и `0x48f432` — ветка состояния 31
функции ввода `0x48efc0` (`cmp eax,0x1f` в `0x48f30e`), пока правило ввода
возвращает 0 («перерисовать»).

### 2.2. Заголовок

`NAME OF NEW KEY SET` — строка `0x4bdd8c`, пушится в `0x48ebd7`; шрифт `5`
(`0x48ebdc`), `centered = 1` (`0x48ebd5`), `x = 0x26` (`0x48ebd3`, игнорируется
центрированием), `row = 0xe` → **y = 14** (`0x48ebd1`), `item = -1`
(`0x48ebcf`). Ветка `centered` в `0x485dd0` считает `x = (196 - width)/2`
(`0x485de1`..`0x485dfa`) — в тесте это 44 при ширине 107.

### 2.3. Строка имени

* Текст — поле `name[16]` записи набора `0x6c2058 + set*0x108` (`shl esi,5;
  add esi,ecx; lea edi,[esi*8+0x6c2058]` в `0x48ebf1`..`0x48ec01`).
* Шрифт — **3** (`push 0x3` в `0x48eca3`), т.е. `FONTS2`, ячейка 16×16
  (`TEXT_LAYOUT.md` §2.1); `y = 28` (`push 0x1c` в `0x48ec9a`), страйд 196
  (`push 0xc4` в `0x48ec95`), последний аргумент 0 — 8-битный буфер
  (`0x47fb4b`..`0x47fb61`).
* `x` — `98 - width/2`: ширина берётся тем же измерителем `0x47fa50`
  (`0x48ec49`), затем `mov esi,0x62` (`0x48ec60`), `sub esi,eax` (`0x48ec6a`)
  после `sar eax,1` (`0x48ec65`). Это **не** `(196-width)/2` из `0x485dd0`:
  для нечётной ширины значения расходятся на 1 пиксель, поэтому в модуле стоит
  буквальная формула.
* Порядок: рамка каретки (`0x48ec8b`) рисуется **до** имени (`0x48eca5`),
  поэтому глифы перекрывают её.

### 2.4. Каретка

Каретка — не символ буфера (в отличие от экрана 15) и не спрайт, а **рамка**,
которую рисует `0x485d40`:

* `x` — `name_x + width(префикса)`: локальный буфер `[esp+0xc]` заполняется
  копией символов имени, пока индекс меньше `[0x661770]` (позиция курсора,
  `0x48ec0c`..`0x48ec40`), затем его ширина прибавляется к `name_x`
  (`0x48ec6c`..`0x48ec7a`);
* `y` — **27**: `dest = 0x687aa4 + ...`, а `0x687aa4 - 0x6865f8 = 0x14ac =
  27*196` — верхняя строка рамки на 1 пиксель выше ячейки глифа (28);
* высота — **17** (`push 0x11` в `0x48ec82`), т.е. строки 27..43;
* ширина — **advance символа под курсором**: `mov ebp,0x8` в `0x48ebfc`,
  `0x10` для `M`/`W` (`0x48ec3b`) и `6` для `I` (`0x48ec34`). При курсоре в
  конце имени символа нет (NUL), поэтому ширина 8. Форма — **полая**: `0x485d40`
  заливает верхний ряд шириной `w`, затем левый и правый столбцы на `h-2`
  строк, затем нижний ряд (`0x485d50`..`0x485dba`); для 8×17 это 46 пикселей;
* **цвет** — `[0x5a4a74]` (`0x48ec77`), а `0x485d40` берёт младший байт
  пятого аргумента как индекс палитры (`mov dl,[esp+0x14]`, `0x485d44`).
  `0x5a4a74` — счётчик тиков главного цикла (`+1` за тик в `0x44bdda`,
  `INIT.md` §3), поэтому в оригинале рамка **меняет цвет каждый тик**; это
  единственная часть кадра, которую нельзя воспроизвести статически (модель —
  §3.2).

### 2.5. Подсказки

Четыре строки, шрифт `0` (`push 0x0`), `centered = 0`, `x = 0x1a = 26`,
`item = -1`, поэтому `y = row`:

| строка | VA | строка-аргумент | y |
|---|---|---:|---:|
| `TYPE A NAME FOR` | `0x4bdd7c` | `push 0x30` `0x48ecb1` | 48 |
| `THE NEW KEY SET` | `0x4bdd6c` | `push 0x3a` `0x48ecc8` | 58 |
| `PRESS ENTER TO CONTINUE` | `0x4bd6d4` | `push 0x57` `0x48ecdf` | 87 |
| `PRESS ESC TO ABORT` | `0x4bd6c0` | `push 0x66` `0x48ecf6` | 102 |

### 2.6. Поле: лимит, ввод, значение по умолчанию

* Правило ввода — `0x405b20`, вызывается из ветки состояния 31 с аргументами
  `(name, 0x10, &0x661770)`: `push &0x661770` в `0x48f31c`, `push 0x10` в
  `0x48f323`, `call 0x405b20` (`0x48f332`).
* Вставка запрещена, когда `strlen >= 15`: `lea eax,[ebx-1]` (`0x405c1d`),
  `cmp ecx,eax` / `jge 0x405c99` (`0x405c20`/`0x405c22`). Значит, поле 16 байт
  держит **не больше 15 символов** плюс NUL.
* Принимаются `A-Z`, `0-9`, пробел и `-` (`0x405bef`..`0x405c0b`); `a-z`
  приводятся к верхнему регистру до проверки (`0x405b8f`). Остальное
  обрабатывают Backspace (`0x8`), Delete (`0xb1`/`0xa3`), Home/End
  (`0xab`/`0x9b`), стрелки (`0xac`/`0x9d`), Enter (`0xd`/`0xa4` → 1) и Esc
  (`0x1b` → −1).
* При **входе** в состояние 31 поле обнуляется: `mov BYTE PTR [ebp+0x0],0` в
  `0x48d19b` — свежий диалог рисует пустую строку, каретка в позиции 0.
* Если поле принято **пустым**, в него копируется `NEW SET` — строка `0x4bdd3c`
  (`push 0x4bdd3c` в `0x48f3df`, `push 0x10` в `0x48f3dd`, `strncpy` `0x403190`
  в `0x48f3ec`), после чего игра переходит в редактор (`mov [0x4bc440],0x22` в
  `0x48f409`).

### 2.7. Ассеты

`FRONTEND/BMP.IDX`: `PLATE` 196×131 (копия `0x486050`, обязательна — на ней
компонуется кадр), `FONTS4` — грани 5 (заголовок) и 0 (подсказки), `FONTS2` —
грань 3 (имя). Все палитры BMP побайтово совпадают (общая палитра фронтенда:
`(155,15,15)` индекс 53, `(19,15,15)` индекс 144, `(239,239,239)` индекс 142,
`(255,255,255)` индекс 96). Все три атласа и `PLATE` проверяются даже при пустом
`background`, потому что оригинал компонует кадр на копии платы.

## 3. Модель (что решено не буквально)

### 3.1. Плата не рисуется неявно

Как и у соседних рендереров (`SAVE_NAME_RENDER.md` §3, `KEYCFG_RENDER.md`):
`0x486050` копирует `PLATE` в буфер композиции, но куда этот буфер блитится на
320×200, здесь не доказывается. Поэтому `PLATE` — выбор вызывающего
(`background = "PLATE"`), по умолчанию холст чёрный; текст и рамка клипаются к
196×131 — это доказано адресом назначения.

### 3.2. Цвет каретки — модель

Оригинал передаёт в `0x485d40` счётчик тиков `[0x5a4a74]` (§2.4), т.е. индекс
палитры меняется каждый тик. Воспроизвести это статически нельзя, а «случайный»
цвет сделал бы кадр недетерминированным. Модуль рисует рамку фиксированным
индексом `kNewKeysetCaretIndex = 96` — чистый белый `(255,255,255)` общей
палитры фронтенда. Это **единственное** место кадра, где пиксель не доказан
кодом; в тесте оно проверяется как число (46 пикселей рамки) и через
`caret = false`.

### 3.3. Курсор стоит в конце имени

`options` не содержит позиции курсора (`[0x661770]`): API отдаёт только текст
и `caret`. Модуль рисует каретку для позиции в конце имени — это ровно то, что
оригинал делает в свежем диалоге (`0x661770` = 0 при пустом поле, `0x48f3dd`)
и при обычном наборе (курсор всегда после последнего символа). Доказанное
правило ширины для позиции **внутри** имени (8/16/6, §2.4) вынесено в
`new_keyset_caret_width()` и проверено тестом, но середина имени не
моделируется: стрелки и Home/End — сторона ввода.

### 3.4. Значение по умолчанию — `NEW SET`

Эскиз среза упоминал `NEW KEYS`; в бинарнике такого текста нет. Доказанный
дефолт — `NEW SET` (`0x4bdd3c`): это подстановка для принятого пустого поля
(`0x48f3df`), и она стоит в `options.name` по умолчанию (как `A SAVED GAME` у
экрана 15). Свежий диалог — `name = ""` (поле обнулено в `0x48d19b`).

### 3.5. Клип широкого имени

`x = 98 - width/2` может быть отрицательным: 15 символов `M` дают ширину 240 и
`x = -22`. Оригинал в этом случае пишет в буфер композиции по отрицательному
смещению, т.е. **в предыдущую строку** (26-ю) — это артефакт, а не дизайн.
Модуль клипует прогон по левому краю полосы (`x >= 0`), как `keycfg_render` для
конфликтной строки; тест печатает `x=-22`, bbox `(1,29)-(194,41)`.

### 3.6. Прочее

* Цвета берутся из палитр атласов, не пересчитываются (`MENU_RENDER.md` §3).
* `rows`/`step` — доказанные 1/0; `arrows` всегда 0.
* Имя приходит от вызывающего; таблица наборов `0x6c2058` модулем не читается.

Варианты:

Fade (точные таблицы `0x682f90`, собранные в памяти из `FRONTEND/GAMEPAL`):
уровень 11 — **0/64000** отличий от кадра без fade (побайтово); 12..15
отличаются от 11 на **15 878 / 24 394 / 24 633 / 25 514 px**, соседние пары —
**17 440 / 22 584 / 20 631 px**; `ink` не меняется; уровень 13 детерминирован.

Негативы (все тексты `new_keyset_render:` с очищенным буфером): пустой каталог,
каталог без `FRONTEND/BMP.IDX`, архив без `PLATE`, без `FONTS4` (грани 5/0),
без `FONTS2` (грань 3), `PLATE` не 196×131 (8×16 `CHECK`), неизвестный
`background`, `fade_lut` без таблицы/дампа и отсутствующий дамп. Два прогона
поставочной установки побайтово равны.

## 5. Точный fade `0x682f90`

Тот же путь, что у `save_name_render`/`keycfg_render`/`play_options_render`:
таблицы `0x682f90` — это индекс → индекс, поэтому `render/hud_lut.h::map`
применяется к индексу палитры каждого нарисованного пикселя **до** поиска цвета
(`PaletteFade` в `.cpp`). Так гаснут вместе фон, рамка каретки и глифы, а
нетронутый чёрный холст остаётся чёрным (у него нет индекса). Таблица берётся
готовой (`fade_lut_table`, например из `build_hud_lut`) или из дампа 4096 байт
(`fade_lut_dump`, `HUD_LUT.md` §2); без того и другого — текстовый отказ
`new_keyset_render:`, а не молча непогашенный кадр. Уровни 0..15 берутся как
есть, поэтому 12..15 реально светлеют, а не клампятся к 11.

## 6. Проверка

```sh
export PATH=$HOME/tools/cmake-4.4.4-linux-x86_64/bin:$HOME/tools/bin:$PATH
cmake --build build/sandbox --target gm_new_keyset_render_tests -j 4
ctest --test-dir build/sandbox -R '^new_keyset_render$' --output-on-failure
python3 regress.py --mirror --json
```

Тест печатает блоги заголовка, четырёх подсказок, имени и рамки, `ink`/`diff`
числа и все отказы; при отсутствии установки пиксельные прогоны пропускаются
(`new_keyset_render: game not installed`), модельные проверки остаются.

## 7. Ограничения

* **Нет ввода.** Правило `0x405b20` (фильтр `A-Z`/`0-9`/пробел/`-`, регистр,
  Backspace/Delete/Home/End/стрелки, Enter/Esc) не реализовано и не читается:
  модуль получает готовое имя. Позиция курсора `[0x661770]` тоже не в API
  (§3.3).
* **Нет звука.** UI-звуки (`UI_SOUNDS.md`) не проигрываются.
* **Набор не создаётся.** Модуль не пишет в `0x6c2058`, не копирует `KEYCFG`
  (`0x484cc0`/`0x4859c0`, `0x48f3aa`..`0x48f3c9`), не считает
  `[0x4bc5d4]` (число наборов) и не переключает состояние в редактор 34
  (`0x48f409`): это только кадр.
* **CLI — есть (срез 24).** `--new-keyset [--new-keyset-text NAME]
